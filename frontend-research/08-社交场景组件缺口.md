## 一、结论与旧稿更正

**此前建议三个来源：AffectUI + Arc UI + Shadcn UI Kit；当前用户已选择 AffectUI + Shadcn UI Kit。** 下列三方职责描述用于保留当时的调研依据。

- AffectUI：AI 对话、逐步询问、引导表单和处理状态。
- Arc UI：真人聊天线程、嵌套评论、提问式反馈板和 Tinder 式左右滑卡。
- Shadcn UI Kit：社交信息流整页、群聊整页，以及商品目录式作品列表和详情。

若想先控制来源数量，可以用 **AffectUI + Arc UI** 起步：Arc Pro 的 Product listing 和 Feedback board 提供目录页与提问板骨架；普通信息流及会话列表再组合。若更看重现成页面，则加入 Shadcn UI Kit，减少页面组装。Motion 是 Arc 所列的运行时依赖，无须为同一滑卡交互额外采购一套动效产品。[A1][A2][A3][A4][A5][A6][K1][K2][K3][K4a][K4b]

旧版本“这个赛道基本是空的”“没有一个做真人聊天”“所有库都没有评论”“社交组件只能全部自建”等结论撤回。公开资料已经证实多个反例，不能把没有核查到当作不存在。此次还纠正以下混淆：

| 旧判断 | 本次核实结果 |
|---|---|
| Arc UI 只有泛用动效和 AI chat | 有免费 Comment thread、Chat thread、Card stack，以及 Pro Feedback board |
| AffectUI 没有评论 | 有免费 Comment Thread 和 Pro Comments Panel；用途主要是对象/文档旁的协作 |
| React Bits 都是背景动效 | 免费站偏创意动效；Pro 另有 Application UI，列有 Comments、Chat、Editor、Onboarding |
| Shadcn UI Kit 只有营销和后台 | 有 Social Media App、Social Media Post、个人/团队/群聊区块 |
| BeUI 没有真人聊天 | Pro 有 Web Messaging；另有文档协作评论，Mobile Social 则属于 React Native |
| ShadcnSpace 没有真人聊天 | 有标为 Free 的 Chat 01 应用区块 |

正确的缺口是：**现成界面组件很多；发布、权限、分页、消息同步和业务状态仍要接入本项目接口。** UI 中的“已读”“删除本人评论”“发送成功”演示，不能当作服务端已经实现。

## 三、重点解决场景 4：按帖子形态选组件

### 3.1 想做论坛楼层、楼中楼：先看 Arc Comment thread

官方 API 明确提供：

- `ThreadComment.replies` 表示嵌套回复；`maxDepth` 默认 2，可配置。
- 回复展开/折叠、表情反应、@提及、原地编辑、删除和解决/重开线程。
- `comments` / `defaultComments` 与 `onCommentsChange`，可用于受控数据接入。
- 删除有回复的评论时保留占位，避免线程断裂。
- 本地化 labels、触屏按钮与减少动效说明。

这是真正的评论线程组件，可改造成帖子详情的回复区。默认风格偏对象评审/协作，论坛是否需要“已解决”、如何显示根帖，要自行组合。文档明确提醒：前端依据 currentUser 展示编辑/删除按钮，**服务端仍须验证权限**。长线程没有替你实现服务端分页。[A1]

**获取：免费、开源；官方索引说明免费项采用 MIT。** 它已经足够支持第一版评论区原型，无须先购买所有评论类套件。[A1][A6]

### 3.2 想做“发布问题 → 列表 → 回复”：看 Arc Feedback board

这是 **Arc Pro 的产品反馈板**，官方明确有：

| 已有结构 | 可借给提问/讨论页面的部分 |
|---|---|
| New request + title / details / category | 发布表单的标题、正文、分类 |
| 输入标题时提示相似请求 | 避免重复问题的交互形态；真实检索需接服务端 |
| Top / New、状态筛选、投票 | 热门/最新、筛选与赞同的 UI 骨架 |
| 展开请求、阅读和添加 comments | 详情展开与回复输入 |
| `onSubmit` / `onVote` / `onComment` | 接入业务用例的回调位置 |

它适合轻量提问板或想法征集。**原始数据模型仍是 feature request**：状态是 review/planned/progress/done，评论是平面数组，没有证据表明包含独立答案实体、采纳最佳答案、悬赏或版主管理。把它改成正式问答产品需要改模型和用例，不能只改“反馈”为“问题”就声称完成。[A4]

若不买 Pro，可以用 Arc Rich text editor + 基础标题/分类表单 + Comment thread 组合发帖和回复；编辑器是免费项，官方支持 Markdown 快捷输入、工具栏与 HTML/Markdown 输出。[A8]

### 3.3 想做朋友圈、微博式广场：先看 Shadcn UI Kit

两个入口应分别看：

1. **Social Media App**：公开演示中有 Create Post 入口、内容流、作者、图片、点赞数、评论入口和推荐关注区域。这证明整页骨架存在；本次没有点开创建弹窗验证其全部能力。[K1]
2. **Social Media Post 3**：官方逐项描述了评论输入、附件/语音/表情按钮、评论作者和时间、赞、Reply、查看回复与更多评论入口。它更适合直接拆成一个帖子卡片。[K2]

建议用 Kit 管“帖子卡片与信息流”，Arc Comment thread 管“展开后的回复区”。两个产品都有评论外观，采用时选定一份组件作为项目公共实现，统一字体、间距、圆角和主题。**这是组合建议，未做安装兼容性测试。**

Social Media App 的演示推荐人物区不能直接照搬为全站人物推荐。本项目中，发现/推荐只能基于服务端验证的当前活动；广场的跨活动联系仅来自合法公开帖子作者入口。

### 3.4 其他可选评论来源

| 来源 | 本次证据 | 判断 |
|---|---|---|
| 21st → Efferd 的 Comments | 页面给出 React/Tailwind 用法、回复、头像、删除本人条目、评论/回复表单和回复加载骨架；组件源文件需免费账号 | 适合只补一块评论；逐项确认许可。21st 是来源平台，不能由此认定 Efferd 官网售卖完整论坛套件 [C1] |
| React Bits Pro → Comments | 官方目录及 sitemap 确认 6 个 Comments 条目，同时有 Chat 6、Editor 5、Onboarding 7 | 值得候选；本次公开抓取未呈现条目完整行为，不承诺每个都有楼中楼/编辑/持久化。App UI 属 Pro 及以上，不是免费 React Bits [R1][R2][R3] |
| AffectUI → Comment Thread / Comments Panel | Thread 是一条讨论及回复；Panel 有筛选、解决、输入和 /edit 命令入口 | 更适合作品/文档旁 AI 协作。Panel 官方明确不用于长篇嵌套讨论，不作为主论坛首选 [F6][F7] |
| BeUI Pro → Live Collaboration | 文档旁锚定评论、回复、解决 | 适合协作文档，不当作通用论坛；Mobile Social 则是 React Native，不能视作现成 Web 组件 [B2][B3] |

**不应误认的相邻区块：** Shadcnblocks 的 Community 是社群渠道/邀请展示，Social Media Trending 主要是营销/商品页的社交媒体素材；两者名称不能证明有站内发帖回帖。Product Reviews、Testimonials 和 Social Proof 也需要区分商品评价、营销证明与用户论坛。[S1][S2]

## 四、真人聊天和滑卡的关键发现

### 4.1 真人聊天确实有多个来源

| 来源 | 适合怎样采用 | 边界 |
|---|---|---|
| Arc Chat thread，免费 | 已有主应用壳，单独补私聊或团队讨论线程 | 有消息状态、输入与回调；没有虚拟化，长历史要分页；附件需接真实上传 [A2] |
| Shadcn UI Kit Chat UI 3 / 8，Pro | 想少写团队/群聊整页 | 官方说明块运行在本地 state，需要接数据与实时层；8 明确是 Group messenger [K3] |
| Shadcn UI Kit Soho，付费模板 | 想从独立聊天应用起步 | 是单独整站模板，包含样例状态管理；未接后端；不必与 Chat UI 一起购买 [K5] |
| BeUI Pro Messaging | 喜欢消息发送、回执、表情等细节动效 | 演示有私人聊天；本轮未确认完整群管理流程 [B1] |
| ShadcnSpace Chat 01，页面标为 Free | 想要低成本会话列表 + 消息 + 附件侧栏的整页骨架 | 前端应用壳，需接服务端 [P1] |
| TailAdmin Chat | 用户已经有 TailAdmin 授权，可先检查现有包并复用 | 官方演示是人际聊天；本轮只核公开 Next.js demo，用户 React 包的具体版本和授权覆盖未读取 [T1] |

BoardUI 的 Multi-agent Chat 和 ReUI 的 Echo 则明确面向 AI；不能用它们证明已经有人类群聊。ReUI Echo FAQ 还明确说明回答为模拟生成、会话无后端持久化。[D1][E1]

### 4.2 Tinder 式浏览优先 Arc Card stack

其文档直接包含 `tinder swipe` 关键词，并提供 `onDecide(item, left/right)`、`onUndo`、自定义卡片内容和空态。它支持拖动、按钮与键盘，减少动效时使用淡入淡出。[A3]

React Bits 免费版 Stack 支持拖拽/抛卡/点按轮换，抛出的卡会归到牌堆下方；适合展示，但不能把它等同于有左右业务决定与撤销的推荐队列。若只需浏览可选 Stack；若要跳过/保留优先 Arc。[R4]

Motion 提供底层 drag、约束、速度和手势事件，自行实现也可行；既然 Arc 已有该语义组件，第一版不必从底层手势重新开发。[M1]

**在本项目中：** 卡片只装入当前活动合法候选，候选不足如实结束；不跨活动补数。手势用作浏览或明确标示的本地选择；收藏、好友申请等动作要映射到已批准的业务流程，不能把右滑默认当作申请或自动匹配成功。普通浏览保持 0 次 LLM 调用。

## 六、此前组合与采购建议（当前执行以用户双库选择为准）

### 方案 A：组件来源较少

**AffectUI + Arc UI**。Arc 免费部分先试 Comment thread、Chat thread、Card stack、Rich text editor；确实要 Feedback board 和 Product listing 时再考虑 Arc Pro。列表壳、信息流和作品详情需要组合，主题也需要对齐。

### 方案 B：少写整页的此前候选

**AffectUI + Arc UI 免费组件 + Shadcn UI Kit**。

| 页面或职责 | 选定来源 |
|---|---|
| AI 交谈与十步引导外观 | AffectUI |
| 私聊/讨论线程 | Arc Chat thread；若用 Kit 群聊整页，则保留其中一套线程组件 |
| 消息列表/群聊整页 | Kit Chat UI 3 / 8；已有 TailAdmin 页面可先评估复用 |
| 广场信息流/帖子卡片 | Kit Social Media App / Social Media Post |
| 帖子评论区 | Arc Comment thread |
| 发布帖子/提问 | 基础表单 + Arc Rich text editor；若要带列表的反馈板，可额外选择 Arc Pro Feedback board |
| 商城式作品列表/详情 | Kit Product List / Product Details |
| 人选滑卡 | Arc Card stack |

没有必要先把 React Bits Pro、Shadcnblocks、Shadcn Studio、ShadcnSpace 都买一遍。若对 Kit 的帖子外观不满意，再对比 React Bits Pro Comments 的实际预览和许可包；当前证据不足以把它排在 Arc 的已明确 API 之前。

**用户已获授权的只有 TailAdmin（按用户提供的信息）。** “站内购买可开通”不证明其他库已经授权；官方免费项、Pro 源码与第三方渠道权益要分开核对。本次不提供未经统一复核的套餐价格或总预算，避免把促销价和不同访问层级混算。

## 七、集成约束与验证范围

组合建议遵循项目 [architecture-patterns](../.agents/skills/architecture-patterns/SKILL.md) 的界面适配层边界：组件暴露用户事件，应用用例编排，服务端验证权限与领域规则。没有新增微服务或改变既定技术方案。

- 保持 Next.js / React / TypeScript 主应用与 FastAPI 模块化单体；不因模板附带示例登录/存储而迁移后端。
- AffectUI 要求 React 19，组件自带样式；Arc 使用设计 token、CSS modules、Motion；Kit 使用 shadcn/ui、Tailwind。相同 shadcn CLI 安装方式不等于同一主题或零依赖冲突。[F1][A6][K3]
- 主题变量、暗色、焦点、中文输入法、触屏和 reduced motion 要在真正安装后联合验证。本次没有做安装/运行兼容测试。
- 按现有导航“发现 / 广场 / 消息 / 个人”装配；不复制模板的后台菜单当成产品导航。
