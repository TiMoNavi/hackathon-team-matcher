## 关键边界

- **R03 活动隔离**：普通发现、随机浏览、搜索和 AI 推荐只查询当前有效活动；不能跨活动补足卡片。广场公开帖的作者入口允许跨活动查看获准画像和申请好友，不开放全站用户发现。
- **逐条可见性**：authenticated 为所有登录用户通过合法入口可见，friends 为所有有效好友动态可见，private 为仅本人。普通画像不按每位好友另建授权；联系人独立选择与授权。
- **本人控制画像**：GitHub 与邮箱验证码登录，邀请加入活动；全局画像与活动偏好分别保存。原始资料私有数据库存储，无自动过期；只有本人导入或主动重编辑后按需使用，不定时后台重跑 AI。
- **先导入再补缺**：简历上传与 GitHub 导入是首期必备，放在首个资料页面顶部；GitHub 首次注册自动关联本人公开来源，不再粘贴主页。先预填关键信息再确认补缺，手填为兜底；后续登录不自动重抓。
- **推荐有界**：默认最多 200 条合并召回 → 24 条最小候选摘要送模型 → 最多 5 张结果，不足如实展示。普通列表、筛选、翻页和随机浏览为 **0 次 LLM 调用**。
- **操作由人确认**：AI 可整理资料、起草内容和解释推荐；发送好友申请、接受、发消息、发布与联系人授权由普通业务 API 执行。
- **首日可以协作**：满足对象及活动资格即可发布、发送合法外链和开放讨论，不按注册不足 24/72 小时禁止正常使用；限流按统一配额和真实行为执行。
- **预算与失败一致**：固定推荐最多 2 次；自然语言无澄清最多 3 次、有澄清同一 run 最多 5 次且最多三轮问题。预算不足明确报错，用户可主动转普通发现。

## 目标技术方案

目标为 **Next.js / React / TypeScript + FastAPI 模块化单体 + PostgreSQL + Redis/worker**。推荐按需要接入 pgvector 与独立 embedding 适配器；模型调用通过服务端适配器，不在浏览器保存密钥。
