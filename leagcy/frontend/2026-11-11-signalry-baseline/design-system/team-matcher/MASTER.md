## 保留的视觉特征

**明亮、有活力、带有明确 AI 产品气质。**

- 白色和浅薰衣草色占主要面积，紫色承担品牌和主操作。
- 青柠色少量用于标记、重点和局部装饰，搭配深色文字。
- 标题字重有力，页面留白充分，主要展示区使用 24px 左右的大圆角。
- 对外介绍和登录欢迎区可沿用居中首屏、浅紫渐变、细网格与大幅产品预览。
- 少量深夜紫区块用于集中强调能力或展示辅助内容，控制其占比。

本次选择来自用户指定的模板，优先于之前技能搜索生成的松绿方案。应用内容组织沿用当前已批准交互设计。

原模板主视觉还包含 `#E4DEFF → #F4F1FF → #FFFFFF` 的首屏渐变和 56px 网格。本样张保留该语言；正式应用的连续列表与聊天区域用稳定的纯色背景。

表单输入边界需清楚可识别。样张另设 `input-border` 为 `#9690AD`，这是应用可用性适配，不冒充原模板值。深色区域的辅助文字用单独的浅色变量。状态仍须有文字，不能仅用颜色区分成功、待确认和可见性。

## 字体、间距与形状

- 原模板英文标题使用 **Bricolage Grotesque**，英文正文使用 **Inter**。中文按同一字体栈回退至苹方 / 微软雅黑；不假设英文字体含中文字形。 样张已本地保存两种字体的 Latin 子集与 OFL 许可文本，运行时无需请求 Google Fonts。
- 对外介绍大标题参考原模板 38–68px 的响应式比例；中文按实际行长调整。应用页面标题 24–32px，卡片标题 18–20px，正文 16px，辅助说明 13–14px。
- 原模板紧字距主要适用于英文大标题。中文正文保持正常字距，行高约 1.6–1.75。
- 内容卡片 20–24px 圆角，基础组件以原模板 `--radius: 0.75rem` 为起点。人物和想法通过内容结构区分，不延用此前胸牌色带与便笺小圆角两套视觉。
- 对外页面借鉴原模板的大留白；应用内列表采用更紧凑的 16–24px 内容间距。移动端保持 16px 外边距。
- 控件和图标使用现有 Kit / Lucide；AffectUI 统一套用该主题。普通列表保留清楚的边界，轻紫色阴影用于浮起的预览或交互层。

## 页面如何沿用同一种风格

### 发现

四主导航沿用 **发现 / 广场 / 消息 / 个人**。活动选择器独立于主导航，持续显示当前活动。普通发现默认展示「想法」网格，另有「人选」切换；AI 推荐保持独立入口。

```text
桌面
┌──────────┬────────────────────────────────────────┐
│ 品牌     │ 当前活动选择器                         │
│ 发现     │ 发现                 AI 推荐 / 发布想法 │
│ 广场     │ 想法 / 人选          对应类型的筛选     │
│ 消息     │ [内容卡] [内容卡] [内容卡]             │
│ 个人     │ [内容卡] [内容卡] [内容卡]             │
│          │ 上一页 / 下一页                        │
└──────────┴────────────────────────────────────────┘

手机
┌──────────────────────────┐
│ 当前活动                 │
│ 发现   AI 推荐 / 发布想法 │
│ 想法 / 人选   筛选       │
│ [内容卡]                 │
│ [内容卡]                 │
│ 上一页 / 下一页          │
│ 发现  广场  消息  个人   │
└──────────────────────────┘
```

人物卡按「头像和昵称 → 当前活动的角色/目标 → 最多三项能力 → 一句介绍 → 明确操作」排列。学校、年龄、MBTI 等只在本人确认可展示且有必要时出现，不把它们做成所有人的必填徽章。

想法卡按「想法标题 → 解决什么问题 → 当前阶段 → 需要的贡献 → 发起者 → 详情入口」排列。普通网格对齐等高，详情展开完整内容。

AI 推荐结果沿用同一套人物/想法语言，额外显示真实推荐依据，例如能力互补和本次目标。没有来源就不显示，不编造匹配百分比。卡片上的「添加好友」与「申请加入讨论」保持独立；浏览、滑动或略过不等于已经发出申请。

### 广场

用更接近对话的信息流表现：头像、正文和少量分隔。帖子标明「公开广场」或对应活动范围，保留现有范围切换。尽量减少多层卡片套卡片。

### 消息与想法讨论

桌面为会话列表与聊天区两栏，手机进入完整聊天页。想法讨论顶部展示所属活动与想法名称；私聊不因切活动消失。本人消息用浅紫，其他人的消息用白色或中性背景。AI 明确标注身份，用稍弱的底色和可折叠内容呈现；不伪装成真人。

### 首次引导和个人资料

引导使用一问一答的轻对话节奏，简历与 GitHub 在首个资料页提供清楚入口，并保留手动补充。导入后先展示可修改的资料条目；「AI 整理中」「待你确认」「已确认」分别呈现。十步流程可保存退出，公开范围与必填状态分开表达。

个人页优先展示「别人会看到什么」，提供非好友登录用户、好友、本人三个预览视角。字段的「登录用户可见 / 好友可见 / 仅自己」用文字与图标共同说明；活动发现范围与字段可见范围分别显示。

## 交互语气和动态反馈

- 使用具体动词：「查看想法」「添加好友」「发送申请」「AI 帮我整理」。同一动作在按钮、确认和反馈里保持同名。
- 关键社交操作展示目标、目的和真实状态。申请待处理用「申请已发送」，收到后端好友成立结果后才能显示「开始聊天」。
- 空状态提供下一步，例如「这个活动暂时没有符合条件的人选。可以调整筛选，或看看活动内的想法。」
- AI 等待状态显示真实阶段，例如「正在整理你提供的资料」；不使用虚构百分比、自动无限轮换的假进度或假结果。
- 普通按下/选中反馈约 120–180ms；抽屉约 180–240ms；滑卡仅作为适用场景的交互反馈。减少动态效果时去除位移，保留状态变化。
- 好友成立的既有「电路接通」反馈可用一次短线条连接表达，仅在真实成立事件后出现，不做常驻电路背景。
- 手机上关键点击区至少 44px，输入和按钮具有可见焦点；滑动操作提供按钮替代。

## 已选组件库如何使用

Shadcn UI Kit 负责基础控件、抽屉、对话框、标签页及聊天布局。AffectUI 只在真实处理中、已完成或需要清楚解释变化的地方补充交互，例如已验证的 thinking-loader。

先查已有 vendor 和文档，再按实际条目组合；保持现有双库来源，不引入其他 UI 套件。统一主题 token、字号和圆角，避免直接保留各模板不同的默认配色。此处是选型方向，不表示本次新增了组件依赖或完成了业务集成。
