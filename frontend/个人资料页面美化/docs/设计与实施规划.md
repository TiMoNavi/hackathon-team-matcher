# 个人主页设计与实施规划

日期：2026-11-12。本文保留初始规划；V1 页面已实现，当前行为与验证见 [V1 实现与验证](V1实现与验证.md)。下文的“本轮”指最初规划阶段。

## 1. 需求理解

访客进入页面，先看见这个人，再逐渐读到他的能力、兴趣、想法和经历。页面需要具备个人作品主页的吸引力，并且让别人容易判断可以从哪里开始交流。

用户已指定的内容顺序与空间关系：

1. Hero 左侧是大幅照片与稳定的身份信息。
2. 右侧有大小不同的详情卡，从照片附近向外发散，像慢速弹幕一样流动、更新。
3. 向下是这个人自己的想法。
4. 然后是正在参加、已经参加过的活动及相关经历。
5. 独立 React 实验，暂不合并，所有产出限定在本目录。

这轮交付理解和规划。后续实现按下述方向展开；动效参数是首轮打样起点，需要以实际画面调整。

## 2. 沿用首页的视觉语言

已对照首页 V6 的桌面与手机首屏截图，并读取主题、字体加载和 Hero 源码。

| 项目 | 本页执行方式 |
| --- | --- |
| 氛围 | 白色与浅薰衣草背景、柔光场、极淡网格、局部青柠强调 |
| 容器 | 沿用 1248px 最大主容器；桌面留白与手机边距按 Signalry 尺度 |
| 首屏比例 | 将 Signalry 的宽窄关系用于约 36% 照片区 / 64% 信息场；扣除列间距后分配宽度 |
| 字体 | 英文展示标题 Bricolage Grotesque，正文 Inter；复用现有本地字体副本，中文逐项验证实际字形和断行 |
| 层级 | 大号姓名、清晰自述、少量身份标签；主信息优先于装饰文字 |
| 卡片 | 以 24px 圆角、细边框和柔和紫色阴影为基础；大小变化服务内容层级 |
| 按钮 | 继承 Signalry 主次按钮，主要操作位置稳定，主按钮高度参考 48px |
| 动效气质 | 延续首页的轻浮动、光影响应、渐隐和慢速滚流 |
| 浏览方式 | 本页采用自然纵向滚动与章节锚点，方便停留阅读长资料；首页的整屏翻页不直接搬入本页 |

用户这次明确指定左右照片与详情，因此 Hero 的构图按本次需求组合，字体、尺度、材质与留白持续对照首页和 Signalry。

示意中的卡片数量和文字仅表达构图，最终以有权展示的实际内容或明确标注的演示数据为准。

### 3.1 左侧照片与身份

- 采用接近 4:5 的大幅人物照片，保留人物完整轮廓与面部空间。首屏的视觉重量首先落在人身上。
- 使用轻微光晕、浅色背景与少量层次，不把照片包进厚重的管理后台面板。
- 姓名、短身份、一句话自述和主要操作保持静止，可以贴近照片底部或紧邻照片排列。
- 照片可有轻微指针视差或倾斜，但保持在小幅度内，文字与操作区保持可读。
- 首版挑选来源明确、可在本地使用的演示素材；实际用户只有小头像时，采用头像与背景组合，避免强行放大产生模糊。
- 本人视角提供编辑入口的演示状态；访客视角主要提供完整资料与合法联系入口。真实社交操作留待后续接入既有流程。

### 3.2 右侧发散资料卡

照片右侧为发散起点，沿上、中、下三条较松的轨迹展开。轨迹外扩的高度与卡片尺寸形成景深，整体方向从人物向右延伸。

**内容层级**

| 大小 | 适合内容 | 首轮桌面参考宽度 |
| --- | --- | --- |
| 小卡 | 城市、角色、兴趣、简短技能组合 | 160–210px |
| 中卡 | 一句话自述、做事风格、近期关注 | 230–290px |
| 大卡 | 一个代表项目、合作期待、本次想做的事 | 310–370px |

- 初始画面就有完整构图，不能等待一轮动画后才出现内容。
- 以约 5–7 张可见卡作为首轮密度目标；资料少时减少卡片数量。
- 卡片不是等大的字段表格。不同内容使用短句、少量标签、小图或项目缩略图，并保留足够空白。
- 主要卡片保持清晰，文字不通过持续模糊表达远近。层次优先用尺寸、位置和阴影表现。
- 稳定身份信息与第一条重点自述无需等轮播；完整资料始终有固定入口。
- 装饰轨迹和光线可以淡淡提示来源，避免把人物主页画成密集关系图。

**动效编排**

| 动作 | 首轮打样参数 / 行为 |
| --- | --- |
| 入场 | 照片先出现，资料卡分批展开；整段约 0.8–1.4 秒 |
| 平移 | 约 12–20px/秒，按路径长度形成约 25–45 秒的缓慢循环 |
| 更新 | 约每 8–12 秒在边缘替换一张卡，各轨道错开；不同时清空全部内容 |
| 替换过程 | 在渐隐区域完成短暂柔焦与淡入淡出，优先保持容器尺寸稳定 |
| 轻浮动 | 约 4–8px 的纵向变化；倾角控制在约 ±3°，不让阅读随卡片摇晃 |
| 悬停 / 键盘聚焦 | 暂停资料场移动，卡片轻抬起；支持查看完整内容 |
| 打开详情 | 保持暂停，关闭详情后恢复到原位置，不重新跳到轨迹起点 |
| 页面不可见 | 离开 Hero 或切到后台标签页暂停连续动画 |
| 减少动态效果 | 切换为静态错落卡片，保留全部内容与操作 |

核心效果是“个人信息从这个人身边慢慢展开”。首先保证漂亮的静态构图，然后增加轨迹和替换。照片与信息场承担主要动效，下方正文以稳定阅读为主。

资料卡的“刷新”指本地展示顺序变化，首版不轮询后端、不调用 AI。移动内容不持续触发读屏播报；循环副本需要 `aria-hidden` 与 `inert`，不能重复进入键盘顺序。

## 4. 下方内容

### 我的想法

采用有封面的作品展陈。第一张重点想法占较大面积，其他想法使用较小卡片，延续首屏的大小对比。

- 展示标题、简述、所属活动，以及数据明确提供的作者或参与身份。
- 封面可使用合规演示素材、项目截图或双库组件的主题化视觉；封面来源需要记录。
- 点开后阅读完整想法，演示版使用本地弹层或详情区。
- 想法是作者表达的内容；项目经历另用对应字段呈现，不能相互冒充。
- 若只有一条想法，则用单张完整卡片；没有内容则采用简洁空状态。
- “招募中”“已完成”“获奖”等标签须有真实来源，不能从想法 active/archived 状态自行推断。

### 正在参加

优先突出当前活动，采用横向视觉卡片。展示活动名称、时间、本人角色、本次目标，以及获准展示的合作需求。

- 当前活动语境与全局画像分开标识。
- 同时参加多项活动时，每张卡保留明确的活动归属；不会将多个活动的目标混成一份个人偏好。
- 第一版的时间与状态由演示数据显式给出；接入前核对 Calendar/活动关系实际提供的信息。

### 过去的活动与成果

采用简洁时间线或逐年分组卡片，重点表达参加过什么、承担什么、留下什么作品。

- 成果图、角色和短说明优先于大段字段。
- 活动关系与项目经历关联需要依据，不凭相似名称自动合并。
- 当前资料没有可靠结束时间或历史关系时，使用“活动经历”作为展示标题，暂不擅自划定“已结束”。
- 点开活动仅进入已有权限允许的详情；独立演示版使用本地详情。

## 5. 手机与阅读体验

桌面采用横向发散，手机重排为“人物 → 核心介绍 → 精选资料 → 想法 → 活动”的顺序。

- 照片优先出现在首屏，姓名与主要操作紧邻；保留足够高度展示核心身份。
- 手机首轮使用静态错落资料卡与手动切换精选内容，避免缩小桌面的多条轨迹。
- 如加入极轻背景漂移，正文保持静止，点击区不随运动逃走。
- 长自述、长名字和中英文混排都需要实际排版；详情可展开，不把重要信息仅放在 hover 中。
- 想法卡和活动卡纵向排列，保证 320px 宽度下没有整页横向溢出。
- 操作区至少 44×44px，保留键盘焦点、弹层焦点管理、Esc 关闭与返回入口。
- 减少动态效果、暂停与静态完整资料入口从第一轮实现。

## 6. 资料与演示边界

首版采用明确标注的虚构人物、想法与活动，只模拟本地交互。后端代码在这轮用于核对已有字段与含义，不接通登录、不触发资料修改或社交写入。

已核对的要点：

- 全局资料与指定活动资料已有区分；城市、技能、兴趣与活动目标分别来自各自范围。
- 只展示确认且对当前访问者获准可见的信息。`authenticated`、`friends`、`private` 的含义沿用现行规则。
- 活动与想法参与关系有独立可见性，不能因为个人主页可以打开就展示全部关系。
- 学校与主主页依用户选定的确认条目；选中条目隐藏或失效时，不能自行找另一个顶上。
- 联系方式保留独立授权读取语义；前端卡片隐藏不能代替后端过滤。
- “正在参加 / 过去参加”需要关系与时间依据。这轮确认了字段来源，不代表已经完成实际接口联调。

进一步业务规则直接引用项目现行文档，不在本目录复制第二套契约。

## 7. 实施顺序

| 阶段 | 交付 | 完成判据 |
| --- | --- | --- |
| P0 理解与规划 | 本文与参考清单 | 已核对首页桌面/手机截图、主题、字段与组件候选；本轮完成 |
| P1 首屏视觉 | 独立 React 应用、单个演示人物、静态与动态 Hero | 桌面左照片右发散成立，手机人物与核心介绍完整；视觉打样优先 |
| P2 完整主页 | 想法、当前活动、过往经历和完整资料入口 | 页面形成连续叙事，内容有主次，空数据与长内容有合理表现 |
| P3 交互打磨 | 卡片暂停/展开、详情、章节定位、本人/访客演示状态 | 鼠标、触摸与键盘都可操作；动态不妨碍阅读 |
| P4 验收与说明 | 桌面和手机截图、动效记录、字体与构建检查、启动说明 | 对照首页确认风格；验证结果如实记录，独立目录可运行 |

实现优先采用与首页相容的 React + TypeScript 环境；Next.js 可作为独立运行外壳，以便复用本地字体和基础组件。正式初始化时从首页已锁定的依赖与本地文档核对，保持独立 package.json、锁文件和端口。尚未选定或验证可用预览端口。

仅在本目录复制必要的组件与资源，保留来源记录；不使用指向参考目录的可写链接。首版拆成照片、资料场、想法、活动等 React 组件，便于后续评审与接入。

## 8. 验收标准

- 1440px 桌面、768px 中等宽度、390px 与 320px 手机都截图核对。
- 首屏一眼看出“人物照片 + 发散资料”，照片面积和资料层级达到预期。
- 与首页对照主题、字体、留白、卡片材质和动效速度；不能只核对紫色。
- 字体同时检查文件加载与实际渲染；中文姓名、自述、标点和长标题单独检查。
- 观察至少一个完整动效周期，检查卡片重叠、循环接缝、刷新突跳与可读停留时间。
- 验证暂停、悬停、聚焦、详情关闭后恢复，以及减少动态效果。
- 验证资料很少、无想法、无活动、长内容和缺失照片等状态。
- 实现后运行类型检查、lint 与构建，并结合浏览器实际画面和交互记录交付。

以上属于后续验收计划，本轮未执行应用构建、浏览器交互或真实业务验证。
