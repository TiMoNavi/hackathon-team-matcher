# 路线 3：独立 Next.js 前端验证

页面已经可以浏览，桌面和手机交互检查通过。此次证明的是两个本地组件来源能在新的 React 前端中共同使用，并能做出一致的发现首页；没有证明 HumHub 的登录、权限、消息或资料接口已经接通。

## 打开与重启

- 地址：`http://127.0.0.1:3193`，也可使用 `http://localhost:3193`。
- 本目录是独立项目，未改原有 HumHub 或其他路线。
- 当前进程 PID 记录在 `server.pid`，启动日志为 `server.log`。
- 生产构建：`NEXT_TELEMETRY_DISABLED=1 npm run build`。
- 启动：`NEXT_TELEMETRY_DISABLED=1 npm run start`。绑定 `127.0.0.1:3193`。
- 已有服务时不要再启动一份；如需停止，仅停止 `server.pid` 中本验证项目的进程。

## 做出的效果

首页采用浅灰绿背景、墨绿色导航、温白卡片与少量浅杏/浅蓝装饰。桌面有左侧导航、活动概览、两列成员和活动侧栏；手机使用单列成员卡与固定底部导航。插画由本地 CSS 和 Lucide 图标组成，不请求外部图片或字体。

页面包含共同要求的活动统计、四位演示成员、角色筛选、姓名和技能搜索、可关闭的详情对话框、本地关注切换、两个想法卡片。广场、消息、个人入口给出明确演示提示，未制作对应业务页面。所有成员及同频度均来自共同演示文件，界面标明“交互演示 · 非真实成员数据”。

## 双库实际使用情况

| 来源 | 本地原文件 | 实际作用 | 源码改动 |
| --- | --- | --- | --- |
| Shadcn UI Kit | `vendor/shadcnuikit/dashboard/components/ui/card.tsx` | 成员、想法及活动共 7 张 Card | 原样复制，SHA-256 一致；通过 className 和主题变量定制 |
| AffectUI | `vendor/affectui/affectui-components/progress-tracker.tsx` | 侧栏“出发前，再近一步”，复选步骤与进度条联动 | 原样复制，SHA-256 一致；覆盖组件提供的 `--ui-pg-*` 变量 |

`metrics.json` 记录确切绝对路径和摘要。没有修改 `components/ui` 内部源码。页面结构、响应式布局、搜索与详情交互由本验证编写，不能把它描述为直接下载并安装了某个完整付费首页模板。没有进行付费包授权、完整资源下载或所有组件兼容性的验证。

实际技术栈为 Next.js 16.3.2、React/React DOM 19.2.8、TypeScript 6.0.3、Tailwind CSS 4.3.3。直接运行依赖另外包含 Lucide 0.522.0、clsx 2.1.1、tailwind-merge 3.6.0。没有添加第三套 UI 库。版本已经锁在 `package-lock.json`。

遇到的实际问题：

1. 最初一次大段中文源码经工具传递时发生 Python 输入编码错误，没有写成文件。改成分段 patch 后完成。这是本次编辑工具问题，不能归因于 Next.js 或组件库。
2. 首次浏览器验收发现默认请求的 `favicon.ico` 返回 404。补齐本地图标并重启本路线服务后，完整桌面与手机检查重新通过。
3. 指标脚本首次运行因传输层换行转义失败；修正字符串写法后采集成功，未影响应用代码。

## 路线难度与后续边界

就“做出这个首页”而言，本路线最直接的好处是不用迁就 HumHub 的旧页面资源和运行周期，两个 React 组件可以直接组合，视觉自由度足够。它同时新增了一套独立构建、发布和运行入口。即使页面做得很快，也不代表完整替换 HumHub 很快。

真正继续做这条路线，需要逐项补上：

1. 确认由 HumHub 继续承载哪些业务，再建立只暴露所需字段的接口适配层。不要让前端直接访问数据库。
2. 实现并验证登录态、会话续期、退出、CSRF/跨域规则，以及 SSR 场景如何安全获取用户信息。
3. 由服务端验证当前活动、成员可见性与关系权限；当前的前端筛选只是演示，不能承担这些权限检查。
4. 将搜索、详情、关注、想法、消息分别接到真实业务用例，覆盖错误状态、分页、异步状态和权限变化。
5. 验证旧页面入口、深链接、插件兼容、上传附件、通知与消息等迁移路径，再决定逐页替换还是全面切换。

这些接口和迁移工作本次都没有做，不能据此声称“HumHub 前端已经重写完成”。如果只是尽快升级首页视觉，本次只能证明该路线有很好的页面表达能力；是否比主题或独立插件更划算，要结合另外两条路线的实测接入成本一起判断。
