# 三路线前端验证共同要求

用户已授权三个子 agent 并行制作验证；仅衡量改造难度与实现效果，不改现有 HumHub 主预览、数据库或业务模块。

页面为“同频 CoLab / AI 创造者周末”的发现首页。四个主入口：发现、广场、消息、个人。使用 shared/demo-data.json 的同一组纯演示数据，页面明确标注“交互演示 · 非真实成员数据”。

视觉方向：现代、精致、温暖的协作社区。温白/浅灰绿背景、墨绿文字、松绿色强调色，少量杏色/淡蓝卡片；优秀字体层级、留白和边界，避免密集后台表格。桌面可有侧导航和右侧活动概览，移动端保持清晰导航。三版信息和功能相同，允许充分发挥各技术路线的视觉能力。

必须实现：活动概览和三个数字；成员卡片；角色筛选按钮（全部、前端、后端、设计、产品）；按姓名/技能搜索；查看成员详情弹窗或侧栏；关注按钮本地切换（不得写真实后端）；两个想法卡片。控件使用语义元素和可访问名称，键盘可关闭详情。桌面 1440x1000、移动端 390x844 均无横向溢出。

资源限定 AffectUI + Shadcn UI Kit，以及路线 1 原生 HumHub/Bootstrap 所需资源；可读 frontend/vendor 源码并按需复制，不得另引入 UI 库。React 路线至少实际使用一个 Kit 组件及一个适合场景的 AffectUI 组件，记录确切源文件和必要改造。原生路线不加载 React，记录同等视觉/交互需要转写的内容。禁止把大批模板无选择地加入 bundle。

路线 1 是真实 HumHub PHP 视图 + Bootstrap/原生资源的主题改造验证；路线 2 是真实 HumHub 模块路由承载的独立 React 文档，用户页不加载 HumHub/Clean/Bootstrap/PJAX 视觉资源；路线 3 是独立 React/Next.js 前端，同样展示这些演示数据。所有业务写操作只在本地演示状态内发生。

各子 agent 仅写自己的 route 目录，不能改 backend/ 或其他 route。主 agent 负责隔离 HumHub 运行环境、模块接入、统一浏览器验收和对照页。使用 shared/context.json 里的目标路径和端口，后端凭据不输出、不传递给其他 agent。

交付 route/REPORT.md 和 route/metrics.json：实际框架、资源来源、改动的文件数/源码行数、依赖、构建字节数（适用时）、测试结果、遇到的问题及解决办法、未验证边界。记录真实耗时与问题，不编造长期成本或完成百分比。不将演示页面宣称为业务已接通。
