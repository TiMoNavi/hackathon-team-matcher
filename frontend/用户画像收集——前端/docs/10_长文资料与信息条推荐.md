# 长文资料与信息条推荐

2026-11-12，第四版。当前入口 http://127.0.0.1:4199/guide 。所有源码、截图、说明和独立审查均在本专项目录。原 /references 的 48 组组件、模板原版与旧样张保留。

## 本次调整的依据

用户指出资料填写不适合大量文本，页面留白过大，桌面推荐不宜依赖拖动，详情希望像纵向冒出的消息条。独立子 agent 先审查第三版，再复查实际第四版页面。

原先的问题在于大封面、重复身份标题与多重滚动。另发现实际功能问题：新草稿输入昵称的第一个字，会使另外两个默认字段消失。第四版统一默认字段初始化，导入自述没有昵称时也提供昵称入口。

## 第三、五、八步：文档工作区

- 左侧小型角色和目录，右侧宽正文。桌面目录跟随滚动，手机目录横向浏览。目录展示每段字数，同名“技能”等段落增加内容摘要。
- 缩短顶部标题和身份展示。样例正文起点约为桌面 458px、手机 550px；原版审查分别约为 800px、1030px。
- 正常阅读使用整页滚动，无固定高度的资料卡。点击正文或编辑按钮即可编辑该段，不再先进入总编辑模式。
- 长输入复用 AffectUI TextArea，原位随原文完整增高；“专注编辑”打开大编辑窗口，只有编辑器内部滚动。明确显示字数，沿用每段 20,000 字上限，可继续添加其他段落。保存完整换行，不把长文提炼成标签。
- 专注编辑进入时聚焦正文并保留光标选择；关闭后内容同步回原位草稿。进入原位编辑定位段首。保存失败继续使用已有明确提示。
- 第五步直接提供逐段可见性与本人／登录用户／好友预览。
- 第八步只显示一份资料，接完整想法计划与本活动设置。其他人视角隐藏本人活动设置及其目录项，避免误导可见范围。下方固定于阅读区域的确认条旁，为右下角角色预留空间。

主要文件：document-workspace.tsx、document-text.tsx、profile-steps.tsx、final-review.tsx、document-flow.css。LongText 统一委托 DocumentText，活动描述、计划修改及来源自述均使用相同长输入能力；聊天发送框仍按消息输入的行为保留有限高度。

## 最后一步：照片与纵向信息条

左侧保留 Shadcn UI Kit 图片卡结构和照片堆。桌面提供“上一张／下一张”和人物缩略入口；照片本身把阅读定位到介绍。手机可额外滑动，但点击入口始终存在。点击只切换候选对象，不发送请求。

右侧取消包围详情的大卡片与重复头像。沿细竖线排列消息式内容，以小连接线和分隔线组织；每组内容从左侧错峰进入。先展示介绍、方向和可以开始的话题，再展示想问的问题与可贡献的内容。

- 轮换的是同一对象的介绍组，对象由用户点击决定。
- 每组根据文字量保留 9–30 秒。悬停、键盘焦点、页面不可见或信息区离开视口时暂停；手动暂停与“展开全部”随时可用。
- 展开全部展示完整文字，不截断正文。系统或页面减少动态设置生效时，直接显示五条完整信息，不自动轮换。
- 切换候选时重置介绍组并清理旧计时器，照片与详情同步。退出中的旧照片不可交互。
- 照片仍明确标注示意配图，不冒充虚构人物真实照片。
- 保留想认识名单、移出本次列表、单人／多人申请确认。想法的关注与讨论申请独立。所有发送仍为本机演示。

主要文件：candidate-deck.tsx、candidate-story.tsx、final-steps.tsx。移动定位继续使用第三版的真实 DOM 锚点；文档和推荐操作区为右下角角色留位，防止角色覆盖按钮。

## 组件与视觉来源

整体使用 Signalry 主题、Inter 与 Bricolage Grotesque，AffectUI 原组件通过 props 和外层样式适配。TextArea、Glow Cloud、Thinking Loader、AI Answer 等原文件未改动。信息条为现有 Motion 运行时的业务组合，并非下载的完整官方消息流模板；第三版 Social Profile 封面已停用。
