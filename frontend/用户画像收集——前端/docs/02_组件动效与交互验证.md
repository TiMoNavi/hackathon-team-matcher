## 2. AI 形象如何对应状态

| 页面状态 | 形象表现 | 用户看到的文字 |
| --- | --- | --- |
| 欢迎、等待选择或输入 | `idle`，缓慢呼吸 | “准备好了”或不显示冗余标签 |
| 任务排队 | 轻度空闲，旁边显示排队状态 | “正在等待处理，可以先离开” |
| 任务处理中 | `thinking`，收束成工作环 | 当前真实阶段，如“正在整理经历” |
| 正在输出文字 | 可用 `speaking` 的波纹形态作为输出动效 | 明确写“正在整理回答”，不显示语音录制或播放承诺 |
| 等待本人确认 | 回到 `idle`，减弱背景运动 | “请你核对一下” |
| 完成 | 回到 `idle`，结果旁一次勾选反馈 | “整理完成”或“已保存”，取决于真实完成对象 |
| 失败、取消或结果过时 | 平静或静止形象，停止成功动画 | 具体原因与恢复操作 |

`VoiceOrb` 原有标签包含“Tap to speak”，必须替换或隐藏。文本流程不接入 `onPress` 录音操作，不使用 `listening`，不显示虚假的声音输入。输出波纹只表达文字在生成，不映射成假音量。错误与成功不新增不存在的组件 state，使用外围状态文字和图标。

## 3. 动效编排

以下时间和位移是本页原型的起始建议，需结合 Signalry 原版和实际设备校准，不是通用强制数值。已有原版动效优先保留。

| 动效 | 建议方式 | 触发与停止 | 减少动态效果时 |
| --- | --- | --- | --- |
| 渐变背景 | 低对比浅紫光晕缓慢移动，约 16–24 秒一周期；主要动 opacity / transform | 页面可见且未减少动态时；阅读长文、输入时减弱，后台标签页暂停 | 保留静态渐变 |
| AI 形态变化 | 使用组件现有状态过渡 | 由真实状态驱动；不每次输入一个字就重建画布 | 每个状态一个静态形态 |
| 步骤转场 | 下方内容淡出、轻移约 8–16px，再显示新内容；约 180–260ms | 真实操作完成后；旧页面及时退出，避免同时可点 | 直接换内容并移动焦点 |
| 选项反馈 | 边框、底色和勾选变化，约 120–180ms | 点击或键盘选择；不自动倒计时翻页 | 立即显示选中态 |
| 真实进展 | 状态文字轻替换，已确认完成的节点出现勾选 | 任务事件到达；当前事件未知时维持等待 | 静态文字与图标 |
| 画像出现 | 卡片一次淡入，只有本次变化的内容短暂突出 | 当前版本结果可用时 | 立即显示结果及变化标记 |
| 详情切换 | 约 150–200ms 的轻淡入淡出 | 卡片选中改变；取消旧转场，显示最后一次选择 | 立即替换详情 |
| 手机翻卡 | 有明确按钮的短翻面或同位置内容切换 | 仅查看详情按钮或规定的卡面区域 | 无旋转切换，保持阅读顺序 |
| 好友成立 | 一次电路接通反馈 | 服务端确认成立的通知；按通知标识去重，可关闭 | 文字确认和进入聊天按钮 |

一个视图最多突出两个运动主体。默认是 AI 形象与当前交互反馈；背景只作低强度氛围。读取日志、光球、长文打字和整屏弹幕不同时抢注意力。

进展区展示可验证的任务摘要，例如“已读取 1 个资料来源”，不展示模型内部推理过程，不编造“已脱敏”“已发现伙伴”等未经服务确认的日志。

## 4. 数据状态与动画状态分开

这里仅描述前端应如何呈现已有状态，不新增 API、数据库或模型调用协议。产品接口以 [共享契约](../../../docs/共享数据与接口契约.md) 和 [画像专项任务入口](../../../docs/用户画像收集/task.md) 为准。

### 页面应保留的状态

- 当前章节、步骤、问题批次、题号和已保存答案。
- 当前画像草稿版本、已确认版本及逐条展示范围。
- 每个独立想法的草稿、版本和当前编辑项。
- 来源读取状态、任务状态、当前活动与发现设置。
- 输入未保存状态、推荐选中卡片、手机正反面、主题与减少动态偏好。

前端临时缓存只用于界面恢复，业务确认以服务端为准。主题与减少动态偏好可本地保存；真实原始简历、联系方式和完整私密草稿不写入公开演示文件或无保护的浏览器持久存储。纯演示只能持久化明确标注的虚构测试数据。

### 三类完成不能混用

| 完成类型 | 可以改变什么 | 不能代表什么 |
| --- | --- | --- |
| 组件动画结束 | 停止转场、显示静态展示态 | 上传成功、AI 成功、资料确认、好友成立 |
| 任务执行成功 | 展示当前且仍有效的候选结果 | 用户已接受、已公开、已保存到正式版本 |
| 用户确认并保存成功 | 更新对应正式版本与展示范围 | 自动发布想法、自动发送好友申请 |

AI 任务执行状态包括 queued / running / succeeded / failed / cancelled；同时检查结果是否 current / superseded / revoked。成功但已过时或撤销的结果不能继续套用到卡片。用户修改、切换活动或退出后，晚到响应也不能覆盖新的上下文。

### 页面必备的异常状态

| 场景 | 页面行为 |
| --- | --- |
| 文件不支持、超限或读取失败 | 在该来源旁说明原因，可移除、换文件、重试或用其他来源继续 |
| 多个来源部分成功 | 保留成功项，用户选择使用当前结果或继续等待，不统一清空 |
| 任务排队或耗时较长 | 显示已知阶段及可离开说明，不造剩余秒数 |
| AI 不可用 | 明确失败；若基础方式可用，由用户主动选择并标明实际模式 |
| 保存失败或离线 | 保留输入，显示未保存并提供重试，不显示下一步成功 |
| 版本冲突或旧任务晚到 | 提示已有更新，保留本次编辑，核对后继续，不静默覆盖 |
| 组合预览部分保存失败 | 显示成功与失败的具体画像或想法；只重试失败对象 |
| 无活动或邀请失效 | 资料与想法仍可编辑；提供邀请入口和广场，不发送全站推荐 |
| 推荐成功但零结果 | 友好说明真实不足，可调整条件或浏览本活动 |
| 推荐预算不足或服务失败 | 显示相应失败原因，普通发现由用户主动选择 |
| 好友申请待处理、被拒绝或已撤回 | 根据真实状态显示；不自动开放资料，不阻挡进入应用 |

## 5. 后续交互原型的范围

首个原型应在独立业务目录完成同一条十步路径，优先做布局、状态与操作验证，再精修形象和背景。可以先用演示数据驱动，但页面持续显示“交互演示”；登录、上传、处理、保存和好友申请的模拟反馈不能伪装成真实能力。

原型应能切换成功、部分失败、无材料、无活动、零推荐和旧结果晚到等场景，验证流程分支。预设数据只用于演示；不要复制真实资料到前端夹具。此范围不要求先接通语音、模型选择、外部应用连接或后台推送。
