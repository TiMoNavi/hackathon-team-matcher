# 用户画像引导采集 · 页面与十阶段说明

更新日期：2026-11-11。交付类型为前端设计说明，供后续页面实现与交互验证使用。

## 1. 整体体验

用户进入一个明亮、安静但有生命感的引导空间。浅紫渐变在白色背景上缓慢流动，一个 AI 光球停留在画面中间偏上的位置。光球下方是当前引导语，再下面是用户此刻需要操作的区域。这里会依次出现资料导入、处理进展、可修改的画像卡、选择题、想法对话以及推荐结果。

整个流程像游戏开场时逐渐认识自己的角色。用户先交出已有材料，看到系统整理了什么，再用几次选择和少量补充，把个人介绍与想法变得清楚。每个阶段都给出具体结果，不让用户面对一整页待填表格。画面主体保持稳定，阶段变化主要发生在引导语和下方交互区。

白色模式是默认视觉，另提供夜间模式。沿用 Signalry 的字体、紫色主操作、浅紫层级、圆角、留白与控件比例；渐变和 AI 形象在这套主题中工作。具体复用及动效约束见 [组件与交互验证](02_组件动效与交互验证.md)。

## 2. 页面应该有哪些区域

```text
┌─────────────────────────────────────────────────┐
│ 产品标识   当前章节 / 当前活动     主题   保存退出 │
│                  章节进度与保存状态               │
│                                                 │
│                      AI 形象                     │
│                 空闲 / 整理 / 输出                │
│                                                 │
│                   当前引导主句                    │
│              一句解释、当前结果或隐私提示          │
│                                                 │
│               当前阶段的交互内容                  │
│       上传 / 进展 / 画像 / 选择 / 对话 / 结果       │
│                                                 │
│             返回       主要动作       暂时跳过     │
└─────────────────────────────────────────────────┘
       背景渐变始终位于内容下方，不承载重要信息
```

### 顶部轻导航

- 左侧为产品标识；中间显示当前章节，涉及活动的阶段显示已验证的当前活动。
- 右侧提供“浅色 / 深色 / 跟随系统”、减少动态效果和“保存退出”。入口可收入一个设置菜单。
- 章节进度使用“认识你 → 了解你的偏好 → 让想法成形 → 遇见同频者”。显示当前步名称，已到达的步骤可返回。
- 保存状态只显示真实结果，如“正在保存”“已保存”“未保存，重试”；用户离开时不能丢掉输入或假装保存成功。
- 不把十个节点展开成十个密集标签，也不把未知总耗时显示成精确倒计时。

### 中上方 AI 形象

优先采用 AffectUI 的 Voice Orb，作为文字引导助手的抽象形象。它通过呼吸、收束、环形运动和轻微波纹表达空闲、整理和输出。首屏建议使用组件原有 220px 尺度，长内容或手机输入时缩到 112–144px；这些是本页待原型校准的尺寸，不改变 Signalry 的文字和控件规范。

没有语音功能时不出现麦克风、“正在聆听”或假音量。等待选择时保持空闲态；收到真实任务状态后才进入工作态。完成与错误由相邻文字、图标和内容说明，不能只靠光球颜色。用户正在阅读、编辑时，形象降低动态强度。

### 中间引导文字

每屏一个短主句，下面一到两行解释。主句告诉用户现在要做什么，解释说明为什么需要、会得到什么、是否可跳过。英文标题沿用 Bricolage Grotesque，正文沿用 Inter；中文字形、行高和换行需实际检查。

流程标题沿用 Signalry 登录页 32 / 36px 层级；只有首页演示使用 Hero 的展示标题尺度。短欢迎语可轻微淡入，题目、错误和操作说明立即完整呈现。AI 输出可以随真实流式内容出现，不把已经拿到的长段文字逐字慢放。

### 中下方交互区

这是页面随阶段变化的主要区域。每次只突出一个任务，可以是上传框、一张核对卡、一道题、一个对话输入框或一组结果。辅助说明、来源和长记录可展开查看。主要按钮的位置和命名保持可预测。

单项输入以原登录表单的 400px 内容宽度为起点。引导文字使用原版 640px 介绍宽度；画像与结果需要更多空间时，在原版最大 1248px 容器内展开，沿用面板留白和网格。不要让所有内容都变成同一个巨大卡片。

### 底部操作

每屏一个主要动作，如“继续整理”“这些信息正确，继续”“保存我的资料”。旁边按需显示“返回”“暂时说不准”“保存退出”。选择题点选只改变选中态，点击继续才推进，给用户修改和理解的机会。

底部可以在长内容中吸附，但必须预留空间，不能遮住最后一行内容、输入光标或手机键盘上的按钮。

## 3. 首页、登录与开场怎样衔接

这三个入口不占用十步编号。它们说明产品价值并完成身份进入，正式采集仍以已有资料优先。

| 入口 | 页面内容与动作 | 动效与信息边界 |
| --- | --- | --- |
| 首页演示 | Signalry Hero 中展示人物卡、想法卡和推荐理由的示意；主按钮“开始认识同频伙伴” | 少量卡片依次出现，允许暂停；统一标“产品演示”，不虚构当前在线人数、匹配百分比或真实用户成果 |
| 登录 | 复用 Signalry 桌面双栏、手机单栏；GitHub 为主操作，邮箱验证码为另一入口 | 右侧展示区可有慢速流动的想法短句；输入时减弱或暂停；未授权的用户资料不能成为未登录弹幕 |
| 欢迎 | 登录后在资料页上方出现一句“先让我认识你，再一起看看你想做什么。” | 首次进入短暂呈现，可立即操作下方资料入口；不额外添加等待页或必答兴趣题 |

登录旁的说明为“使用 GitHub 可从你的公开资料开始整理，不读取私有仓库”。第一次通过 GitHub 注册后，资料页直接显示已连接账号与公开读取状态，不要求重复输入主页或授权。普通再次登录恢复原进度，不自动重抓资料。

“想法尽早出现”的意图通过首页的项目演示、欢迎文案和进度章节表达。深度想法输入仍在第 6 步展开，避免在首个资料页之前加一道拦路问卷。

## 4. 十阶段总览

| 章节 | 阶段 | 下方出现的内容 | 用户得到什么 |
| --- | --- | --- | --- |
| 认识你 | 1 提供已有资料 | 简历、已连接 GitHub、网站、文字入口 | 从已有信息开始，不必重复填表 |
| 认识你 | 2 整理已有信息 | 真实处理阶段、来源状态 | 知道哪些材料已经读取 |
| 认识你 | 3 核对初步资料 | 可修改的初步身份卡 | 确认 AI 或基础整理有没有理解错 |
| 了解你的偏好 | 4 回答补充问题 | 逐题选择与可选短输入 | 补齐材料没有表达的合作偏好 |
| 了解你的偏好 | 5 生成并确认画像 | 完整画像、逐条范围、受众预览 | 一份自己认可的个人介绍 |
| 让想法成形 | 6 讲讲你的想法 | 一句话输入、独立想法卡 | 留下希望一起讨论或实践的方向 |
| 让想法成形 | 7 完善想法 | 轻量对话、每个想法的方案草稿 | 把方向整理成能交流的计划 |
| 让想法成形 | 8 最后确认 | 画像与想法组合预览 | 确认保存哪些内容、别人能看到什么 |
| 遇见同频者 | 9 在本活动寻找 | 资格确认、真实推荐进展 | 用已确认的信息寻找同活动人选或想法 |
| 遇见同频者 | 10 查看结果与进入应用 | 人物卡、想法卡、详情与好友申请 | 主动开始交流，或继续浏览应用 |

第 2、5、7、9 步的处理状态都是对应步骤内的子状态，不为每次加载多造一步。无材料时，第 1 步可直接进入第 3 步；第 2 步标记本次不适用，不显示伪造的解析动画。

## 5. 每一阶段的页面内容

### 阶段 1 · 提供已有资料

**引导语**：“先给我一点已有资料，我来帮你整理。”

解释：“一份简历、GitHub 公开资料或一段介绍都可以；也可以直接开始。”

下方首先展示简历上传和 GitHub 两个入口。GitHub 用户看到已连接账号和状态；邮箱用户可主动连接。网站与粘贴文字收进“其他资料”，避免首屏同时摊开多组表单。允许使用多种材料，每个来源显示名称、类型、状态及移除操作。

上传区同时支持点击选择和拖拽。文件格式、大小、扫描件支持范围按实际服务能力显示，不照搬组件里的图片上传限制。个人网站输入公开页面地址，不能承诺所有网站均可读取。

主操作“继续整理”；次操作“直接开始”进入第 3 步。资料说明为“原始材料仅用于你的资料编辑；整理结果经你确认后，按你选择的范围展示”。AI 模式另说明本次处理所使用的材料。不能承诺原文从不离开设备或自动过期删除。

### 阶段 2 · 整理已有信息

**引导语**：“正在把你的经历整理成一张容易认识的卡片。”

下方是一块紧凑的进展面板，逐项展示“接收材料”“读取可用内容”“整理候选信息”“准备核对”等真实阶段，以及对应来源的成功、等待或失败状态。仅在后端确认某阶段完成后显示勾选。

AI 光球进入工作态；短等待使用 AffectUI Thinking Loader 的受控状态。没有可测总量时用阶段文字，不显示凭时间增长的百分比。基础规则模式显示“基础整理中”，不能标成正在调用 AI。

本轮选中且可用材料的当前版本整理结果就绪后，立即进入第 3 步，不等动画循环结束。仍在读取或失败的来源单独提示，用户可选择等待、重试或使用已有结果继续，也可直接填写。长任务可保存退出，回来恢复真实状态。

### 阶段 3 · 核对初步资料

**引导语**：“这是我目前了解到的你，有哪里需要改吗？”

下方展示第一张可编辑资料卡，优先放昵称、一句话介绍、角色、技能和一两项作品。来源以小标签或展开信息呈现；不确定的内容标“待确认”，不把推测写成事实。

点击文字进入局部编辑，标签可删除、增加。修改后保留用户原来的内容和选择，不自动重写其他字段。直接填写的用户在同一页确认昵称，并自愿添加希望提供的信息；不生成虚假的初版画像。

主操作“这些信息正确，继续”。普通字段可选，用户添加了某条记录才按该记录规则校验。当前新增确认条目的默认展示范围应明确可见，不能让用户误以为此处保存永远只对本人可见。第 5 步会继续提供完整范围编辑与受众预览。

### 阶段 4 · 回答补充问题

**引导语**：“再了解几个小偏好，就更容易介绍你了。”

一次只显示一道题。题目下有单选或多选按钮、“我想自己说”和“暂时说不准”；自填输入仅在选择后展开。每题最多解释一句为什么问，例如“项目经历已经比较清楚，这一题只了解你的协作习惯”。

题目批次按现行规则为 **3–8 题**，资料充分时用较短批次。页面显示真实题数，如“第 2 / 3 题”，刷新恢复同一批问题与答案；不临时无限加题。原稿中的 1–3 题为早期建议，本说明沿用现行批次上限。每题都可跳过，全部跳过也不强迫补填。

问题示例只作为文案参考，实际题目来自当前批次：

- “合作时，你更习惯怎样沟通？”选项如文字异步、固定短会、先写后讨论。
- “遇到一个新点子，你通常先做什么？”选项如做小样、梳理问题、找伙伴讨论。
- 有有效活动时可问“这次活动你更希望贡献什么？”并标“仅用于本次活动”。

无活动资格时先收全局偏好，不把活动答案写进无效上下文。选中反馈简短、明确；点击“继续”后保存答案并展示下一题。AI 回应不对每个选择重复夸奖或追加长段解释。

### 阶段 5 · 生成并确认画像

**引导语**：“现在，这张卡片更像你了吗？”

先显示真实整理状态，完成后呈现第二版画像。卡片分为基本介绍、能力与作品、合作方式、当前活动安排。没有内容的可选模块可以收起，不用“完整度不足”制造填满所有字段的压力。

每条内容支持修改、删除和展示范围选择；新增与改动处短暂突出，确认后恢复正常样式。提供“我的视角 / 其他登录用户 / 好友”切换，同时注明合法入口和活动上下文。切换预览不能触发重新生成画像。

原始资料和未确认草稿仅本人可见。当前普通资料与可选联系方式的新增确认条目默认“所有登录用户可见”，用户可逐条改为“好友可见”或“仅自己可见”；既有设置保持。联系方式单独管理，不把登录邮箱当联系邮箱自动填入。

主操作“保存我的资料”；次操作“返回修改答案”或“保存退出”。保存失败时留在当前卡片并保留编辑，不进入成功转场。

### 阶段 6 · 讲讲你的想法

**引导语**：“你想和别人一起讨论，或者做成什么？”

下方提供一个简短输入框，示例“想做一个让线下讨论更容易留下结论的工具”。一句话就能开始；可选补充问题、第一步或希望得到的帮助，不要求先写商业计划。

有多个想法时点击“再加一个”，每个成为独立草稿卡。想加入别人项目的用户可选“我想加入别人的项目”，填写具体探索方向或希望贡献的角色，形成探索草稿。不能用一张空卡冒充已完成。

主操作“整理这些想法”，也可手动编辑后继续；无思路可保存退出。正常完成整条引导需至少一个有效想法或探索草稿，这不影响用户先进入有权限的应用功能。

### 阶段 7 · 完善想法

**引导语**：“我们把这个方向整理成别人能接话的计划。”

下方采用嵌入式 AI 对话，不引入普通聊天页的会话侧栏。当前想法名称始终可见，避免聊着聊着编辑了另一个点子。每次一个问题，可用快捷选项回答，也可直接输入。

对话围绕三个信息槽展开：想解决什么问题、这次先做出什么、希望伙伴贡献什么。它们是本页的建议交互骨架，不改写后端调用预算，也不把每轮输入自动映射成一次模型调用。已有信息足够就直接生成草稿；建议最多补充三轮，并始终提供“按目前信息整理”。用户可直接编辑，不因缺少技术选型阻断。

桌面可在下方用 Signalry 宽窄面板同时展示对话和方案，手机切换“对话 / 方案”两个视图，保留输入与滚动位置。AI 形象缩小但保留，输入框靠近当前问题。

方案草稿包含标题、一句话问题、目标对象、最小可行尝试、当前阶段、希望的贡献。技术路线仅在用户提供或采纳时展示；推测建议明确标注，不能把 AI 拟议内容写成已有成果。

各想法分别显示待处理、整理中、可核对或失败。一个失败不阻挡其他成功草稿；可重试指定项。用户编辑后晚到的旧结果标过时，不覆盖输入。主操作“保留这些草稿，去确认”；保存不自动发布或邀请任何人。

### 阶段 8 · 最后确认

**引导语**：“这是你的介绍和想法，最后看一眼。”

上方为画像摘要，下方为独立想法卡；每个模块有明确的编辑入口。可以回到对应步骤，回来后仍定位到刚才修改的位置。

再次提供逐条范围与三种视角，沿用第 5 步的选择。主操作“保存画像与想法，准备推荐”，旁边说明“保存草稿不会自动发布到活动或广场”。各对象分别保存，部分失败时指出是哪一张卡未保存，不能显示全部成功。

进入下一阶段前，复核当前活动。未加入活动时显示邀请入口及“先去广场”，不把无活动用户带进全站找人。有效活动下再确认本次目标、角色与投入等可选安排。

“允许本活动成员发现我”单独显示，默认关闭；用户明确开启才变更发现设置。关闭也可浏览本人有权访问的内容。想法关联活动也由用户选择，切换活动不能自动迁移所有想法。

### 阶段 9 · 在本活动寻找

**引导语**：“正在本活动中，寻找可以和你交流的人与想法。”

页面展示当前活动名称、用于本轮寻找的需求摘要，以及真实的校验、检索、整理解释状态。AI 光球和下方受控加载状态保持同步；不显示完整候选名单或未经授权的资料。

刷新恢复同一次任务，不重建推荐请求。切换活动后停止展示旧任务结果，旧响应晚到也不能覆盖当前页面。零结果、超时、预算不足、资格失效分别说明。

可用文案如“这次 AI 推荐暂时无法完成。你可以重试，或自己浏览本活动。”进入普通发现必须由用户主动选择，不能暗中跨活动推荐或把普通筛选伪装成 AI 结果。

### 阶段 10 · 查看结果与进入应用

**引导语**根据结果变化，有结果时为“可以从这些人或想法开始聊聊”，零结果时为“本活动暂时没有符合这次条件的结果”。

正常展示真实数量的结果，通常为 3–5 张，少于 3 张照实展示。每张卡标注人物或想法类型、相关理由、尚待沟通的问题，不凭空生成技能分数、人格段位或匹配百分比。

桌面下方展开左侧卡片选择区与右侧详情区，沿用 Signalry 的容器和宽窄关系。切换卡片时详情短暂淡出再出现；快速连续选择以最后一次为准。普通发现页面仍使用既定分页网格，本轮推荐展示不改变主应用结构。

手机默认单张卡片，正面放昵称或标题、角色与技能、简短介绍；点击“查看详情”进入背面或详情面板。提供“返回概览”“上一张 / 下一张”按钮，滑动只作辅助。长详情允许正常滚动，卡内按钮不会误触翻面。减少动态效果时直接切换内容。

人物卡可“添加好友”，进入接收人、首条消息与可见范围预览，再由用户点击发送。发送成功显示“申请已发送”，不提前显示已成为好友或自动播放连接成功。联系方式按本人已确认的范围和独立联系规则读取；发送申请不改变字段可见性，也不开放完整简历下载。

想法卡的“关注想法”“申请加入讨论”“向发起者添加好友”分别操作。真实好友成立事件才可触发一次可关闭的电路接通动效，并提供“开始聊天”。

零结果提示提供“调整条件”“浏览本活动”“进入应用”。不得虚构三个补位候选、“已加入广播队列”或承诺稍后通知。等待申请、被拒绝、无人可推荐均不阻挡进入应用。

## 6. 用户画像卡应展示什么

页面默认展示一个易读摘要，更多可选信息在编辑时展开；这里是呈现分组，不新增数据库字段或强制用户填写全部内容。

| 分组 | 默认呈现 | 展开后可补充 |
| --- | --- | --- |
| 我是谁 | 昵称、头像、一句话介绍 | 自愿提供的常驻城市、语言、时区等 |
| 我能贡献什么 | 角色与 3–5 个用于速览的技能标签 | 更多技能、本人描述的熟练程度，不自动评级 |
| 我做过什么 | 1–2 项代表作品或经历摘要 | 本人角色、贡献、证明链接、其他经历 |
| 我怎样合作 | 沟通习惯、长期协作偏好 | 兴趣、做事风格、长期合作期待 |
| 这次活动 | 本次目标、希望角色、投入与可用时段 | 当前活动内的需求、现场或远程安排 |
| 怎样联系 | 单独的可选联系区 | 每一条联系方式的展示范围 |

技能、经历、长期偏好属于全局画像；本次目标、角色、投入和安排属于当前活动。切换新活动时不默认复制旧活动答案。MBTI、电话、真实姓名等不成为首次引导的必答项，不根据仓库或简历推测人格。

## 7. 日夜模式与响应式表现

**白天**保留 Signalry 的白底、浅紫渐变、清晰深色文字。背景的移动幅度小，标题与输入区域保持稳定、干净，主按钮继续使用品牌紫色。

**夜间**延续同一紫色主题，使用深紫底、略亮的面板和清晰浅色文字，降低背景光晕强度；输入、选项、弹层、错误、焦点和 AI 组件全部覆盖。Signalry 原有深色区块不等于完整夜间模式，后续需在独立业务主题中补齐语义变量并检查对比度。本说明不另立一套全站色板。

首次访问以浅色展示；用户主动选“跟随系统”后跟随系统，并保留选择。刷新恢复主题，不在页面加载后整屏闪白。主题切换只影响外观，不重置步骤、输入或任务。

桌面以视觉居中为主，上方 AI、中央引导、下方交互形成清晰纵向顺序；内容较长时允许页面向下延展。不能用固定百分比高度强行把十种内容都压进同一屏。

手机保留相同顺序，顶部控制简化。软键盘弹出后优先显示问题、输入和发送按钮，缩小或暂时收起装饰形象；卡片和选择按钮自然换行。长内容用页面滚动，避免整个引导被锁在不可滚动的固定高度容器里。

## 8. 实现时应保留的体验边界

- 用户可以理解当前要做的事，不需要读完一页说明才开始。
- 能从已有材料获得初步结果，也能不导入资料直接填写。
- 回答和编辑可返回；保存退出不等于已完成，恢复后不重新播放所有开场动画。
- AI 推测、本人确认、公开展示三个状态清楚区分。
- 所有动态效果可以减少；关键任务和按钮不依赖动画结束。
- 原稿中早期的假人数、默认全隐藏、好友自动交换全部隐私、跨活动补结果等表述，按现行资料与发现规则修正。
