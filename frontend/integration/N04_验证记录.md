# N04 登录与关联前端验证记录

日期：2026-11-12。范围限定 `frontend/integration/`、`frontend/首页/integration/` 与 matcher-webapp 的生成资源目录。后端身份绑定、原生注册、邮件投递、OAuth 回调与真实登录会话由主执行者另行验收。

## 本次实现

- 自有 `/matcher/app/login` 使用现有首页 Brand、Button、Input、Providers、Signalry 主题及本地字体；保留原生登录和 dashboard 回退。当前身份存在时呈现明确的“关联登录方式”，不切换成另一个用户。
- 可用方式读取是 GET；发码／重发、验证码验证、GitHub 启动和退出均要求对应用户操作。退出包含明确确认，所有变更通过同源会话和页面内存 CSRF；没有自动请求重试。
- 发码成功只接受 HTTP 202、48 位小写十六进制 challenge、600 秒有效期和 60 秒重发时间。验证与退出只接受 HTTP 200，且验证 `authenticated`、`bound` 与当前意图、严格应用根 `next_url`。成功后完整导航，重新读取 session/CSRF。
- HTTP 409 `REGISTRATION_REQUIRED` 且 `details.next_url` 精确等于 `/user/registration` 时，显示用户主动点击的“补充注册资料”。其他状态、错误码、路径、查询参数或外站地址均不显示这个动作；该状态没有认证成功回执。
- 邮箱和验证码仅存在当前表单内存；提交后清空验证码，离开页面清理状态。未知服务错误和 GitHub 错误只显示固定文案，不反射第三方原文。
