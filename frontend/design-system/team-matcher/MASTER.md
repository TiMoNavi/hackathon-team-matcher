# 核心页面风格与布局规范

> 状态：用户已确认的执行基准，2026-11-11。
> 基准为完整的 **Signalry AI SaaS Landing Page Template 原版**。核心页面的风格和布局规则必须按原版执行。
> 原版查看方式见 [预览说明](../../experiments/signalry-original-preview/PREVIEW.md)。此前助手制作的适配样张已停用并归档。

## 1. 如何判断是否遵循基准

### 对话布局的专用参考

用户于 2026-11-11 进一步指定 **Soho Chat App Template** 作为对话布局参考。对话页的导航 / 会话列表 / 消息区、独立滚动和手机切换方式以 [chat.md](pages/chat.md) 为专用补充；字体、色彩及通用控件主题仍服从本规范。Soho 原版预览保留原貌以便比较，不据此将全站换成 Soho 风格。

以原版实际页面和对应源码为对照，继承字体、字号层级、页面比例、容器宽度、网格关系、对齐、留白、圆角、边框、阴影与动效。更换业务文案和数据时仍应看得出同一套设计。

只采用紫色、青柠色或大圆角，不足以满足要求。不得另做「胸牌」「便笺」「松绿」等新方向，也不得把原版压缩为另一套静态 HTML 风格板后宣称等效。

本规范决定视觉和布局规则；[主应用交互设计](../../../docs/前端主应用交互设计.md) 与 [共享契约](../../../docs/共享数据与接口契约.md) 决定导航、页面任务、数据和权限。不同职责同时满足，不用模板示例覆盖业务约定。

## 3. 字体与排版

### 原版字体职责

- 英文展示标题：**Bricolage Grotesque**，原版通过 `--font-display` / `font-heading` 使用，权重 500、600、700。
- 英文正文和控件：**Inter**，原版通过 `--font-body` / `font-sans` 使用，权重 400、500、600、700。
- 沿用原版字体变量与组件 class，不在全站随意指定另一字体，不以浏览器默认字体或字体加载失败后的 fallback 代替。
- 不能因为英文字体加载成功就宣称中文效果一致。中文需检查实际渲染字体、字重、行高、标点和换行；本次没有额外指定一款中文品牌字体。
- 原版英文标题的紧字距不要不加判断地套给所有中文正文。保持相同的信息层级与阅读密度，用真实页面对照实际效果。

### 源码中的参考尺度

下表是原模板不同部件的真实尺度，应在相同角色的部件中沿用，不能把所有页面标题统一变成营销首屏大字。

| 部件 | 原版尺度 |
| --- | --- |
| Hero 展示标题 | 38 / 48 / 60 / 68px，600 字重，1.05 行高，英文 -0.04em 字距 |
| 功能区大标题 | 34 / 52px，1.08 行高 |
| 功能卡标题 | 24px / 30px，600 字重 |
| 登录标题 | 32 / 36px，1.1 行高，600 字重 |
| 功能卡正文 | 16px / 24px；区块介绍按源组件使用 16–18px |
| 登录表单正文与输入 | 15px；辅助信息 13–14px；输入高度 44px |
| 大号主按钮 | 高度 48px，16px / 桌面 17px，600 字重 |

## 4. 主题与组件外观

主题直接复用原版 `app/globals.css`，业务组件引用语义变量，不重新散布色值。

| Token | 原版值 | 角色 |
| --- | --- | --- |
| background / card | `#FFFFFF` | 主背景和内容卡 |
| foreground | `#13111C` | 主要文字 |
| primary | `#5B3DF5` | 品牌与主操作 |
| primary-foreground | `#FFFFFF` | 紫色主按钮文字 |
| secondary | `#EEEAFF` | 选中区、辅助背景 |
| muted / accent | `#F7F5FF` | 浅紫内容层 |
| muted-foreground | `#6E6C7E` | 次要说明 |
| border / input | `#E8E6F0` | 内容边界 |
| lime | `#D9F85F` | 青柠强调 |
| night | `#16122B` | 深色区块 |
| body | `#4A4858` | 较长正文 |

- 基础 `--radius` 为 0.75rem，组件依原版的派生尺度和显式尺寸使用；功能卡主要为 24px，登录展示面板为 28px。不要把所有控件强制设成同一圆角。
- 首屏沿用 `#E4DEFF → #F4F1FF → #FFFFFF` 的背景过渡与 56px 网格。登录展示区使用自身原有的 48px 网格及渐变。
- 保留原版主次按钮、选中态、紫色轻阴影、浅紫层级和少量青柠强调。状态仍需文字或图标，不能只靠颜色表达。
- 深夜紫内容块是页面中的区块，不等于已经实现完整深色模式。
- AffectUI 组件接入后也必须服从这一主题和尺寸体系。

## 5. 布局规则

### 共通原则

1. 从原版已有容器、组件与布局开始组合，保留主次层级和比例。不能仅凭截图另写一套近似骨架。
2. 同一层级页面共享布局规则。修改字号、容器、间距或圆角时先定位对应源组件，明确业务适配原因，避免逐页自由发挥。
3. 宽屏、窄屏均按原版响应式方式组织内容，真实文字与操作不得溢出。不同业务页可以有不同内容结构，视觉语言与空间关系必须一致。

### 原版可直接沿用的尺度

| 原版结构 | 布局规则 |
| --- | --- |
| 主容器与顶部导航 | 最大宽度 1248px；导航距顶部 16px，外部宽度为视口减 32px，圆角 16px |
| 首屏标题区 | 居中排列，标题最大宽度 880px，介绍最大宽度 640px，主次按钮相邻；手机纵向组织 |
| 功能区块 | 区块内容最大宽度 1248px；外侧横向留白 20 / 40 / 96px；纵向留白 64 / 80 / 120px |
| 功能区宽窄卡片 | 桌面示例 64% / 36%，卡间 20px，内容内边距 28 / 32px，窄屏纵向排列 |
| 应用展示外壳 HeroDashboard | 桌面示例为 200px 侧栏 + 自适应主区 + 300px 辅助区；响应式折叠取源组件规则 |
| 登录页面 | 大屏左右两栏，左侧居中表单最大宽度 400px，右侧展示区；手机仅保留表单主区 |

宽窄卡片比例用于原版相同用途的展示区；普通发现的同级对象仍遵循业务规范的等高网格，不能为模仿展示区而破坏逐项浏览。聊天页也不搬入营销首屏的大段垂直留白。

## 6. 核心页面的复用关系

| 核心页面 | 结构与样式依据 | 业务内容处理 |
| --- | --- | --- |
| 产品首页 / 活动介绍 | Hero、SiteHeader、Features 等原版页面区块 | 使用真实产品与活动内容，保留区块节奏及排版，去掉无业务需求的价格和客户演示数据 |
| 登录 / 注册入口 | 原版 LoginPage + LoginForm + LoginShowcase | 保留表单与展示区布局；登录方式采用项目规定的 GitHub 与邮箱验证码 |
| 首次画像引导 | 登录表单的内容宽度、标题与控件，结合原版面板 | 承载现有十步引导、资料导入、本人确认与可见性，不改写业务步骤 |
| 发现 / 想法 / 人选 / AI 推荐 | 原版应用展示外壳、内容区块与 Card / Tabs / 筛选控件 | 保留活动上下文、想法/人选等高网格、分页及独立 AI 推荐入口 |
| 广场 | 原版 UnifiedInbox 的列表层级和主题，配合已选 Kit 信息流组件 | 使用帖子与作者信息；发布范围保持明确 |
| 消息 / 想法讨论 | Signalry 视觉主题 + [Soho 对话布局](pages/chat.md)，使用原版导航、会话列表与消息区结构 | 保留列表/会话关系；长文本阅读优先，实际消息和权限遵循契约 |
| 个人 / 资料编辑 / 隐私 | 原版表单、Card、Tabs、Dialog 与文本层级 | 承载实际资料和逐条可见性，不新增未经确认的信息规则 |

应用主导航继续为 **发现 / 广场 / 消息 / 个人**。活动切换器作为上下文控件。原模板的 Platform / Pricing 等营销导航不直接替换主应用导航。来源页面没有完整业务对应物时，复用它的组件和布局规则完成组合，不能声称原模板已经包含该业务页。

## 7. 动效与交互

原模板的首屏入场、浮动标签、按钮反馈、卡片交互及登录展示效果作为实现依据。不要因通用 Skill 的偏好擅自移除或替换用户选定的设计。

具体业务页按内容需要复用对应动效；长聊天、列表正文和输入内容保持稳定。处理中、成功、失败以真实任务状态驱动，示例数字不能变为虚构业务状态。键盘焦点、弹层关闭、手机菜单和减少动态效果均需验证。

## 8. 交付检查

- 先对照原版运行页面，再检查对应源组件；不以已停用样张校准。
- 确认实际字体加载、渲染字体与字重，中文额外检查真实字形和断行。
- 对照容器宽度、网格关系、留白、标题层级、按钮与卡片尺寸，不能仅核对颜色。
- 至少查看 1440px 桌面、768px 中间宽度、390px 与 320px 手机宽度；检查页面溢出和关键内容。
- 实际操作导航、筛选、表单、弹层和键盘交互，检查加载与运行错误。
- 页面仍使用示例数据时明确标注；真实业务验收遵循 [实施要求](../../前端实验结论与实施要求.md)。
