# 前端实施要求

> 当前执行基准：Signalry 完整原版；对话功能布局另参考用户指定的 Soho。视觉与布局的具体约束统一见 [MASTER.md](design-system/team-matcher/MASTER.md) 及其 [对话页补充](design-system/team-matcher/pages/chat.md)，本文不再复制另一套样式规则。

## 页面实施顺序

1. 阅读 [原版预览说明](experiments/signalry-original-preview/PREVIEW.md)，查看原版首页与登录页。
2. 在规范的源码对照表中找到当前页面对应的结构、字体和组件，从真实源码复用或组合。
3. 在独立目标目录接入产品文案、数据与业务操作；保持版式与主题，不修改 vendor 或原版对照副本。
4. 先验证一个真实核心页面的字体和布局效果，再把同一组组件与主题用于其他页面，避免逐页出现不同风格。
5. 做桌面与手机对照、真实交互和业务权限检查，再记录已完成的范围。

## 组件与技术边界

- 只使用用户已选择的 Shadcn UI Kit 与 AffectUI；资源位置见 [TEMPLATES.md](TEMPLATES.md)。
- 优先用已存在的本地源码；需要新资源时按当次 MCP 文档与现有 CollectUI registry 获取，不猜组件 slug，不自动换 registry 地址。
- 适配使用主题变量、props、className、cn() 与外层布局。保持基础组件和商业快照可追溯。
- React 组件直接复用需在 React 页面运行。沿用已验证的样式隔离方式，不将 Bootstrap / Clean Theme / jQuery / PJAX 混入新页面外壳。
- 路由入口、认证、权限、CSRF 与业务数据按已有服务端约定接入。模板中的登录演示、表单反馈和模拟数据不视为真实业务实现。
- 本次确定的是页面视觉与布局要求，不自动批准全站迁移、后端更换或新的接口设计。

## 必须保持的产品规则

具体字段与流程以 [主应用交互设计](../docs/前端主应用交互设计.md) 和 [共享契约](../docs/共享数据与接口契约.md) 为准。

- 主导航为发现 / 广场 / 消息 / 个人，活动选择器独立。
- 发现、搜索和推荐限制在服务端已验证的当前活动；公开广场与既有聊天按各自规则处理。
- 普通发现采用分页网格，AI 推荐独立；模板布局不能替代业务排序、权限和状态。
- 用户资料、来源、确认与可见性沿用现有规则，AI 不能擅自公开或修改确认数据。
- 发消息、发帖、加好友、申请加入讨论等操作需要真实用户动作与后端授权；本地演示反馈不能冒充保存成功。
- 保留未登录、无权限、无数据、加载失败、待确认等实际状态。

## 技术实验怎么使用

[三路线比较](experiments/humhub-ui-comparison-2026-11-11/COMPARISON.md) 和其测试记录继续保留，作为原生视图、React 插件、独立前端的技术证据。其旧首页、绿色配色与样式不作为新页面参考，历史通过数也不代表正式业务已经验收。

此前建议优先继续验证独立 React 前端插件；具体交付仍按当前任务授权推进，不借本次视觉确认扩大迁移范围。

## 完成标准

- 视觉：按 MASTER 对照原版字体、布局、间距、卡片、按钮与响应式表现。
- 功能：实际测试本轮页面的关键交互，并区分演示与真实保存。
- 工程：运行适用的构建、类型检查和浏览器检查，修复本轮引入的问题。
- 记录：列明本轮页面、复用源码、必要适配、真实验证与尚未接入的业务。
- 边界：冻结文档、凭据、原版快照与未授权业务不受影响。
