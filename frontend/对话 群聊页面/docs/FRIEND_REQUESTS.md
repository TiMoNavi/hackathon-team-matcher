# 好友申请侧栏

用户要求增加等待添加好友的确认侧栏，并适当美化。入口位于会话列表的「新的朋友」卡片，以及导航中的「新朋友」。桌面从右侧展开，手机使用接近全宽的抽屉；继续默认日间并支持夜间。

## 展示与操作

- 收到的：展示虚构申请人的头像、角色、来源、招呼、有效期和可展开简介；支持接受或婉拒。
- 已发出：展示等待对方确认的申请，只提供查看和撤回。
- 已处理：保留接受、婉拒、撤回及过期记录；已接受记录可以进入同一条私聊。
- 数字徽标是本地收到且待确认的申请数量，非服务端未读计数。
- 接受后加入演示联系人，并建立唯一空会话。首条申请招呼留在申请卡片中，不伪造为已发送聊天消息。
- 申请中未选择共享联系方式。接受后不会自动发送消息、交换联系方式、邀请进群或追加活动资格。

样式沿用首页的紫色、青柠点缀、柔和边框和圆角表面。顶部概览、分类分段、招呼引用块、到期状态和操作按钮采用明确层级；信息列表独立滚动，关闭和说明区域保持可见。

## 代码与规则

- `lib/friend-requests.ts`：独立虚构数据和纯状态转换。
- `lib/conversations.ts`：接受操作在一次内存更新中修改请求、联系人和会话；版本过期、重复处理、错误方向与终态请求不再生效。
- `components/chat/friend-requests.tsx`：入口、侧栏和卡片。
- `app/friend-requests.css`：通过局部语义变量适配日夜模式和小屏。

组件复用已有 Shadcn UI Kit 的 Drawer、ScrollArea 和 Button，未改动 `components/ui`。状态转换按项目 architecture-patterns Skill 的边界原则独立于界面，以纯函数和内存 store 校验。业务含义遵循 [共享契约](../../../docs/共享数据与接口契约.md) 与 [主应用交互设计](../../../docs/前端主应用交互设计.md)。

本次只实现本地演示，人物、来源、时刻和有效期均为固定示例；没有真实 API 调用、授权验证、并发事务或服务端通知。活动卡片及广场帖子分别展示来源，但源对象真实性由未来服务端校验。刷新恢复初始申请，主题偏好仍保留。

## 验证

运行 [verify-friend-requests.cjs](../scripts/verify-friend-requests.cjs)，报告见 [friend-requests-verification.json](friend-requests-verification.json)。

- 纯转换及真实 store 验证：版本不匹配、重复接受、收发方向错误和过期请求被拒绝；未接受不可开启私聊；重复操作不重复建立好友或会话。
- 浏览器验证：接受、婉拒、撤回、简介展开、计数更新、处理记录、空状态、刷新重置、草稿保留和显式发送。
- 验证日夜主题、Escape 关闭与焦点返回；390×844、320×568、768×900、390×420 下无横向溢出，列表可滚动到最后一张申请。
- 构建、TypeScript 与变更文件 ESLint 检查通过。未进行真实多用户、生产权限或实体手机验收。
