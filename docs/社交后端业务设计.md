# 社交后端业务设计

> 更新日期：2026-11-10。状态：可交接设计，业务接口及数据结构待实现。
> 本文负责普通社交业务。产品决策见 [完整方案 v3](完整方案设计_v3.md)，模块依赖见 [系统架构与领域设计](系统架构与领域设计.md)。字段名称、请求响应、状态枚举与错误码统一以 [共享数据与接口契约](共享数据与接口契约.md) 为准；联调场景见 [联调验收与交付路线](联调验收与交付路线.md)。
> [用户人工引导原稿](首次注册与开场引导_用户原稿_冻结.md) 保持冻结。本文不修改原稿，也不把设计接口描述成已上线功能。

## 1. 交付目标与模块边界

首期形成不依赖模型的完整基础社交闭环：GitHub 或邮箱验证码登录，凭邀请加入活动，手工编辑资料与想法，发帖评论、点赞收藏，发送好友申请，接受后文字私聊，参与活动内想法讨论，处理通知、屏蔽和举报。AI 不可用时，这些能力仍能使用。

沿用 FastAPI 模块化单体、PostgreSQL 权威存储与 Redis 缓存/限流/后台任务，不因为模块较多就拆成微服务。按项目级 architecture-patterns Skill 分离领域规则、应用用例与外部适配器；HTTP、ORM、消息推送和模型 SDK 不进入领域实体。

| 业务模块 | 拥有的事实和用例 | 不能代替的职责 |
|---|---|---|
| 身份与会话 | 用户、登录身份、验证码、会话、账号状态及初次公开导入意图 | 不拥有画像事实；GitHub 自动公开导入不授予私有仓库访问或画像发布权限 |
| 活动与资格 | 活动、组织者、邀请、成员、角色与可见状态 | 当前活动不是全局好友的所属容器 |
| 画像展示策略 | 已确认字段、字段可见性、活动字段投影 | 不组织模型推断，不返回原始材料 |
| 想法与讨论 | 想法、活动关联、关注、入群申请、群成员 | 关注不是入群，入群不是加好友 |
| 好友与联系授权 | 好友申请、全局关系、定向联系方式授权 | 不给每个好友复制普通画像字段清单 |
| 消息与通知 | 私聊、群消息、未读、通知、可靠投递 | 不将通知或摘要当成聊天记录 |
| 广场与治理 | 帖子、评论、点赞、收藏、屏蔽、举报与处理 | 公开内容不能变成跨活动用户搜索库 |

应用用例通过 UserRepository、EventAccessPolicy、ProfileProjection、ConnectionRepository、ConversationRepository、UnitOfWork、Outbox 等端口协作；具体命名和参数以共享契约为准。推荐服务只消费经授权投影，不直接改好友、消息、入群或字段权限。

## 2. 账号、登录与会话

### 2.1 GitHub 与邮箱验证码

- GitHub OAuth 回调校验 state 及提供方返回，按提供方稳定账号 ID 识别登录身份。昵称可以重复，内部用户 ID 唯一；昵称不是全站搜索用户的授权凭据。
- 邮箱验证码同时支持注册与登录。验证码只用于本次指定邮箱和用途；发送接口不暴露邮箱是否注册，验证成功后创建或恢复账号会话。
- 初始可配置值为验证码有效期 10 分钟、重发间隔 60 秒、单码最多 5 次失败；重发立即使旧码失效。实现时还须按邮箱、IP 和账号维度限流，避免只限制页面按钮。
- 验证码以不可逆形式保存，成功消费为原子操作；日志不记录验证码、完整邮箱、OAuth 令牌或会话凭据。
- GitHub 与邮箱身份绑定要求已登录用户再次证明目标身份，不因两边邮箱字符串相同就自动合并账号。发生已有归属冲突时不转移身份，返回可恢复提示。
- GitHub 首次注册入口说明自动连接并读取公开资料；OAuth 验证后应用用例登记已验证账号对应来源及读取任务，用户不必再次粘贴主页或绑定。登录与来源处理分别保存状态，外部读取失败不撤销登录成功。已有账号普通登录只恢复，不自动重抓或重跑画像；私有仓库和公开展示不在这次初始导入范围内。

### 2.2 会话与账号状态

Web 会话使用服务端可撤销的登录状态及 Secure、HttpOnly Cookie；变更请求采取 CSRF 防护，跨域来源使用明确允许列表。登出撤销当前会话，账号禁用、注销及风险操作可撤销全部会话。客户端隐藏按钮不能代替服务端校验。

认证模块只回答“是谁、账号是否可操作”。是否可见某活动、可读哪项画像、能否发消息，由对应业务策略判断。组织者账号也不能绕过私人资料或私聊权限。

## 3. 活动、邀请与组织者

### 3.1 加入方式

首期通过组织者提供的邀请链接或邀请码加入。统一入口为 POST /api/v1/event-invitations/redeem；链接中的活动标识只作定位，不能自行证明资格。

兑换事务验证邀请所属活动、有效期、撤销状态、使用次数、活动是否接收新成员及用户状态。并发兑换不得突破人数/次数限制；同一用户重复兑换返回既有有效成员关系，不重复扣减次数。邀请密文或散列按认证凭据管理，不进入分析日志。

当前活动上下文由服务端结合请求者及成员记录验证。它包含活动 ID、成员/权限版本，绑定一次查询或操作；不以客户端字段、模型参数或另一个浏览器标签页最后选中的活动作为权限事实。

### 3.2 组织者权限

组织者可维护活动基本信息、邀请、成员资格、活动内违规内容和活动归档。角色变更单独审计；不能给自己绕过平台封禁，不能读取他人原始简历、联系方式或私聊。

活动创建者成为首位组织者。仅剩一名组织者时，先转交组织者角色或关闭活动，再退出；不留下无人管理的活动。移除成员必须说明业务原因并产生通知，不能把移除包装成对方主动退出。

### 3.3 生命周期与既有关系

| 变化 | 发现、申请与活动资料 | 已有好友/私聊 | 活动想法群 |
|---|---|---|---|
| 切换当前活动 | 新请求绑定新上下文；旧发现结果不继续显示 | 保留，按好友与屏蔽规则访问 | 切换本身不取消既有成员资格 |
| 活动自然结束 | 停止新发现及新增活动来源联系；不自动删除想法 | **保留好友关系和私聊**；可继续发消息、查看全局画像和 friends 字段；该活动的活动字段不再可见 | 不自动移除成员；既有群按开放/归档状态继续聊天或只读 |
| 主动退出/被移除 | 撤销活动字段与发现访问，失效未接受的活动来源申请 | 已成立关系保留，活动字段不随好友身份保留 | 立即撤销读取与发送，包括后续分页和缓存 |
| 账号封禁或双方屏蔽 | 更高优先级策略生效，不因活动资格而放行 | 停止相应未来互动与授权读取 | 不允许借群发送定向骚扰或读取被禁止的额外资料 |

**活动结束后的好友行为细则**：
- **好友关系保持有效**：在活动 A 内通过推荐/发现建立的好友关系是全局的，活动结束后关系不解除
- **私聊继续可用**：可以继续发送私信，查看对方的全局画像（authenticated 和 friends 字段）
- **活动字段不可见**：对方在活动 A 中设置的角色、时间投入、活动目标等活动专属字段，在活动结束后即使仍是好友也不再可见
- **推荐和发现停止**：活动 A 结束后，不能在活动 A 的推荐列表中看到新的候选人，但可以在其他 active 活动中被推荐
- **新好友申请停止**：不能再以"活动 A 推荐卡片"为来源发送新的好友申请；但已发送的 pending 申请仍可正常处理
- **跨活动推荐限制**：在活动 A 建立的好友关系全局有效，无需也不能在活动 B 重复建立。活动 B 的推荐索引和模型仍只使用 authenticated 字段；进入获准详情后再按全局好友关系展示 friends 字段，活动字段另验对应资格。

活动结束不是成员被移除。结束后的讨论不产生跨活动成员发现入口，新活动仍需重新兑换有效邀请和建立资格。退出后用户可管理、删除自己的内容，但不能由管理入口读取其他活动成员的内容。

## 4. 普通画像与联系方式权限

### 4.1 普通画像动态计算

ProfileAttribute.visibility 只取 authenticated、friends、private。普通画像不建立按好友复制的 ProfileShareGrant；读取时计算当前字段可见性和当前关系。

| visibility | 对本人 | 对其他人 |
|---|---|---|
| authenticated | 可见 | 已登录、存在合法访问入口、用途允许时可见 |
| friends | 可见 | 当前好友且存在合法访问入口时可见 |
| private | 可见 | 不可见，不因好友关系自动开放 |

合法入口包括当前活动内获准的候选、公开帖作者入口、已合法收到的好友申请、已成立的好友关系。所有登录用户可见不提供全平台用户目录，也不能通过枚举 user_id 绕过入口校验。未登录访问公开帖子可以看到帖子正文与作者主动用于发布的昵称/头像，完整个人画像仍需登录及合法入口。

全局字段与活动字段另有 scope。活动字段必须附所属 event，并同时满足该活动资格与字段 visibility；成为好友不能看到对方其他活动的角色、时间安排、成员或讨论。通过公开帖子认识的人，可以查看允许展示的全局字段，但不会得到活动画像。

修改 friends 字段后，对当前所有好友动态生效；改为 private 后立即阻止后续读取，并使相关缓存失效。前端保存前明确提示影响范围。AI 草稿、未确认推断、原始材料和私信不进入任何对外画像投影。

### 4.2 联系方式独立定向授权

邮箱、微信、手机号等联系方式由独立联系信息记录与 ContactShareGrant 管理，不作为普通 friends 字段批量开放。

- 每份授权明确 owner、viewer、联系方式项目、版本、授予/撤回时间及当前好友关系轮次；两个方向相互独立。
- 发送好友申请时可选择”接受后向对方共享”的联系方式；未接受前只保存待生效的选择，不开放读取。对方接受时可选择自己的分享内容，也可选择不分享任何联系方式。
- 建立好友不要求双方共享等量联系方式。普通画像的 friends 可见字段自动按关系生效，不额外弹出逐好友普通字段授权表。
- **联系方式值变更时的授权处理**：
  - 修改联系方式值（如更换手机号）产生新的 `Contact.version`
  - 已存在的 `ContactShareGrant` 按 `contact_id + version` 绑定，不自动升级到新版本
  - 读取授权时，若 grant 绑定的版本已不是 Contact 的 current_version，返回”联系方式已更新，需重新授权”
  - 本人可在”管理已共享联系方式”页面，批量或逐个更新授权到新版本（需明确确认）
  - **裁决优先级**：Contact.version 变更 > ContactShareGrant 绑定的旧版本，旧授权失效直到用户明确更新
- **关系轮次变更时的授权处理**：
  - Connection.generation 增加时（解除后重建好友），旧 generation 的所有 ContactShareGrant 失效
  - 新建关系时，旧授权**不复活**，需要重新选择共享内容
  - **裁决优先级**：Connection.generation 匹配 > 旧 generation 的授权，关系重建后旧授权永久失效
- 撤回共享、解除好友、屏蔽或账号停用阻止未来读取，失效缓存；不能承诺删除对方已经复制的信息。

## 5. 全局好友申请与关系

### 5.1 关系与来源

Connection 按规范化无序用户对全局唯一，不按活动重复创建；活动只记录认识来源。一个用户对复用一个私聊会话。同一用户对最多存在一条 pending 申请，不能因来源不同绕过限制。

ConnectionRequest 保存发起者、接收者、首条消息、来源、来源必要公开摘要、申请版本、发起者待共享联系方式选择，以及服务端验证记录。不得复制未授权活动画像或简历到来源快照。

| 来源 | 创建申请时 | 接受时 |
|---|---|---|
| public_post | 帖子仍公开、可访问；服务端由帖子解析真实作者；无需共同活动 | 验证合法创建的原申请、双方账号、屏蔽及版本；原帖后来删除不追溯取消申请 |
| event_card | 卡片属于请求者当前有效活动；候选及双方资格有效；服务端确定目标人物/想法发起者 | 复核 origin_event 的资格与活动政策；不能偷偷改成广场来源 |

删除或取消公开的帖子不能再用于创建新申请。既有合法请求提供必要的作者/发起者摘要入口，但不打开全站查人。活动来源申请可以从全局消息页处理，无需强制切换页面；服务端始终核验原来源活动资格。

已是好友时，无论从哪种入口点击，直接打开现有会话；不新建好友、不再次共享联系方式、不重复播放配对动画。感兴趣、点赞、收藏、关注、入群均不等于发申请。

### 5.2 状态与并发

申请状态为 pending → accepted / declined / withdrawn / expired / invalidated；屏蔽、账号异常或来源资格失效将未完成请求置为 invalidated，不冒充用户拒绝，具体原因不对无权用户泄露。想法讨论申请使用相同终态集合。

- 同方向重复请求返回已有申请；幂等重放不得再发首条消息或通知。
- 相反方向同时申请时，只保留一条待处理申请。后提交者看到“对方向你发来申请”，进入接受确认；两次发送不能自动拼成同意。
- 接受必须由原接收者提交准确的 request_id 与 expected_version。申请共享选择变更、撤回与接受按同一版本/锁策略判定，旧版本不能授予新权限。
- 同一用户对关系变更采用统一锁顺序，唯一约束兜底。已有好友关系不得因重复接受而重建；过去轮次的申请不能恢复已解除关系或已撤回授权。
- 解除好友保留本人可读的既有私聊历史，但停止未来发送、friends 字段读取及双方 ContactShareGrant。再次加好友是新一轮申请和授权，不能复用旧同意。

### 5.3 接受事务

一次数据库事务完成以下步骤：

1. 锁定申请及用户对关系，校验接收者、pending 状态、版本、账号、屏蔽、来源资格和联系方式选择版本。
2. 创建或激活唯一 Connection，创建或复用唯一私聊会话及两个参与者。
3. 将申请首条消息按源申请 ID 幂等归档到会话；请求箱中的展示不是第二次发送。
4. 为双方明确选择的联系方式创建本轮定向授权；无人选择时不创建空授权。普通画像按朋友关系动态读取。
5. 将申请置 accepted，写入 outbox 配对事件，提交后才投递通知并允许前端播放电路接通动画。

发起者待共享联系人版本过期时，先按共享契约返回 CONTACT_CHOICES_CHANGED 且保持 pending；接收者明确选择 omit_stale_requester_contacts 后才能重试。失效项不升级授权、不导致静默半成功；接收者自己的失效选择必须重新选择。跳过失效项后仍在同一事务完成关系与有效授权，并通知发起者。

首条消息在创建申请事务中就连同申请可靠保存，由对方的请求箱展示；接受事务负责唯一归档。网络中断后的重试返回既有结果。消息、关系、授权任一写入失败，接受事务全部回滚，不能留下“已成功”通知。

## 6. 想法、关注与活动讨论

Idea 表示可长期维护的想法，独立于个人画像。一次保存想法不代表发布帖子，也不代表邀请他人加入。IdeaActivity 表示想法在具体活动中的目标、阶段、需求和开放状态。

IdeaCircle 可作为逻辑交流空间；创建空空间不自动生成成员或发送邀请。首期实际群会话绑定单个 IdeaActivity，每个关联最多一个有效讨论会话，成员与消息不会跨活动合并。

### 6.1 关注与成员分离

- IdeaFollow 记录对想法的关注，可独立取消；只订阅本人有权限接收的公开/活动更新，不能看到其他活动中的同想法消息。
- DiscussionMembership 管理每个活动讨论的申请、接受、在群、退出或移除。加入要求有效活动资格及本人意愿；首期由想法发起者审批，组织者可因活动治理移除违规成员。
- 关注、申请入群、退出群与是否在发现池中互不替代。用户可以同时参与多个想法，不存在“已组队因此不能再推荐”。
- 群成员可见昵称及合规画像；群友不是好友，不自动得到 friends 字段或联系方式。

### 6.2 群消息范围

新成员默认只能读取加入后产生的消息，服务端记录本次加入位置/消息序号；客户端改变分页游标不能读到更早记录。重新加入开启新的可读区间，不自动恢复过去成员期的历史访问。

退出、被移除或活动资格撤销后，群列表、消息详情、历史分页、实时订阅和缓存均不可继续读取；只保留最少的退出记录与本人举报处理凭据。群归档后现有获准成员可读其原有授权范围，不能继续发消息。

公开想法摘要、主动发布的进展与群私信独立存储。用户公开一段进展不意味着群消息全部公开，AI 也不能用群消息生成未经授权的公开摘要。

## 7. 广场、帖子与互动

### 7.1 发布与浏览

帖子有 public 或 event 发布范围；event 帖必须带合法活动 ID。公开帖子正文允许未登录阅读；发帖、评论、点赞、收藏及查看完整画像需登录。活动帖、评论和计数继承活动可见范围。

首期支持文字帖子、想法引用及文字评论，不以聊天附件方式承载简历上传。发布由用户确认内容和范围后完成；AI 整理想法、保存画像或群内发言均不自动发帖。

公开帖引用想法时，仅展示此次明确发布的摘要快照，不把活动内完整想法、成员或聊天作为嵌入对象公开。后续编辑想法不自动改写已发布帖子；用户主动更新帖子才形成新版本。

### 7.2 评论、点赞与收藏

- 评论属于具体帖子，继承其可见范围。首期为一级评论，可用 reply_to 表达回复关系，不引入无限嵌套结构；作者可编辑/删除自己的评论，删除保留必要占位以免回复关系断裂。
- 点赞按用户与目标唯一，重复请求幂等。收藏只对本人可见，不通知作者，不暴露收藏者名单；收藏不能延长被删除或失去权限内容的访问权。
- 所有计数按当前获准内容计算。活动评论或成员数不能混入公开统计导致范围泄露。
- 删除帖子后停止新评论与新申请入口；评论随帖停止展示，已合法创建的 public_post 好友申请仍按自身状态处理。
- 屏蔽用户的内容与互动按屏蔽策略过滤；通知和列表分页再次检查可见性，不能把旧消息摘要当成持续访问许可。

公开帖子作者入口可发跨活动好友申请，但论坛不得提供全平台用户目录、按技能找所有作者或将作者集交给推荐 Agent。用户对公开内容的主动浏览与受限的找人服务分开。

## 8. 文字聊天、未读与断线恢复

### 8.1 消息规则

首期只做文字私聊和活动想法群，不做语音、视频、文件附件或后台代聊。使用 HTTPS 与受控服务端存储，不承诺端到端加密。私聊正文不能成为默认 AI 画像输入或推荐语料。

GET/POST /api/v1/conversations/{id}/messages 分别用于分页读取和发送。消息发送校验当前参与者、会话类型、有效好友/群成员、屏蔽、账号状态及限流；不能仅凭曾经打开页面或持有会话 ID 放行。

每条消息具有会话内稳定排序位置、服务端时间、发送者和客户端消息标识。相同发送者在同一会话重放相同客户端标识，只返回已保存消息；标识相同但正文不同返回冲突，不静默覆盖历史。

发送事务写入消息及 outbox。只有持久化成功才返回发送成功；实时推送只是分发通道，失败不会丢失历史。服务端不执行用户消息中的 HTML/脚本，链接作为普通受控文本呈现。

### 8.2 未读与补拉

PUT /api/v1/conversations/{id}/read-state 提交已实际展示的最后消息位置。已读位置只向前推进，且不得超过用户有权读取、服务器已经存在的消息；不以客户端时间覆盖服务端事实。

首次打开与断线恢复用稳定游标分页补拉，实时通知只提示“存在新消息”。重复推送按消息 ID 去重；先收到通知后拉取历史、网络切换和多个终端并发均得到相同顺序。群成员的可读起点同样作用于分页及未读计算。

好友解除或屏蔽后，双方仍可查看自己此前合法参与的私聊历史，但不能发送新消息、刷新对方受限画像或联系方式。账号注销后历史显示注销占位身份，不继续提供资料入口。群历史则按成员期规则处理，不套用私聊保留规则。

## 9. 站内通知与可靠投递

首期通知覆盖好友请求/结果、首条联系、未读消息提示、入群结果、必要活动变化、帖子评论/回复及治理结果。赞或其他高频互动可以聚合；收藏不生成通知。用户可关闭可选提醒，必需的账号和治理结果仍留在站内记录。

新入群申请通知有权审批的作者/管理者，同时进入 /me/discussion-requests 的 incoming 列表。通知丢失或已读不应使审批入口消失；申请人只能查看本人 outgoing，不获得其他申请者名单。

业务事务写 outbox，worker 提交后投递站内通知；推送通道采用可重试、至少一次投递，业务和客户端按 notification_event_id 去重。该标识不是业务活动 event_id。

读取通知或打开目标时重新校验权限。目标删除、退群、屏蔽、授权撤回后，通知显示“内容已不可用”，不能继续返回旧敏感摘要。未登录设备预览只显示通用提示，不显示联系方式或私信正文。

通知离线保留，用户不必停在首次引导等待回应。配对成功动画只由已提交的成功事件驱动，每次关系成立只展示一次；补拉和重新登录不会反复播放。

## 10. 屏蔽、举报与注销

### 10.1 屏蔽优先级

屏蔽立即禁止双方的新好友申请、私聊发送、直接互动和受限资料读取，失效待处理申请、联系方式授权及相关缓存。解除屏蔽不自动恢复已解除好友、旧授权或已失效申请。

共同群不因屏蔽自动踢出任意一方，但消息展示与可操作入口执行屏蔽过滤；举报取证由本人选择自己曾合法可见的消息。活动管理员处理群成员资格，个人屏蔽不能成为移除别人活动资格的按钮。

### 10.2 内容检查与正常使用

内容治理由普通业务用例编排，领域规则决定发布资格和限制范围；链接、文件检查及可选外部审核通过适配器执行，不调用推荐模型、不授予模型处罚权限。检查具体内容和实际行为；注册时长、有没有好友、单个关键词或机器置信度不能直接代替违规事实。所有配额与错误结构统一引用共享契约。

**首日可用性**：

| 操作 | 正常使用 | 风险触发后的处理 |
|---|---|---|
| 发帖、发消息 | 新老账号使用同一普通配额；没有新号 2 条/天、20 条/小时附加限制 | 真实超频返回 RATE_LIMITED 与等待时间，保留输入 |
| 添加好友 | 使用普通配额、每用户对唯一 pending 及屏蔽政策 | 不因账号不足一天限制为 3 条待处理；幂等重试不重复计数 |
| 发作品、项目、协作文档链接 | 登录后即可发送合法外链，无 72 小时等待 | 拒绝已知恶意链接和危险协议；未知站点用外链提示，不因陌生域名直接处罚 |
| 创建活动讨论 | 作者具备活动资格且明确选择开放，即可创建并成为首位成员 | 校验归属、活动、账号状态及唯一讨论，不设 24 小时等待 |

活动邀请不绕过内容规则，也不扩大活动范围。首期文字聊天的默认突发限流为每用户每分钟 60 条，详见共享契约；不再用每小时 100 条或新用户每小时 20 条限制持续协作。

**同步内容检查**：

| 检查 | 处理规则 |
|---|---|
| 消息长度 | 首条申请消息最多 500 Unicode 码点，私聊/群文字最多 4,000；超长为字段错误，不累计账号违规 |
| 不安全内容 | 不执行用户 HTML/脚本；危险链接协议拒绝。展示外链不自动抓取其正文或发送凭据 |
| 重复与突发 | 先按 client_message_id/Idempotency-Key 去重；同一消息网络重试不是刷屏。“收到”等常用短句不只因内容相同被判违规 |
| 关键词 | 仅作上下文检查信号，不用单个政治、医疗或安全研究词汇直接判定违规；实际拦截给出可修正原因及规则标识 |
| 明确恶意链接 | 拒绝本次内容，返回 CONTENT_POLICY_VIOLATION；不静默替换用户正文后发送，不仅凭一次拦截自动封号 |

**头像与资料边界**：

首期公开图片入口只有头像，帖子/聊天不据此扩展图片附件。头像先验证格式、大小和文件真实性；如接入外部图片审核适配器，待审或失败期间保持旧头像/占位，不先公开再删除。审核模型命中只产生内容层处理或待复核信号，不能按固定置信度直接封禁账号。用户可换图或请求复核。私人简历、来源文件和私聊不是公开图片审核的默认输入。

**治理与恢复**：

被拦截内容、一般校验失败和已确认违规分别处理。ContentViolation 只记录有依据的治理决定及规则版本、有效期、影响动作和复核状态；正式限制须有可审计理由，不能由累计格式错误自动升级成永久冻结。处理范围、结束时间和申诉入口显示在本人通知及 /me/content-restrictions。申诉通过 /reports 的 content_restriction 目标类型提交，引用本人获准决定和本人明确选择的证据。撤销误判后解除对应限制并通知用户，不恢复已被独立撤回的好友或联系人授权。

普通发布被拒绝返回统一错误包装：

~~~json
{
  "error": {
    "code": "CONTENT_POLICY_VIOLATION",
    "message": "链接无法安全发送，请检查或移除后重试",
    "retryable": false,
    "details": {"field": "body", "rule_id": "unsafe_link"}
  },
  "meta": {"request_id": "req_demo_01"}
}
~~~

检查不在通用日志复制正文、简历或联系人。人工处理只使用获准案件和用户明确提交的证据，不获得全量私聊权限。图片服务可用性、费用、误判率和人工处理时效均待实施验证，不把未经验证的单价或响应时间写成当前承诺。

### 10.3 举报处理

用户可举报帖子、评论、画像、好友请求或消息；提交时校验对象在其可访问范围内，保存必要证据快照和原因，不提供任意查询私聊的后台入口。

平台治理人员按职责访问案件。活动组织者只处理本活动内容和资格；对私人消息的处理依赖用户明确提交的举报证据，不因组织者角色获得全量聊天权限。处理结果、采取措施、操作者和时间写审计记录，并保留复核入口。

### 10.4 注销与删除

注销需要再次确认身份。立即停用账号、撤销会话、停止可发现状态和新互动、撤回联系方式授权，再以可重试任务清理资料、来源和派生缓存；每项清理有可观察状态，不能仅标一个“已删除”布尔值。

用户自己的帖子/评论停止公开并按关联要求留删除占位；聊天对方已收到的历史不承诺从其设备或合法历史中撤回。必要举报证据、处理记录与备份按单独保留策略管理，用户提示要区分即时停用与后续物理清理。

## 11. API、事务与安全合同

### 11.1 稳定接口入口

所有业务接口统一 /api/v1。下表仅定位用例，不另定义与共享契约竞争的请求响应结构。

| 入口 | 用例 |
|---|---|
| POST /event-invitations/redeem | 兑换邀请链接/码并取得活动资格 |
| POST /connection-requests | 基于合法 public_post 或 event_card 来源申请好友 |
| POST /connection-requests/{id}/accept | 接收者确认并建立关系 |
| POST /connection-requests/{id}/decline | 接收者拒绝申请 |
| POST /connection-requests/{id}/withdraw | 发起者撤回申请 |
| GET/POST /conversations/{id}/messages | 授权分页与幂等文字发送 |
| PUT /conversations/{id}/read-state | 单调推进已读位置 |
| GET/POST /posts | 按范围读取帖子及主动发布 |

表内路径均接在 /api/v1 后。身份、资料、组织者、群、互动、授权、通知和治理的其他接口以共享契约为准。所有列表采用有界分页；不能提供不受限的“返回全部用户/消息/成员”。

### 11.2 事务边界

| 用例 | 必须共同成立的事实 |
|---|---|
| 验证码登录 | 验证有效、单次消费、身份归属与会话创建 |
| 邀请兑换 | 邀请余量、成员唯一性、资格建立及通知事件 |
| 好友申请 | 唯一待处理请求、来源验证记录、首条消息及通知事件 |
| 接受好友 | 同意版本、全局关系、会话、首条消息归档、联系方式授权及成功事件 |
| 解除/屏蔽 | 关系状态、待处理申请、授权失效、权限版本及失效通知 |
| 入群/退群 | 成员状态、可读消息起点、资格版本及通知事件 |
| 发消息 | 有效发送权限、唯一客户端标识、消息位置及通知事件 |
| 发帖/评论 | 内容归属、合法范围、正文版本及通知事件 |

策略读取与写入要在同一事务内取得一致结果；屏蔽、资格撤销、入群等并发更新采用共享契约指定的版本/锁顺序。事务提交后再驱动缓存失效与推送，不能用 Redis 或模型输出替代 PostgreSQL 中的授权事实。

### 11.3 安全与可观察性

- 认证失败、对象不存在与无权访问按统一错误策略返回，不用详细错误泄露私有对象或谁屏蔽了谁。
- 变更用例校验 owner/participant/organizer，限制字段集合，防止批量赋值修改角色、身份、来源、权限或账号状态。
- 对登录、邀请兑换、联系请求、发消息、评论和举报分别限流；好友消息正常聊天与陌生请求使用不同预算，配置变化留审计。
- 缓存绑定访问者、对象、活动/关系及权限版本。后台任务与实时订阅在投递前再次授权，不能因为最初检查通过就永久放行。
- 监测请求冲突、重复提交、消息投递延迟、未读一致性、outbox 积压、举报处理时长及权限拒绝。日志只保留必要标识和结果，不记录正文、验证码、原始资料或凭据。
- 首期不开放模型或通用工具直接读取账号、私信、联系方式或执行管理动作；普通接口上线及回归测试不依赖模型密钥。

## 12. 核心用例与验收

用内存 Repository、固定时钟、假通知适配器验证领域用例；用真实 PostgreSQL 验证唯一约束、事务和并发；再做前后端端到端场景。只检查 HTTP 200 不构成验收。

| 场景 | 必须成立的结果 |
|---|---|
| 邮箱验证码重发/重复消费/连续错误 | 旧码失效，成功只消费一次，达到失败上限不可继续使用 |
| GitHub 与邮箱同名但未绑定 | 不自动合并身份，不能获取另一账号会话 |
| 同一邀请码并发兑换/重复兑换 | 不超量；既有成员不重复占用名额 |
| 无共同活动，从公开帖作者入口申请 | 可发送首条消息并建立好友，不能因此得到跨活动发现/AI 推荐 |
| 删除公开帖前后发送 | 已合法请求可继续处理；删除后不能新建来源申请 |
| 伪造作者、卡片、活动或用户 ID | 服务端拒绝，不能枚举或越权读取画像 |
| 不同来源同时向同一人申请 | 一条 pending；同方向幂等，相反方向转接受确认，不自动好友 |
| 接受与撤回/屏蔽/资格退出并发 | 只有符合原状态和版本的一方生效，不留无权关系或授权 |
| 接受成功但响应丢失后重试 | 一个 Connection、一个会话、一份首条消息及一次配对事实 |
| fields 从 friends 改 private | 所有好友后续读取与缓存均立即遵守新策略 |
| 成为好友但未选联系方式 | friends 普通字段可见，联系方式仍不可读 |
| 退出活动后仍是好友 | 旧私聊可继续；该活动画像、候选、群消息不可读取 |
| 想法同时属于两个活动 | 关注仍独立，群成员/消息/摘要不串活动 |
| 群新成员翻到入群前/退出后重放游标 | 均不能读取；未读只计算其获准区间 |
| 消息超时重发、乱序通知、多端已读 | 正文不重复，顺序稳定，已读不后退，断线能补齐 |
| 解除好友及重新添加 | 旧历史保留，未来发送/旧联系方式授权撤销；新关系需新同意 |
| 发帖后评论、点赞、收藏和范围变更 | 操作幂等，收藏私密，子内容及通知继承当前访问权限 |
| 屏蔽后复用缓存、通知、旧连接 | 不恢复未来互动或已撤销资料访问 |
| 组织者查看举报/管理成员 | 可处理本活动事务，不能读取未提交的私人消息或联系方式 |
| 注销中断后任务重试 | 账号不可再登录，清理可恢复，旧引用不重新公开资料 |
| 关闭全部 AI 服务 | 登录、邀请、手工资料、想法、帖子、好友、聊天、通知与治理仍可完成 |

完成标准是上述业务用例及其权限负例通过，并与共享接口、前端状态和联调文档保持一致。本文仅交付设计，不宣称应用、数据库迁移或自动化测试已实现或执行。
