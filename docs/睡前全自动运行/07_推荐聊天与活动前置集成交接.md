## 4. 精确入口与API依赖

- 宿主页面：`/matcher/app`、`/matcher/app/home`、`/matcher/app/login`、`/matcher/app/discover`。独立4203首页为未连接提示，`/demo`不是正式结果。
- 身份/活动：`GET /api/v1/me`，`GET/PUT /api/v1/me/current-event`；选活动的写前置为 `expected_revision`，不是 `expected_version`。当前选择属于(actor,认证会话)，不等于跨设备共享。
- 普通发现：`GET /api/v1/events/{spaceId}/discovery` 与 `/discovery/people/{ownerId}`，只当前服务端验证活动，签名cursor，0新增模型调用。
- 规则分析：`GET/PUT /api/v1/events/{spaceId}/recommendation-analysis/self-selection`；`POST .../people/{ownerId}`。绑定本人选择版本、`expected_current_event`的selection_revision/access_version及候选版本；本人选择是原生会话绑定SQL/CAS，不复用整个DbSession覆盖。
- 导入提示：`GET /api/v1/auth/github/import-status`，有来源引用时再读 `/api/v1/me/profile/sources/{id}/progress`。读状态不导入、不重试、不调模型；旧8113的404是历史装配负例，另一队隔离401不能证明该实例已修复。
- N05后端已交接候选合同：`GET /api/v1/me/events`本人有效正式成员分页；`POST /api/v1/event-invitations/redeem`本人明确兑换；`GET /api/v1/event-invitation-receipts/{id}`本人回执。以新模块最终README/实际DTO为接线准据，不把候选接口当已部署。加入和选择分两次明确操作，旧收据membership_current=false不能再加入或选中。
- 聊天入口与API由聊天队交接；N04/N05放行不表示既有私聊必须选择当前活动才能读取。好友、想法讨论、消息、推荐AI均不由活动面板自动触发。
