## 所有权和运行保护

backend_readiness 单写新活动模块；frontend_readiness 单写活动客户端、面板及专项测试；baseline_gate_audit 单写独立审查和 HTTP 脚本。root 单写公共 current-event 恢复补丁、宿主、固定升级工具及文档。未修改 HumHub 原版、vendor、mail、P8、AI 插件或另一队的 V5 原型。

升级工具只接受固定隔离库 `humhub_overnight_n01_20261112`、8113 和准确版本名单。必须先停本工具拥有的进程，私有备份核验成功后再升级；不恢复旧空库、不删除真实账号、不重抓来源。测试创建单独标记的虚构账号和 Space，只有登记并再次校验来源的夹具可变更。合成 native session 不计入真实 provider 登录证据。

根侧已补活动请求早期边界，放在 ModuleAutoLoader 之后、LanguageSelector 之前；仅模块窄 POST 路由处理 JSON，保留原始正文供严格校验，不修改 HumHub 核心。

## 撤权与界面恢复

原实现中，A 活动撤权后 GET 返回普通 403，却不再提供本人选择的 revision。用户因此无法在同一会话安全选择仍合法的 B。新增行为仅作用于 GET：本人选择仍为同一代且原生授权返回 access_denied 时，返回 `403 CURRENT_EVENT_ACCESS_REVOKED`，details 仅包含 `selection_revision`；不包含 Space ID、名称或 access_version。并发选择变化仍返回 `409 CONTEXT_CHANGED`。PUT 继续先验证目标资格再 CAS，不接受 null 绕过已有选择。

前端只识别这个严格错误合同；其他 401/403 仍清空私态。失效回执的 membership_id 仅代表历史代次，不能否定后来合法加入的新 membership_id。宿主对未知权限拒绝设置当前身份的暂停状态，用户主动点击后才重试，避免自动刷新循环。
