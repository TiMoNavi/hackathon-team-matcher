## 2. 当前活动必须沿用的精确合同

- GET /api/v1/me/current-event 成功的 data 为 `{space_id:int,selection_revision:string,access_version:string}`；无选择为 409 CURRENT_EVENT_REQUIRED，不是 200/null。401 表示未认证；资格撤销为 403；CURRENT_EVENT_MISMATCH、CONTEXT_CHANGED 为 409。
- PUT 同路径只接受 `{space_id:正整数,expected_revision:null或读到的selection_revision}`。null 只创建初始选择；已有选择必须比较版本，不能改名为 expected_version。selection_revision 为 selection- 加 32 位十六进制，即使再次显式选择同一 Space 也生成新 revision。
- 唯一存储按 `(actor_id,session_hash)` 绑定原生登录会话，**不是账号级跨设备共享选择**。同一会话各页共享当前选择；新登录、会话轮换、另一设备必须重新读取，必要时由本人再次选择。可恢复的画像草稿属于用户与 scope，不能因此自动替用户切换当前活动。
- access_version 是当前选择、活动访问策略和原生资格事实的指纹；DTO、URL、localStorage、邀请回执都不授予成员资格。实际业务入口再次 resolve/assertCurrent，返回前再检查版本，不跨活动补数据。
- 选择 CAS 成功后若复核失败，既有实现只清理本次写入的 revision，不恢复旧 Space，也不删除并发产生的新 revision。HTTP 失败时先 GET 真相，不自动用新 revision 重发用户原来的旧切换意图。

证据：[选择存储与补偿](../../backend/protected/modules/matcher-recommendation/adapters/native/SqlCurrentEventSelectionStore.php#L25)、[存储键](../../backend/protected/modules/matcher-recommendation/adapters/native/CurrentEventSelectionSchema.php#L13)、[会话身份适配](../../backend/protected/modules/matcher-recommendation/adapters/native/YiiActorSessionSource.php#L11)、[授权指纹](../../backend/protected/modules/matcher-recommendation/adapters/native/NativeCurrentEventAccess.php#L21)。该调用链不含模型调用；切换不会自动导入、生成画像或发起推荐。

## 3. 邀请凭据与兑换的最小方案（拟新增）

本节全部是待实施设计，不锁定新模块 ID、版本、路由或数据库表名。由单一集成人在 N04 放行后登记接口与迁移，不能把下列用例名当作当前 HTTP 端点。

| 拟新增用例/记录 | 最小输入或持久事实 | 约束与输出 |
|---|---|---|
| 创建/撤销活动邀请 | 服务端 actor；目标 Space；有限 expires_at、正整数 max_uses；撤销带 expected_invitation_version。记录 invite_id、space_id、issuer_id、token_digest、version、status、时间、额度。 | 每次检查该 Space 原生 InviteUsers 权限及有效资格。固定只授予普通成员身份，不接受客户端指定管理员角色。默认建议单次使用；多人码必须显式设置有限次数和期限。原生 InviteUsers 默认并非仅管理员，不能擅改产品权限定义。 |
| 邀请凭据 | 建议 32 字节密码学随机值，服务端只持久化其摘要；原始凭据仅创建时向有权创建者展示。 | 不存明文令牌到日志、分析事件、公开文档或回执；猜码/失败尝试独立限频。凭据只映射一个 Space，不接受请求里的 event_id/space_id 改目标。 |
| 兑换活动邀请 | 已认证 actor、凭据或登录衔接的服务端 pending handle、明确加入意图、Idempotency-Key。 | 登录态、CSRF、严格字段与大小验证；核对凭据、有效时间、未撤销、余额、目标 Space、本人未屏蔽以及签发者当前邀请权限。成功只建立合法原生 membership，不自动选择活动、确认画像或加入聊天。 |
| 兑换收据 | receipt_id、invite_id/version、actor_id、space_id、membership_id、结果、是否消耗一次、创建时间、请求键摘要与请求内容摘要；唯一约束至少覆盖 invite+actor 与 actor+操作+幂等键。 | 收据不含凭据或私人资料。只本人/有权管理者读取；重放同时返回历史结果与现时成员资格，不能凭历史成功重新赋权。 |

有效期限按服务器 UTC 判断；过期和余额为状态推导，撤销需 expected version。建议签发者丧失该 Space 邀请权限后未兑换凭据不可用；已经加入的成员不因邀请码过期/撤销被自动移除。反过来，成员主动退出或被管理员移除后，旧成功收据或旧码重复请求不得自动把他重新加入；再次加入需新的有效邀请及新的明确动作。

**使用次数口径：** 只对本邀请首次成功使该 actor 成为正式成员消耗一次；同键重放、同人换键重复、已经是正式成员均不重复扣次。已正式成员可返回 already_member 回执，但仍检查凭据有效性与合法来源；既有 invited/applicant 只有完成本次有权邀请的接受/批准转换后才算一次。失败/事务回滚不扣；成功后退出、撤权或邀请撤销不返还历史使用次数，避免反复进出扩容。多人争抢最后一个名额必须最多一人新增成员成功。

**登录衔接：** 登录前输入的邀请只保存为短期、不可伪造且会话绑定的 pending handle；它只是恢复用户意图，不能在 OAuth state/return URL 塞明文凭据或让登录回跳自动兑换。N04 登录/会话轮换成功后重验 pending handle，再由本人确认加入；取消登录、登出换账号和过期均不得沿用旧身份授权。真实双登录的这一衔接仍待 N04/N05 联合验证。

## 4. 事务、幂等和副作用

建议兑换流程分为两项明确操作：**兑换并加入** → **本人选择当前活动**。先提交加入收据，再调用已有 PUT current-event；后一步冲突/失败显示“已加入，当前活动尚未切换”，保留成功加入，不再扣码、不回滚为未加入、不自动覆盖另一页的新选择。

兑换事务内部的拟定顺序为：验证本人 → 按统一锁顺序锁邀请与原生目标/成员资格 → 核对幂等与历史收据 → 当前性/额度再验 → 经审查过的原生成员写适配器建立普通 membership → 原生正式成员复核 → 写兑换收据并条件增加一次额度 → 提交。相同 key/不同请求拒绝；相同 key/相同请求只重放。超时后先查该本人收据，不能用新 key 盲目重新兑换。原生同一 Space/user 并发唯一性与所有既有写入口必须实测，不能凭 ORM 查询或本地锁假定无重复。

两个必须先解决的源码限制：

1. **选择用例拒绝活动数据库事务。** SqlCurrentEventSelectionStore::mutate 与 NativeEligibilityQuery::run 在连接已有事务时抛 authorization_transaction_unsupported，原因是普通 repeatable-read 快照不能充当最新授权。因此不能把 current-event 选择/resolve 原样嵌入邀请兑换或 P1 的既有事务；独立提交后的选择步骤应沿现有实现。画像的事务中授权方案见下一节。
2. **原生 addMember 不是纯数据库插入。** silent=true 只抑制部分通知，仍可能触发 MemberEvent、成员活动、取消关注和通知删除；inviteMember 遇 applicant 会直接批准。不能把“创建邀请记录”误接成已加入，也不能声称 silent 没有副作用。实现前须通过原生适配器验证事务回滚、提交后事件和重放只触发一次；不能未经审查直接 INSERT membership 绕过原生生命周期。若通知/事件无法随事务安全处理，先建立经验证的提交后派发/去重边界，未解决前不验收 N05。

证据：[事务拒绝](../../backend/protected/modules/matcher-recommendation/adapters/native/SqlCurrentEventSelectionStore.php#L86)、[新鲜授权读取限制](../../backend/protected/modules/matcher-recommendation/adapters/native/NativeEligibilityQuery.php#L71)、[addMember 副作用](../../backend/protected/humhub/modules/space/behaviors/SpaceModelMembership.php#L402)、[canJoin 并非可直接加入](../../backend/protected/humhub/modules/space/models/Space.php#L338)。创建凭据本身不发送邮件/消息；通知能力是否接入应另有明确业务动作及验收。

## 5. 与画像草稿、任务和晚到响应衔接

**已存在但不能混淆：** GET/PUT /api/v1/me/events/{spaceId}/profile-context（spaces 别名也存在）仅按本人、目标 Space、画像 expected_version 授权；PUT 带 attributes 与 confirmation_intent=confirm，直接正式确认，不适用于第 3 步私有核对。P2 start/get 按 owner+scope 保存恢复；当前 AI capture/applicability 核对 scope、会话、来源、画像/草稿/批次版本，没有保存 selection_revision/access_version。用户仍是 A 的成员时，仅切到 B 不必然让旧 A 画像任务失效。以上是差异事实，不把它误写成现有越权读取或已完成的切换防护。

**拟新增的接入前置：** 十步旅程及其活动关联写操作保存/提交服务端验证的当前活动上下文；请求前置建议沿既有分析接口的形状 `expected_current_event={selection_revision,access_version}`，但它目前不是 P1/P2 可接受字段，不得直接加到旧请求体。新用例需同时验证 scope 对应的 Space、当前选择、membership、画像/草稿版本及旅程版本；身份与全局资料仍保留全局事实，不复制到新 Space。只更改 UI 分类不得变更安全 scope。

- 切换前保存成功的 A 草稿保留在 A；切换后载入 B 自己的上下文，新 Space 从空的活动专属输入开始，复用全局资料。失败的本地输入明确提示未保存，不偷偷写入 B。
- 响应绑定发起时的 Space、selection revision、旅程/草稿版本。前端仅显示与当前上下文相符的响应；abort 只是减少浪费，不能替代后端提交前和读取时的重验。A→B→A 的旧响应同样拒绝。
- 活动相关 AIJob 拟绑定发起的可信上下文引用；开始执行、安装、采纳、读取均校验。选择版本变化归 superseded，成员/账户/Space 授权消失归 revoked；旧结果不能覆盖新稿。切换不自动重试/重跑模型；已在途请求可能结束并产生真实用量，不能伪记零。
- worker 没有浏览器活跃会话，不能直接套当前 YiiActorSessionSource。应通过受控服务端上下文引用读取被绑定的选择及最新原生授权，不在 job 存会话 cookie、原始 session ID 或客户端宣称的权限。
- P1 已有事务使用其原生行锁；推荐 CurrentEventAccess 当前拒绝同连接活动事务。N06 必须增加经测试的事务兼容授权端口/适配策略（明确选择与原生资格锁、当前读或独立授权连接的边界），且阻止“前验通过、提交前撤权/切换”的竞态。单独在事务外前后各读一次不能证明未授权写未提交，不能作为充分验收。

细化画像结构与第 3/5/8 步确认继续见[画像后端差异](../用户画像收集/画像接入后端能力与差异_2026-11-12.md)。现有原生成员事实、全局画像及有效好友/私聊不因切换删除；活动相关发现、推荐、想法讨论仍各自重验。
