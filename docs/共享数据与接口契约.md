# 共享数据与接口契约

> 日期：2026-11-10。状态：待实现的权威工程合同；接口存在与否不以本文为证明。
> 九份设计文档共同引用本文的数据、状态、权限、版本、错误和 API。产品决定以 [完整方案 v3](完整方案设计_v3.md) 为准；模块划分见 [系统架构与领域设计](系统架构与领域设计.md)，业务解释见 [社交后端](社交后端业务设计.md)、[画像处理](Agent用户画像与资料处理设计.md)、[发现推荐](发现推荐与Agent工具设计.md)。

## 1. 通用约定与版本

- 全部业务 API 前缀为 /api/v1，下表的相对路径均拼接此前缀。JSON 使用 UTF-8、snake_case；ID 为服务端生成的不透明字符串，时间为 UTC RFC 3339，版本和消息序号为非负整数。
- 除公开帖子读取、登录入口外均需登录；全部写操作需本人实际请求及 CSRF/等效校验，并按用途验证 owner、participant 或 organizer。me、owner_id、actor_id 从登录会话派生，不接受客户端改写。
- 成功响应统一为 {data, meta:{request_id}}。同步创建为 201、查询/更新为 200、无响应体删除为 204；异步为 202，data 含 job_id 与状态，推荐另含 run_id。
- 可编辑草稿、画像上下文、申请接受和已有内容修改提交 expected_version；服务端只在版本一致时递增写入，否则 409。创建无需伪造已有版本；首次答案写入 expected_version=0。
- POST 创建实体、启动 AI、好友申请及接受须携带 Idempotency-Key，作用域为 actor + method + route。记录初始保留 24 小时；相同键和规范化 payload 返回原结果，不同 payload 返回 409 IDEMPOTENCY_CONFLICT。
- 幂等记录不是授权旁路：每次重放先校验当前会话及对象访问，再按当前权限裁剪原结果。永久唯一约束仍防止 24 小时后重复好友、首条消息或客户端消息。
- 普通列表默认 limit=24、最大 48；不支持无界 limit 或全量导出。列表 data 为 {items, next_cursor, has_more}，耗尽的发现批次另返回 exhausted=true。
- cursor 由服务端签名，有效期 15 分钟，绑定 viewer、资源/活动、查询哈希、排序、位置、权限版本和过期时间；过期 410，篡改或上下文不符拒绝。分页读取仍重新授权。
- 错误统一为 {error:{code,message,retryable,details},meta:{request_id}}；details 只含该用户有权知道的字段错误、最新版本或可恢复状态，不暴露 SQL、凭据、原文或其他人的存在性。

数据库字段映射可按 ORM 实现调整，但以上唯一性、归属与权限语义不能由实现者自行简化。源原件首期存受限 PostgreSQL 私有 blob/文本；模型和公开 API 都不直接访问这些表。

HumHub 插件路线的具体物理适配见 [原生数据库复用与字段落地规划](用户画像收集/05_原生数据库复用与字段落地规划.md)：当前单值使用原生 user/profile，当前扩展条目与策略使用插件记录，ProfileVersion 由不可变修订快照提供；API 返回统一逻辑字段。全局/活动状态、稳定条目 ID、草稿并发与指定版本读取按本契约验证。

同类经历、作品、技能可具有相同 key，各条以 attribute_id 独立编辑、引用和设置可见性；跨确认版保留该 ID，新增条目才分配新 ID。ProfileClaim 不另建表。全局版本唯一性用 owner+version 的部分约束，活动版用 owner+event+version，避免空 event_id 绕过唯一性。

保存已有条目必须携带 attribute_id，新增条目可省略该 ID 由服务端分配；确认只引用该草稿所属条目及其当前值。不能凭 key 覆盖同类其他经历，不能提交他人条目 ID 或通过 scope/event_id 改变归属。

DiscussionSpace 是 IdeaActivity 对应 Conversation(type=discussion) 的领域名称，不另建空间表。IdeaCircle 仅指长期想法的逻辑交流概念；具体群及其唯一成员事实分别为该 Conversation 和 DiscussionMembership。首次明确开放活动讨论时建群并加入确认该动作的创建者，不自动加入关注者或其他人。

昵称/头像只使用本人确认的展示身份；GitHub OAuth 信息仅为待选择建议，不能自动发布实名。EventContext={event_id,membership_version,permission_version} 由服务端生成；卡片最少返回 target_type,target_id,event_id,summary,access_ref，模型理由另含 explanation_source 与可公开依据，不返回隐藏字段。

## 3. 状态枚举与权限视图

| 对象 | 状态 / 枚举 | 约束 |
|---|---|---|
| User | active / suspended / deletion_pending / deleted | 非 active 不允许新互动 |
| Event / Membership | draft / active / ended / archived；active / left / removed | 自然结束不自动退出；推荐和新增活动来源联系要求 active；已有讨论群不受活动结束影响 |
| Membership.role | member / organizer | 组织者不能阅读私人材料或未举报私聊 |
| ProfileAttribute | visibility=authenticated / friends / private；confirmation=draft / confirmed | 新 AI 字段默认 private+draft；用户确认不等于真实性认证；last_confirmed_at 记录最后确认时间 |
| Draft / Source | editing / confirmed / discarded；received / processing / ready / failed / deleted | 草稿确认生成新版本；失败不虚构资料 |
| AIJob.execution_status | queued / running / succeeded / failed / cancelled | 执行结果不表示可以应用 |
| AIJob.applicability | current / superseded / revoked | 输入变更为 superseded；删除/撤权为 revoked，不能再返回内容 |
| InteractionDraft.status | editing / submitted / discarded | submitted 记录业务对象，不因重新打开草稿重复发布/发申请 |
| RecommendationRun.interaction_status | processing / awaiting_input / completed / failed / cancelled | 等用户回答时为 awaiting_input，当前 AIJob 已结束；不向 AIJob 增加等待状态 |
| Idea / IdeaActivity | draft / exploring / in_progress / completed / paused / archived；open / closed | 想法阶段不是用户是否排他入队 |
| ConnectionRequest / DiscussionRequest | pending / accepted / declined / withdrawn / expired / invalidated | 屏蔽、账号或资格失效终止为 invalidated，不伪称用户拒绝 |
| Connection / DiscussionMembership | active / ended；active / left / removed | 关系重新建立有新 generation；群读取只限当前成员期 |
| Conversation / Post / Comment | active / archived；published / deleted / hidden | 想法讨论群不因活动结束自动归档；由想法发起者决定是否归档；归档后只读 |
| Report / Outbox | submitted / reviewing / resolved / dismissed；pending / delivered / retrying | 状态及操作者审计；重试不重复业务事实 |
| RecommendationAction | shown / opened / skipped / saved / unsaved / interested / contact_requested | 独立追加，不以一个字段覆盖过去动作 |

| 读取视图 | 可返回 | 不能由此获得 |
|---|---|---|
| 匿名 public 帖 | 帖子正文、作者发布昵称/头像、公开评论 | 完整画像、活动成员、联系方式 |
| 登录+合法入口（陌生人） | 当前确认 authenticated 全局字段；活动字段另验资格 | 全平台用户目录、原文、private 字段、friends 字段 |
| 当前好友+合法入口 | 上一行加 friends 字段，按当前关系动态计算 | 他人其他活动字段、未授权联系方式 |
| 当前活动候选/推荐工具 | 经发现政策允许的 authenticated 字段及该活动上下文；AI 人选推荐另执行下述联系状态过滤，普通网格不据此隐藏成员 | friends 字段（即使查看者恰好是好友），原始材料，联系方式 |
| 本人资料编辑 | 本人确认版、草稿、选定来源/答案/证据 | 自动重读所有来源、自动调用模型 |
| ContactShareGrant | 本轮有效授权的指定联系方式版本 | 其他联系人、普通画像的权限扩大 |
| 活动群成员 | 当前成员期 seq>join_seq 的群消息 | 入群前消息、别的活动同想法群消息 |

活动字段始终取”字段 visibility AND 相应活动资格”，friends 不绕过活动范围。private 永远不向其他用户展示；普通字段设为 friends 对所有当前好友动态生效。公开帖子入口并不改变发现/AI 的活动边界。

### 3.1 字段可见性语义明确

**authenticated（陌生人可见）**：
- 定义：全局公开，任何已登录用户通过合法入口（活动内发现、推荐卡片、公开帖子作者、已收到的好友申请）都可以看到
- 推荐范围：仅限当前活动内的候选筛选和推荐，不提供跨活动全站搜索
- 典型字段：技能标签、公开作品链接、职业方向、协作偏好等愿意让潜在协作者了解的信息

**friends（好友可见）**：
- 定义：只有建立好友关系后才能看到，对所有当前好友动态生效
- 推荐行为：**不进入推荐工具的候选索引和模型输入**，即使查看者恰好已经是该候选人的好友
- 详情页行为：点击推荐卡片查看详情时，如果查看者恰好是该候选人的好友，此时才显示 friends 字段
- 典型字段：真实姓名、当前全职工作单位、更详细的个人背景等希望先建立信任再分享的信息

**private（仅自己）**：
- 定义：仅本人可见，任何情况下都不对外展示
- 使用场景：敏感个人信息、未完成的草稿内容、用于自己记录的备注等

**设计原则**：
- 字段可见性与活动边界是**两个独立维度**：authenticated 决定”谁能看”，活动边界决定”在哪里能被发现”
- 推荐工具统一使用 authenticated 字段，保证所有用户看到的推荐依据一致，避免因好友关系导致推荐解释不一致
- AI 人选推荐排除任一方向 pending 申请及当前有效好友；本人已发送的 declined/withdrawn/expired/invalidated/accepted 历史申请也作为排除依据，避免重新推送已联系过的人。此过滤不扩展到普通网格、随机浏览、好友页或想法推荐；普通入口展示关系状态，显式重新申请仍受普通业务规则约束。

### 3.2 access_ref 与合法入口

access_ref 是服务端签发的 15 分钟不透明引用，绑定 viewer、target、source_type/source_id、event_id（若有）、相关字段/关系/成员权限版本及期限；客户端不能自签或改变目标。每次读取仍查询最新资格、可见性和屏蔽，不把引用当永久授权。

合法入口由发现卡、公开帖作者、本人收到的合法申请、既有好友或获准讨论成员列表签发；GET /profiles/{user_id}?access_ref=... 必须核对绑定目标。讨论成员来源 discussion_member 仅用于获准画像读取，不直接作为好友申请的第三种来源；活动结束后不能由群成员入口绕回新活动联系。无此引用不提供任意用户详情查询。过期需从原合法入口重新取得；原入口失效不能续签。

好友申请 source_type=event_card 时 source_id 就是 access_ref，服务端解析目标与 origin_event；source_type=public_post 时 source_id 是帖子 ID，服务端由帖子解析作者，不能接受任意 recipient_id。评论作者不得冒用无关帖作者来源。

**资料处理方式**：extractions、question-batches、syntheses 使用 `generation_mode=rules|ai`，默认 rules，响应回显实际方式。rules 采用结构映射、规则题库和模板组装，直接返回结果，模型调用数为 0；ai 创建 AIJob 并返回 202，任务保存输入版本及实际用量。两种方式共用字段、草稿、问题批次、答案和确认语义。

规则处理直接返回的 batch 至少包含 batch_id、profile_version、scope、event_id、version、questions、generation_mode、schema_version、policy_version。综合草稿仍由本人编辑和确认。AI 功能不可用时返回相应能力错误，用户可主动以 rules 发起新的资料处理。

资料服务提供完整基础路径：来源接收 → 信息核对 → 规则补问 → 模板画像 → 逐条可见性与确认。个人中心直接使用同一组用例；OnboardingSession 记录步骤和对象引用。SSE 失败回退轮询，前台初始 2 秒间隔，持续无变化逐步退避至 10 秒，隐藏页面停止轮询。

**资料优先的首期合同**：简历上传和 GitHub 导入均为首个用户可用版本必备能力，出现在首个资料页面顶部。可提取文本的 PDF、DOCX 及 MD/TXT 须有真实解析路径；用户可以只提供其中一种材料，手填只是兜底，不代表功能可省略。

GitHub 首次注册入口在点击前说明会连接并读取公开资料。服务端完成身份验证后，以真实用户操作及已验证 AuthIdentity 登记初始导入，登记来源元数据和 outbox 后立即完成登录；worker 经画像用例读取公开资料，不让外部 GitHub 请求阻塞 OAuth 回调。该动作无需再粘贴主页或二次绑定；公开来源读取不等于 AI 调用，更不等于公开画像。已有账号普通登录、回调重放、刷新页面、切活动均不再次导入；删除过或取消初次读取的来源也不因登录恢复，只有用户主动重试/重新连接或刷新时再处理。

来源已登记不等于内容已就绪。首次读取或解析成功前，current_snapshot_id 与 last_updated_at 返回 null，前端分别显示“已连接”和读取状态；抽取只能选择已成功生成的本人快照。主动刷新失败保留之前的有效快照和读取时间，并提示本次刷新失败；不得把旧快照标为刚刚更新，也不能因此清空已有预填或确认资料。

公开读取范围为本人可读取的公开账号介绍，以及最多 10 个公开仓库的简介、语言/主题标签和 README 等项目说明；优先本人明确选择的项目，无选择时按确定性更新时间和稳定 ID 排序。作为一个 GitHub 来源保存，说明本次读取范围；不全量抓取代码、提交历史、关注关系或其他用户资料，不请求私有仓库权限。原文件限制沿用单文件 20 MiB、每批最多 5 个来源、合计 50 MiB；范围限制为可配置初值，超限明确提示，不能宣称已完整分析所有项目。

第 3 步展示已整理信息与待补项，用户核对后保存仅本人可恢复的草稿与私有核对快照，不写入正式画像，也不提前更改正式昵称或头像。问题提供者依据该私有输入版本准备一批 3–8 题，优先了解剩余协作维度和当前活动目标。规则模式从题库选择，AI 模式生成语境化问题；完整批次保存后逐题展示。第 5 步经本人逐条预览和明确提交后才正式确认；第 8 步按画像、身份、想法及活动对象分别显示回执。重新编辑期间旧正式版本保持有效。此处是当前产品合同，HumHub 私有核对输入与身份待确认引用仍需 N06 实施，不能直接调用现有正式确认 action。

发布、发申请或发消息前要求有效账号及本人确认的最小展示身份；尚未填写昵称时只引导补齐昵称，不强制完成资料导入、问卷或整个十步。活动操作仍须对应资格。

普通 AIJob 读取只给 current 的 result_ref；review 是单独的本人差异审阅入口，不返回原始材料、不适用于推荐结果、不把旧结果改回 current。采纳差异必须基于最新草稿重新提交 expected_version 并再次确认；revoked、已删除输入或不再具备活动资格时禁止审阅。

sort 首期为 recent / relevance；recent 按 updated_at,id 降序，relevance 使用服务端规则及稳定 ID 次序，均非 LLM。filters 接受领域、技能、角色、阶段、线上/地点、投入时间等白名单字段；person/idea 使用各自结构，未知条件 422，不转任意 SQL。

规则匹配核心不依赖 AI 扩展、模型密钥或向量服务；relevance 与 rule 批次可以独立完成规则召回/排序。AI 扩展调用同一主模块的有界查询能力，不能扩大活动、字段或工具权限。分数排名不保证达到推荐门槛；不足时给出用户主动普通浏览/调整条件入口，不自动混入弱匹配凑数，也不把 AI 故障伪装为空结果或规则推荐成功。此约束不新增公开字段或枚举，普通分页和 AI 卡片上限各按下文执行。

DiscoveryBatch 初始最多保存 200 个 ID、查询/种子与已曝光位置，15 分钟到期，不复制全活动 payload。普通发现可用签名游标遍历全部合法对象；随机批次只遍历本批次，换一批显式新建并优先排除近期曝光，耗尽如实返回，不跨活动补足。

AI 服务端召回最多 200，粗排后送模型最多 24 条紧凑摘要，最终 0–5 张卡；完整模型请求序列化 UTF-8 总长度不超过 24 KiB。固定入口正常 1 次、含修复最多 2 次；自然语言无澄清正常 2 次、含修复最多 3 次，有澄清时整个 run 硬上限 5 次，最多 3 轮问题。全部阶段共享最多一次 search_candidates 和一次有余量的修复；3 次澄清+1 次条件生成+1 次精排用满 5 次后不再修复，零候选不精排。

澄清问题是模型的结构化输出，不是额外工具调用；question 包含 id、kind=clarification/filters、options 及可自由填写出口。当前 job 完成后 run 可 awaiting_input；用户续答启动新的短任务，绑定同一 run 和当前问题版本。达到三轮仍不明确时提供结构化筛选器，不生成第四轮问题。修复前须预留后续必需调用；预算不足返回明确错误，不通过续答、HTTP 重试或偷偷新建 run 重置计数。

selected_self_fields 使用本人条目的稳定 attribute_id，不使用可能重复的 key；服务端校验归属、确认版本和本轮选择目的，活动条目另校验 scope/event。

entrypoint=onboarding/ai_recommend/ai_chat；target_type=person/idea。Skill 工具 search_candidates(target_type,intent,filters,current_idea_id?) 不接受 viewer/event/SQL 参数，服务端注入并重验。候选 friends/private、原始资料、联系方式及私信不进入候选索引或模型。缓存默认 15 分钟，每读仍检查权限，TTL 不是撤权延迟。

| GET/POST /posts/{id}/comments；PUT/DELETE /comments/{id} | 分页；body,reply_to?；本人编辑 expected_version → comment |
| PUT/DELETE /posts/{id}/like；PUT/DELETE /posts/{id}/save | 本人幂等点赞/取消、私有收藏/取消；收藏不通知 |
| GET /me/saves | 本人合法收藏页；失权对象只保留不可用占位 |
| PUT/DELETE /me/saves/{target_type}/{target_id} | access_ref（人物/想法）或合法帖子入口 → 本人收藏/取消；普通卡片无需推荐 run 即可收藏 |
| GET /notifications；PUT /notifications/{id}/read | 本人通知页；读标记幂等，不授权读取失效目标 |
| GET /notifications/events | 本人 SSE，Last-Event-ID 补拉；只返回通知必要字段 |
| POST/GET /me/push-subscriptions；DELETE /me/push-subscriptions/{id} | 本人主动启用后提交 endpoint,keys,device_label；列表只返回设备摘要；撤销立即停止后续推送 |
| GET/PUT /me/notification-preferences | expected_version,push_enabled,enabled_types,dnd_start/end?,timezone → 偏好；不替用户授予浏览器通知权限 |
| PUT /me/presence | client_instance_id,visibility,active_conversation_id? → expires_at；绑定当前会话，30 秒上报、60 秒过期，仅为触达提示，不能授予访问或标为已读 |
| POST /blocks；DELETE /blocks/{target_user_id} | 合法入口证明+目标 → 屏蔽；解除不恢复旧好友或授权 |
| POST /reports；GET /me/reports | target_type/id,reason,所选合法证据 → report_id；本人处理进度 |
| GET /me/content-restrictions | 本人当前及历史治理决定摘要、有效期及复核入口；可通过 reports 的 target_type=content_restriction 提交本人申诉，不暴露他人举报者 |
| PUT /reports/{id}/resolution | expected_version,status,reason,action → 治理结果；平台/活动权限分别检查 |

好友申请默认 7 天到期。相向申请返回已有请求和 requires_accept=true，不自动成为好友；同向返回 requires_accept=false。event 来源接受时复核 origin_event，不要求页面当前正选该活动；public_post 已合法发出的请求不因原帖后来删除失效，但删除后不能创建新申请。

活动自然 ended 不自动终止已经合法发出的 pending 好友申请；接受时双方原活动成员资格仍有效、请求未过期且未受屏蔽等限制即可处理。主动退出/被移除会使该来源 pending 失效；新建 event_card 申请仍必须是 active 活动，不能把两种操作混用同一个状态判断。

request_version 是申请版本，接受输入 expected_version 与其比较。source、接收人、首条消息及待共享联系方式版本在该申请轮次固定；修改须撤回后新建，避免对方看到的确认内容与实际授权不同。联系方式可不选，普通 friends 字段由关系动态生效。

接受时发起者所选联系人已变更/删除，返回 409 CONTACT_CHOICES_CHANGED，申请保持 pending，不创建关系或部分授权。接收者可明确选择“仍然添加好友，暂不接收已变更的联系方式”，携带 omit_stale_requester_contacts=true 和当前 expected_version 重试；事务只授予仍有效的选择，并通知发起者重新选择失效项目。接收者自己的 contact_choices 版本失效仍须本人重新选择，不能静默忽略。

帖子和申请可在最终 POST 中携带 interaction_draft_id,draft_version；服务端再次验证具体提交、来源和范围，同事务标记草稿已提交。草稿保存不是发送授权，过期 access_ref 不可借草稿续签。

首次申请消息上限 500 Unicode 码点，私聊/群文字上限 4,000；去除首尾空白后不得为空。服务器在会话事务中分配递增 seq，client_message_id 在同一会话同一发送者下永久幂等，相同标识不同正文 409；不承诺端到端加密。

read_seq 只能单调前进且不能超过已存在、本人获准的消息位置；群只读 seq>join_seq，新成员和重新加入均取得新起点，退出后禁读。未读只计获准范围内、seq 高于已读起点且非本人发送的消息。初次历史页取最新 limit 条并按 seq 升序显示，cursor 向旧消息翻页；after_seq 用于升序补拉新消息，与 cursor 互斥。解除好友保留合法私聊旧历史，未来发送/friends 字段/联系人授权终止；再次建立增加 Connection.generation，旧授权不复活。

public 帖及公开评论可匿名读；完整画像始终登录且有合法入口。event 帖必须带 event_id 并验证资格，评论继承帖子范围。评论一级展示、reply_to 仅指同帖；点赞与收藏分别唯一，收藏私密。普通 forum/chat API 不调用模型。

## 8. 错误、删除与事务验收

| HTTP / code | 含义与客户端行为 |
|---|---|
| 400 INVALID_REQUEST / EVENT_REQUIRED | 参数结构错误/缺少活动；纠正输入，不调用模型 |
| 401 AUTH_REQUIRED / SESSION_EXPIRED | 重新登录，回跳后重验来源，不复用旧授权 |
| 403 EVENT_ACCESS_DENIED / ACTION_NOT_ALLOWED | 当前资格或操作不允许；不泄露谁屏蔽谁 |
| 404 NOT_FOUND | 对象不存在或该用户不可知；避免 ID 枚举 |
| 409 VERSION_CONFLICT / IDEMPOTENCY_CONFLICT / MESSAGE_ID_CONFLICT | 拉取有权知道的最新版，由用户重新决定；禁止静默覆盖；详见版本冲突处理建议 |
| 409 REQUEST_NOT_PENDING / ALREADY_CONNECTED | 请求已终止/已有好友；返回允许查看的现态或现有会话 |
| 410 CURSOR_EXPIRED / ACCESS_REF_EXPIRED / INVITATION_EXPIRED | 从原合法入口重新取引用或邀请，不跨范围续签 |
| 422 VALIDATION_FAILED / SOURCE_UNREADABLE / INVITATION_INVALID | 字段或来源不可用；允许改材料、手填或更换邀请 |
| 429 RATE_LIMITED / AI_BUDGET_EXCEEDED | 限流或预算超限；见 § 8.1；平台 AI 预算不足立即报错，不自动生成/返回规则推荐；用户可主动返回零 LLM 普通发现 |
| 500 AI_SERVICE_ERROR | AI 服务内部错误（模型超时、输出格式错误等）；明确告知用户，不静默降级到规则排序 |
| 503 DEPENDENCY_UNAVAILABLE | 短期依赖故障；资料可选择手工，推荐可由用户主动转普通发现，不能自动返回规则结果冒充 AI 成功；普通业务不假成功 |
| 409 CONTACT_CHOICES_CHANGED | 申请待共享联系人版本失效；显示明确选择，不静默改为新版本授权 |
| 422 CONTENT_POLICY_VIOLATION | 当前内容未通过规则；保留输入并给可修正说明，不把一般格式错误或重复网络重试累计为账号违规 |

AI 业务失败通常体现在 job.execution_status=failed 及 safe_error_code；HTTP 200 读到失败任务不表示任务成功。取消、输入取代、撤权各保留真实语义；result_ref 只有仍获准且适用时返回。

### 8.1 限流契约

为防止滥用和保护平台资源，所有 API 端点实施分层限流。限流基于滑动窗口算法，按维度独立计算。

**限流维度与配额**：

| 维度 | 限流键 | 默认配额 | 窗口 | 适用端点 |
|---|---|---|---|---|
| IP 级别 | client_ip | 300 次/分钟 | 60 秒滑动 | 所有公开端点（登录前） |
| 用户级别 | user_id | 600 次/分钟 | 60 秒滑动 | 所有认证端点 |
| 敏感操作 | user_id + action | 见下表 | 按下表各操作窗口 | 特定端点 |
| AI 用户启动任务 | user_id + task_family | 5 个新任务/5 分钟 | 300 秒滑动 | generation_mode=ai 的画像/问卷任务，以及想法 AI 与推荐任务；各任务族分别计数 |

画像工作流的 rules 请求使用普通用户级配额，模型调用和 AI 启动任务计数均为 0。来源读取/文件解析按普通导入规则处理；实际模型调用单独记录用量。

**敏感操作配额**：

| 操作类型 | 限流键 | 配额 | 说明 |
|---|---|---|---|
| 验证码请求 | email | 3 次/10 分钟 | 防止邮箱轰炸 |
| 登录尝试 | email | 5 次/15 分钟 | 防止暴力破解 |
| 好友申请发送 | user_id | 10 次/小时 | 防止骚扰 |
| 消息发送 | user_id | 60 次/分钟 | 防止突发刷屏；不以每小时 100 条限制正常持续协作 |
| 帖子发布 | user_id | 5 次/小时 | 防止刷屏 |
| 举报提交 | user_id | 10 次/天 | 防止恶意举报 |
| 头像上传 | user_id | 3 次/小时 | 防止资源滥用 |

**429 响应格式**：

~~~json
{
  "error": {
    "code": "RATE_LIMITED",
    "message": "请求过于频繁，请稍后再试",
    "retryable": true,
    "details": {
      "limit": 10,
      "window_seconds": 3600,
      "retry_after_seconds": 1800,
      "dimension": "friend_request"
    }
  },
  "meta": {
    "request_id": "req_demo_01",
    "timestamp": "2026-11-10T12:34:56Z"
  }
}
~~~

**响应头**：
- `X-RateLimit-Limit`: 当前窗口配额上限
- `X-RateLimit-Remaining`: 剩余配额
- `X-RateLimit-Reset`: 窗口重置时间（Unix 时间戳）
- `Retry-After`: 建议重试等待秒数（仅 429 响应）

**客户端处理**：
1. 收到 RATE_LIMITED 后至少等待 Retry-After；指数退避的附加间隔可封顶 60 秒，但不能把服务端 30 分钟等待截成 60 秒。写操作仅对同一幂等请求重试；AI_BUDGET_EXCEEDED 不自动重新启动模型
2. 主动监控 `X-RateLimit-Remaining`，接近 0 时降低请求频率
3. 用户级限流触发时，显示友好提示："操作过于频繁，请在 X 分钟后重试"
4. AI 调用限流触发时，明确告知："AI 功能使用次数已达上限，请稍后再试"

**豁免与调整**：
- 只读操作（GET /me/events、GET /posts）遵循通用限流，不另套发送/发布配额
- 活动组织者在其活动内的管理操作有更高配额
- 限流配额为工程默认值，部署时根据实际资源调整
- 限流日志记录到审计系统，用于识别异常流量模式

配额对新老账号一致，不叠加账号注册未满 24/72 小时的发帖、外链、讨论或好友限制。幂等重放、同一推荐 run 的澄清续答/内部修复不重复占“新任务”名额，实际模型调用仍计入 run 的 2/5 次硬上限和平台预算；HTTP 请求仍受通用限流。平台预算不足与用户请求超频须用不同错误码说明。

### 8.2 版本冲突处理建议

当多个编辑操作并发或 AI 任务晚到时，会产生 409 VERSION_CONFLICT。前端应该提供友好的冲突解决界面，而不是简单地显示"保存失败"。

**冲突场景与处理**：

| 场景 | 冲突检测 | 推荐的用户界面 |
|---|---|---|
| 画像字段并发编辑 | expected_version 不匹配 | 显示"有人（或你的其他设备）刚刚更新了画像"，展示当前版本与用户编辑的差异，提供[使用我的版本][使用最新版本][手动合并]三个选项 |
| AI 整理结果晚到 | AI 任务成功但 base_version 已变化 | 显示"AI 整理完成，但你已经手动修改了画像"，并排展示 AI 建议和当前内容，允许选择性采纳 AI 建议的字段 |
| 好友申请并发接受 | request_version 不匹配 | 自动刷新状态，显示"该申请已被处理"或"对方已撤回申请"，不需要用户手动选择 |
| 消息重复发送 | client_message_id 冲突 | 静默去重，不显示错误；如果内容不同则提示"该消息已发送不同内容" |

**冲突解决界面设计要点**：
1. **可视化差异**：使用颜色标记新增（绿）、删除（红）、修改（黄）的字段
2. **按字段选择**：允许用户逐字段选择保留哪个版本，而不是只能全选一方
3. **保留用户输入**：冲突解决过程中用户的编辑不应丢失，提供"保存为草稿"选项
4. **时间戳说明**：显示每个版本的更新时间和来源（"你在 5 分钟前修改" vs "AI 在 2 分钟前生成"）
5. **预览合并结果**：在确认前预览合并后的完整画像

**实现建议**：
- 409 响应的 `details` 字段应包含 `current_version` 和可选的 `conflicting_fields` 列表
- 前端缓存用户的编辑内容，即使保存失败也不丢失
- 提供"稍后处理"选项，将冲突标记为待解决，用户可以之后再回来处理
- 对于简单冲突（如只改了一个字段），可以提供"快速解决"按钮一键采纳某一方

原始资料无自动到期清除，且不会后台自动抓取远程来源或重跑生成。本人删除即时撤销读取、取消可应用结果并清理派生投影；活跃存储清理 24 小时、备份最长 30 天作为工程默认，必须在部署阶段核验实际能力，不能先承诺已达成。恢复备份必须先重放删除标记再对外服务，防止被删材料复活；依法/治理必要的证据另行明确保留范围，不混作日常画像来源。

| 事务/负例 | 必须验证 |
|---|---|
| 验证码、邀请 | 原子消费/余量；重复与并发不多建身份或成员 |
| 画像确认、任务晚到 | expected_version 锁定输入；AI 成功但 superseded 不覆盖人工确认 |
| 好友接受 | 唯一用户对、明确接收者同意、会话、首条消息归档、可选联系授权及 outbox 同事务 |
| 相向申请/撤回/屏蔽并发 | 一条 pending，无自动好友；旧版本与旧 generation 不可复活 |
| 消息/已读/入群 | client_message_id 去重，seq 事务分配；单调 read_seq、join_seq 边界、退出撤权 |
| 跨活动与 access_ref | 伪造来源、他人引用、过期引用、旧分页、旧缓存和后台晚到均不能越权 |
| AI/普通发现 | 普通列表零 LLM；200→24→5、24 KiB、一次工具/修复；不足不跨活动补齐 |
| 动态字段/联系人 | friends 对所有好友当前生效；private、活动字段及未授权 contacts 不泄露 |
| 论坛/通知/删除 | 评论继承范围，通知不能绕过删帖或撤权，恢复备份不能重公开删除内容 |

以上默认值集中配置并版本化；变更先修订本契约再同步前端、画像、推荐、社交及联调文档。当前交付仅为设计，尚未执行数据库迁移、真实接口测试或生产清理能力验证。

### 9.1 所有权与适用规则

本轮采用HumHub 1.19.4同源React插件，不重建FastAPI或平行用户／好友／消息库。原生user/session/AuthClient、Space/membership、friendship、mail保留事实所有权；P1/P8/P2分别拥有资料、授权投影、引导编排；matcher-recommendation拥有唯一current-event及发现／推荐。UI、认证、邀请、社交适配经ports调用原生用例，不把能力开关或模型输出当同意。

以本节的真实传输映射接线；产品不变规则与最新明确要求优先，源码不符处标待修。R03、authenticated/friends/private、公开帖跨活动联系例外、全局／Space分离、普通发现0 LLM、AI无社交写权限及任务applicability保持。新增确认普通画像和可选联系方式默认authenticated，既有明确范围保留；联系方式独立读取并沿用本人逐条范围，不把旧额外联系人授权流程强套成现有必需入口。未确认资料私有，参与关系逐对象默认private，活动字段与实际资格取交集。

第4节的目标架构 `/events/{id}/invitations` 与 DELETE 路由不作为当前 HumHub 已实施端点。matcher-event-access 0.1.0 使用以下 `/api/v1` 路由，严格 DTO、签名 cursor、配额及错误详见[模块合同](../backend/protected/modules/matcher-event-access/README.md)：

| 当前 HumHub 路由 | 事实与授权边界 |
| --- | --- |
| GET `/me/events` | 仅本人当前有效正式成员关系；默认24、最大48，签名cursor；不列全站活动或他人成员关系 |
| POST `/events/{spaceId}/invitation-codes` | 原生有效成员且具有当前 InviteUsers 权限；该权限默认可含普通成员，不能另用目标架构 organizer 文案替换原生策略；明确 create_invitation 意图及 Idempotency-Key |
| POST `/event-invitations/{id}/revoke` | 原生当前邀请权限、expected_version 与明确 revoke_invitation 意图；不删除已加入成员 |
| POST `/event-invitations/redeem` | 本人、CSRF、token、明确 join 意图和 Idempotency-Key；邀请码余量、普通 membership、回执和待提交副作用同事务 |
| GET `/event-invitation-receipts/{id}` | 本人历史回执；membership_current 必须匹配当前有效 membership_id；旧回执不重新入会或改变当前选择 |

凭据随机32字节、43位base64url，只保存digest且创建时展示一次；创建重放不再返回token。原生成员生命周期经受限适配与提交后副作用记录处理，不改核心表定义，不另建成员事实，不自动建立朋友、聊天或想法讨论关系。

推荐0.4.1新增当前活动的窄恢复合同，唯一 GET `/me/current-event` 在本人已存在选择失去权限时返回 `403 CURRENT_EVENT_ACCESS_REVOKED`；details只能含本会话不透明 `selection_revision`，不返回旧Space/名称/access_version。必须重新验证选择代次未变，否则409 CONTEXT_CHANGED。PUT仍使用既有 `{space_id,expected_revision}`，先验证新活动资格再CAS；null只用于真正无选择的初次写入。前端仅识别上述精确恢复错误，其他403仍清除旧授权状态；加入和选择保持两次本人操作。
