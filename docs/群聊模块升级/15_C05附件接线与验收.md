## 本批范围与分工

继续现有受管 direct 的文字能力，增加本人暂存上传、显式附件发送、取消与授权下载。复用原生 file 和 message_entry；不另建好友真相，不自动建新私聊，不扩大到群或活动讨论。首页和画像继续使用 [通用接口目录](12_首页画像通用社交与聊天接口.md)，N08 新交接须以实际实现为准。

- 后端 agent 单写 matcher-chat 附件用例、SQL/HTTP 适配、迁移与离线测试。
- 前端 agent 单写 integration 源码与测试，保留原页面布局和日夜样式。
- 独立审查 agent 检查原生文件旁路、撤权、暂存生命周期与最新 N08 接口；结果写入 [16 独立审查](16_C05附件独立审查.md)。
- root 单写隔离工具、构建产物、本文、task 与实施回执，负责运行实例、数据库和定向发布。

## 实施合同

本批锁定单文件 5 MiB、每条最多 3 件、暂存 24 小时，每用户最多 20 个有效暂存（最多 100 MiB），滚动 60 秒最多 20 次成功新上传；合法重放和失败不计额度，取消不退还历史速率。允许 JPEG / PNG / PDF / UTF-8 纯文本。这是聊天本批的保守实施选择，并非沿用画像上传限额。新增 attachmentsEnabled 属性与持久设置双开关，默认关闭；读取旧十字段 bootstrap 不变。

| 入口 | 请求与结果 |
|---|---|
| POST /api/v1/conversations/{id}/attachments | multipart 仅 client_upload_id（小写 UUIDv4）与 file；新建 201，同键同原文件名和字节重放 200，异载荷 409 |
| DELETE 同路径/{attachment_id} | 取消本人暂存；返回 cancelled 或 expired；已绑定 409 |
| GET 同路径/{attachment_id}/download | 已绑定文件逐次授权，强制 attachment / no-store，无长期 token、重定向或内联预览 |
| POST /api/v1/conversations/{id}/messages | 在既有 client_message_id、body 上增加可选 attachment_ids（最多 3 个）；有附件才允许空正文 |

纯附件消息 kind=attachment、body=null。附件投影只有 id、name、mime、size、download_path。context.attachments 为可选能力，缺失即关闭；包含 upload_enabled、download_enabled、max_file_bytes、max_files_per_message、allowed_mime_types 与 staging_ttl_seconds。已绑定历史下载不会仅因关闭新上传开关而消失，但仍逐次验证读取范围。

文件只能绑定本人、同一会话的有效暂存。消息提交与永久幂等回执同事务；失败不得遗留可读未授权文件，回放不能恢复已删除或失权内容。每次下载重新检查当前资格与消息历史范围，禁止直接暴露长期公开地址。原生未知文件仍拒绝。

原生物理删除早于旧守卫事件，故新增 [17 中性前置保护补丁](17_原生文件存储前置保护补丁.md)，实际聊天授权仍由模块负责。必要依赖和升级复验已单独登记。

## 验收计划

1. 领域与 HTTP/客户端合同离线验证，覆盖所有权、类型大小、纯附件、重复提交、取消及失权。
2. 固定隔离迁移与新版本夹具，验证旧数据哈希、真实上传下载、原生入口拒绝、事务失败与回收。
3. 双用户页面验证显式上传、发送、重试与下载；检查桌面手机、日夜布局。
4. 独立复核，关闭本批运行开关并停服，记录限制与定向发布回执。

### 已发现并修正

1. 原生类名配置前导反斜线与严格StorageManager检查不一致，合法类名正规化后严格相等，不允许任意子类。
2. read hook在原生MIME fallback与setContent catch中可能被吞，路径检查移到try之前；实际Yii126检查验证。
3. 重放成功后会话列表被清空但未补读，补一次安全GET并取消旧列表在途请求；最终浏览器实际列表已恢复。
4. 非业务异常savepoint未完整回退，导致同进程重试冲突；修复自有边界、丢弃异常连接，真实故障恢复通过。
5. attachment_ids显式null曾被当缺省，现422并纳入最终真实HTTP回归。
