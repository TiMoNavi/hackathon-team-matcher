# 聊天入口接管与恢复方案

> 日期：2026-11-12。用户已同意：启用聊天插件时，可以关闭指定原生聊天入口，改用插件提供的入口。本文件记录新的实施方向，尚未实现入口切换，也未开启主预览。
> 入口：[任务](task.md) · [推进计划](07_真实接线推进计划.md) · [C01合同](03_C01_聊天实施合同.md) · [实施记录](02_实施记录.md)。本次方向更新不改写既有隔离验收结果。
> 后续更新：T1/T2最小读取接管子集已有实现与隔离证据，见[11回执](11_T1T2入口接管隔离验收.md)。总专项最新覆盖式原则取消停用后必须回原生的要求；本文“返回原生”作为可选恢复方案，安全维护或兼容版本恢复也可。本批导航暂停仅约束导航/新页面，不代替独立API的真实业务授权。下文保留最初规划，不作为全部已实现声明。

## 1. 决策与边界

采用“插件接管指定聊天界面，原生 mail 继续提供消息存储”的模式。接管范围内不再要求原生与插件两套完整界面同时读写；验收重点改为入口映射、完整替代所声明的能力、权限覆盖及可恢复切换。

- 安装文件本身不切换入口。安装、依赖检查通过并启用接管后，由插件扩展点替换约定的聊天菜单和页面；不直接修改 mail/core、全局主题或其他专项代码。
- 原生会话、成员、消息、文件保持单一事实来源；matcher-chat 保存规则元数据，matcher-chat-ui 提供界面。禁止用 mail::disable/remove 隐藏界面，其生命周期操作会删除消息数据。
- 接管范围必须同时写清“哪些用户、哪些会话和哪些能力”。涉及聚合列表、搜索或通知时，不得因某个受管会话而让该用户其他合法会话无入口，也不得影响其他用户。
- 好友申请、想法发布、画像、登录和全站导航的业务所有权保持原分工；接管聊天入口不赋予新的社交资格。
- 停用 UI、恢复原生入口和卸载业务保护是三种不同操作。原系统其他功能应继续运行，数据保留；聊天恢复须满足相同权限语义，不能通过关插件扩大历史访问。

## 2. 入口映射

以下是目标行为，不是当前已具备的能力。实施时先逐项登记真实路由、请求方法、扩展点、受影响用户/会话、替代能力及未支持时的表现，再开放对应项。

| 原生入口或能力 | 启用接管后的目标 | 开放条件与边界 |
|---|---|---|
| 收件箱菜单、聊天列表页 | 指向插件会话列表 | 覆盖接管范围内全部合法会话；未支持的群或附件会话不得被静默隐藏 |
| 会话页及旧聊天深链 | 验权后跳转插件对应会话页 | 仅对确认无写副作用的 GET 路由重定向；只保留经验证的会话 ID，固定同源目标，不转发任意 returnUrl |
| 发消息按钮、原生编辑器 | 使用插件发送界面及同一发送用例 | C05-A/C06-T真实收发和幂等通过后替换；只读版不宣称已替代发送 |
| 附件上传、预览、下载 | 插件入口调用受权文件适配 | C05-B/C06-A通过；旧直链仍逐次验权，不能只隐藏上传按钮 |
| 建群、邀请与成员管理 | 插件明确建群与邀请流程 | C07通过；接受前不可读取消息；未接管合法旧群需保留已验证的可用路径 |
| 活动想法讨论入口 | 指向获准的活动讨论会话 | C08及N09窄接口通过；按想法发布和Space隔离，不自动建群或接受邀请 |
| 旧写请求、REST及第三方调用 | 使用同一授权用例，或明确拒绝已被替代的动作 | 不将 POST/PUT 等写请求重定向后重放；不靠菜单隐藏阻止旧请求；返回可识别的不可用/迁移结果 |
| 搜索、未读、通知、live | 聊天摘要与跳转遵守相同权限，可只停用被替代的聊天部分 | 不允许最终方案封锁整个 live 服务或非聊天通知；聚合结果逐项授权并保留无关功能 |

入口跳转只负责页面导航，不把文件下载或搜索/API响应重定向成HTML，也不以307/308转送旧写请求。会话列表、正文、已读和文件仍由服务端用例验权，深链或通知携带 ID 不构成授权。旧GET若原本隐式标已读，须在旧控制器动作执行前接管，并由插件按实际查看更新已读。

## 3. 开关与恢复

下列是待实现的逻辑状态，不是现有配置字段。现有 uiEnabled/readUiEnabled/readEnabled 不能直接代表入口接管或安全恢复。

| 状态 | 用户看到的行为 | 数据与权限 |
|---|---|---|
| 原生模式 | 使用原生聊天入口 | 未纳管范围沿原生规则；已有受管数据仍须通过保护适配，不因状态名称绕过规则 |
| 接管模式 | 指定聊天入口统一使用插件 | 仅在能力与覆盖检查通过后切换；隐藏旧UI同时约束旧服务端入口 |
| 暂停或插件不可用 | 给出明确不可用状态或已验证的合法替代路径 | 不自动开放不安全的旧入口；其他站点功能继续工作 |
| 返回原生模式 | 自动检查通过后恢复相应原生菜单与页面 | 保留消息和必要保护适配；有不兼容项则明确列出受影响会话/能力，不扩权，不伪报恢复成功 |

目标是让管理员使用一个明确的接管开关。后台负责检查依赖与覆盖、记录状态，并避免出现“先打开旧入口，再补授权”的切换窗口；若切换失败，保持最后一个安全状态并报告原因。验收必须包含并发请求和重复切换。

对于新群的邀请、加入前历史、退出和重新加入规则，原生界面可能需要保留保护适配才能安全恢复。当前不承诺任意带数据状态下删除全部聊天插件后仍能立即使用所有增强会话；完整卸载是独立的数据/权限迁移任务，不能删除元数据来规避限制。

## 4. 当前事实与下一批任务

当前已有受限真实读取和已读能力。发送、附件、群邀请及活动讨论尚未交付；当前 NativeGuard 对受管用户的 mail/live 存在大范围拒绝。这只是隔离实验中的临时保护，不是已经完成的接管方案。UI关闭也不会自动恢复原生路由。

| 工作包 | 下一步产出 | 完成条件 |
|---|---|---|
| T1 接管策略与映射 | 主集成人锁定入口/能力/用户/会话覆盖矩阵；后端agent定位插件扩展点 | 不改原生源码；无未登记入口；不能按会话细分的聚合入口有明确处理方案 |
| T2 最小切换适配 | 后端agent实现接管状态、旧入口处理和聊天范围的保护；主集成人处理宿主菜单适配 | 安全GET可导航、旧写不重放；无关live/通知正常；UI故障与切换不产生越权窗口 |
| T3 真实替代能力 | 前端agent完成列表/深链/不可用态；随后C05-A/C06-T提供文字发送 | 读取阶段仅用于明确范围的隔离验证；文字可用后验收可声明的私聊替代范围，不以全套旧UI并行可用为前置 |
| T4 逐步扩展与回退 | C05-B附件 → C07群邀请 → C08活动讨论；独立审查者检查每批接管与恢复 | 双用户真实业务、旧路径负例、数据保留、撤权与切换竞态；每批只开放已有证据的能力 |

T1/T2与发送合同和离线准备可并行，不必等所有原生聊天界面同时支持增强规则后才开始发送。真正开放发送仍须具备必要好友/资格/唯一绑定接口、发送与幂等验证，以及对应接管范围的旧写保护。某分支缺少依赖，只暂停该分支。

主agent维护合同、共享接口、构建与8124隔离环境；后端、前端和独立审查agent按单写范围执行。不操作8113、主预览、真实用户私聊或凭据。

## 5. 验收口径调整

1. 接管范围内不再要求“两套完整聊天UI交叉读写”；改验同一份原生数据、正确的入口映射和实际可用的替代能力。原生适配器的内部写入与SQL并发仍须验证。
2. 旧URL、REST、文件、搜索、通知与live不能绕过邀请、历史和撤权规则；同时验证未接管用户/会话和非聊天功能未受误伤。
3. 开启、关闭UI、暂停、恢复原生及重复升级分别有证据；消息不丢失，未确认写入不自动重放，切换不能扩大访问。
4. 当前真实focus/visibility、身份生命周期和自动/并发撤权等缺口仍待验证。改变接管模式不能把未测项变成通过，也不能把当前只读版称为可完整替换聊天。
5. 历史审查08及读取回执09保持原文结论；新方向及后续实现另行记录，不反写旧测试。
