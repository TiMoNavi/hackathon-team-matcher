# C07-P 普通群与邀请合同

2026-11-13（Asia/Shanghai）。本批只交付未装配的领域用例、内存适配、前端合同和动作状态；不注册新 HTTP API、不迁移数据库、不开放群 UI。生产能力仍限既有 direct 0.3.0。入口：[task](task.md) · [公共接口目录](12_首页画像通用社交与聊天接口.md) · [独立审查](19_C07普通群离线独立审查.md)。

## 1. 责任与依赖

普通群创建、邀请、接受／拒绝／撤回、退出及成员期由 matcher-chat 单一写入。后续 SQL 适配继续复用原生 message、user_message 和 message_entry；内存数据只是测试替身，不成为第二套运行时消息库。领域与应用只依赖领域端口，不依赖 Yii、HTTP、SQL 或 React。

N08 拥有好友申请、合法来源、接受版本、持久历史和唯一私聊绑定。本批资格端口表达启用账号、有效双向好友与双向屏蔽交集，真实适配留后续；不包办好友业务。matcher-ideas 继续拥有想法／Space 发布、永久绑定与 tombstone。普通 group 没有 Space/idea/current-event，不替代活动 discussion，不提供全站人物搜索。C08 的审批与成员事务交接仍待落实。

## 2. 明确策略

GroupPolicy 必须显式注入。离线参考配置为邀请有效期72小时（259200秒）、每群最多50个 active 成员（含 owner）和50个有效 pending 邀请。这是本批普通群的独立选择，不是原生默认或好友规则；尚未装配到生产。创建及邀请的真实持久速率限制留下一批。

| 情形 | 规则 |
|---|---|
| 创建 | 创建者明确操作，只建立本人正式成员；无假首条消息、不自动邀请或接受 |
| 管理 | owner 唯一有邀请／撤回权限；普通成员无管理权 |
| 候选 | owner 与目标当前均启用、双向好友、双向未屏蔽；接受重新检查；已有好友不绑定当前活动 |
| 去重 | 同群同目标最多一个有效 pending；active 不能再邀；重邀用新 key 与新邀请 ID |
| 接受 | 仅 invitee，expected_version 匹配、未过期、当前资格有效；同事务建立成员期 |
| 拒绝／撤回 | invitee 拒绝、owner 撤回，均检查邀请 expected_version；终态不恢复 pending |
| 过期 | now 达到 expires_at 即不可接受，不依赖定时任务及时运行 |
| 退出 | 普通成员明确退出并检查成员 version；owner 返回 GROUP_OWNER_CANNOT_LEAVE，转让／解散留后续 |
| 重入 | 重新邀请与接受；generation 增长，join_seq 取接受时最新 seq；加入前及退出期间历史不可读 |

邀请 pending/accepted/declined/withdrawn/expired 与成员 active/left 分开。pending 不建立原生成员，不返回正文、成员列表、附件或消息摘要；历史 accepted 不授予当前读取权限。群标题投影只给当前正式成员，邀请最小展示与合法姓名投影留真实页面阶段核定。旧群不得按人数猜类型或伪造历史起点。

## 3. 命令与回执

用例为 create/invite/accept/decline/withdraw/leave 和本人邀请详情。命令包含 UUIDv4 client_command_id 与明确 confirmation_intent；邀请决策绑定邀请 expected_version，退出绑定成员 expected_version。真实 actor、CSRF 和用户操作的验证属于后续同源装配；离线字符串本身不是同意证明。

永久幂等范围 actor + operation + key，摘要绑定对象、expected_version 和正文。同键异内容拒绝；失败不留部分成员或回执。成功重放只返回当前授权投影，不重新创建群／邀请／成员。资格与状态在一致性边界中重验；内存故障注入不证明 MySQL 并发正确。

| 成功 envelope 字段 | 类型／语义 |
|---|---|
| data.group | null 或 conversation_id、type=group、title、owner_id、version、active_member_count；只给当前正式成员 |
| data.invitation | null 或 id、conversation_id、inviter_id、invitee_id、status、version、created_at、expires_at、resolved_at；仅获准双方可见 |
| data.membership | null 或 conversation_id、user_id、generation、join_seq、status=active/left、version；仅当前 actor 本人 |
| data.replayed | boolean，命中历史收据不等于恢复权限 |
| meta.request_id | 本次请求标识，不是幂等键或授权凭证 |

数字为 JS-safe 正整数／非负序号，时间为严格 UTC 秒 `YYYY-MM-DDTHH:mm:ssZ`。群标题为非空白 UTF-8，最多100码点／400字节，不允许C0/C1控制字符，保留原文。前后端拒绝额外字段、类型污染、身份／会话不匹配和矛盾状态。pending可伴随本人上一成员期的left投影，但绝不伴随受邀者active；历史终态与当前成员期分别解释。邀请详情在到期时以expires_at作为稳定resolved_at投影expired，不因读取自动写数据库。邀请列表、签名cursor、候选读取和真实限流仍待后续。

新增服务端调用均为内部离线接口，尚无对应可调用HTTP路由：

| 调用 | 精确输入与责任 |
|---|---|
| `new GroupCommand(operation, body)` | create为title，invite为target_user_id，其余为expected_version；每种body另含client_command_id与对应confirmation_intent，拒绝未知字段 |
| `new ChatGroups(repository, authority, clock, policy)` | 注入领域端口和显式策略；当前只有测试内存适配，后续SQL／原生事实必须共用事务与锁边界 |
| `create(actor, command, requestId)` | 创建本人单成员空群 |
| `invite(actor, conversationId, command, requestId)` | 群主向当前合格好友发邀请 |
| `accept/decline/withdraw(actor, invitationId, command, requestId)` | 受邀者接受／拒绝、群主撤回；校验邀请版本 |
| `leave(actor, conversationId, command, requestId)` | 非群主本人退出；校验成员版本 |
| `invitation(actor, invitationId, requestId)` | 邀请双方读取最小当前投影；不授予消息访问权 |

这里的actor与requestId必须由未来同源HTTP适配提供；请求body不能指定actor，字符串confirmation_intent也不能替代用户真实操作／CSRF检查。精确前端导出及宿主示例见[GROUP-MODE](../../frontend/对话%20群聊页面/integration/GROUP-MODE.md)。

## 4. 首页、画像与前端调用

本批新增隔离parser与无I/O动作状态，不修改现有ChatApi或direct-only保护。显式提交绑定账号期、作用域期与尝试序号；换账号、同账号重登录、撤权、销毁均清理。未知结果保留原key/payload，仅用户明确重试；409冲突和确定业务失败不能原样重试，须重新读取后由用户重新确认。迟到回执、失败或刷新失败不能自动create/accept/send。

成功只产生重新读取意图。后续页面必须重新读取本人获准列表和上下文，再显示消息；接受回执不能直接授予权限。首页／画像可引用本离线合同；当前可调用的实际接口仍以12为准。仅人物ID不能猜会话或创建私聊，好友申请继续复用原生事实的 N08 公共适配，不临时直连原生 add/delete 冒充完整产品流程。
