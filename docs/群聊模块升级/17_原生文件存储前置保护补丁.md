# 原生文件存储前置保护补丁

日期：2026-11-13。所有者：聊天专项集成人。状态：源码已写，独立与运行验收见 [15 附件回执](15_C05附件接线与验收.md) 和 [16 独立审查](16_C05附件独立审查.md)。本补丁属于用户已批准的必要最小核心覆盖，不涉及全局产品或其他模块业务。

## 原因与范围

当前工作区 HumHub 1.19.4 的 File::beforeDelete 在父级 BEFORE_DELETE 事件之前删除存储；FileManager::attach 使用 updateAttributes 绕过常规 BEFORE_UPDATE。仅在插件注册原有事件无法在物理文件变动前阻止未授权操作。

两个原生文件增加中性扩展点，不直接依赖 matcher-chat：

- File 增加 EVENT_BEFORE_STORAGE_MUTATION 和 assertStorageMutationAllowed。beforeDelete、beforeNewStoredFile 在任何物理变动前触发；updateAttributes 同时检查当前对象与应用拟议属性的 clone，避免只看旧关联。
- StorageManager 的 setContent、setByPath 和 delete 在 I/O 和吞异常的 try 块之前调用此检查。
- File 同时增加 EVENT_BEFORE_STORAGE_READ / assertStorageReadAllowed，StorageManager::getPath 在解析存储路径前触发。原生 REST 导出与直接 File 内容读取不能绕过插件的已授权事务范围；不是只拦主下载路由。
- 无订阅时事件不改变正常文件行为。有订阅时，处理器可抛异常拒绝；具体聊天资格与附件生命周期仍由插件负责。

## 依赖与运行边界

matcher-chat 的附件能力须验证扩展点存在、迁移就绪及原生 data mount 位于 Web 根以外。存储继续使用原生 File / StorageManager，不生成公开临时 URL；原生 GUID、REST 数字 ID、预览、删除和重新绑定路径由插件守卫核查。

本隔离实例使用 backend/.runtime/chat-upgrade-files/data，0700，并验证独立归属标记；Web 根仍为 backend/.runtime/chat-upgrade。不移动任何其他实例数据，不读取或发布私有凭据。

这不是任意受信 PHP、raw SQL 或直接文件系统调用的沙箱。各模块仍须使用受保护的业务入口；真实后台任务和数据导出按实际验收范围报告，不以事件存在代替完整系统安全结论。

## 升级与回退

升级 HumHub 时须对下列基线复核调用顺序，重跑实际 Yii hook 检查、非聊天文件正例、原生上传/下载/预览/删除负例和附件生命周期测试。不能只检查常量名字存在就宣布升级兼容。
