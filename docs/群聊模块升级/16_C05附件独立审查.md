## 事务与生命周期检查清单

1. 上传／绑定／取消使用有限且不可换归属的上传键；超时未知结果保留原键，重复上传不重复消耗配额，不向另一个会话偷偷复用。
2. 本人、会话、有效成员、当前发送资格与文件状态在同一实际一致性边界重新验证；绑定与取消／过期并发有唯一胜者。
3. 原生 File、绑定元数据、消息 entry／seq／receipt 原子提交；物理存储单独处理补偿和未知提交，不能把数据库回滚写成字节回滚。
4. 正文＋附件集合共同进入永久消息幂等 hash；同键换附件冲突；纯附件语义、数量／大小／MIME、顺序与文件名由冻结合同定义。
5. 下载和 metadata 依据当前获准历史及真实绑定，不使用当前好友发送资格误删旧历史权限；撤权之后的新下载／Range／HEAD 不得复用旧缓存或外链。
6. 字节释放时点、授权撤销和已开始下载的边界必须有定义；不把已发送到客户端的字节承诺为可撤回。
7. 前端区分选择、本地预览、上传中、暂存成功、发送中、结果未知；无明确用户动作不上传／发送／下载。切会话、身份或撤权时终止请求并清对象 URL／草稿，晚到结果不能恢复旧附件。
8. 单件／单消息上限之外还需持久暂存件数、总字节与上传频率边界；新 UUID 不应无限占满 24 小时暂存。取消／过期保留上传幂等终态，重放不新建。
9. 原 SqlState 对任何关联 file 都 revoke。新增附件只能放行本模块完整核验的 bound 文件，不能删除总保护或把未知文件默认为可读；关闭上传只限制新写，不把获准旧附件历史全部撤销。

[15 本批合同](15_C05附件接线与验收.md) 当前锁定单件 5 MiB、最多 3 件、24 小时暂存、JPEG／PNG／PDF／UTF-8 文本、强制 attachment 下载与无 inline／预览；context.attachments 缺失即不可上传。root 后续冻结每用户最多 20 个有效暂存、最多 100 MiB，滚动 60 秒最多 20 次成功新上传；合法重放与失败不占次数，取消不退还历史速率。私有存储按 17 登记，合同冻结不等于实际运行验收完成。

### 真实事务故障、修复与离线复验

root 随后真实执行附件 SQL 故障注入，发现生产事务泄漏：SqlReadStore 原来只捕获 ChatException，RuntimeException 越过内部 savepoint，SqlState 的一次 rollback 仅把 Yii 同一 Transaction 对象从 level 2 降到 level 1；同进程原键重试被活动事务拒绝。此前离线业务／SQL seam 通过未覆盖真实 Yii 嵌套事务语义，不能据此认定异常回滚完整。独审核对 vendor Transaction：嵌套 begin 返回同一对象，commit／rollback 在底层操作之前降低 level，因此底层失败时 Yii level=0 也可能留下活动 PDO 事务。

后端已修复 [SqlReadStore](../../backend/protected/modules/matcher-chat/adapters/persistence/SqlReadStore.php) 与 [SqlState](../../backend/protected/modules/matcher-chat/adapters/persistence/SqlState.php)：捕获所有 Throwable，有限展开本用例拥有的嵌套层级；只有业务阶段的 ChatException 且成功恢复至外层时才提交授权观察。committing 标记区分 savepoint 释放失败，避免该阶段的 ChatException 被误当业务拒绝。外层验证层级，异常时完整展开并关闭连接，即使 Yii 已报告 inactive；保留原异常身份。关闭连接是处置不确定连接状态，不承诺未知提交必然回滚。

独审读取完整 [transactions.php](../../backend/protected/modules/matcher-chat/tests/transactions.php) 并实际运行，最终 **30 checks 通过**（替代早一版 28 项，不相加）。实际 Yii Transaction／Connection 接内存 PDO 协议，0 次数据库／HTTP。覆盖正常提交、RuntimeException／Error、业务拒绝、savepoint rollback／release 失败、底层 rollback 抛错、commit 前后抛错、深层嵌套与成功回调漏关事务、同适配器重新打开连接，以及原异常对象保持。commit 后报错的情景明确保留已提交结果，不把未知提交写成已回滚。

另外复核 ApiController 用 property_exists 区分 attachment_ids 缺失与显式 null；缺失默认 []，null 原样进入 SendText 并被拒绝。attachments-native 独审最终 **39 checks 通过**，取代早一版 38 项；这里新增的是源码断言，真实 HTTP 422 由下方最后一轮回执另行证明。最终对 matcher-chat 全部 PHP、两份核心文件及两份独审探针共 **73 个 PHP 文件 lint，零失败**。
