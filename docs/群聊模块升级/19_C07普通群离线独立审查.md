## 1. 范围与证据口径

本批只审查普通群的离线领域、应用用例、内存端口和隔离前端 DTO／动作状态。独审仅写本文件；root 维护 18 号合同、task 与实施记录，后端和前端各自单写实现。12／15／16／17 已封板，不反向改写。

已读取项目 architecture-patterns 完整 Skill。核对领域规则独立、用例通过端口编排、原生存储与 HTTP 留在外层；内存模型测试不能证明真实事务、原生授权或运行接线。

- 普通群由 matcher-chat 单一写入；原生 message／user_message／message_entry 仍为会话、真实参与人与正文事实，不另建平行正文或好友库。
- matcher-ideas 的既有永久绑定不扩展为讨论申请、审批或成员管理；N08 好友来源、请求版本及历史不在本批代做。
- 功能暂停、UI 关闭、代码卸载和删除数据分别处理；按最新覆盖式原则允许必要依赖，不要求移除后原生产品功能等价。
- 不执行数据库、HTTP、服务、迁移、构建、开关或 Git；不读取 .local、凭据、私有原文或真实运行夹具。只运行已检查副作用的相关离线测试及 lint。

依据：[聊天任务](task.md)、[C01 合同](03_C01_聊天实施合同.md)、[推进计划](07_真实接线推进计划.md)、[18 号合同](18_C07普通群与邀请合同.md)及 root 本批单写授权。具体 DTO、邀请期限、角色、上限、版本与幂等策略以 18 号合同和本批源码为准；不从好友申请或演示 UI 推导默认值。

## 3. 发现与处理记录

本批发现均已由各文件 owner 修复并完成独立复核；保留发现过程，不将首次失败改写为原本通过。

- 初稿 create 收据／创建端口缺失，所有动作被强制 expected_version，且 PHP nullable 标题与前端冲突。后端统一为严格 GroupCommand(operation, body)，显式 create 与匹配的标题规则；首次创建／邀请及成员期初值验证通过。
- 初稿 pending 拒绝受邀者所有 membership，误伤退出后的重邀。现在允许本人上一期 left，继续拒绝 pending 对应 active；实际 PHP→TS 的重邀详情通过。
- UTC 秒、终态时间与 expected_version+1 已统一；pending 无 resolved_at，接受／拒绝／撤回的 resolved_at 不早于创建且早于到期，expired 不早于到期。回执跳版本和小数秒被拒绝。
- 独审临时内存探针曾复现损坏适配将 inviter 改成非 owner 后仍能接受。后端补决定／投影的 owner 一致性校验后，accept、detail 均拒绝且快照不变；相应负例已进入 groups.php。
- 终审临时内存探针曾复现同群 receipt 错指另一受邀者：保留原 key／payload hash，只换 invitationId，重放返回错误 invitee。后端补实际邀请与原命令的角色／目标核对，以及决策终态／精确版本核对；原探针复测拒绝且快照不变，新增正式负例通过。合法 leave 重放在重入后仍返回新成员期，不重做退出。
- [GROUP-MODE](../../frontend/对话%20群聊页面/integration/GROUP-MODE.md) 已明确这些函数未挂载、无 HTTP 或存储；未知结果的原键只在当前内存状态保留，不承诺刷新／离开／重登录后恢复。撤权仍须立即清理，不能为了恢复而保留无权资料。

两种损坏适配探针证明的是领域端口防错缺口，不是 HTTP 用户能够直接修改存储。最终在本批离线范围内未发现未解决的阻断项；真实接线缺口仍列在第 5 节。
