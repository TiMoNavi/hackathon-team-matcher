# C07-A2 群读取与成员期消息计划

2026-11-13。状态：设计准备，尚未实现。本计划依据后端、前端和独审三个子 agent 的明文分析，承接 [C07-A1](20_C07A群生命周期持久化与API.md)。用户已授权继续推进聊天；本文件用于划分实现顺序与合同，不增加新的审批要求。

## 1. 当前事实与本批入口

A1 已发布空群生命周期七路由及独立 createGroupApi，后端0.4.0；真实 HTTP80请求／290检查、SQL9模式和独审通过。但没有本人群列表、邀请收件箱、群历史／发送／已读／附件或正式群UI。现有 direct 客户端和页面继续保持私聊范围；Next /groups 仍是美术参考，不是 HumHub 正式群入口。

下一项优先交付 **A2-R 群列表与邀请收件箱只读闭环**。先在领域合同、内存用例和跨语言DTO上核对边界，再接SQL／HTTP及专用夹具。消息能力分批推进，不通过删除 direct-only 检查假装具备群授权。

## 2. 实施顺序与文件分工

| 阶段 | 交付范围 | 核验要求 |
|---|---|---|
| A2-R | 本人有效群分页、本人待处理邀请分页、自己的成员期投影 | 三账号、签名游标、身份变化、邀请终态、未接受／退出不可成为可读成员，direct并存 |
| A2-H | 当前成员期群历史分页与增量 | seq严格大于join_seq；退出／重入、旧游标、旧摘要失效；真实SQL和HTTP |
| A2-S | 群文本发送、永久幂等与按成员期已读／未读 | 双用户真实收发；同键、退出与发送／已读竞争；当前资格和迟到结果检查 |
| A2-A | 群附件暂存、绑定、取消、下载 | 成员期、退出／重入、撤权与文件旧入口；不复活前一代上传权限 |
| A2-X | 群相关原生入口与身份钩子综合验证 | mail／REST／live／file及实际存在的搜索／摘要入口；原生AR、锁序与维护升级 |
| C07-B | 群列表、邀请待办及正式群会话页面 | 对应后端能力通过后挂载；宿主bootstrap／深链、桌面手机及双账号浏览器 |

后端 agent 单写 matcher-chat 的群读取领域／端口／存储及授权测试；接口／前端 agent 单写协调后的路由／HTTP适配、独立群客户端和页面状态；独审维护新批报告与限定验证。每批开始列精确文件，避免两名 agent 同写 Module／config／公共DTO。root只负责合同、固定隔离工具、运行验收与定向交付，不接手子 agent 的产品实现。

上述顺序是实现依赖，不表示每项可提前独立开放。A2-H可先准备读取实现，包含真实消息的完整成员期链路待A2-S发送API可用后合验；不得用SQL种正文冒充收发。A2-X是综合补验，每个消息／附件能力在开放前仍须完成本能力所影响的原生入口授权检查，不能把保护统一延后。

## 3. A2-R 最小读取合同（待源码验证后冻结）

- 拟增加 GET /api/v1/conversations/groups 与 GET /api/v1/group-invitations，分别返回本人当前有效群和本人待处理收件邀请。前者与A1同路径POST共存；注册前验证路由／方法匹配。发件历史、全成员名单、候选搜索不在首批。
- actor只取原生session，不接受查询用户ID。默认limit=24、最大48，使用签名cursor。绑定actor、过滤／排序和服务端授权上下文；分页遇撤权或成员期变化须重新核验，不能沿旧页复活权限。具体排序键、签名版本及错误码在实现合同中统一。
- 群列表只返回当前active且与原生user_message对齐的群，以及本人membership的generation、version、join_seq等必要字段；群标题仅对当前获准成员展示。owner只作为必要标识，不拼接未授权画像。首批不返回消息摘要、未读数或联系方式。
- 邀请收件箱仅返回邀请所需最小字段，如invitation ID、conversation ID、双方ID、状态、版本和有效时间。pending不返回群标题、成员名单、消息或附件；详情沿用A1 invitation(id)的当前授权投影。到期与终态如何过滤必须明确，GET不得悄悄执行决策或创建成员。
- 群与direct分开分页，不把两个cursor合成伪造统一序列。普通群不接Space／idea讨论资格，已有讨论类数据不得按普通群读取。
- 群客户端保持独立源码出口。首页／画像可调用共用接口，但不能据群邀请建立好友或用人物ID猜会话；目标人仍来自获准入口，禁止全站搜索。

## 4. 群消息的成员期边界

后续历史授权须同时核对启用账号、群状态、原生当前成员和matcher-chat当前active成员期。原生message／user_message／message_entry继续是事实来源，不另存群消息正文。

当前generation是授权上下文；历史只允许 seq > join_seq。接受邀请时，以同一事务内实际last_seq设定新代join_seq。退出关闭当前代，重入建立新代和新起点。旧cursor、已读状态、列表摘要、暂存附件和成功回执不能把旧代内容带入新代。未接受邀请始终没有正文和附件资格。

现有direct发送、附件和读取适配包含双人／好友假设，应新增明确群授权端口或证明类型化扩展等价，不直接复用direct grant。遇到无法映射的原生entry／sequence继续拒绝，不能猜序号。未知会话类型和成员代次也不能默认为可读。

## 5. 必须先确定的产品与技术决策

| 决策 | 当前结论及处理顺序 |
|---|---|
| 接受后取消好友 | 好友与群成员是独立关系；建议取消好友只影响未来邀请，不自动关闭既有成员期。尚须结合现行产品合同冻结，A1的入群检查不能推导未来消息权限 |
| 接受后发生屏蔽 | 先检查HumHub真实屏蔽语义，再明确共享群内读写、附件、退出及解除屏蔽后的行为。未决定前不开放群消息；不默认允许，也不擅自整群撤权 |
| 停用／删除账号 | 保留A1保守策略：当前active成员身份变化使整群永久撤权；历史left成员后续停号不影响群。细粒度单成员撤权／恢复另批 |
| 刷新后的未知写结果 | 当前动作态仅在内存。评估actor范围的回执恢复或最小短期sessionStorage；必须绑定账号、退出清除，不能存消息／附件内容，不能自动换键或重发 |
| 宿主与深链 | 正式页面由HumHub提供actor／CSRF／退出入口和资源；URL只作导航意图，重新请求当前授权。群ID不能送入只支持direct的旧页面入口 |

这些事项不阻止先做A2-R的合同和最小读取实现；任何会暴露受屏蔽影响内容的投影须先明确相应规则。涉及消息写入、历史和附件的批次须先把适用决策写入合同及测试，不把建议当作已实施事实。

## 6. 新夹具与验收

每一新批使用专用版本和归属marker，保留A1的5群／7邀请／18收据以及C05B末态撤权，不清键、不重置序号、不恢复被撤权限。只在root拥有的固定隔离实例运行；无主预览操作。夹具人数和数据上界先列明，凭据只留私有runtime，不传给其他agent。

A2-H以后使用明确消息序列验证边界：owner发m1 → 邀请并接受（join_seq=m1）→ member发m2 → 退出 → owner发m3 → 再接受（新generation，join_seq=m3）→ member发m4。实际消息必须通过对应已实现API写入，不能SQL种正文后声称真实发送。两代分别证明可见范围，旧cursor／read／附件不能跨代；pending、第三人和终态邀请另测。

真实HTTP检查请求和身份边界；独立SQL进程以持锁握手验证同键、退出与读写、附件绑定与退出、身份／关系变更的提交顺序。SQL表写探针不能冒充原生AR钩子验证。正式群页面接入后，再做双账号浏览器的列表、邀请、收发、分页、已读、退出重入、刷新、换号、焦点和附件。

每批前后保留旧消息／文件／queue与授权状态，明确功能开关、服务和带数据升级结果；失败证据保留，成功首轮不覆写。未覆盖入口和竞态列为缺口，不扩大验收结论。
