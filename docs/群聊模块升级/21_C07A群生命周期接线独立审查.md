## 2. 初审风险与处置

- 原 SqlReadStore::prepare 遍历全部成员代次并调用只支持 direct 的 synchronize；新增 group 或多代成员会使同账号 direct 列表失败。已限定 `c.type=direct AND m.generation=1`，在 SQL 层先过滤再检查 scope 数量；源码、seam 和 root 提供的真实并存证据一致。
- 原 EntryCoverage 对所有 managed 会话调用 direct synchronize。已分流：direct 沿用同步，group 核元数据门槛并计入被保护范围，不提供群消息 capability。
- NativeGuard 保留对 group 当前及历史已退出成员的识别，group 开关不参与保护解除。原身份失效继承历史成员语义会使 left 用户日后停号影响全群；已按 root 决策仅匹配 group 当前 active，direct 原策略不变。
- 原生 UserMessage::afterSave 默认创建加入系统通知，afterDelete 总会 inform 离开。群 SQL 适配使用原生表 raw SQL，不走这些 AR 副作用；仅提交成功后失效必要计数缓存。root 首轮证据未产生群 entry、附件或队列增量。
- HTTP 验证服务端 actor、canonical ID、方法、严格 JSON、CSRF 及配置／持久双开关；group 不凭当前活动授予资格，不绕过真实好友与屏蔽校验。测试夹具的 request ServiceLocator 注册问题已修复。
- 后端 SQL probe 初稿直接用仅 Web 可成立的 Module::isGroupsEnabled 验证 CLI，独审发现后已交作者修为核配置／持久意图与存储 ready；生产 Web／poll 门槛未放宽。
- 配额 probe 初稿只断言新增数不超过上限，不能排除提前限流。已补当前 actor／operation 的窗口基线，触限时按当前窗口重算旧回执，断言新增数＋仍在窗口的基线恰为 5／20。
- SQL wrapper 原 finally 清理链中任一步失败会跳过后续恢复。已改为每个自有子进程及 refriend／unblock 均尝试执行，最后汇总失败。独审核对了修正源码；最终证据确认正常收尾关系恢复，未据此声称所有清理故障都已注入验证。

## 5. 后续边界

群生命周期 API 可用不等于群消息闭环完成。群历史与附件的成员期授权、正式页面、多账号浏览器、活动想法讨论及全站发布仍需后续独立完成。

本批限定范围无未处理的生产阻断。新增 group 身份失效的 active／left 分流有源码与独审 seam，尚未以真实原生 User AR 停号／删除做专项竞态验收；群建立后的 EntryCoverage 分支已源码核对，未把现有 HTTP 列表并存测试冒充所有入口覆盖。后续开放群正文前应补这些权限与入口用例，并与成员期消息授权一同验收。

本批没有性能或容量成功结论。SQL 群校验会逐成员读取最新成员期，当前可用性与投影复核中存在重复查询；固定小夹具通过不能替代 50 人群容量和长期成员历史测试。为保留现有授权复核，本轮没有据此引入未经验证的缓存。
