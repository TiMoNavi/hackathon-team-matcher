# C04 隔离读取接线回执

日期为2026-11-12，入口见[task](task.md)、[推进计划](07_真实接线推进计划.md)与[独立审查](08_C04真实接线审查.md)。本批只处理聊天的持久化读取、已读与独立页面，不接管登录、画像、好友申请、想法发布或推荐。

## 已实现

- matcher-chat新增原生SQL适配、显式既有私聊准入、六张引用/权限元数据表，以及列表、历史/增量、显式已读三个同源端点。消息正文继续存于原生mail。
- 私聊只接收明确两个有效原生成员、无附件的获准历史。sender姓名/头像尚无正式授权适配，返回unavailable；发送、邀请、退出权限均为false。
- seq、成员代次、read-state及viewer revision持久保存。SQL适配使用InnoDB事务与锁；纯追加不推进权限revision，编辑/删除等投影变化会失效旧缓存。不能仅凭实现声明所有并发场景通过。
- matcher-chat-ui读取页使用原生session签发v2 bootstrap，actor_id仅分区客户端状态；API独立验权，并支持X-Matcher-Chat-Actor预期断言。退出/失焦清理与重新聚焦刷新不等于完整session代次绑定。
- 读取页独立构建至resources/read-app，保留原shell。已有Soho布局和Signalry主题继续复用；禁用尚未交付的发送、附件、建群控件，不填演示业务数据。

## 固定隔离目标

只操作127.0.0.1:8124、humhub_chat_c02_20261112和聊天私有runtime；不操作8113。原生mail3.4.6、HumHub1.19.4，新增matcher-chat0.1.0，迁移从230增加至231。首次和重复升级通过。

从已验证空库显式生成三个虚构账号、三个原生会话、七条虚构文本。A/B拥有两个准入私聊，其中一个为空；B/第三人另有一个未准入会话。没有真实用户原文，没有AI调用，也没有启动worker/cron。队列原有一项保留，不消费或清空。

随机密码、cookie和数据库凭据不进入本回执、子agent消息或源码。密码只由固定验证脚本内部消费，通过原生用户名→密码两步表单获取session，不通过注入session绕过登录。

## 必须保留的限制

受管用户的整套原生mail网页和live入口目前采取保守拒绝，包括该用户其他未管会话；存在受管数据时mail REST整面拒绝。UI关闭后这些限制仍在。这是隔离试验的安全边界，**不满足用户最终要求的完整可撤回插件体验，不得在主预览或生产启用**。

手动或在途通知、第三方调用、bulk/raw SQL、File删除的物理文件先行副作用，以及同actor重登录代次仍需专项处理。文件尚未接入，不能以无附件夹具宣称下载撤权安全。发现新的原生搜索旁路须先修复并补真实请求，不能只依赖纯stub或不存在的路由404。

正式读取完成仍需剩余撤权/版本/并发与浏览器证据，并完成原生兼容方案。C04与C06保持in_progress；发送与附件、群邀请、活动讨论仍按原计划逐批实施。好友申请/接受事务和唯一空私聊绑定由N08与聊天共同交接，想法发布/审批由N09提供，不用夹具冒充这些业务完成。
