## 1. 交付目标与范围

将 [对话 群聊页面](../../frontend/对话%20群聊页面/README.md) 接入现有 HumHub，保留页面视觉与主要交互，复用原生 mail 的会话、成员、消息与附件。新 UI 可单独关闭，原生合法聊天和数据继续可用。基础聊天不依赖推荐模型或全站 React 外壳。

本专项的完整交付包含：真实本人会话列表、私聊及已有群聊读写、历史分页与未读、真实附件、明确建群、邀请接受/拒绝/撤回、活动想法讨论的聊天接线、原生入口保护，以及 UI 撤回回归。基础私聊通过可作为阶段交付，不代表完整群聊与讨论已完成。

- 不接管 GitHub/邮箱登录、活动邀请码、画像、推荐、想法编辑和发布；依赖对应所有者提供的真实接口。
- 好友申请侧栏消费 N08 的业务合同，不在聊天插件另建好友关系、申请历史或来源授权。
- 活动仍为 Space；想法、活动发布与 Messenger 分别建模。既有合法私聊不随切活动消失；活动讨论按自己的资格及历史边界授权。
- 未接受邀请不等于群成员。消息、建群、邀请、接受均须真实用户操作，不自动发消息或自动拉人。
- 关闭新 UI 与卸载业务/数据模块分开；禁止调用原生 mail 的 disable/remove 作为回退。

5. 未达到真实验收的条目保持未完成；模块缺失时明确能力不可用，不填 mock、不扩大活动搜索、不关闭权限。
