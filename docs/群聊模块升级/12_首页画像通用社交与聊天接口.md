# 首页、画像通用社交与聊天接口

2026-11-12 启动，2026-11-13 收尾冻结（Asia/Shanghai）。供首页、画像、推荐与聊天团队共同引用。本页先记录已核对的源码与实际可复用边界，再列尚待实现的公共适配；不是运行实例放行。C05 受限文字发送与公共客户端已完成源码、离线复核，以及 root 执行的限定隔离 HTTP／SQL／浏览器验证；证据与保留边界见 [C05 独立复核](14_C05文字发送独立复核.md)。

入口：[专项任务](task.md) · [共享契约 HumHub 映射](../共享数据与接口契约.md#92-已有传输与待补差异) · [HumHub 实施合同](../睡前全自动运行/04_HumHub实施合同.md) · [T1/T2 限定验收](11_T1T2入口接管隔离验收.md)。

## 1. 先复用什么

原生 `user_friendship` 是当前好友／待处理申请事实，`contentcontainer_blocked_users` 是屏蔽事实；原生 mail 的 `message`、`user_message`、`message_entry` 是会话、真实参与人及消息正文事实。新模块不得复制一套好友或消息库。产品来源证明、明确接受、版本、终态历史和请求幂等仍需外层适配，不能从原生表存在推断这些能力已经完成。

| 使用场景 | 当前可复用入口 | 接线边界 |
|---|---|---|
| 首页或画像进入已获准聊天 | `/matcher/chat/conversations/{conversation_id}` | ID 必须来自服务端已授权会话结果；导航仍重新验权，不把 user_id 当 conversation_id |
| 本人会话、正文、本人已读与受限文字发送 | 第 4 节读取／已读与第 7 节发送端点 | 原生 session、逐次授权；读取、已读与发送能力分别检查 |
| 当前好友／待处理状态 | 原生 `Friendship` 查询；既有 NativeContactEligibilityReader／NativeProfileRelations | 这些是服务端内部适配，不是可由浏览器直接调用的通用 JSON API |
| 原生好友管理页面 | `/friendship/manage/list`、`/friendship/manage/requests`、`/friendship/manage/sent-requests` | 原生 HTML 页面；sent-requests 只有当前未接受的发出请求，不是持久历史 |
| 画像的活动／群参与关系与联系方式 | 已有画像隐私 API | 授权投影不是好友申请、群邀请、成员变更或聊天授权 |
| 发出申请、明确接受、撤回、拒绝、解除及历史 | 复用原生事实后补 N08 公共适配 | 仍待所有者交接；不能临时直接接原生 add/delete 冒充产品流程 |
| 给某用户查找／创建唯一私聊 | 尚未交付公共入口 | 不能按两人名单猜 ID、前端扫全会话或自行创建空会话 |

## 2. N08 的实际现状与所有权

核对依据包括总专项 N08 任务、实施合同、共享契约第 9 节，以及当前模块 `config.php`、控制器和关系适配源码；结论不建立在“找不到某个模块名”上。

- 总专项将合法来源、申请／接受、持久发出历史和相关幂等分配给 N08；聊天队拥有既有会话读取与本轮受限文字发送。N08/N09 的独立模块 ID 与交接合同仍需总集成人确认。
- 当前可确认的原生写入口和关系读取确实存在；本次检索未发现已经交付的 N08 通用 JSON 申请／接受／终态历史／唯一私聊绑定接口。这个源码快照不表示其他团队无人开发，接线前仍需取得其冻结接口和验收回执。
- [NativeContactEligibilityReader](../../backend/protected/modules/matcher-recommendation/adapters/native/NativeContactEligibilityReader.php) 明确 `supportsSentHistory() === false`，`readSentHistory()` 拒绝 `unsupported_history`。当前无关系不能推导 `ever_sent=false`，当前待处理列表不能代替终态历史。
- 该读取器的 `version` 是 `native-relationship:` 当前事实指纹，不是可用于接受申请的单调 `request_version`；它还绑定当前活动候选上下文，不能强加到跨活动保留的既有私聊。
- [NativeProfileRelations](../../backend/protected/modules/matcher-profile-privacy/adapters/native/NativeProfileRelations.php) 已复用启用身份、原生 friendship 开关、双向好友和双向屏蔽，用于画像可见性判断。它不是发消息用例，也不提供关系写入／申请历史。

## 3. 原生好友能力目录

源码：[RequestController](../../backend/protected/humhub/modules/friendship/controllers/RequestController.php)、[Friendship](../../backend/protected/humhub/modules/friendship/models/Friendship.php)、[ManageController](../../backend/protected/humhub/modules/friendship/controllers/ManageController.php)、[ListController](../../backend/protected/humhub/modules/friendship/controllers/ListController.php)。

| 原生入口／方法 | 实际输入或返回 | 不可冒称的能力 |
|---|---|---|
| `POST /friendship/request/add?userId={id}` | 原生登录和 CSRF；写当前方向 `user_friendship`。AJAX 返回 FriendshipButton HTML；普通请求重定向 referrer | 同一动作既发申请又接受已有反向请求。没有产品 `source`、`expected_version`、独立接受意图或统一 JSON 回执 |
| `POST /friendship/request/delete?userId={id}` | 删除该用户对的一个或两个方向，按现态表现为撤回／拒绝／解除；返回同上 | 不能将三个产品动作无条件映射为同一个 delete；不会保留完整终态申请历史 |
| `GET /friendship/manage/list` | 本人好友 HTML，原生分页每页 20 | 不是 `/api/v1/connections`，不是签名 cursor DTO |
| `GET /friendship/manage/requests` | 当前收到、未回应申请 HTML | 不能证明请求来源、版本及完整处理历史 |
| `GET /friendship/manage/sent-requests` | 当前发出、未获接受申请 HTML | 已接受、拒绝、撤回后不能靠此页重建历史 |
| `GET /friendship/list/popup?userId={id}` | 原生好友弹层 HTML | 不作为产品全站人物检索或逐项可见性 API |
| `Friendship::getStateForUser/getFriendsQuery/getSentRequestsQuery/getReceivedRequestsQuery` | 服务端内部查询；NONE、FRIENDS、REQUEST_RECEIVED、REQUEST_SENT | 查到状态不代表取得申请来源证明或会话授权 |
| `Friendship::add/cancel` | 原生内部写；包含通知、follow 或关系事件副作用 | 不能在页面加载、AI 处理或发消息重试中隐式调用 |

原生 `add` 的并发唯一键处理仅处理同方向关系行竞争，不等于带业务请求键的幂等回执。`cancel` 删除双方当前关系；模型中没有产品申请轮次、终态保留和 `expected_version` 比较。原生按钮可继续作为原生功能存在，但首页／画像不能把其 HTML 或重定向当作产品 API 成功。

屏蔽复用 [ContentContainerBlockedUsers](../../backend/protected/humhub/modules/content/models/ContentContainerBlockedUsers.php) 与 [ContentContainerActiveRecord](../../backend/protected/humhub/modules/content/components/ContentContainerActiveRecord.php)。用户 A 屏蔽 B 的事实是 A 的 `contentcontainer_id` 对 B 的 `user_id`；发消息需检查两个方向。原生屏蔽还可能解除好友，解除屏蔽不构成重新建立好友。不要依赖对象上的缓存列表完成事务授权。

## 4. 已注册、可供接线的聊天接口

源码：[路由](../../backend/protected/modules/matcher-chat/config.php)、[ApiController](../../backend/protected/modules/matcher-chat/controllers/ApiController.php)、[ChatReader](../../backend/protected/modules/matcher-chat/application/ChatReader.php)、[读取客户端](../../frontend/对话%20群聊页面/integration/src/chat/http.ts)。本表描述已有 C04/T1/T2 读取合同；安装、开启和能力放行仍由运行环境负责。

| 方法与路径 | 输入 | 关键输出／规则 |
|---|---|---|
| `GET /api/v1/conversations` | `limit` 默认 24、最大 48；可选不透明 `cursor` | `items,next_cursor,has_more,authorization_revision`；只含本人当前获准会话，不是某用户所有聊天的查询器 |
| `GET /api/v1/conversations/{id}/messages` | `limit,cursor` 或 `limit,after_seq`，后两者互斥 | `items,next_cursor,has_more,read_seq,unread_count,context`；历史初页取最新再升序显示，cursor 向旧页，after_seq 向新消息 |
| `PUT /api/v1/conversations/{id}/read-state` | JSON 仅 `read_seq` | 单调合并本人已读；不能超过本人获准且真实存在的位置，GET／导航不会自动写已读 |
| `GET /matcher/chat` | 页面导航 | 可用时装配本人列表；mixed／暂停时明确不可用，不交付部分收件箱 |
| `GET /matcher/chat/conversations/{id}` | 正规范整数 ID | 固定同源深链；服务器和读取 API 再验权，深链不创建会话、不授予权限 |

共用调用约定：

1. 使用同源原生 Cookie session，不传 actor 查询参数；不得复制登录系统或将 token 写进 URL。`X-Matcher-Chat-Actor` 是当前 session 的正安全整数预期值，仅防跨账号缓存串用，不授予身份。
2. PUT／POST 使用 `Content-Type: application/json` 与当前页面原生 CSRF 头／令牌；既有读取 bootstrap 提供 `csrf_header`、`csrf_token`。公共客户端当前只支持合同规定的 `X-CSRF-Token`，不能擅自接另一种头配置。不要硬编码隔离实例的 CSRF 参数，不把令牌写进日志、截图或持久缓存。
3. 成功统一为 `{data,meta:{request_id}}`，失败为 `{error:{code,message,retryable,details},meta}`。当前空 `details` 可为数组，遵循真实解析器；错误不能当作空会话成功。
4. 页面／API 响应 `private,no-store`；状态按 actor 和 session 隔离。身份变化或真实授权失效要清空旧投影，异步晚到响应不得恢复旧内容。
5. 逐会话消费服务端 `permissions`，不得从好友、页面可见、模块已安装推导 send/invite/leave。读取版仅 `read=true`；C05 仅在第 7 节全部条件满足时给出 `send=true`，invite／leave 仍关闭。sender 可为 `unavailable`，不能拼接未授权姓名或头像。
6. 读取 gate 与入口接管 gate 分开：导航暂停不是业务撤权。已打开页面在 readEnabled 与真实授权仍有效时可以继续获准 API；通用 503 不是全局授权撤销信号。

| 读取错误 | 调用方处理 |
|---|---|
| `401 AUTHENTICATION_REQUIRED / SESSION_CHANGED` | 清除当前身份分区与旧会话，进入重新登录／重新装配；不重放旧写请求 |
| `403 ACCOUNT_UNAVAILABLE / PRIVATE_CONTENT_UNAVAILABLE / CROSS_ORIGIN_DENIED` | 明确拒绝，不能借原生入口或另一个用户 token 兜底 |
| `404 CONVERSATION_UNAVAILABLE` | 移除失效会话投影，不猜测不存在还是无权 |
| `409 AUTHORIZATION_CHANGED / CURSOR_CONTEXT_CHANGED` | 丢弃旧授权上下文，显式重新读取；不沿用旧 cursor |
| 输入、游标错误或 `405/415` | 按真实错误修正请求，不用无限重试 |
| `503 CHAT_DEPENDENCY_UNAVAILABLE` 等 | 显示不可用并允许用户手动恢复；不降级到示例数据或假成功 |

当前没有“按 user_id 查或创建唯一私聊”的公共 API。首页／画像若只有人物 ID，应保留明确不可用或待适配状态；不能拿好友事实创建会话，也不能遍历全列表猜对方。

## 5. 首页与画像可复用的相邻读取

以下路由已有配置和控制器，仍须满足所属模块的开关、当前活动和逐条授权。这里只列用途；完整 DTO 由对应所有者维护，不把聊天目录当画像合同副本。

| 路径 | 所属与用途 | 不能据此执行 |
|---|---|---|
| `GET /api/v1/events/{spaceId}/discovery`、`.../discovery/people/{ownerId}` | matcher-recommendation 的普通发现与详情；绑定唯一服务端当前活动 | 跨活动凑候选、好友申请写入、全站人物搜索 |
| `GET /api/v1/events/{spaceId}/profiles/{ownerId}/overview` | matcher-profile-privacy 的获准概览 | 绕过普通详情授权或读取未确认资料 |
| `GET /api/v1/events/{spaceId}/profiles/{ownerId}/relations?kind=...&limit=...&cursor=...` | 获准活动／群参与关系投影 | 加好友、建群、自动接受邀请或读取消息 |
| `GET/PUT /api/v1/me/profile/relation-sharing?space_id=...` | 本人逐对象展示范围；PUT 有 expected_version 和确认意图 | 关系创建／删除或聊天成员变更 |
| `GET /api/v1/me/contacts`、`GET /api/v1/profiles/{ownerId}/contacts`、`GET /api/v1/spaces/{spaceId}/profiles/{ownerId}/contacts` | 独立联系方式投影；按 self/space/friendship/public_post 合法入口检查 | 由好友自动公开全部联系方式，或创建旧设计额外共享授权流程 |

源码：[推荐路由](../../backend/protected/modules/matcher-recommendation/config.php)、[隐私路由](../../backend/protected/modules/matcher-profile-privacy/config.php)、[隐私控制器](../../backend/protected/modules/matcher-profile-privacy/controllers/ApiController.php)。`relations` 是参与关系展示，与好友 request/history 不是同一资源。联系方式按当前 HumHub 映射及本人逐条范围执行，不能仅复制早期逻辑 API 表的 ContactShareGrant 设想。

普通发现卡片已有 `relationship.state = friend / pending_out / pending_in / none`，另有 `friend`、`pending_out`、`pending_in` 布尔值和 `native-relationship:` 指纹。首页可复用该合法活动入口下的展示状态；它不是全站关系查询 API，也不能把指纹作为接受申请的 `expected_version`。

## 6. 最窄公共社交适配建议（尚未注册）

保留共享契约已有 `/api/v1/connection-requests`、`/connections` 路径设计，由 N08 唯一写者适配原生关系；不另造第二组 `/friends` 事实接口。具体 DTO、来源证明与迁移须由所有者冻结后才能调用。

| 服务端端口／职责 | 最小输入与输出要求 |
|---|---|
| 当前关系读取 | 原生身份、已验证目标入口 → none/pending_out/pending_in/friend、允许的显式动作、当前请求引用（若有）；状态未知不可默认 none |
| 发申请 | 用户真实提交＋event_card 或 public_post 的可验证来源＋幂等键；同向返回已有请求，反向要求明确 accept，不能自动互加 |
| 接受／拒绝／撤回 | 独立动作、正确操作者、请求 ID 和服务端 request_version；接受旧版本冲突，不能拿 native facts hash 代替 expected_version |
| 当前好友／请求与终态历史 | 复用原生当前关系；新增必要请求轮次／来源／历史元数据，不复制平行好友真相；历史完整性能力需显式报告 |
| 解除／屏蔽 | 当前用户真实意图、适用来源与授权；更新原生事实并使未来发送资格失效，不删除获准旧消息 |
| 既有唯一私聊引用 | 由唯一绑定所有者返回获准 conversation_id；未建绑定时明确 unavailable，不由每个页面各自 get-or-create |

event_card 新申请验证当前活动和双方资格；public_post 验证可访问公开帖作者，不能误套同活动要求。已发请求的接受规则、来源生命周期和过期以共享契约为准，不与新申请共用一条粗略“当前活动必须相同”判断。元数据、原生写、幂等回执与必要唯一会话绑定须建立清楚事务边界；原生通知副作用不能在回滚前发出后再声称原子成功。

前端共用状态建议：`loading / unavailable / none / pending_out / pending_in / friend` 加独立 `submitting / outcome_unknown / conflict` 操作态。只有真实成功回执才变成已发送／好友；失败保留可核对的请求键，超时不能换新键自动重发；pending_in 显示明确接受，不用“加好友”按钮隐式接受反向申请。

## 7. 本轮文字发送与公共客户端交接

源码：[ChatSender](../../backend/protected/modules/matcher-chat/application/ChatSender.php)、[SendText](../../backend/protected/modules/matcher-chat/domain/SendText.php)、[原生发送资格](../../backend/protected/modules/matcher-chat/adapters/native/NativeSendEligibility.php)、[SQL 写适配](../../backend/protected/modules/matcher-chat/adapters/persistence/SqlSendStore.php)、[公共客户端出口](../../frontend/对话%20群聊页面/integration/src/chat/client.ts)。POST 已注册；这不代表任意实例或任意好友都能发送。

当前只针对显式准入的 active、无附件 direct。`Module.sendEnabled` 配置和持久 `sendEnabled` 设置均需开启，读取依赖也必须可用；原生 friendship 开关、双方启用身份、双向好友、双向无屏蔽及完整会话授权仍逐次验证。`isSendingEnabled()` 只报告配置／依赖就绪，页面实际能力看对应 `context.permissions.send`。历史读取独立，不创建好友／新会话，不编造 N08 generation。

| 发送合同 | 当前源码约定 |
|---|---|
| 路径 | `POST /api/v1/conversations/{id}/messages`，JSON 对象只能包含 `client_message_id`、`body` |
| 消息键 | 小写 UUID v4；永久幂等范围为 conversation＋sender＋client_message_id，同键异正文为 `409 IDEMPOTENCY_CONFLICT` |
| 正文 | 有效 UTF-8，1–4000 个 Unicode 码点，最多 16000 字节；不能只有约定空白；拒绝 C0/C1 控制字符，但允许 TAB／LF／CR。保留原文、空格、换行、组合字符，不做 trim 或规范化后落库 |
| 新增／重放 | 新增 `201`＋`replayed=false`；同键同原文重放 `200`＋`replayed=true`。重放也先验当前发送资格；解除好友或屏蔽后不能靠旧键绕过 |
| 成功 data | `message,client_message_id,replayed,read_seq,unread_count,context`；外层仍为 `{data,meta:{request_id}}` |
| 频率 | 每发送人滚动 60 秒最多 60 条新增，跨其会话合计，以数据库时钟和永久回执计数；成功重放不占新额度。超限 `429 RATE_LIMITED`，HTTP `Retry-After` 给出秒数 |
| 已读／通知 | POST 不写本人 `read_seq` 或原生 `last_viewed`，不表示对方已收到／已读；当前不调用原生 ReplyForm、notify 或富文本后处理，仅提交后刷新原生未读数缓存 |
| 数据落点 | 正文仅存原生 `message_entry`；新增回执只存键、原文 hash、原生消息引用、seq 与时间，跟原生 entry／seq 同事务提交 |

永久重放返回**当前获准投影**：原消息后来编辑时返回当前正文，删除时返回 `kind=deleted, body=null`；不恢复旧正文。只有 `201` 新发要求回执原文与请求完全一致；`200` 重放仍校验会话、消息键和 replay/status 对应，原始正文 hash 由后端校验。此前前端仅接受 text／相同正文的限制已修复，并通过实际 PHP 输出到 TypeScript 客户端的离线交叉检查。

常见发送专属错误是 `422 INVALID_CLIENT_MESSAGE_ID / INVALID_MESSAGE_BODY`、`403 SEND_FORBIDDEN`、`409 IDEMPOTENCY_CONFLICT / SEND_RECEIPT_UNAVAILABLE`、`429 RATE_LIMITED`、`503 CHAT_SEND_UNAVAILABLE`。原生 CSRF 失败当前为 `400 INVALID_REQUEST`，不要只监听不存在的专属 CSRF 码。输入字段不符或 JSON 无效为 `422 INVALID_ARGUMENT`；媒体类型错误 415、请求体超过 65536 字节 413。其他会话、身份和授权错误沿用第 4 节；格式错误状态以 `ChatException` 默认 422 为准，不能误写成 CSRF 的 400。

发送事务重新锁定身份、设置、两方向屏蔽主键范围（含缺失键）、两方向好友，以及会话成员／历史事实。原生 cancel/block 不遵循聊天 mutex，必须通过真实数据库冲突／提交顺序验证；离线 SQL seam 不能证明锁等待或死锁回滚已通过。

公共出口位于 `integration/src/chat/client.ts`，目前是仓库内可引用源码，尚未发布成独立 npm 包：

| 导出 | 调用合同 |
|---|---|
| `chatListPath()` | 返回固定 `/matcher/chat` |
| `chatConversationPath(conversationId: number)` | 正安全整数 → 固定 `/matcher/chat/conversations/{id}`，不按 user_id 查找 |
| `createChatApi(config)` | `apiBase: "/api/v1", csrfToken: string, expectedActorId?: number, fetcher?: ChatFetcher`；调用方从当前获准 session bootstrap 传入，建议始终给 expectedActorId |
| `api.list / history / increment / readState` | 显式调用第 4 节端点；各自 options 类型为 PageOptions／IncrementOptions／ReadOptions |
| `api.sendText(id, {clientMessageId,body,signal?})` | 返回 `Promise<Envelope<SendReceipt>>`；客户端 camelCase 转为 POST 的 snake_case 消息键。只有用户明确发送或明确重试时调用 |
| `api.dispose()` | 终止待处理请求并清令牌；所属身份／页面生命周期结束时调用 |
| `createClientMessageId / validateClientMessageId / validateMessageBody` | 新建 UUID v4 或纯输入检查；不请求、不改正文 |
| `ChatApiError / MessageInputError` | 明确错误类型；HTTP 客户端不自动重试 |

另导出类型 `ChatApi,ChatApiConfig,ChatFetcher,PageOptions,IncrementOptions,ReadOptions,SendOptions,SendReceipt`。导入、构造和生成深链没有 I/O，也不导入 React、不授予权限、不包含好友接口或 get-or-create。页面加载、聚焦、Enter 输入法组合期间都不能隐式发 POST。

网络中断、超时、畸形成功回执等未知结果必须保留当前身份／会话内的原 body 和原 key，提供用户明确的同键重试；不显示“已发送”，不自动换键。真实撤权、身份改变或切会话时清理敏感草稿与晚到响应。用户主动放弃重试后再编辑会使用新键，需提醒可能形成另一条消息。发送专用未知回执分支已修复，包含控制器完整链路测试，未放宽读取流程的无权内容清理。

前端接入示例和调用方责任见 [SEND-MODE.md](../../frontend/对话%20群聊页面/integration/SEND-MODE.md)。独审复跑前端 97 项与 typecheck；另用实际 PHP ChatSender 输出经过实际 TypeScript parser／HTTP client，核对新增、原样重放、编辑后重放、删除后重放、FEFF 新增和异文冲突共 6 个场景，均通过。该交叉检查使用合成 fetch，0 次数据库／HTTP，不是浏览器或部署完成证明。

本节追加 C05-B／C06-A 已接线的源码与客户端合同，不改写第 1–8 节所属阶段的历史验收。实施与真实运行结果以 [15 附件接线与验收](15_C05附件接线与验收.md) 为准，独审见 [16 附件独立审查](16_C05附件独立审查.md)，前端完整用法见 [ATTACHMENT-MODE](../../frontend/对话%20群聊页面/integration/ATTACHMENT-MODE.md)。版本为 0.3.0，仍是仓库内可引用源码，未发布独立 npm 包；版本存在不代表目标实例的上传开关已开启。

公共出口仍为 [integration/src/chat/client.ts](../../frontend/对话%20群聊页面/integration/src/chat/client.ts)，既有构造、读取方法与十字段 read v2 bootstrap 保持兼容。以下方法均由用户明确操作后调用，不在构造、渲染或选择文件时自动执行。

| 客户端增量 | 请求与结果 | 调用约束 |
|---|---|---|
| `api.uploadAttachment(conversationId, {clientUploadId,file,signal?})` | POST `/api/v1/conversations/{id}/attachments`；multipart 仅 `client_upload_id` 与 `file`；返回 `Envelope<UploadReceipt>` | 当前获准 direct、`permissions.send=true` 与 `context.attachments.upload_enabled=true`；同次未知上传保留原 key／File／文件名，不换键自动重试 |
| `api.cancelAttachment(conversationId, {attachmentId,signal?})` | DELETE `/api/v1/conversations/{id}/attachments/{attachmentId}`，无 body；返回 `Envelope<CancelReceipt>` | 仅取消本人暂存，已绑定返回 409；未知取消只显式重试同附件 ID，不能把停止传输当作已取消服务器暂存 |
| `api.downloadAttachment(conversationId, {attachment,signal?})` | GET 固定附件下载路径，返回 `DownloadedAttachment`，含获准 `Blob` 与 DTO | `attachment` 必须来自该会话获准消息，依 `download_enabled`；发送或新上传关闭不自动取消合法历史下载。helper 不自动创建 URL、打开窗口或保存 |
| `api.sendText(conversationId, {clientMessageId,body,attachmentIds?,signal?})` | 原 messages POST 可增加 `attachment_ids`；仍返回 `Envelope<SendReceipt>` | 最多三件有序、不同 UUID；仅非空附件列表允许正文为精确空字符串。消息键、正文与有序附件共同确定原请求；未知结果仍重试原键与绑定 |

`context.attachments` 为可选能力，缺失即不开放附件；包含 `upload_enabled,download_enabled,max_file_bytes,max_files_per_message,allowed_mime_types,staging_ttl_seconds`。当前单件 5 MiB、每消息三件、JPEG／PNG／PDF／UTF-8 TXT，暂存 24 小时；每用户有效暂存最多 20 件、滚动 60 秒最多成功新上传 20 次。上传成功仅表示暂存成功；纯附件持久消息为 `kind=attachment, body=null`。下载强制 attachment、private/no-store、nosniff，禁止原生 GUID／token／外部临时 URL／inline 预览；调用方自行管理并及时撤销已创建的 Blob URL。

首页和画像可复用上述客户端，但必须从**已有且获准的 conversationId** 出发，并接收真实会话能力。只有人物 ID、好友关系或想法 ID 时不能猜会话或自行 get-or-create。好友申请、接受／拒绝／撤回及其版本／终态历史，以及按人物创建／返回唯一新私聊，仍由 N08 待交接；本节不把设计中的 `/api/v1/connection-requests`、`/connections` 冒充已注册 JSON 端点。

N09 现有 `PUT /api/v1/idea-activities/{activityId}/messenger` 接受 `expected_version,message_id,confirmation_intent=bind_existing_conversation`，只永久关联已有会话元数据；真实讨论创建、申请／审批、成员变更与讨论消息接线仍未交付，不能据此开放群聊或跨活动消息。
