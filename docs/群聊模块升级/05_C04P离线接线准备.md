## 1. 本轮依据与交付边界

用户继续授权接入，并明确要求用子agent推进。主agent复读了总专项任务和 N04 最新阶段回执：真实双登录尚未完成，N05 及依赖尚未放行。该结论只针对当前回执；认证所有者的新成果须重新核验。

在不启用依赖业务的前提下，本批准备能够独立验证的读取规则和前端客户端，缩小后续接线范围。它们不创建消息 API、不启动 HumHub、不连接数据库，也不把内存测试称为真实聊天。

本批范围：

- 新增 `matcher-chat/` 下框架无关的领域、应用用例、端口和内存测试；暂不含 `Module.php`、`config.php`、`module.json`、迁移或路由，不能作为已安装业务模块使用。
- 新增指定聊天目录 `integration/src/chat/` 的 DTO、同源客户端、会话状态管理与离线测试；不由 C03 页面入口导入或激活。
- 用 PHP 用例生成有限合成响应，由 TypeScript 客户端解析器交叉验证，避免两边各自通过却无法对接。
- 保留现有 shell bootstrap、页面资产、零业务请求约束；构建检查拒绝提前导入未装配业务层。

本批不实现发送、附件、邀请接受、当前活动选择、唯一私聊关系写入或真实登录；不新增另一套好友事实，不开放原生全站 picker。

## 3. 约束与待锁定细节

- 显式区分 direct/group/discussion，不能通过参与人数猜类型。群/讨论内存规则不代表真实入口已开放。
- 读取资格、发送资格分开；普通既有私聊不因未选择或切换当前活动而消失。
- 群历史采用当前成员代次 `seq > join_seq`；退出和资格撤销拒绝，重新加入使旧授权上下文失效。
- 分页默认 24、最大 48；cursor 与 after_seq 互斥。cursor 绑定用户、对象、权限版本/代次、位置和 15 分钟有效期。
- read_seq 单调前进，只允许实际存在且本人获准的位置；未读只计获准范围中非本人发送的消息。读取列表与历史不隐式写已读。
- JSON 的 ID、seq 和版本采用 JavaScript 安全整数；超界显式拒绝，不能截断、四舍五入或将全局 entry ID 当成 seq。C03 深链仅位置解析的 PHP 整数上限不等于业务 DTO 上限。
- 前端默认不激活，无自动轮询/重试或示例回填；会话内容仅保存在内存，登出、身份切换、401 和 dispose 清理。Abort 与上下文代次共同丢弃晚到响应。
- 相对路径固定，使用同源 session、no-store、禁止重定向；写已读需要当前 CSRF。HTTP 错误、无权、非 JSON 与真实空页分别处理。

### 3.1 本批 DTO 补充

沿用 C01 的 `data/meta` 和 `error/meta` envelope，本批锁定以下最小响应；它们尚非已注册的 HTTP API。所有成功响应只包含获准投影，`permissions.read` 必须为 true。

| 对象 | 字段与语义 |
|---|---|
| ConversationSummary | C01 基础字段；仅 discussion 增加 space_id、idea_activity_id，普通群不绑定活动 |
| Message | id、conversation_id、独立 seq、kind、sender、body、created_at、attachments |
| kind/body | text/system 使用非空纯文本；deleted 使用 null，且 sender 为 unavailable |
| sender | available 时仅 user_id、display_name、avatar_ref；unavailable 时不保留过期姓名/头像 |
| attachments | 本批严格为空数组，未提供附件读取授权能力；后续独立升级合同 |
| last_message | Message 去除 conversation_id/attachments 的摘要，或 null；仅当前可读范围 |
| context | conversation_id、type、version、authorization_version、authorization_revision、membership_generation、history_after_seq、permissions；discussion 追加对应活动/想法发布引用 |
| 列表 data | items、next_cursor、has_more、authorization_revision；该版本覆盖当前用户的读取范围及获准 sender 投影 |
| 消息页 data | items、next_cursor、has_more、read_seq、unread_count、context |
| 已读 data | conversation_id、read_seq、unread_count、context |
| meta | request_id；不把请求 ID 用作身份或授权凭证 |

初始/旧页的 items 升序，has_more 与非空 next_cursor 对应；增量按 after_seq 升序，next_cursor 始终 null，has_more=true 时由调用者显式以本页最后 seq 再请求，不自动无限补拉。列表采用稳定 ID 降序分页，不把该顺序冒称“最近活跃”。日期为 UTC `YYYY-MM-DDTHH:mm:ssZ`。

`authorization_version` 是会话成员授权版本；`authorization_revision` 是当前用户整个读取/投影范围的版本。姓名/头像可见性改变也必须推进后者，并在空增量页返回。前端发现该版本变化时清理所有旧摘要和消息，禁止跨版本合并列表/历史。仅给 cursor 签名或只校验成员 generation，不能清除此前已缓存的失权姓名；这是本批独立审查发现并要求修复的跨请求问题。正式服务的通知/失效传播仍待后续接线，不声称浏览器会在无请求时立即感知服务端变化。

该 revision 是 viewer 维度单调递增的安全整数；真实适配器必须持久维护，不能随进程重启或缓存淘汰归零。客户端在同一登录会话内保存已观察到的最高 revision，包括发现升级但拒绝合并的响应。清空页面缓存不会重置这个下限，列表和详情的旧响应都必须被拒绝，避免并发乱序或旧副本重新恢复已隐藏资料；身份/登录会话切换才重置。当前内存适配器只验证这一合同，不证明真实持久化版本已经实现。

PHP 用例通过 `tests/export-contract.php` 输出有限合成场景，前端 `scripts/verify-contract.mjs` 从 stdin 读取并调用真实解析器，另外损坏这些响应验证拒绝行为。输入明确标记 `matcher-chat-c04p-synthetic-contract`；不持久化真实私聊，不在正式请求失败时使用该数据。实际命令和结果见第 5 节。

## 4. 从准备进入真实接线的条件

1. 获取 N04 真实双登录与 N05 活动/撤权回执，并确认 N08 私聊关系、类型准入及代次的单一所有者。
2. 实现数据库事务适配、原生 entry/seq 同步、授权投影和签名密钥来源，再注册明确的同源端点。
3. 单独扩展聊天隔离工具的有限合成数据能力。现有 `backup-restore` 只接受业务全空基线，不能为方便验收放宽该保护。
4. 覆盖真实双用户、第三人、权限撤销、历史/增量、原生入口及附件/通知旁路后，才升级 bootstrap 并启用连接态。

既有 C02/C03 回执继续有效于原范围；本批不声称 SQL 并发、真实身份、发送持久化、群聊或完整 UI 撤回验收完成。
