# C05 文字发送接线与验收

> 2026-11-12 启动，2026-11-13 完成限定范围验收（Asia/Shanghai）。入口：[task](task.md) · [真实接线计划](07_真实接线推进计划.md) · [通用接口目录](12_首页画像通用社交与聊天接口.md) · [独立复核](14_C05文字发送独立复核.md)。已交付 matcher-chat / matcher-chat-ui 0.2.0 的受管既有 direct 文字发送与页面；不是完整 C05、群聊或生产放行。

## 本批范围

先让已明确准入、无附件的原生双人私聊完成真实文字收发。复用原生 user、user_friendship、contentcontainer_blocked_users、message、user_message 和 message_entry；新增内容仅为发送幂等、配额和现有读取元数据，不另建好友或消息正文库。当前双向好友、零双向屏蔽、启用账号和有效会话成员均在发送事务中重新验证。历史读取资格与未来发送资格分开，不要求选择当前活动。

POST /api/v1/conversations/{id}/messages 接受 client_message_id 与 body。新发返回 201，同会话同发送者同键同文重放返回 200，异文返回 409；不同会话的相同键不互相冲突。正文保留原文，去首尾空白仅用于判空，原文最多 4,000 Unicode 码点，不进行自动文本归一化。每分钟 60 条的持久配额只计新提交，重放不重复占用。

原生好友申请动作、好友持久申请历史、来源证明、expected_version 和唯一新私聊绑定仍由 N08 所有者提供；本批不能把原生 add/delete HTML 动作称为产品 JSON API。首页、画像、引导应通过专项公共接口目录了解可调用能力，不复制好友关系、不自动申请或发消息。

## 隔离验证边界

只使用已登记 127.0.0.1:8124 与 humhub_chat_c02_20261112。旧 C04 的三个用户、三个会话、八条消息、撤销的 empty 和已读位置保留，不重置旧夹具来配合新测试。本批另建有版本、nonce 和固定归属的有限 C05 虚构用户及空私聊，首次准备及重跑验证都拒绝接管未知数据。原生好友关系仅为明确的测试前置，不作为已完成产品好友流程的证据。

必须分别验证实际收发、刷新/分页、同键重试、异文冲突、非法正文、无权限/跨源/CSRF、开关、好友解除与屏蔽后停发、旧入口无旁路和原数据保留。原生通知副作用不与事务前写入混用；没有通知交付证据时明确标未开放。浏览器只用正常原生登录与本批合成账号。

8113、主预览、共享宿主、画像和推荐模块不在写入范围。不读取或分享 .local，不消费原有队列，不启动模型/worker/cron，不调用 mail disable/remove。结束关闭隔离开关、停止自有 8124，保留数据与保护；发布与主预览部署分别记录。

## 实际结果

### 实现与公共接线

- 后端新增受控发送用例、当前原生关系资格适配、永久消息键回执及发送配额。正文只写原生 message_entry，HTML 标签作为纯文本实体往返，不调用事务前 notify／RichText。发送不更新 read_seq 或原生 last_viewed。
- 前端保留现有 Soho／Signalry 页面与本地字体；从服务端 context.permissions.send 开放输入，支持明确点击、组合输入保护、重复提交阻止和原键原文手动重试。网络结果不明不显示成功、不自动重发；授权失效与身份切换清理。
- 合法重放返回消息当前投影，可为编辑正文或删除墓碑。前端重放后重新读取历史，避免恢复已删除正文；畸形成功回执保留原消息键而不误清草稿。独审发现的两处前后端差异及 FEFF 判空差异均已修复。
- 首页／画像只需引用 [12 接口目录](12_首页画像通用社交与聊天接口.md) 与 [SEND-MODE](../../frontend/对话%20群聊页面/integration/SEND-MODE.md)。公共 client.ts 无 React 或导入副作用，提供深链、列表、历史、已读及明确发送方法。原生好友查询和写能力已列清；N08 来源／版本／历史／唯一绑定 API 仍待适配，不让调用方误用原生 add 的反向自动接受行为。
