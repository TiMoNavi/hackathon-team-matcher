# C07-A1 群生命周期持久化与 API

2026-11-13。状态：C07-A1 空群生命周期通过真实 SQL／同源 HTTP 验收及独审，发布回执另记。承接[C07-P合同](18_C07普通群与邀请合同.md)与[离线独审](19_C07普通群离线独立审查.md)。本批实现原生空群创建、邀请决策、退出和重入的真实存储／同源API及公共客户端；群正文、附件、候选搜索、邀请列表、正式群UI和活动讨论仍分别后续，不把A1称为C07整体完成。

## 1. 单写与原生复用

后端agent维护SqlGroupStore、原生资格、群迁移与SQL测试，必要时最小修正SqlReadStore／EntryCoverage避免group及多成员期污染既有direct。接口agent维护Module／路由／请求边界、新GroupController和独立group-http客户端。独审只写[21](21_C07A群生命周期接线独立审查.md)。root维护本合同、task、记录、固定隔离工具和定向交付，不接手两名实现agent的文件。

原生message／user_message仍为会话与当前成员事实；matcher-chat只增加owner、邀请、命令收据和成员期规则元数据，不复制消息正文或好友关系。不使用UserMessage的自动inform制造假消息／通知。普通group的pair_low／pair_high为空，不伪造direct用户对；既有direct保持原语义，旧未知群不按人数自动准入。

## 2. 本批边界

- 只有真实空群生命周期。检测到未适配的原生群正文时拒绝操作，不推断历史起点；当前join_seq只能为经核对的实际0。之后开放群消息必须另验成员期历史与附件边界。
- groupsEnabled配置与持久设置双闸，默认关闭，并在事务内锁读核验；暂停不删除群／成员／邀请，不卸载mail。
- 继承72小时／50正式成员／50有效pending策略。新增持久速率策略为每actor滚动60秒最多5次成功新建群、20次成功新邀请；重放与失败不占新额度，返回Retry-After。此为本批选择，不冒充原生默认。
- 永久键actor＋operation＋key，hash绑定目标／正文／版本；状态和收据同事务，重放按当前授权读取。原生账号、两方向好友与屏蔽、群和成员变更须有真实行锁保护，不能只靠聊天mutex。
- 身份撤权保留当前保守策略：group当前active成员停号时整群永久暂停；已经left者日后停号不影响原群。单成员精细撤权与群恢复另需后续设计，direct既有永久撤权策略不变。
- 同用户既有direct读取继续可用；尚未开放的group不进入会话正文列表，group消息／已读／发送／附件接口仍拒绝。原生mail／文件／live保护继续覆盖group及已退出者。

## 3. 同源接口与公共调用

| 方法与路径 | 明确动作 |
|---|---|
| POST `/api/v1/conversations/groups` | 建立仅本人为成员的空群 |
| POST `/api/v1/conversations/{id}/invitations` | owner向当前合格好友邀请 |
| GET `/api/v1/group-invitations/{id}` | 邀请双方读取当前最小投影 |
| POST `/api/v1/group-invitations/{id}/accept` | 受邀者接受 |
| POST `/api/v1/group-invitations/{id}/decline` | 受邀者拒绝 |
| POST `/api/v1/group-invitations/{id}/withdraw` | owner撤回 |
| POST `/api/v1/conversations/{id}/leave` | 非owner成员退出 |

正文和回执沿用18合同，actor仅来自原生session。未知body/query字段、跨源、无CSRF、错误方法和超限JSON均拒绝。新写201、同键合法重放200，detail200；所有接口私有no-store。七路由已注册并通过固定隔离验证；目标实例仍需满足开关和依赖，不能因源码存在声称生产可调用。

独立`createGroupApi`要求expectedActorId，只校验前端身份期，不能代替服务端身份。方法与本表一一对应；没有自动重试、人物搜寻、好友写入或群消息能力。调用入口与例子写入[GROUP-MODE](../../frontend/对话%20群聊页面/integration/GROUP-MODE.md)。首页／画像的已有direct与附件仍用[12通用接口目录](12_首页画像通用社交与聊天接口.md)；N08完整好友来源／版本／历史和唯一私聊绑定仍由其唯一写者提供。
