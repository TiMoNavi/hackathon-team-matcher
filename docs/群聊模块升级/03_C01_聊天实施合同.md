## 3. C03 页面合同（本阶段固定）

### 3.1 路由、展示与菜单

| 入口/状态 | 固定行为 |
|---|---|
| GET `/matcher/chat` | 独立页面壳；不包含会话、用户、成员、消息或邀请数据 |
| GET `/matcher/chat/conversations/{id}` | id为十进制正整数、长度不超过19且不超过宿主PHP整数上限；仅保留客户端导航位置，不查询或授予该会话资格 |
| GET直接Yii `/matcher-chat-ui/app/index` | 先验证UI、路径及方法，再302到服务端baseUrl加固定`/matcher/chat`及获准深链；不转发returnUrl/其他query，不读取会话，关闭仍404、非GET仍405 |
| 其他子路径、负数/零/超长id、路径穿越 | 404；不将任意后端路径转发给前端 |
| 有效路径非GET | 405且无写入；C03没有写动作，此方法负例不冒称业务CSRF测试 |
| uiEnabled关闭 | 新页面和直接Yii action入口均404；菜单撤回，原生mail保持启用 |
| 构建产物缺失/manifest失败 | 503安全静态页，只含原生首页/登录入口，不回填原型或执行未验证资源 |

C03 页面可供未登录用户GET并返回200，因为仅为无业务数据的壳；不得把该200标为“已登录读取通过”。页面明确写“聊天接入中，尚未读取会话”，不显示“你没有消息”这种未经查询的结论。深链也不显示虚构对象名称。发送/附件/联系人/建群控件不可执行。

本批前端不读取 `/me`、current-event、conversations 等业务 API，不轮询、不发通知、不做隐式社交写入。登录入口和首页均为明确链接，不接受returnUrl或任意重定向。仅允许模块自己的账户菜单事件增加“聊天（接入中）”，只对已登录且UI开启者显示；不替换原生mail菜单、不改全站路由/主题。

### 3.2 Bootstrap v1

根节点固定 `div#matcher-chat-root`；数据节点固定 `script[type=application/json]#matcher-chat-bootstrap`。以下8个字段为完整白名单，字段/类型未知或缺失时前端显示不可用并停止初始化。

| 字段 | 类型/来源 |
|---|---|
| schema_version | 整数1 |
| integration_stage | 字符串`shell`，表示当前构建阶段；不是用户资格/业务可用性证明 |
| base_path | 字符串`/matcher/chat` |
| api_base | 字符串`/api/v1`；C03不据此发起业务请求 |
| native_home_url | 服务端`Url::to(['/dashboard/dashboard'])`，校验为同站路径 |
| native_login_url | 服务端`Url::to(['/user/auth/login'])`，校验为同站路径 |
| csrf_header | 字符串`X-CSRF-Token` |
| csrf_token | 本请求Yii当前掩码CSRF值，只保留页面内存 |

使用JSON_HEX_TAG/AMP/APOS/QUOT与失败异常编码，沿用宿主Html::nonce()与CSP，不放宽unsafe-inline。页面使用private,no-store与nosniff。不下发actor/profile/current-event/模型或认证凭据，不存入localStorage，不根据cookie名称推断已登录。今后启用连接态必须在对应批次升级/明确扩展此合同，不能在shell阶段偷偷请求消息。

### 3.3 Manifest、资源与构建桥

- 源码入口固定放在 `frontend/对话 群聊页面/integration/`，业务组件留在原目录；保留现有Next预览脚本，不修改components/ui源组件或全局frontend/integration。独立构建依赖/lock限本目录，不升级所有页面。
- 产物目录固定 `backend/protected/modules/matcher-chat-ui/resources/app/`，包含 `index.html` 与显式 `manifest.json`。index.html只是构建入口标识，不由PHP直接输出其脚本。
- 使用Vite形状manifest：`index.html`节点必须isEntry=true并有JS file；imports/dynamicImports递归指向manifest节点，css/assets为本地相对文件列表。PHP模板自己输出根、bootstrap及验证后的入口。
- 每页一份兼容React；首阶段只引用必要静态样式/本地字体与无数据壳组件，不把原型fixtures/定时回复编进正式入口。不需要常驻Node/Next服务。
- 全图验证：manifest最大1MiB、最多2048节点、深度不超过64；拒绝环/缺节点/缺文件、外部URL、绝对路径、点段、隐藏段、反斜杠、超240字符路径和任意symlink。路径realpath必须在产物根内。
- 发布只含验证图可达的JS/MJS、CSS与允许的图片/字体等静态资源；不发布manifest、构建HTML、source map、PHP、配置或未知文件。不允许linkAssets绕过发布白名单。资源基址必须同源。
- 构建检查同时禁止CSS/JS引入外部字体、图片或开发端口；开发/原型链接不得进入正式壳。处理本地字体与Next专用包装，不拼接多个Next运行时。
- 可参考已有[manifest实现](../../backend/protected/modules/matcher-webapp/adapters/assets/Manifest.php)，但聊天模块自有实现与测试，不在运行时import或依赖matcher-webapp；只复制通用思路，不抢写其文件。

### 3.4 uiEnabled与本阶段负例

模块属性uiEnabled为bool、默认true；设置项未配置视为允许，已配置仅true、1、`1`、`true`允许，其他值拒绝。最终为属性与设置项的逻辑与；query、bootstrap修改或localStorage不能打开服务端已关闭的页面。关闭检查同时覆盖友好路由与直接`matcher-chat-ui/app/index`路由。

C03必验：GET基础页/合法深链；guest无私有内容；未知/越界/穿越路径；非GET无写入；uiEnabled两层false与非法设置值；manifest缺失/恶意引用/符号链接/动态import；CSP与JSON的`</script>`转义；无JS安全回退；资源同源和禁止额外文件发布；窄屏/日夜/字体/减少动效。合法深链测试不得读取同ID原生会话。

此阶段不声称业务401、发送CSRF、真实空列表、附件或聊天验收通过。C03未提供消息API的404属于未注册端点，不能包装成已授权或业务空结果。

## 4. 后续API与最小DTO（C04起，尚未注册）

由matcher-chat单一所有者实现以下共享语义。注册使用明确路径/方法，不新增`/api/v1/*`通配；每批只开放有授权与验证回执的端点。

| 路径 | 输入/输出与责任 |
|---|---|
| GET `/api/v1/conversations` | limit/cursor；返回本人获准ConversationSummary分页，不按前端活动选择一刀切隐藏私聊 |
| GET `/api/v1/conversations/{id}/messages` | limit、cursor或after_seq二选一；消息页、当前read_seq和权限上下文 |
| POST 同messages路径 | client_message_id、body；C05扩展attachment_ids需先锁定文件合同；返回持久message_id/seq/created_at，成功201、合法重复200 |
| PUT `/api/v1/conversations/{id}/read-state` | read_seq；返回单调合并后的read_seq及真实unread_count |
| PUT `/api/v1/conversations/{id}/notification-preferences` | expected_version、muted；返回本人偏好/版本，不授予成员资格 |
| 群创建/邀请/接受/拒绝/撤回/退出 | matcher-chat拥有普通群聊天用例；C07锁定新扩展具体路由，不提前创建假端点，也不注册N09的discussion-requests路径 |

基础DTO锁定：

- ConversationSummary：`id`=原生message.id正整数；`type`=`direct/group/discussion`；`title`可null；`version`正整数；`last_message`为获准MessageSummary或null；`unread_count`为非负消息数；`permissions`为明确布尔read/send/invite/leave。discussion额外仅返回获准space_id与idea_activity_id，普通群不强绑Space。
- Message：`id`=原生message_entry.id；`conversation_id`、独立`seq`正整数；`sender`仅user_id/display_name/avatar_ref的获准投影或不可用标识；`body`为安全文本投影，`created_at`为UTC带时区时间；`attachments`仅获准文件摘要。系统事件与删除占位单独kind，不注入原生HTML，不泄露失权成员。
- Page：`data={items,next_cursor,has_more}`、`meta={request_id}`；历史页items按seq升序，初次取最新limit，cursor向旧页；增量after_seq升序。limit默认24、最大48，禁止全量导出。
- 客户端状态：sending/failed/outcome_unknown只为本地状态，收到持久id才显示已发送。服务端无逐条送达/已读回执时不伪造“对方已读”；本地Blob不等于上传成功。

所有API复用普通用户session+Yii CSRF；actor只来自会话，拒绝冒充访问。错误用`error={code,message,retryable,details}`及meta，保留details为空数组的兼容；401未登录、403无资格、404无权披露/不存在、409版本/幂等冲突、410游标过期、422校验、429限流、503依赖未就绪分开。无效CSRF沿宿主400；不以retryable自动重复写入。

## 5. 原生引用、序号、幂等与历史

原生user、user_friendship、Space/membership、message、user_message、message_entry及file保持事实所有权。扩展仅保存引用与规则元数据，不复制消息正文、好友真相、画像或current-event。SQL物理名/迁移在C04/C05单写锁定，下面约束不可省略。

| 扩展边界 | 锁定的不变量 |
|---|---|
| ConversationState | message_id唯一；显式type/status/version/last_seq，不能仅按成员数猜类型；不复制title正文 |
| EntrySequence | entry_id唯一、(message_id,seq)唯一；删除保留序号占位或墓碑，seq永不复用；全局entry.id不是seq |
| MemberHistory | (message_id,user_id,generation)记录join_seq/leave边界；active仍须与真实UserMessage及对应业务资格取交集 |
| ReadState | 本人会话已读序号单调前进且不能超过实际获准消息位置；last_viewed仅兼容原生显示，非新API权威 |
| ClientMessageKey | (message_id,sender_id,client_message_id)永久唯一，存payload摘要及entry引用；同键异正文/附件409 |
| RequestIdempotency | actor+route+key，有限期回执/原对象引用；重放先重新授权，不缓存可绕过撤权的完整正文 |
| GroupInvitation | 独立pending/accepted/declined/withdrawn/expired、version、邀请双方与会话引用；accepted前不创建UserMessage |
| PrivateConversationBinding | N08关系事实的单一绑定服务拥有唯一用户对与message引用；聊天通过端口取引用，不另存第二份关系事实 |

发送在同一数据库事务中锁会话、验证当前资格、分配seq、写原生entry与序号/幂等元数据，再提交。并发、回滚和通知副作用一起设计；[ReplyForm](../../backend/protected/modules/mail/models/forms/ReplyForm.php)保存时直接notify，不能在外层事务未提交前照搬并宣称一致性已保证。适配器可复用校验与模型，通知须提交后按持久事件去重/恢复；不承诺外部邮件绝对只投递一次。

存量会话不得自动按两人/多人猜业务类型或合并。按显式准入清单一次性建立序号，以稳定entry.id顺序生成会话内连续seq；与原生并发写入串行化。无真实历史加入边界的旧群不伪造join_seq，C04只开放已证明合法的私聊；旧群等待C07明确兼容策略和验证回执。

新增群成员只读seq>join_seq；退出后禁读，重新加入新generation与新起点。私聊解除好友后的旧历史与未来发送分别授权；重新成为好友不自动复活旧授权。读、发、已读、列表摘要、附件、通知和增量结果均重验，不能只保护主消息页。签名cursor绑定viewer、会话/活动、筛选/顺序、位置、权限版本和15分钟有效期，权限变化后旧cursor拒绝。

原生读取可能标seen、编辑/删除可能改变通知及最后消息；新适配必须显式处理并保留墓碑。未完成原生写入与序号同步前，不开放“新旧UI同时可写”的承诺。空会话不插入假正文，创建者资格、配额、事务、可恢复失败与通知由新用例明确验证。

| [通知与live](../../backend/protected/modules/mail/models/MessageNotification.php) | 原生按当前participants发送，含事件/邮件/推送 | 在真正发送/补拉时重验；未接受者无正文摘要，退出后无晚到正文；不能只过滤React |
| [想法关联](../../backend/protected/modules/matcher-ideas/application/IdeaService.php)及成员关系摘要 | 永久绑定与原生成员投影 | 调用原所有者，tombstone不复用；活动资格、成员可见性和真实聊天成员取交集 |

优先在matcher-chat用模块events、Yii EVENT_BEFORE_ACTION、专用策略/文件适配等扩展点实现，保留原生代码。钩子的触发顺序、原生REST重建user、文件直接动作及后台通知不一定被单一controller钩子覆盖，必须逐项验证。覆盖不了时对应能力拒绝开放并列出最小改动需求，不先承诺全量核心零修改，也不自行扩大核心修改范围。

原生live/轮询只作为待确认的HumHub传输适配，不能称统一SSE/Web Push已经交付。C03无实时连接；后续若采用有界补拉，必须记录与共享实时合同的阶段差异、离页清理和晚到结果授权，不新增全站通知平台。

## 7. 附件、正文与可选能力

文件归原生file，聊天仅保存消息关联引用。C05先锁上传最大字节/MIME/数量、本人暂存所有权、幂等关联及失败回收，再开放UI；不将简历5MiB限额套成聊天事实。上传与消息提交不得默默把他人暂存文件绑定到当前消息。下载每次重验文件关联消息的当前历史范围，不生成长期公开地址。

文字遵循共享契约去首尾空白后非空、最多4000 Unicode码点；附件单独发送若要允许，须作为明确的有附件消息变体，不能以空正文假装已满足现有文字合同。原生富文本需经安全投影，禁止dangerouslySetInnerHTML直接注入返回内容。群公告、在线、置顶、提醒偏好等逐项按已有服务端能力开放，未实现时不伪造保存成功。

## 8. N08/N09非聊天交接与阻塞

- **N08交付给聊天**：普通好友申请/来源授权、expected_version接受、撤回/拒绝、真实发出历史、拉黑/解除与有效关系/代次查询；原生user_friendship是双向事实，不能从一条单向记录推断已互为好友。另指定唯一私聊绑定服务单一所有者，并提供与接受同事务的ensure-empty-conversation端口。聊天负责原生空会话创建和消息用例，不负责写第二套申请状态。
- **唯一私聊待交接细节**：历史重复双人会话选定、重新加好友复用还是新会话、原申请附言是否仅留申请。前端最新约定为唯一空私聊/不自动复制附言；未取得N08一致合同前C05相关功能保持未开放，不自动合并/删除存量。
- **N09交付给聊天**：想法与活动发布合法性、开启讨论资格、申请审批/成员权限、对应Space与永久绑定接口及tombstone；这些不是当前“仅元数据绑定”已经实现的完整讨论。普通群邀请由聊天负责，活动讨论申请/批准仍归N09所有者，通过明确成员变更端口同步真实UserMessage与历史起点。
- **C07待定策略**：普通群邀请期限、管理者/邀请人权限和旧群历史迁入策略尚无可复用完整实现，必须先形成明确值与规则，再开放端点；不得从好友申请7天规则推导群邀请默认值。
- **C04当前闸门**：真实N04双登录与N05活动/撤权回执未取得；继续C02/C03，不用合成登录证明外部闸门已过。N04/N05程序前置不表示私聊读取逻辑必须绑定当前活动。

## 9. 本阶段交付与核验口径

C01的明确产物是本合同与当前源码/路由核对，不是业务验收。C02可据此建立独立空库、有限合成账号、明确端口与隔离执行入口；不得接管其他专项隔离实例或主预览。C03按第3节单独实施/核验，消息接口、扩展表、关系写入与通知调用全部留待对应任务。

本轮只校验本文链接、标题/表格、字段一致性及限定文件范围，不启动服务或调用模型/邮件/OAuth。主执行者在[实施记录](02_实施记录.md)登记真实审查和后续测试结果；每个阻塞只影响依赖分支，不阻止已授权的独立页面工作。
