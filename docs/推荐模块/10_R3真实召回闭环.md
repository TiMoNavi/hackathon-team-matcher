# R3 真实召回闭环

> 2026-11-11。用户恢复按 task 推进并要求子 agent。本轮人物获准索引、SQL 召回、评分与内部活动选择已通过隔离验收；勾选 R3.4、R3.6，其余按实际依赖保留。完整 R3/M1 尚未完成。没有部署、连接现有数据库或启动 AI。

## 1. 本轮计划

1. 读取完整当前活动资格集合，分批调用 P1/P8 获准投影，每批最多 200 人，不能先截前 200 人。
2. 建立当前请求专属的最小索引代次，绑定 viewer、活动、选择版本、规则与字段用途版本。索引只存规范词项摘要和明确时段边界。
3. 在 SQL LIMIT 前完成全部硬条件筛选，补齐硬时段语义；结构化 80、全文词项 40、合并最多 200。
4. 召回后重读完整候选集合及授权投影，验证代次所依据的版本和内容；成功或失败均清理该代次。
5. 补充显式活动选择的内部服务，用推荐自有 SQL 表按服务器 actor/session 哈希做版本更新；浏览 Space 页面不能隐式替换当前活动。
6. 串接真实适配器，验证 0/1/30/35/40/300/400 人、撤权、字段变化、时段、故障和无 AI；更新对应 task 状态及未完成项。

## 2. 关键边界

长期授权 epoch 尚未由上游提供，因此本轮索引不跨请求复用。每次创建新 generation，并用完整活动资格集合和分批获准投影复核；请求中的版本指纹不是长期通行证。有限观察窗口仍存在，不宣称跨表原子事务或检测所有 ABA 历史变化。

构建预算独立于召回预算。默认最多处理 2,000 个活动候选、250,000 行派生索引，可由可信装配层显式收紧；超出时明确容量错误，不把截断集合冒充完整。此上限不限制后续普通分页的活动总人数。没有每人 SQL 或每人模型比较。

词项以 SHA-256 保存，查询按相同规范化编码，避免把已确认的整段简介复制到推荐表。它维持现有精确词项相等语义，不代表分词、语义搜索或数据匿名化。时段只保存 UTC 秒边界。

两份迁移只管理推荐自有词项、时段与当前活动选择三张表。测试仅新 SQLite 内存库；没有对现有库执行迁移或启用本机推荐模块。AI、想法目标、完整申请历史和公共 API 不在本轮交付内。

## 3. 分工与验证

子 agent 分别完成索引生成、召回与活动选择；另一个子 agent 独立审查。主代理完成实际适配器整合、阶段回归、迁移往返测试与文档。

| 能力 | 实现 | 实际边界 |
|---|---|---|
| 获准索引发布 | [SqlCandidateIndexAccess](../../backend/protected/modules/matcher-recommendation/adapters/index/SqlCandidateIndexAccess.php) | 完整活动 roster，按每批最多 200 个 ID 调用获准投影；未召回人员的版本或内容变化同样使整代失效 |
| 生命周期 | [ManagedCandidateIndexAccess](../../backend/protected/modules/matcher-recommendation/contracts/ports/ManagedCandidateIndexAccess.php) | 原实例签发的 snapshot 才能使用；finally release，跨 viewer、复制 DTO、跨实例或已释放代次拒绝 |
| 硬条件召回 | [SqlCandidateRetriever](../../backend/protected/modules/matcher-recommendation/adapters/retrieval/SqlCandidateRetriever.php) | token 与完整时段覆盖均在 LIMIT 前；SHA256 与旧 plain 测试模式显式区分；语义路线仍不可用 |
| 当前活动选择 | [SqlCurrentEventSelectionStore](../../backend/protected/modules/matcher-recommendation/adapters/native/SqlCurrentEventSelectionStore.php)、[SelectCurrentEvent](../../backend/protected/modules/matcher-recommendation/application/SelectCurrentEvent.php) | 首次 INSERT、后续 expectedRevision 条件 UPDATE，认证身份与会话来源只由服务器提供 |
| 真实装配 | [NativeRuleDiscoveryFactory](../../backend/protected/modules/matcher-recommendation/adapters/composition/NativeRuleDiscoveryFactory.php) | 显式注入 P8、目录、策略、批次存储与时钟，固定本次活动/策略，拒绝旧映射与新策略混用 |

普通关系继续展示 friend/pending 状态；本轮不加入 AI 人选才需要的终态申请历史排除。词项仍是规范化后的精确相等，不宣称已经接入全文分词或向量服务。硬时段支持相邻、重叠及同一规则多个候选特征的合并覆盖，不能将一段交集当作完整满足。

原 YiiSessionSelectionSource 保留只读兼容。新的选择写入不修改 HumHub 原生 session 行，也不自动与旧来源混用。调用前资格或参数失败保持旧选择；CAS 成功后若资格已撤销，只删除仍属于本次 revision 的行，不恢复旧活动、不覆盖并发请求的新选择。仍需 R4 的真实用户操作、CSRF、HTTP 与错误转换才能开放入口。

索引与选择 schema 均有独立迁移，实际 up/down 仅在新 SQLite 内存库执行，回退后原生 user 与 P1 state 表及行保持不变。这不代表完成全部策略、批次和反馈存储迁移。
