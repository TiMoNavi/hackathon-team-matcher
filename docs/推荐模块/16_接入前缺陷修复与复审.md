## 范围与执行计划

1. 修复会话正文来源撤权、跨轮待确认硬要求丢失、已确认软偏好被草案覆盖三个已复现问题。
2. 独立验证者先固化失败反例，再执行修复后的回归与边界审查；覆盖空卡片、历史上下文、恢复会话和明确修改条件。
3. 核对新 ConversationProvider 的可选插件注册及移除，补齐能够独立验证的内部接入，不用测试替身填充生产依赖。
4. 主代理复跑相关离线套件，检查变更范围、文档链接和任务状态，记录剩余接入条件。

代码只写两个推荐插件；文档只写本目录。HumHub 原版、画像/隐私等其他插件、冻结原稿保持只读。不读取 .local，不调用网关，不连接现有数据库、不操作 worker、不启用模块、不开放新的 HTTP 路由、不提交 Git。

按 [architecture-patterns](../../.agents/skills/architecture-patterns/SKILL.md) 保持领域与应用独立，外层适配器承担存储、模型和框架集成。主插件不依赖 AI 子插件具体实现，普通发现仍不调用模型。

本轮基线见 [源码指纹](sources/preintegration-fixes-baseline_2026-11-12.json)。基线记录源码哈希，不包含凭据或用户资料；它不是远程上游或 ignored vendor 全量一致性证明。

## 审核清单

- [x] 正文和历史所依赖的全部候选来源在读取与继续对话时重授权；未入选人及空卡片也受保护。
- [x] 待确认要求跨轮、服务重建及换批保持有效，模型或自由文本不能冒充可信确认操作。

- [x] 新对话提供者可选注册、获取与移除的行为明确；无 AI 时既有普通/规则链保持独立。
- [x] 独立回归与定向套件通过；审核中发现的重复来源读取、澄清中撤权及三轮确认上限问题已闭合。

## 修复与接口影响

| 问题 | 已实现行为 | 验证边界 |
|---|---|---|
| 未入选人、空卡片的正文撤权 | batch.source_refs 记录实际送模型的全部候选指纹，独立于入选 refs；GET、submit、讨论及模型前后重验 | 不保存完整候选画像；授权失败不继续展示原正文 |
| 来源经历史或换批传播 | turn、需求与派生条件记录来源批次；来源失效清正文、历史及相关派生条件，禁止继续传模型 | 同会话换批的用户文字保守视作依赖可见旧批，旧来源撤权可能使后续批次同时失效；独立新会话不受连带影响 |
| 待确认硬要求被绕过 | pending_confirmation 与 requirements_version 持久化；普通续答、模型输出、refresh 不解除 | confirmedIntent 仍来自可信调用层；等待确认计入同 run 最多三轮澄清，第 4 次明确失败，无隐藏检索 |
| 已确认软偏好被覆盖 | 用户确认的硬软条件都保留；显式完整快照可替换或撤回，已撤回的同值条件不能被草案重新加回 | 模型仍可以增补未确认的软草案，不获取确认权限 |
| 旧快照缺少来源 | 无完整来源的旧候选文本保守失效；旧待确认硬要求恢复后继续等待可信确认 | 三份修复前实际生成的合成状态回归，不从新结构伪造旧快照 |
| 多批次依赖重复读取 | 一次授权验证内复用已验证的批次，跨请求及模型前后重新校验 | 20 轮/20 批次稠密依赖图一次 GET 至多 20 次来源读取；这是离线读取次数断言，不是 MySQL 性能结论 |

submit 参数签名不变。confirmedIntent 现在明确表示用户确认的**完整**条件快照，空列表表示明确撤回全部；expectedVersion 绑定当前状态。部分字段更新调用方必须先构造完整快照，不能将模型草案直接标记 user_confirmed。内部 view 新增 requirements_version / pending_confirmation；模型的 conversation-v1 输入仍只接收既有 messages / conditions，不向模型暴露内部授权指纹。

自然语言硬要求检测目前仍是有限词语护栏，不保证识别所有表达。正式 UI/API 还须实现可信的条件确认与版本核验，不能把本次内部端口修复写成自然语言确认功能已经完整上线。

## 待接入事项

主插件 AiProviderRegistry 新增 registerConversation、conversation、conversationIdentity 独立能力槽；AI 子插件新增显式 setConversationProvider / attachConversation。旧解释器与精排器注册接口保持兼容，会话能力不要求同时安装旧能力。按提供者 ID 撤除不会影响另一 ID 所有的能力，加载插件也不会创建默认模型客户端或调用网络。
