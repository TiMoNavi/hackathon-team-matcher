# 对话插件实施与验证

> 2026-11-12。用户授权按文档 14 继续实现，并明确要求子 agent 协作和插件独立运行。独立会话基线已实现，最后一轮真实合成测试完成 9 轮对话；**完整产品语义验收仍未通过**。这不是已部署的正式人物推荐服务。

> 后续接入前审计发现初版正文只跟踪入选卡片来源，另有硬要求跨轮丢失及确认软偏好覆盖缺陷，初版撤权测试不足以证明全部正文安全。这些缺陷及内部可选会话注册现已修复并通过独立复审，详见 [16 接入前缺陷修复与复审](16_接入前缺陷修复与复审.md)。本文保留原测试和真实模型失败记录；最新来源追踪、确认快照和旧会话行为以文档16为准。

## 本轮执行计划

1. 固定主插件端口与可序列化会话合同；推荐主体不引用 AI 子包、Yii、HTTP 或模型 SDK。
2. 并行实施会话编排/权限、独立存储适配器、可替换自然对话提供者；主代理负责契约、集成和验收。
3. 用内存与独立 SQLite 验证上下文恢复、当前名单讨论、明确换人、实际工具事件、幂等和并发；不连接现有库。
4. 使用新的任务型合成数据执行连续真实模型对话，保留失败与实际调用计量；最后复核原规则路径、插件依赖及文档。

## 写入范围与边界

只改两个推荐模块中新增的 conversation 目录/端口与对应测试；Module/config/已有普通发现由其他工作推进，本轮不覆盖。文档只写本目录，其他插件和原版只读。不启用生产模块、注册新公共路由或迁移现有库。真实网关只由主代理使用本地凭据发送合成数据；子 agent 不读 .local、不联网。

## 内部合同 v1

- ConversationStore：create(id, ownerId, eventId, snapshot)、load(id, ownerId)、compareAndSwap(id, ownerId, expectedVersion, nextSnapshot)。snapshot.version 初始1，CAS仅加1；存 JSON，不反序列化 PHP 对象。并发或异常不得留下半次写入。
- ConversationProvider：plan(input, permit) 与 respond(input, permit)。只实现语言理解/表达；主包注入身份、事件、候选、账本及工具，子包无数据库/社交写权限。
- plan 返回 action=clarify/search/discuss，message，conditions。conditions 沿用 QueryIntent 结构，模型只产生 soft/interpreted_draft；字段说明和允许值由主包附带，self_type 非法枚举拒绝。
- respond 输入 mode=recommend/discuss，用户需求/有限历史、当前允许候选与短事实 ID；返回 message、items[{id,fact_ids,reason,gaps}]。recommend最多5，discuss不新建推荐、不改变原卡；事实 ID 必须属于对应已发送候选。文案属于有据表达，仍需真实样本人审，不能把合法引用等同于句句正确。
- ConversationService：create(viewerId, spaceId?)；submit(viewerId, conversationId, expectedVersion, message, idempotencyKey, command=chat)；get(viewerId,id)。command为可信调用方根据真实用户操作提交的 chat/recommend/refresh，不由模型设置。chat不能偷偷创建新的已完成推荐轮次。
- 会话配置必须显式注入。内部验收使用最多20个用户turn、会话最多40次调用、讨论每turn最多2次；普通推荐维持原3/5次和一次修复、一次检索。平台预算端口仍必须注入；这些是明确有限的内部配置，不冒充已接通生产平台账本。
- 会话持久化保存需求/消息和名单引用、版本及调用计数，不保存完整候选画像。向模型发送/返回讨论前重授权；旧名单失效后不能凭历史文本恢复授权。跨进程执行不使用 PHP serialize。

以下区分内部实现、真实模型表现与尚未接入的产品能力。

## 独立运行的装配边界

主模块的 ConversationService 通过构造器接收当前活动、策略、检索、获准投影、关系历史、平台额度、ConversationProvider、ConversationStore、Clock 和 ConversationLimits。业务层不创建 PDO、不读取环境或凭据、不导入 AI 子插件。没有 AI 时继续使用原来的普通发现和规则入口；不把 AI 请求静默降级成规则成功。

AI 子模块的 ChatConversationProvider 只实现 plan/respond，并复用已有 ChatCompletionsClient。模型提出条件与排序建议，执行检索、确认硬条件、选择活动、校验候选和计数始终属于主模块。当前内部调用入口的 command=chat/recommend/refresh 必须由可信调用方根据用户真实操作提交，不接受模型自称用户同意。

新增 ConversationStorageSchema::install(PDO) 是显式安装器，仅建立推荐自有的 matcher_recommendation_conversation 表；适配器构造器不执行 DDL。内部验收使用新建临时 SQLite 文件，每轮重新实例化服务和数据库连接。MySQL DDL 的存在不等于 MySQL 已验收。

合成验收会通过 submit 最后的 confirmedIntent 参数传入用户测试消息中明确确认的后端意愿和联调时间。它是可信测试调用层的结构化输入，不表示真实聊天里已实现自然语言硬条件确认 UI/API。正式接入必须验证确认操作与需求版本，不能让模型直接填写 user_confirmed。

## 测试分工与固定样本

- 会话核心 agent 负责纯编排、状态与授权测试。
- 存储 agent 负责 JSON/CAS/隔离与跨进程测试，并在交付后独立只读审查整链。
- 提供者 agent 负责输入/输出协议、自然表达约束及假传输测试。
- 主代理负责实际 SearchAiCandidates → 确定性规则 → 会话提供者的整链和真实网关记录。

新样本见 [40 人项目型合成资料](examples/conversation-project-corpus_2026-11-12.json)。36 人属于当前活动、4 人属于其他活动；包含愿意后端但缺部署经历、只愿指导、仅周日参与、时间未知、有可迁移交付经历等差异。人物与经历均明确虚构，未创建真实账户。样本在真实调用前固定，不能看模型输出后给某人补经历。原 40 人失败演示保持不动。

测试入口为主模块 tests/conversation_store/run.php、tests/conversation_core/run.php、tests/conversation_integration/run.php、tests/conversation_integration/safety.php，以及 AI 子模块 tests/conversation_provider/run.php、tests/conversation_provider/integration.php。真实调用是单独的 tests/conversation_demo/run.php --allow-network，带固定样本哈希、显式本地配置、单次最多16次请求、同样本本轮累计最多32次、每run预算和逐次落盘；默认测试不运行它。本轮实际共27次，已停止追加调用。

### 有限上下文与失败行为

本轮装配20个用户 turn、40次会话调用，讨论每 turn 最多2次；普通推荐最多3次，出现澄清后同 run 最多5次、最多3轮问题、共享最多一次修复。累计额度不会因恢复服务实例而重置。平台 reserveAttempt 仍通过显式端口注入，本轮平台适配器为合成测试账本。

最近最多6个已完成 turn、12条消息、8 KiB历史进入模型；当前批已重新授权的 assistant 答复和卡片理由可继续提供，旧批候选文字不再进入新一轮推荐。项目需求单独保存，不把过往完整画像塞进上下文。这是有限持续上下文，不是无限记忆。

完整请求包含提示、两份 schema、需求、历史与候选，仍不超过24 KiB或更低的配置值。主包优先从尾部移除整个人选，保留需求与硬条件；讨论不偷偷删当前名单。每人不超过768字节，不能完整容纳硬条件事实时不将该候选发给模型。内部会话快照设192 KiB上限并预留失败落盘空间；容量不足记录明确失败，不无限累积，也不留下永久 processing。

真实工具开始/完成事件由后端产生，人数由实际检索及裁减结果计算。它们可用于未来轮询/呈现，但本轮没有实现前端流式工具 UI。不会展示或伪造模型内部逐字思维链。

### 为什么产品验收仍不勾选

独立审阅的最终结论是“可以作为内部插件受控演示，尚不通过完整产品语义验收”。第三次成功不能抵消前两次失败，也不能证明模型稳定。

1. A8/A9仍把5024声明愿意做API部署，预设成已有部署经历；当次发送的经验事实只有入库脚本。用户画像全量可能有其他事实，也不能替代这次实际发送的证据。
2. A9将候选的FastAPI技能写成项目已经确定的技术栈，用户并未确认。
3. A6/A8的可见理由露出(fN)内部事实编号，仍有调试文案观感。
4. A6补入仅有入门课程证据的第五人，虽说明不足，但是否应只给更有依据的少数人，取舍还不稳。
5. A9要求一句提问却返回多段及额外人选问题；A5“现场”措辞比用户允许线上更窄。

下一步优先处理“贡献意愿/经历/用户已确认决策”的逐句归属，及引用标记的呈现层、少量强依据结果、简短续答验收；不能只靠继续加提示或重复抽样把偶然好结果写成通过。本轮不再追加模型调用。
