## 用户本次明确的方向

- 优先参考 HumHub example-basic 的插件接入方式。
- LightFM 不作为首选新依赖，重新寻找适合当前需求的开源参考后端。
- 同时支持项目匹配、兴趣爱好相似、角色互补，以及用户确认的性格/协作偏好。
- 例如领导协调、技术实现、商业推进可以互补；不能把所有人只按单一相似度排序。
- 规则包含相似、差异互补、兼容与明确约束，并预留 AI 接入。
- 主模块须在无 AI 时独立完成规则匹配，AI 以单独子扩展接入；兼顾 30 多人和 300–400 人候选池。
- 按分数排序，但不以“无论如何有结果”为由越过权限、硬条件或推荐依据；不足时提供用户主动探索入口。

“领导者、技术、商业”首先是用户愿意承担的贡献角色，可以一人多角，不等同于人格类型。差异是否有价值取决于项目缺口和双方偏好，不能对所有不同字段一律加分。

本目录承接本次新方向，属于当前设计的专项细化。既有 [共享契约](../共享数据与接口契约.md) 继续管理活动权限、API、版本、预算与错误；新增规则/字段的提案不会静默成为线上接口。

前一轮规则路径：获准投影已接通 SQL 召回、无 AI 规则评分、SQL 批次保存和跨请求整批复核，总计 1,989 项检查通过。固定批次使用签名分页；策略回退、活动切回和页外撤权均不能复活旧结果。请求索引有固定租约及到期清理能力，但生产调度、遗留行维护、身份/评分理由展示合同、公开 API 与 MySQL 验证仍待后续，不能据此声称完整 R3/R4/M1 或线上可用。

本轮累计 2,514 项离线检查通过，另有 287 项独立审查（不重复相加）。内部 AI 路径：后端最多一次有界检索，粗排最多 200 个候选、24 个最小摘要、最终 0–5 个有据结果。AI 单向依赖主插件，无 AI 时规则继续运行。指定网关用合成人物通过两条链路；完整申请历史缺口仍阻止真实 AI 人物入口，生产 run/预算与统一接入未完成。
