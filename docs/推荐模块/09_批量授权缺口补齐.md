## 1. 范围和计划

允许精确追加 P1 用户画像、P8 隐私插件及推荐适配器的只读批量能力与隔离测试。既有单人服务、资料写流程、引导、原版表及公共路由保持兼容；不能绕过隐私边界或循环单人服务冒充批量。推荐接入记录写本目录，用户画像专项文档遵循其负责目录约定；本轮不推进原阶段任务勾选。

1. 固定有界批量契约，保留 global/current Space 独立内容和权限版本及身份版本。
2. P1 实现真实批量来源和读取期间版本复核，最多 200 个去重 ID，只读取请求的已确认公开来源。
3. P8 实现批量 discovery 授权，前后验证活动资格、账号、屏蔽、可见性和来源用途，不设管理员绕过。
4. 推荐侧接通 CandidateProjectionReader，复核服务端已选活动，沿用现有字段映射生成可评分投影。
5. 验证撤权、退出、屏蔽、身份变化、缺字段、故障、空数组及固定查询次数，回归既有流程。

不读取凭据或真实资料，不连接现有数据库，不启用模块、部署、执行生产迁移或调用模型。只用新 SQLite 内存库与合成数据。

## 2. 跨模块合同

P1 内部 DiscoveryProfileBatchReader 接收 owner IDs、Space ID、source keys；返回 schema_version 与按 owner 分组的 profiles。scopes 含 global 和 space:N，各有 revision、permission_version、attributes；独立 identity_version 只表示版本。缺失 scope 为 0/0 加空 attributes，缺失身份状态版本为 0，不隐式创建状态、不返回身份原值。

P8 DiscoveryBatchService 接收可信调用方绑定的 viewer、Space、候选 IDs、来源 keys，返回同一结构及 policy_version。服务验证实际活动成员与屏蔽；推荐侧负责把活动绑定服务端已选择上下文并前后重验。它是内部能力，不新增 HTTP 接口。不可访问候选省略，不返回隐藏排除原因。

条目限 confirmed + authenticated，排除 friends/private、contact_*、草稿、原文和未审阅用途来源。空请求即为空，超限、非法来源、版本冲突、依赖故障明确失败，不伪装无候选。字段变化撤销受影响来源许可并记录未知，不要求恢复原版资料字段。

## 4. 实施与验证

两个子 agent 分别完成 P1 与 P8，主代理接通推荐适配并统一验收，第三个子 agent 独立审查。

| 层 | 已实现能力 | 入口 |
|---|---|---|
| P1 | 批量读取、确认标记校验、两作用域与身份版本、读取期间版本冲突检测 | [DiscoveryProfileBatchReader](../../backend/protected/modules/matcher-user-profile/application/DiscoveryProfileBatchReader.php)、[SQL 来源](../../backend/protected/modules/matcher-user-profile/adapters/persistence/SqlDiscoveryProfileBatchSource.php) |
| P8 | 18 个审阅用途来源、三次活动资格检查、两次批量投影比较、最后撤权过滤 | [DiscoveryBatchService](../../backend/protected/modules/matcher-profile-privacy/application/DiscoveryBatchService.php)、[原生批量资格](../../backend/protected/modules/matcher-profile-privacy/adapters/native/NativeDiscoveryRelations.php) |
| 推荐 | 服务端已选活动复核、字段许可与目录变化、带证据的逻辑特征 | [P1CandidateProjectionReader](../../backend/protected/modules/matcher-recommendation/adapters/profile/P1CandidateProjectionReader.php) |

P1 Module 追加 getDiscoveryProfileBatchReader，P8 Module 追加 getDiscoveryBatchService。旧 P1 缺少能力时，批量 getter 在访问数据库前明确报 PROFILE_DEPENDENCY_UNAVAILABLE/503；原单人依赖版本规则保留。推荐 Module 不安装默认测试提供者，不自动启用服务。

可信装配层可以显式注入已初始化的模块能力。以下是装配示意，不是已经部署的公共入口：

~~~php
$reader = new P1CandidateProjectionReader(
    $currentEventAccess,
    new P1FieldCatalogAdapter([$profileModule, 'getFieldCatalog']),
    $publishedPolicy,
    [$privacyModule->getDiscoveryBatchService(), 'read'],
);
~~~

P1 单次固定 3 次 SELECT；P8 稳定批次为 6 次资格 SELECT 加两次 P1 读取，共 12 次；推荐投影前后验证已选活动再加 2 次，共 14 次。1、30、200 人实测均保持相同查询次数；400 人活动中请求后面的 200 人也正确投影。没有逐人调用 getProfile。这里仅验收投影链，不把 14 次查询当作完整召回、评分和分页的总开销或生产性能结论。

用户可见性、确认状态、Space、成员、双向屏蔽与账号有效性继续限制读取；原生账号设置为不可发现时也不返回。管理员没有额外分支。字段缺失或已审阅 schema 不匹配时，受影响特征变为未知，其余获准特征保留；配置不能自行批准新用途。没有资料状态但仍有资格的候选可以带未知特征返回，不能伪造身份、能力或匹配依据。

## 5. 验收边界

读取采用有限窗口内的前后重验，不是跨表原子快照或长期授权凭证。输出不可用作持久索引授权 epoch；后续展示、异步使用和评分后仍须重新读取。没有增加持久化权限代次，没有承诺覆盖全部 ABA 历史变化。

本次执行没有修改原版核心、vendor、原生字段配置、冻结原稿或共享白名单。P1 中另有并行出现的资料导入文件及配置变化，完成检查单独记录，不计入本补缺、不回滚。既有资料写流程、推荐业务内核及阶段任务勾选保持本次执行不变。

完整索引同步、正式请求装配、公共 API 和生产数据库仍未验收。原 task 继续暂停，R3/M1 不因这次补缺自动标记完成。
