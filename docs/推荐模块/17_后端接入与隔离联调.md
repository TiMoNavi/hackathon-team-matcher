# 后端接入与隔离联调

> 2026-11-12。用户授权由一个子 agent 谨慎接入，随后由另一位独立 agent 在隔离主程序后端建立虚构数据验收。接入实现、主代理离线回归及隔离 HTTP/MySQL 验收已完成；生产所需完整申请历史、平台预算及共享异步任务仍未接齐，不代表生产服务已经开放。

## 执行顺序

1. 单一实施 agent 核对真实依赖，补推荐自有存储迁移、持久业务开关、提供者版本、额度账本与装配。
2. 主代理核对 HTTP 合同及插件边界，再接入默认关闭的插件会话扩展；不能借管理员开关跳过授权。
3. 完成离线回归后，主代理判断是否开启独立主程序联调，使用专用隔离数据库、端口和虚构数据。
4. 复查来源撤权、当前活动、owner、CSRF、幂等/版本、预算、插件移除及无 AI 普通发现，记录成功与阻塞。

## 范围与真实依赖

代码默认只写两个推荐插件，文档只写本目录。HumHub 核心及其他插件只读；不读取 .local、不使用真实模型、不修改共享预览库或 worker、不提交 Git。后续整机验收如需启动服务和写数据，只允许专用隔离目标，先明确目标再执行。

继续按 [architecture-patterns](../../.agents/skills/architecture-patterns/SKILL.md) 区分纯业务端口与框架/数据库/HTTP/模型适配器。推荐不接管画像、隐私、好友申请事实或画像专用任务仓储。

当前核查确认原生 Friendship 只提供现存关系，取消/拒绝后可能删除记录，不能还原完整发出申请历史。其他插件的 ProfileAiJob 是画像专用任务，不等于平台统一 AIJob。两项能力缺失时必须明确拒绝对应 AI 请求，不把没有记录解释为从未申请，不通过测试替身或管理员特权开放真实推荐。

## HTTP 合同处理

共享契约中的 recommendation-runs 使用异步 202/job_id。本轮不以同步 ConversationService 伪造该协议，不新增虚假任务 ID，也不占用已有社交 /conversations 路径。

本 HumHub 插件提供独立的 recommendation-conversations 扩展，默认业务开关关闭，只有所有要求的依赖通过可信装配后才允许执行。下列合同已实现并经真实 HTTP 隔离验证。这是插件接入扩展，不修改全项目 FastAPI 目标方案，也不宣称共享 run/AIJob 接口已实施；以后统一产品 API 时需明确协调。

所有路径以 /api/v1 为前缀，使用普通登录会话、写请求 CSRF、服务端当前活动、本人资源和 private/no-store。客户端不能指定 viewer、权限、内部来源或模型凭据；所有额外 query/body 字段拒绝。

| 方法与路径 | 请求与行为 | 响应 |
|---|---|---|
| POST /events/{event_id}/recommendation-conversations | 空对象 body，Idempotency-Key；校验当前活动与依赖，幂等创建空会话，0 次模型 | 201，data 为会话视图，无 job_id |
| GET /recommendation-conversations/{id} | 本人会话，重验活动、开关/提供者版本和所有来源；不重算 | 200，当前视图，0 次模型 |
| POST /recommendation-conversations/{id}/turns | expected_version、message、command=chat/recommend/refresh，Idempotency-Key | 200，同步处理后的视图；必须检查 execution_status、interaction_status 和 error，终态 failed 不表示推荐成功 |
| POST /recommendation-conversations/{id}/requirements/confirm | expected_version、requirements_version、confirmation_intent=replace_complete_requirements、message、command=recommend/refresh、conditions，Idempotency-Key | 200，可信确认完整条件快照后同步处理 |

conditions 中每项只接受 feature/operator/value/strength（hard 或 soft），客户端传 origin 等字段拒绝；仅确认适配器在真实用户请求通过版本、CSRF 和本人校验后生成 user_confirmed。完整快照的空数组表示明确撤回全部条件，部分更新不能直接当完整替换。文本“确认”或模型输出不调用这个确认入口。

响应沿用 data/meta 信封；会话视图包含 conversation_id、version、event_id、requirements_version、pending_confirmation、当前批次、turns、状态及用量，当前授权有效时可提供 confirmed_conditions 供用户完整修改。HTTP 不返回授权指纹、来源映射、幂等摘要或模型 permit_id；工具开始/结束事件与真实计数可保留。

输入、版本、幂等和额度错误沿用 INVALID_REQUEST、VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、AI_BUDGET_EXCEEDED、AI_SERVICE_ERROR；本插件依赖未就绪用 503 AI_UNAVAILABLE，并给受限 reason（如 disabled、history_unavailable、platform_budget_unavailable、provider_unconfigured、policy_unavailable、storage_unavailable）。不泄露底层 SQL、连接配置、异常链或凭据。

推荐自有持久额度只是额外上限，不能替代 host 的平台预算。生产装配必须显式提供平台预算和权威申请历史；测试注入须仅在隔离测试配置，并单独标记其验证范围。持久提供者 revision 与进程内注册 generation 分开，在读取与在途执行前后检查，不把简单重新 attach 认作跨请求授权版本。

## 已落地的接入代码

主插件版本为 0.3.0，AI 子插件为 0.2.0；AI 子插件最低主版本同步为 0.3.0，因为新的 ConversationProviderSource 端口是必要依赖。主插件仍不要求安装 AI。

- NativeConversationFactory 按请求惰性装配真实当前活动、P1 字段目录、P8 授权投影、已发布策略、SQL 索引/召回及原生当前关系。缺策略不回退到测试策略。
- HistoryBackedContactEligibilityReader 仅从宿主取发出申请历史，好友、屏蔽及当前 pending 仍使用 NativeContactEligibilityReader；注入历史不能覆盖原生当前关系。
- m261112_000002_conversation_runtime 显式建立推荐自有 conversation、runtime、quota、attempt 四张表。默认 disabled、额度为 0；构造服务不自动建表。迁移 down 返回 false，避免回滚重置会话和额度，破坏性删除须另行处理。
- PdoConversationRuntime 保存运行修订号、业务开关及提供者配置版本；暂停/恢复都会变更修订号。ConversationService 在请求及模型调用前后复核，旧会话不会因重新开启复活。
- PdoRecommendationBudget 原子预留推荐子域额度，再调用必需的宿主预算。宿主拒绝或进程中断时保守保留本地预留，不自动退款、重试或放通；额度不是费用账单或跨产品平台余额。
- 模块 disable 先暂停对话并递增版本，再走原生注销，保留推荐数据和迁移；尚无 runtime 表的旧安装可以禁用，真实数据库故障不伪装成“未安装”。保留原生代码移除策略，没有额外禁止卸载的管理框架。

可信部署代码每请求注入宿主能力并配置 AI 提供者；不从 HTTP 接收这些对象、配置或凭据。主插件 setConversationDependencies(history, platformBudget) 与 AI configureConversationGateway(config, revision) 是宿主装配入口。测试可使用 configureConversationProvider(fake, revision)，但只能在专用测试 bootstrap。任何网关配置都由 AI 叶子包持有，不进入推荐内核。

部署时先正常安装/升级模块，再经 PolicyLifecycle 验证、回放、发布符合真实目录的策略，配置累计推荐额度，最后显式开启 runtime。getConversationRuntime 支持不含 Web session 的可信 console 部署；开启开关不等于授权依赖已经就绪。没有新增公开管理员配置端点。

## 验收记录

整机验收按以下场景执行，实际结果及环境限制见 [18 隔离后端接入验收](18_隔离后端接入验收.md)：

| 场景 | 要验证的结果 |
|---|---|
| 默认关闭 / 权威历史或平台预算未装配 | 明确 503、0 次模型，不生成成功推荐 |
| 普通登录与 CSRF | 匿名拒绝；缺失 CSRF 拒绝；普通用户可使用获准入口，不需要管理员特权 |
| 当前活动与本人资源 | 跨活动、非成员、其他 owner、路径/query 注入均拒绝，不能跨活动补人 |
| 幂等与版本 | 重复创建/提交不生成重复会话或模型调用，复用 key 改内容冲突；过时会话/需求版本不能确认 |
| 真实 P1/P8 最小投影 | 只有 confirmed/authenticated 且本活动合法候选进入检索；不用演示合成经历字段 |
| 持久状态与撤权 | 跨请求恢复；未入选人来源撤权也使正文失效；回应与历史不能继续携带原事实 |
| 预算与运行版本 | MySQL 原子扣减不超限，宿主拒绝不可变成成功；暂停/替换前后旧会话不复活 |
| 无 AI 与迁移 | AI 禁用后普通发现仍可用；重复迁移不重置对话、配置和已用额度；未迁移旧版本可正常禁用 |

测试替身如确有必要，仅由独立测试 bootstrap 注入三个尚未接齐的边界：模型、权威申请历史、平台预算。原生用户/活动/好友/屏蔽以及 P1/P8 投影仍走真实主程序代码。该成功路径验证“接入机制与真实资料链”，不证明替身所代表的生产能力已经存在。

### 独立整机实际结果

[18 验收报告](18_隔离后端接入验收.md) 记录 PHP 8.5.12、MySQL 9.7.4、HumHub 1.19.4 下的 28 个虚构普通账户与 2 个活动。真实 HTTP 55/55、MySQL 并发与迁移 9/9、追加生命周期 25/25，共 89 个检查条目通过；其中含重复准备步骤，不是 89 个互不重复业务场景。本轮没有验证 MySQL 8，也不把隔离库成功当成现有生产数据迁移通过。

真实登录、CSRF、活动与 owner、P1/P8、原生好友/屏蔽和 SQL 存储使用主程序实现；模型、完整发出申请历史及跨功能平台预算仅由测试 bootstrap 提供。20 个进程争 7 次额度，恰 7 个成功、13 个拒绝。模型前后撤权、未入选人正文来源撤权、暂停/恢复、AI 禁用及重复迁移均通过。默认 disabled 和缺权威历史时明确拒绝，禁用 AI 后普通发现仍为 0 次模型。

合成 provider 实际调用 11 次（plan 6、respond 5），真实外网模型为 0。model_calls_used 是保守计入的尝试数；预算预留后、provider 执行前撤权时可高于实际调用数，不能当供应商出站计数或费用账单。

[清理记录](sources/backend-host-cleanup_2026-11-12.json) 确认专用 HTTP 已停止，测试库、DB 账户、随机凭据配置和 session 已删除。保留可复现测试脚本与脱敏证据；未改共享预览库或现有 worker。

完整终态发出申请历史、平台统一持久预算、共享 recommendation-runs/AIJob/队列仍待接通；真实模型理由语义、前端确认流程及生产性能仍未验收。独立测试没有发现需要修改生产插件源码的问题，也没有因此勾选完整 M1/M2/R6/R7。
