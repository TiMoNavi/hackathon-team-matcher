## 2. 当前允许的模块内实现

原生活动适配必须把请求 event_id 作为一致性提示，不能据此选择活动。当前认证主体、已选择 Space 和选择版本来自独立服务端来源；每次 resolve/assertCurrent 重新校验正式成员、账号、Space 状态和屏蔽。原版没有统一单调权限版本时，事实指纹只代表观察到的状态，不能替代每次授权复核。

当前关系按批量读取保留 friend、pending_in、pending_out 和 blocked。召回只查本模块自有、已获准的最小派生索引，先限制当前 Space 与原生资格，再按相关性预排和路线限额返回。真实索引来源、同步和实时撤权需要下节的批量投影；没有提供者时明确失败，不创建假数据或回退原生 Profile。

## 3. 完成人物 R3 所需的上游扩展

用户已确认本轮保持 P1、隐私及其他插件只读。下列内容是未实施的上游依赖提案，不是当前已授权的修改，不改变原版表、资料确认/编辑流程、已有公共路由或资料可见性默认值：

1. 在 P1 应用边界新增一次调用的批量读取，接收可信 actor/current Space、去重 owner IDs（最多 200）和获准 source keys。内部按 owner+global/current Space 批量读状态和确认条目，不能 N+1。
2. 与隐私模块衔接批量 discovery 授权，验证当前成员、屏蔽、逐条可见性及用途，排除联系人、私有原文、草稿和未确认条目。推荐仅接收授权后的最小结果。
3. 返回 global/space 各自 revision、permission_version、当前 schema/privacy policy 版本及独立 identity_version；不可访问对象省略，依赖故障抛出，不能把故障伪装为无人。
4. 补充纯合成、隔离数据库的批量与撤权测试；原有单人服务行为保持兼容。不能把新增方法签名或 fake 实现当成实际批量能力已经完成。

本轮没有实施这一提案，没有通过循环单人服务或直接读 P1 表绕过边界。即使以后人物批量能力补齐，真实想法适配仍是独立 M1-I 交付，不能用人物验收勾选 R3.9。

字段来源许可按稳定语义键、作用域、基数及完整 schema 核对。global role/skill 是能力，event_role/event_contribution 才是本活动的声明贡献；人格仅参与本人明确偏好。新字段、未审阅 schema 或来源语义变化默认不获许可；缺少未绑定的旧字段不影响其余目录，不要求用户填写 about/title 等原生列。

`assertBindings()` 用于严格的策略发布/装配校验，不能被未来 reader 当成忽略字段变化的依据。运行时须结合 `sourceGrants()` 与 `bindingIssues()` 撤销受影响的特征，再按既有规则记录未知；真实 reader 尚未接通，本轮未声称完成此链路。

`YiiSessionSelectionSource` 只读 `matcher-recommendation.current-space`，包含 actor_id、space_id、selection_revision；与当前认证账号比对。缺少该会话状态就拒绝，不从请求参数、cguid 或可访问的公开 Space 推断当前选择。请求中的活动 ID 只是比对条件。

原生授权查询拒绝调用方已开启的事务，因为主库和禁缓存仍可能处于旧的 REPEATABLE READ 快照；适配器不会提交或回滚调用方事务。未来需要事务调用时必须提供明确的 current-read 或独立授权连接。执行期间关闭查询日志和性能记录，成功或异常后恢复原设置；数据库异常不携带可能包含查询词的原始 SQL 链。

成员/关系版本目前是当前事实指纹，不是原生单调 revision，也不能声称识别所有 ABA 历史变化。好友结果描述当前存储关系；其他插件的全局好友功能开关属于其入口政策，本轮未改变。

## 5. 召回的实际语义

测试索引只含 generation、space_id、target_id、route、feature、term。它代表已获准的最小派生词项，不存原始简历、联系人或私密资料。生产索引表和写入器尚未创建。`CandidateIndexAccess` 必须确认真实批量来源、用途许可、完整特征覆盖、当前权限版本和可用代次；DTO 本身不是授权证明。

结构化路线最多 80，全文词项路线最多 40，合并不超过策略收紧后的上限 200。SQL 在当前 Space 和原生资格范围内按本次命中词项预排，再做 LIMIT，不先截取最早注册的 200 人。软主题/贡献条件以 OR 参与召回，缺少软偏好不变成全条件 AND。

用户确认的硬 token 条件在 LIMIT 前逐条应用：相似/供需/缺口要求完整覆盖，明确偏好采用可接受值中的任一项。每条条件保持自己的来源和别名，不让一个字段的软条件满足另一个字段的硬要求。最终评分仍须读取新鲜获准投影并重验所有条件。

词项与资格行均先 DISTINCT，重复索引事实、同一字段的重复条目或重复 join 不会抬高召回分。合并路线采用既有 RRF；候选粗排分继续由 R2 评估器计算。

当前索引只支持显式、精确的词项，不宣称已接 MySQL FULLTEXT、文本分词器或语义模型。硬 interval 缺少获准时段索引时明确报依赖不可用；同一逻辑特征在不同规则采用不同 alias 映射也明确拒绝，不能靠模糊索引产生假空结果。语义路线未提供者时明确失败，不悄悄替代成其他路线。

主代理在子 agent 完成后统一执行稳定源码，新增三套检查共 230 项通过，加上 R0–R2 回归，合计 671 项通过。76 个 PHP 文件语法检查通过，48 个纯层文件依赖检查通过；R2 已有 62 个模块文件均保持原散列，本轮新增 15 个文件。

|---|---|---|
| tests/native_access/run.php | 103 | 真实原生常量与 Yii SQL，新建 SQLite 内存表；包含日志、事务、撤权、关系方向 |
| tests/profile_adapter/run.php | 69 | 真实 P1 FieldCatalog 元数据，字段用途许可及不兼容变化 |
| tests/retrieval/run.php | 58 | 真实 Yii SQL，合成词项/成员数据与测试索引授权闸门 |

关系读取 1、30、200 人均为 3 次 SELECT，活动解析为 1 次。召回测试规模 30、35、40、300、400 人均为 4 次 SELECT（两次当前访问复核和两条路线查询）。300/400 人的合成例返回 119 个去重候选，结构化 80、全文 40，两路重合 1 人；这仅是该合成例结果，不是线上推荐数量或性能承诺。

完整实际命令、断言、查询次数与源码散列见 [R3 测试记录](sources/r3-test-results_2026-11-11.json)。新测试可从项目根目录复跑：

```sh

rec_module=backend/protected/modules/matcher-recommendation
for rec_test in tests/native_access/run.php tests/profile_adapter/run.php tests/retrieval/run.php; do
```

独立审查用相同的 SQLite 反例确认修复了两项问题：重复索引词抬高排名、先截断再过滤硬条件造成真实合格者漏召回。尚未支持的时段/别名能力现在明确拒绝，不用文档中的免责声明掩盖成功空结果。没有访问现有数据库、真实画像或模型，也没有完成 MySQL 集成、生产性能或推荐质量验收。
