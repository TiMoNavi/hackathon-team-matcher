# R3 批次重放与 R4 持久化

> 2026-11-11。用户要求继续按 task 推进并使用子 agent。本轮完成推荐自有策略/批次存储、人物固定批次重放及请求索引生命周期；R3.7 仅按已接通的人物规则与固定批次路径勾选。完整 R3、R4 和 M1 尚未完成。

> 后续记录：用户随后要求优先内部 AI，已实施的可选扩展与真实合成验证见 [12 R6](12_R6可选AI子插件与内部验证.md)。本文描述上一轮规则存储交付；“没有 AI 调用”仅指该轮。

## 1. 范围与分工

沿用项目 architecture-patterns 的领域、应用、适配器边界。一个子 agent 负责持久存储，一个负责批次重放和签名 cursor，第三个独立审查；主代理完成索引生命周期、真实适配器装配、跨请求集成测试及文档。

代码限推荐模块，P1/P8 和 HumHub 原版只读，文档限本目录。不读取凭据、连接现有数据库、启用模块或运行现有库迁移；测试只用新 SQLite 内存库及合成资料。没有公共路由、后台调度或 AI 调用。

最新身份接口重新核对后仍不具备获准批量展示值：P1/P8 的批量结果包含 identity_version，但不包含 nickname/avatar_ref；相关来源白名单也不接受它们。单人身份读或本人编辑接口不能代替批量发现授权。本轮保留 R3.1，不循环单人读取，也不从原版姓名或头像补齐。

## 2. 持久化与策略版本

[RecommendationStorageSchema](../../backend/protected/modules/matcher-recommendation/adapters/persistence/RecommendationStorageSchema.php) 与迁移 000003 管理四张推荐自有表：policy_draft、policy_published、policy_active、discovery_batch，实际表名均有 matcher_recommendation_ 前缀。安装只创建空 active 槽，不预置或启用生产策略。

- [SqlPolicyRevisionStore](../../backend/protected/modules/matcher-recommendation/adapters/persistence/SqlPolicyRevisionStore.php) 提供草稿 revision CAS、发布事务、嵌套 savepoint、不可复用的历史版本；失败不留下半次发布。
- [PublishedPolicyStore](../../backend/protected/modules/matcher-recommendation/adapters/persistence/PublishedPolicyStore.php) 只读明确发布的策略，前后重验活动，未发布即明确失败。
- [SqlDiscoveryBatchStore](../../backend/protected/modules/matcher-recommendation/adapters/persistence/SqlDiscoveryBatchStore.php) 保存有序 IDs、上下文/投影/关系/策略绑定和时间；最多 200 人、15 分钟，不保存画像值、查询原文或模型摘要。
- [TypedJsonCodec](../../backend/protected/modules/matcher-recommendation/adapters/persistence/TypedJsonCodec.php) 严格校验类型、键、容量和 JSON，保留微秒、浮点与数字键映射，不使用 PHP 对象反序列化。校验摘要用于发现损坏，不声称抵御特权数据库篡改。

原策略版本只取决于参数摘要，同内容回退会恢复旧版本。本轮改为 draft ID、revision 和参数摘要共同确定版本，并禁止重复发布历史版本。回退必须重新建草稿、校验、回放并发布，恢复相同规则也产生不同版本，旧批次不会因回退复活。

DiscoveryBatch 增加 policyFingerprint，防止仅检查策略版本而遗漏内容变化。旧构造器的 null 默认值保留兼容；新 SQL put 拒绝 null，重放也拒绝未绑定策略内容的旧批次，不把兼容读取视为升级成功。

策略管理权限与字段目录版本贯穿提交所需的外部锁或 epoch 尚未装配。SQL 原子性仅覆盖推荐拥有的数据，不能据此开放管理发布入口。

## 3. 固定批次重放

[ReadDiscoveryBatch](../../backend/protected/modules/matcher-recommendation/application/ReadDiscoveryBatch.php) 按保存的 ID 顺序读取，默认每页 24、最大 48。每页两轮重取整个有界批次的获准投影和关系，包括页外候选，再校验保存批次、策略内容/版本、服务端当前活动与绝对到期时间。资料、身份版本、关系、活动选择或策略变化导致旧批次失效；不重新召回、重新打分、补人或续期。

[HmacDiscoveryCursorCodec](../../backend/protected/modules/matcher-recommendation/adapters/cursor/HmacDiscoveryCursorCodec.php) 绑定 batch、viewer、Space、上下文、查询摘要、策略、完整批次指纹、位置及原创建/到期时间。拒绝篡改、跨上下文、非法 JSON/base64 形状及超长输入。密钥只由可信装配器显式注入，不读取配置或本地凭据；签名不是加密。

独立审查用合成密钥复现了 factory 早退异常参数携带签名器的问题。已将签名器参数标为 SensitiveParameter，并禁止对象序列化/恢复、隐藏调试表示中的密钥；主回归新增四项对应检查，独立复验通过。

[NativeRuleDiscoveryFactory](../../backend/protected/modules/matcher-recommendation/adapters/composition/NativeRuleDiscoveryFactory.php) 增加 createBatchReader，按当前请求重新绑定策略和活动，再复用 P1/P8 投影与原生关系适配。其输出是内部获准投影、关系和位置，不是已完成的昵称/头像卡片，也不捏造重放分数或理由。正式展示合同、HTTP、错误转换和全活动普通发现分页仍留后续。

这是最多 200 人的固定规则批次分页，不能冒充可遍历整个活动的普通发现；最后一页 nextCursor 为 null，重读游标可得到同一页，不自动创建下一批。两轮重验仍有有限观察窗口，不宣称跨表原子快照、长期授权 epoch 或捕获所有 ABA 历史。

## 4. 请求索引生命周期

迁移 000004 增加推荐自有 index_generation 表，保存 generation、created_at_us、expires_at_us。时间为 UTC 整数微秒；元数据与词项/时段同事务发布，不包含画像原文。

[SqlCandidateIndexAccess](../../backend/protected/modules/matcher-recommendation/adapters/index/SqlCandidateIndexAccess.php) 默认固定有效期 300 秒，可信构造可设置 1–900 秒，不自动续租。构建及最终复核都校验截止时间和精确元数据；到期或元数据变化即拒绝，时间本身不授予候选读取权限，也不允许跨请求使用 snapshot。

[SqlCandidateIndexCleanup](../../backend/protected/modules/matcher-recommendation/adapters/index/SqlCandidateIndexCleanup.php) 从可信 Clock 取得一次 cutoff，默认每次最多 100、上限 500 个已到期 generation。每个 generation 先条件删除元数据，再在同事务删除两张派生表；只有条件删除成功者才清理子行。release 与 cleanup 统一采用元数据→词项→时段锁顺序，避免交叉锁序。清理可重复，某个代次失败会回滚该代次；此前完成的代次可以保留已提交状态。

未到期有效代次不清理；已超时请求即使仍在运行也已失效，不能要求它继续读取。正常 finally 仍负责即时清理。进程被强杀留下的新代次可由到期回收处理，但本轮没有注册定时任务。

旧表里没有 generation 元数据的遗留行无法可靠判断年龄，本轮不猜测、不直接扫除。部署前仍需要停用推荐写入的维护窗口和明确清理步骤，以及 MySQL 验证。迁移 000004 的回退只移除其自有元数据表，不能把它当作完整卸载方案。
