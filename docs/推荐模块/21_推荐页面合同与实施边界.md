## 2. 当前可复用的读取接口

以下路径统一以 `/api/v1` 开头。现有成功信封为 `{data, meta:{request_id}}`。源码存在与生产装配、前端接线、正式验收是不同状态。

| 方法与路径 | 当前数据/输入 | 推荐页消费方式 |
|---|---|---|
| GET `/me` | `user_id:int`、`nickname:string|null`、`identity_version:int`、`avatar_ref:string|null` | 身份来自宿主原生会话；空昵称/头像不拿演示人物补齐 |
| GET `/me/current-event` | `space_id:int`、`selection_revision:string`、`access_version:string` | 唯一当前活动权威；URL 或页面缓存不能覆盖 |
| PUT `/me/current-event` | 恰好 `space_id` 与 `expected_revision`；首次 revision 为 null，后续用读到的值 | 必须明确切活动，重验原生成员资格；不是 `expected_version` |
| GET `/events/{spaceId}/discovery` | `target_type`、`filters`、`sort`、`limit`、`cursor` 白名单 | 普通发现，0 次模型；按签名游标前进 |
| GET `/events/{spaceId}/discovery/people/{ownerId}` | 无附加 query；返回当前合法普通卡 | 重新授权的普通卡详情，内容范围仍是 discovery |
| GET `/events/{spaceId}/profiles/{ownerId}/overview` | P8 普通详情用途的全局/本活动投影与展示选项 | 按需展开获准完整资料；不能把返回全文直接转发模型 |
| GET/PUT `/me/events/{spaceId}/discovery-settings` | PUT 为 `expected_version`、`discoverable` | 本人是否参与普通发现；关闭不等于退活动 |

依据：[P1 本人控制器](../../backend/protected/modules/matcher-user-profile/controllers/ApiController.php#L48)、[推荐路由](../../backend/protected/modules/matcher-recommendation/config.php#L14)、[当前活动与发现控制器](../../backend/protected/modules/matcher-recommendation/controllers/ApiController.php#L41)、[P8 路由](../../backend/protected/modules/matcher-profile-privacy/config.php)。

### 2.1 普通列表的精确语义

- 当前只接受 `target_type=person`；`sort=recent|relevance`，默认 recent；limit 默认 24、范围 1–48。`filters` 是 URL 参数中的 JSON 对象字符串，不能直接发送嵌套查询数组。
- 普通字段为 `direction`、`role`、`skill`、`interest`、`event_role` 的 code 数组；`event_seeking` 为 `role_codes`/`skill_codes` 数组对象；`event_availability` 为 `starts_at`/`ends_at` 区间数组，时间必须带时区。
- 同字段多值 OR、不同字段 AND。时间要求每个请求窗口被候选可用区间完整覆盖，不把部分重叠当完整满足。
- `recent` 取已确认身份/资料的更新时间，不能显示“最近活跃”。`relevance` 是筛选命中数，不能显示“匹配度 97%”。
- 返回 `space_id`、`target_type`、`sort`、`items`、`next_cursor`、`has_more`、`exhausted`、`limit`，没有总人数、页码、随机跳页或随机批次合同。
- 游标绑定本人、活动、资格、查询和获准集合快照，固定 15 分钟；条件改变须重新开始。失效不能在旧列表上继续拼接新结果。
- 普通发现可遍历合法集合，不受 AI 200→24→5 限额限制；当前原生适配器最多支持 2,000 名可发现用户，超限返回明确能力错误，不静默截断。

依据：[查询与过滤](../../backend/protected/modules/matcher-recommendation/domain/browse/OrdinaryDiscoveryQuery.php#L9)、[列表/游标用例](../../backend/protected/modules/matcher-recommendation/application/BrowsePeople.php#L13)、[原生批量适配](../../backend/protected/modules/matcher-recommendation/adapters/browse/NativeOrdinaryDiscoverySource.php#L13)。

### 2.2 普通卡、概览和模型证据不能互换

普通卡当前包含 `owner_id`、`space_id`、`display_name`、`identity_version`、`avatar_ref`、`global`、`space`、`updated_at`、`relationship`、`discovery_version`、`privacy_policy_version`。关系状态为 none/pending_out/pending_in/friend；这是读取状态，不是允许前端直接调用原生关系表的授权。

普通 discovery 卡的 `global`/`space` 最终仅包含 `revision`、`permission_version`、`attributes`；资料所属活动由卡片 `space_id` 与服务端批量上下文校验，前端不能强制要求 scope 内再出现 `scope`/`space_id`/`schema_version`/`policy_version`。依据为 [SQL 批量投影](../../backend/protected/modules/matcher-user-profile/adapters/persistence/SqlDiscoveryProfileBatchSource.php#L80)及 [P8 最终批量裁剪](../../backend/protected/modules/matcher-profile-privacy/application/DiscoveryBatchService.php#L101)。条目可含 `attribute_id`、`key`、`value`、`visibility`、`confirmation`、`last_confirmed_at`、`display_label`、`sort_order`、`schema_version`；并不存在可直接假定的独立 `attribute_version`。其中 last_confirmed_at 当前保留 P1 的 SQL UTC 字符串，不能套用 updated_at 的 ISO 格式要求。

P8 概览返回 `owner_id`、`space_id`、`global`、`space`、`school_overview`、`primary_portfolio_link`、`additional_portfolio_links`、`presentation_version`、`policy_version`；此处 scope 才保留 `scope`、`space_id`、`revision`、`permission_version`、`schema_version`、`attributes`、`field_definitions`、`policy_version`。学校/主链接根据本人引用选择；引用不可见后不自动替选。概览按 detail 用途可能允许 friends 条目，普通发现与模型推荐证据仅能使用规定的 authenticated 资料。

页面适配时应：

1. 用 `owner_id` 联结普通卡和概览，并核对同一个服务端当前活动；不能按昵称联结。
2. 只展示返回的字段和允许的切片，空条目不提示“对方隐藏了一段资料”。
3. `avatar_ref` 作为不透明媒体引用交给宿主正式解析；不当成任意 URL、路径或上传权限。
4. 普通详情里的 friends 字段可供用户合法阅读，但不塞进推荐摘要、AI 对话或其派生五维依据。
5. 普通卡和模型候选使用不同 DTO。当前原生推荐的 `id` 是规范正整数字符串，普通卡 `owner_id` 是整数；转换在适配层严格校验，不泛化为任意 ID。

依据：[普通卡构造](../../backend/protected/modules/matcher-recommendation/adapters/browse/NativeOrdinaryDiscoverySource.php#L36)、[P8 概览](../../backend/protected/modules/matcher-profile-privacy/application/ProfileOverviewService.php#L10)、[公开投影白名单](../../backend/protected/modules/matcher-profile-privacy/domain/VisibilityPolicy.php#L19)、[推荐候选 ID 边界](../../backend/protected/modules/matcher-recommendation/adapters/profile/P1CandidateProjectionReader.php#L45)。

## 3. 同步推荐会话的现有合同

推荐会话是插件专用同步扩展，不是 Messenger，不是异步 RecommendationRun/AIJob。

| 动作 | 精确输入/返回 |
|---|---|
| POST `/events/{spaceId}/recommendation-conversations` | JSON 必须为 `{}`；`Idempotency-Key`；成功 201 |
| GET `/recommendation-conversations/{id}` | 本人归属、当前活动与装配能力重验；已有对象不代表始终可展示 |
| POST `/recommendation-conversations/{id}/turns` | 恰好 `expected_version`、`message`、`command`；command 为 chat/recommend/refresh；`Idempotency-Key` |
| POST `/recommendation-conversations/{id}/requirements/confirm` | 恰好 `expected_version`、`requirements_version`、`confirmation_intent`、`message`、`command`、`conditions`；intent 必须为 replace_complete_requirements，command 为 recommend/refresh |

请求必须为 JSON 对象，总正文不超过 16 KiB。条件确认最多 16 条；每条恰好 `feature`、`operator`、`value`、`strength`，strength 为 hard/soft；由后端设置 origin=user_confirmed，不能由客户端自称授权。输入版本为正整数，Idempotency-Key 为 1–128 个允许字符；同键不同内容返回 409。确认是完整替换，不是增量 patch。

顶层公共输出白名单包含 `conversation_id`、`version`、`event_id`、`requirements_version`、`pending_confirmation`、`interaction_status`、`execution_status`、`applicability`、`model_calls_used`、`current_run_id`、`message`、`confirmed_conditions`、`items`、`events`、`turns`、`current_batch`、`error`。

- 单个 item 仅 `id`、`reason`、`gaps`、`rule_score`、`ai_rank`。没有昵称/头像、完整项目、五维数组或公开证据引用。展示资料须另从普通获准入口读取。
- current_batch 仅 `batch_id`、`display_version`、`ordered_ids`、`items`；这里的显示顺序能支持“第二位”，不能表达当前屏幕选中了谁。
- turn 公开 `turn_id`、`user_message`、`command`、`run_id`、`batch_id`、`message`、`calls_used`、`status`，以及裁剪后的 items/events/error。
- event 仅 `type`、`tool`、`stage`、`message`、`candidate_count`、`model_candidate_count`。这些是已产生事件，不构成可轮询实时进度或 SSE 的承诺。
- applicability 非 current 时，公共 items/conditions/current_batch 会清除。客户端不能用旧画像缓存补回。HTTP 200 仍要检查 execution_status、applicability 和 error。

依据：[严格输入解析](../../backend/protected/modules/matcher-recommendation/adapters/conversation/ConversationHttpInput.php#L10)、[HTTP 投影](../../backend/protected/modules/matcher-recommendation/adapters/conversation/ConversationHttpView.php#L8)、[controller 与幂等](../../backend/protected/modules/matcher-recommendation/controllers/ConversationController.php#L41)。

### 3.1 三处必须显式处理的差异

**chat 不天然等于只聊人。** 当前 `submit` 仅在已有 completed run 时将 chat 作为讨论；无完成 run 时可以进入 recommend 分支。普通浏览卡上的“问 AI”不能直接发 chat 并宣称不会检索。首版人物讨论只允许有效推荐批次；任意普通卡单人咨询需要独立用途合同。

**本人字段选择未接通。** QueryIntent 有 selectedSelfAttributeIds 概念，但当前同步会话明确拒绝非空值，HTTP 也不接收该字段。不能因为领域类型存在就让前端发 `selected_self_fields`。

**重搜不保留当前展示。** 当前 refresh 开始会清空 current_batch；没有 pending_run/last_valid_display 分离，也没有“本人当前活动最近有效会话”的公共路由。现有 ConversationStore 仅 create/load/compareAndSwap，没有最近会话查询。旧批次留存与恢复必须后端实现后才能承诺。

依据：[会话提交](../../backend/protected/modules/matcher-recommendation/application/conversation/ConversationService.php#L58)、[模型显示上下文](../../backend/protected/modules/matcher-recommendation/application/conversation/ConversationService.php#L395)、[存储端口](../../backend/protected/modules/matcher-recommendation/contracts/ports/ConversationStore.php)。

## 4. 拟新增对象的最小边界

本节全部为候选设计。字段名用于评审与离线样本，尚未进入公开 HTTP；本文不指定新路由、不分配 API 版本，也不授权前端向现有严格输入追加字段。内部准备代码可以使用更窄的数据结构，集成时须显式映射。

### 4.1 PersonPresentation

优先在前端适配层组合现有普通卡与按需概览，不先造全量“推荐人物表”。最小内容是目标/活动引用、身份显示值、可选切片、原数据版本与来源。切片数量由获准条目决定，0–多个，不固定六条。

展示切片应保留本人资料、规则整理、AI 建议的区别；项目经历与活动意愿分别呈现。任何图表或轮播只改变展示，不产生新推荐、额外 AI 或新的用户资料事实。

### 4.2 MatchAnalysis 与证据

建议五个 dimension 为 contribution、project_direction、role_complementarity、availability、collaboration。产品维度固定不意味着把某版 HumHub 字段硬编码为永远必需。

每项最小结构：`dimension`、`status`、`evidence`、`suggestion`、`questions`、`explanation_source`、`basis_version`。status 候选值 supported/partial/unknown/conflict，表示证据状态；不是人格分数、成功概率或排序权重。规则结果不调用模型，AI 仅在已有显式调用中增强表达。

证据必须区分 self/candidate，附稳定资料引用、范围和已验证版本。已有 P8 只提供资料 revision/permission_version 与 attribute_id；适配层不能伪造每条独立 version。basis_version 的生成与失效由服务端确定，不让浏览器声称证据有效。公开返回不包含内部 permit、授权 hash、存储 claim 或来源原文。

规则解释至少满足：

- 贡献能力来自能力/经历与本次需求的对应；历史使用过技术不等于愿意承担本次开发。
- 项目方向要求明确主题或可说明的迁移经验；共同爱好不能冒充完成项目能力。
- 双向互补同时看双方提供与需求；只知道一方时显示 partial/unknown，不默认“你负责 AI”。
- 时间用有时区区间比较，明确硬条件是否要求完整覆盖；缺时段为未知。
- 协作安排基于本人明确偏好；不把 MBTI、角色差异或资料更新时间当天然匹配结论。

当前 P8 discovery 白名单已包含 event_seeking 与完整 project 结构，但推荐 `P1SourcePurposePolicy` 只把 project.tech_codes 映为 capability，未提供 event_seeking 的用途 grant。增加需求/项目解释须同时审核目录、字段形状、用途与真实投影，不能把“P8 允许返回”直接当成“推荐已能解释”。

依据：[发现字段策略](../../backend/protected/modules/matcher-profile-privacy/domain/DiscoveryFieldPolicy.php#L12)、[推荐用途策略](../../backend/protected/modules/matcher-recommendation/adapters/profile/P1SourcePurposePolicy.php#L65)。

### 4.3 SelectedSelfFields

建议输入仅传本人选中的条目引用与版本，语义包含 attribute_id、global/当前活动范围、资料 revision 和用途确认；本人 ID 从原生身份取得，不接受客户端 actor。精确字段命名和传输位置由 N02 定稿。

后端验证本人归属、已确认状态、活动范围、版本及允许用途，再读取最小值。选中条目不授权整份资料、私有原文或其他活动字段；没有获准输入时可以使用本轮用户明确陈述，不能自动读取 private 内容补齐。撤回选择后，相关派生解释和后续模型历史须失效。

### 4.4 TurnContext

候选内容为 current-event 选择引用、conversation expected_version、batch_id、display_version、focus_target_ids 及可选 focus_item_refs。单人讨论默认一个，比较最多两个同批次对象；项目引用对应稳定条目和资料版本，不能拿标题当 ID。

发送时冻结焦点，纳入幂等摘要、持久 turn 和返回上下文。服务端验证活动、批次、人物、项目归属、版本与用途，不接受客户端提供“可信画像正文”。用户发送后切卡，回复仍绑定发送时对象。未选中对象、池外对象、过期资料与不匹配版本都拒绝。

新字段须按明确版本扩展 controller、解析、用例、持久化和 public view；不能只改前端类型或仅传给模型。旧客户端没有 focus 时保留既有语义，但不得显示“已绑定当前人物”。旧历史缺焦点时标为未指定对象，不反向补造。错误码是否新增由共享契约写者统一，本文不自立一套。

### 4.5 PageResume 与展示保留

候选恢复对象只含本人/当前活动的会话和批次引用、必要状态；通过既有 GET 或拟补的窄查找用例重新授权。浏览器可以保留 UI 位置或对象 ID，但不能把 localStorage 里的旧资料作为当前权威。

后端需要区分 pending_run 与 last_valid_display，并覆盖：刷新处理中、成功非空、成功空结果、服务失败、撤权、超时结果未知。保留旧显示只在重新授权成功时成立，明确标“上次结果”；新空结果不能用旧人填充。切活动或撤权优先清除派生资料。

同步首版只显示真实“处理中”。最近会话查询、跨刷新恢复、持久异步进度与取消是不同能力；不能因 SQL 有快照就承诺离开后一定继续，也不能把断网视为取消或自动新建 run 重试。

## 5. 错误与前端状态对照

当前模块 code 命名存在差异，客户端归类用于交互，保留原始 code/request_id 供排障；不在前端声称后端已经统一。`details` 可能是对象或空数组，非 JSON/网络失败也必须处理。

| 真实情况 | 现有响应示例 | 页面动作 |
|---|---|---|
| 未登录 | 普通 401 AUTHENTICATION_REQUIRED；会话 401 AUTH_REQUIRED | 清身份/活动投影，走宿主登录 |
| 没有当前活动 | 409 CURRENT_EVENT_REQUIRED | 提供合法活动选择；不能误判未登录 |
| 活动切换/资格改变 | CURRENT_EVENT_MISMATCH、CONTEXT_CHANGED、ACCESS_DENIED；会话 VERSION_CONFLICT/FORBIDDEN | 清旧活动数据与在途归属，重读当前活动 |
| 普通集合/游标改变 | 409 DISCOVERY_CHANGED/DISCOVERY_CURSOR_INVALID；410 DISCOVERY_CURSOR_EXPIRED | 结束旧分页，按当前条件重新读取；不接到旧数组尾部 |
| 人已不可发现 | 404 DISCOVERY_PERSON_NOT_FOUND | 移除不可用详情，不跨活动补位 |
| 参数或 CSRF 不合法 | 400 INVALID_REQUEST；普通查询可为 422 INVALID_DISCOVERY_QUERY | 保留未提交输入，明确失败，不显示保存成功 |
| 并发/幂等冲突 | 409 VERSION_CONFLICT/IDEMPOTENCY_CONFLICT | 重读状态；不修改 key 后盲重试旧动作 |
| AI 未就绪 | 503 AI_UNAVAILABLE 与 reason | 真实不可用；可由本人选择普通浏览，不假成功 |
| 预算耗尽 | 429 AI_BUDGET_EXCEEDED | 停止模型调用，不新会话重置限额 |
| 200 但执行失败/不可适用 | execution_status/error/applicability 表明失败或失效 | 按业务终态展示；不得用 HTTP 200 判推荐成功 |
| 网络中断/非 JSON | 没有可信业务终态 | 保留输入，按已有对象/幂等状态恢复，禁止自动付费重发 |

依据：[普通控制器错误](../../backend/protected/modules/matcher-recommendation/controllers/ApiController.php#L21)、[普通游标](../../backend/protected/modules/matcher-recommendation/application/BrowsePeople.php#L21)、[会话错误](../../backend/protected/modules/matcher-recommendation/controllers/ConversationController.php#L21)、[会话失败投影](../../backend/protected/modules/matcher-recommendation/adapters/conversation/ConversationHttpView.php#L26)。

## 6. 插件与依赖边界

推荐主插件保留规则、检索、活动资格、批次/会话及解释用例；AI 子插件经 provider 端口提供模型解释与排序。页面经 HTTP 适配器消费，不直接导入模型 SDK，不从浏览器调用模型网关。P1/P8 继续拥有正式字段、确认、可见性和获准投影；社交/收藏继续拥有真实关系、动作及发出历史。

`NativeConversationFactory` 已检查当前活动、功能开关、真实发出历史、持久平台预算、provider/revision、P1/P8、已发布策略与存储。缺任一项即不可用；测试允许器和无上限预算不能作为生产默认。独立规则分析不需要放开这些 AI 门槛。

现有全站合同明确 N03 不增加汇总 capabilities 端点。因此文档 20 提议的页面能力投影仍是后续候选，不在本批顺手发布；模块已安装或画像 ai-capabilities 可用也不能证明推荐 provider 可用。

实施前置仍为：N02 确认公共合同；N03/N04 提供真实同源宿主和登录；N05 提供活动边界；N06 画像合同、N08 真实申请历史满足后进入 N10；最终页面接线归 N11，真实 E2E 归 N12。不能在推荐专项自行复制认证、当前活动或社交真相。

依据：[原生会话工厂](../../backend/protected/modules/matcher-recommendation/adapters/composition/NativeConversationFactory.php#L36)、[全站依赖](../睡前全自动运行/task.md)、[N03/N10 实施约定](../睡前全自动运行/04_HumHub实施合同.md)。

## 7. 可独立执行的合同验证与验收门槛

可在本目录 `examples/` 下建立完全虚构的 JSON 样本和纯验证器，或由模块定向测试消费同一语义。本文不新增这些文件、不将样本当服务端真实返回。准备项不请求数据库、HTTP、OAuth 或模型。

| 离线验证项 | 必须证明 |
|---|---|
| 当前真实 GET 解码 | 空昵称/头像合法；ID/版本类型严格；items 0/1/2/24 个均正确；不存在的 total/analysis 不补默认假值 |
| 普通列表/概览分离 | 同 owner/活动方可拼接；普通 relevance 不变成匹配百分比；friends 内容不能进入模型输入 |
| 当前 turn 严格白名单 | 未发布 focus/selected_self_fields 必须拒绝；新增内部类型不让旧端点自动接受 |
| 页面纯状态机 | 晚到旧活动/旧请求结果不覆盖当前；条件变化清 cursor；无结果与故障分开；空数组不循环假人 |
| 五维内存用例 | 双向依据、单向未知、角色重复、部分时段、硬条件不足；没有证据不能 supported；不用 MBTI 默认矩阵 |
| 聚焦设计样本 | A 发问后切 B，仍归 A；双人比较受同批限制；标题重复不误指人；focus 纳入幂等与版本 |
| 恢复设计样本 | 新 run 失败可保留重验旧展示；撤权优先；新 0 人不复制旧结果；断网不重置预算 |
| 语义区别 | 初始 chat 可能检索的旧行为必须被识别；普通卡咨询不能借它冒充已支持 |

后续正式验收还需两名普通用户、当前活动 A/B、0/1/2/32/400 人池、真实撤权、版本/幂等冲突、同源 CSRF、移动/键盘、模型计量和有限真实语义核验。页面“可构建”、内存样本通过和历史 89 项后端隔离验收都不能替代这些结果。
