## 3. 后端：显式选择和重验

新增 7 个 PHP 文件，仅位于主推荐插件：

- [AnalyzeCooperation](../../backend/protected/modules/matcher-recommendation/application/analysis/AnalyzeCooperation.php)：内部应用用例。
- [SelectedSelfAttributes](../../backend/protected/modules/matcher-recommendation/contracts/analysis/SelectedSelfAttributes.php)、[CooperationAnalysisRequest](../../backend/protected/modules/matcher-recommendation/contracts/analysis/CooperationAnalysisRequest.php)、[CooperationAnalysisException](../../backend/protected/modules/matcher-recommendation/contracts/analysis/CooperationAnalysisException.php)：内部输入、选择引用及受控错误。
- [SelectedSelfProjectionReader](../../backend/protected/modules/matcher-recommendation/contracts/ports/SelectedSelfProjectionReader.php)：唯一新增窄端口。
- [测试入口](../../backend/protected/modules/matcher-recommendation/tests/cooperation_analysis_usecase/run.php)及[内存替身](../../backend/protected/modules/matcher-recommendation/tests/cooperation_analysis_usecase/Fixtures.php)。

复用 CurrentEventAccess、CandidateProjectionReader 和 ProfileFieldCatalog，不新建活动或画像真相。调用先解析服务端当前活动，再读取明确的一名候选及本人所选最小投影；分析后重新读取并比较完整内容、global/Space revision、permission、schema、profile policy 和 identity，最后独立重验选择与活动。已观察到的变化或依赖失败会阻止返回旧解释，不转换成全 unknown 的成功结果，也不自动重试。

本人选择只携带 ID、版本和完整引用集合，不携带资料值，也不构成同意凭证。新端口必须在权威选择服务上核验 owner、活动、用途、选择版本和引用集合。空选择只校验元数据，0 次本人资料值读取；未选引用、混合未选证据、遗漏选中项及未映射 feature 均拒绝。撤回或替换选择后，旧请求失败，合法新选择不保留被移除条目的解释。

映射和已审核目录 fingerprint 通过构造注入；首尾使用既有目录指纹算法核对。即便 schema 编号未变，目录结构预先改变后保持稳定也不能被自动批准。移除了初稿不恰当的 32 条选择限制：32 个逻辑 feature 的既有边界不等于资料条目上限，40 条引用汇入一个 feature 的正例已通过。未来 HTTP 传输仍须单独约定请求大小，当前内部 DTO 不代表公共合同。

返回结果仅说明内部端口已重验，不是权限令牌或可长期缓存的授权。受控错误不保留上游私有异常文本或异常链。前后读取只能检测读到的变化，不能提供跨领域原子事务；合法 EvidenceRef 也不能单独证明 value 确属该条目，值与引用的绑定仍由未来受审的真实适配器保证。

## 4. 前端：按事实生成可选切片

仅新增 [person-presentation.ts](../../frontend/推荐/lib/recommendation-runtime/person-presentation.ts) 和[离线验证脚本](../../frontend/推荐/scripts/verify-recommendation-presentation.mjs)。纯函数消费已解码 DiscoveryPerson 与 CurrentEvent，不访问网络，不修改原页面、路由、组件或依赖。

显式映射真实 P1 schema 2 和 P8 组合策略 `s3-2026-11-11:discovery-fields-v2` 的 19 个发现字段：

| 范围 | 获准字段 |
|---|---|
| 全局 12 项 | headline、bio、direction、interest、role、skill、seeking、project、mbti、personality、collaboration_preference、communication_preference |
| 当前活动 7 项 | event_goal、event_role、event_contribution、event_seeking、event_contact_preference、event_collaboration_mode、event_availability |

每条 attribute 至多产生一个事实切片，携带 owner、当前活动、scope、attribute_id 和相关版本。没有资料就没有切片，不填充固定六卡；资料可选，不要求用户补齐所有字段。真实 PHP 验证器接受的六类空对象 `[]`/`{}` 也生成零事实。

项目经历、长期技能、本次愿意提供和本次需要的帮助分别呈现；技术标签不会自动归入某个项目，本次意愿不会被写成经历。MBTI 和性格只标注本人自述，不推导领导能力或匹配优劣；资料更新时间不等于活跃度。9 千字介绍、换行、空格、项目年/月精度及活动时区均保留，不补日期或默默截断。

内容均为 plain_text；项目链接经过校验后仍是无交互文本，头像保持未解析引用或中性占位。未知字段/schema/策略/形状不自动全文展示；内部诊断不含原始值且不可直接展示或发送给 AI。联系方式、原文、草稿等用途不兼容字段混入时整体拒绝，避免通过不支持提示泄露它们的存在。

字段配置可变化，但新语义和 schema 须显式审查映射。当前映射只固定已审核的发现投影合同，不绑定 HumHub 原版列，不把某个原版字段设为推荐必填。后端推荐用途 policy 尚未批准的字段，不能因为前端普通发现可展示就自动用于分析。

保留一项体验取舍：项目含不安全链接时，当前实现省略整条项目切片，包括合法标题与贡献；后续可单独设计仅省略链接的降级，不将本批实现描述为已经支持该行为。

## 6. 接下来必须接齐的边界

1. SelectedSelfProjectionReader 尚无生产权威适配。需由既有画像/选择服务供给用途获准的最小投影和可撤回选择状态；不能把 P1 本人 getProfile 全量返回的 private、draft 或来源资料直接传入。

3. 五维、focus、恢复及选择输入仍是待协调的公共合同，未注册新 API。本人选择持久化、具体错误到 HTTP 的映射、投影 adapter 和生产装配均未在本批交付。
