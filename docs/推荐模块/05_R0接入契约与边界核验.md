# R0 接入契约与边界核验

> 本文保留 R0 阶段快照及当时验收结论。用户随后授权继续，R1、R2 已完成；当前模块能力与限制见 [07 R2 验收记录](07_R2规则配置与评分验收.md)。下文“未来 R1”“停在 R0”等表述描述当时范围。

> 2026-11-11。实施范围是 task.md 的 R0.1–R0.7，验收完成后停在 R0。契约代码不是已安装插件，不代表推荐 API、排序器、数据库适配器或 AI 已可用。

## 1. 本轮决定

沿用 HumHub example-basic 的原生模块装配方式：未来 R1 使用独立模块目录、module.json、config.php、Module.php、路由和事件注册。R0 只固定接口与边界，不改核心加载器，不提前安装模板。原版字段通过 P1 外层适配，推荐读取语义特征，不把原生列名或用户填写完整度设为系统硬门槛。

文档只写本目录；本轮代码只进入 `backend/protected/modules/matcher-recommendation/contracts/` 与 `tests/contracts/`。P1、HumHub核心、vendor、其他插件、运行配置和冻结稿只读。不开启模块、不开服务、不迁移、不读取真实用户资料或凭据。

## 2. P1 最新可复用能力（R0.1）

以下路径均相对 [P1 模块](../../backend/protected/modules/matcher-user-profile/Module.php)。源码正在并行开发，下面是本次读取快照，运行安装/端到端状态未由推荐任务核验。P1 的 [S2约定](../用户画像收集/07_S2实施约定.md) 优先于本目录旧 S1 描述。

| 接口 | 已有实现与调用约定 | 推荐边界 |
|---|---|---|
| `humhub\modules\matcherProfile\Module::getFieldCatalog(): array` | schema_version=2；fields/identities/relations；37类普通字段 | 读取 key、value_schema、scope、cardinality 等；native_binding 留给 P1，不流入匹配内核 |
| `Module::getProfileService(): ProfileService` | 返回框架无关应用服务，底层已装配SQL仓储和访问策略 | 同进程外层适配器调用服务，不绕 HTTP，不直接访问 P1 仓储 |
| `ProfileService::getProfile(int $actorId,int $ownerId,ProfileScope $scope,?int $currentSpaceId=null): array` | 非本人只返回confirmed/authenticated条目；本人还可能有私有项、legacy_candidates、editing_draft | 不是推荐批量接口；本人响应禁止整包送模型；候选仍需显式用途过滤 |
| `ProfileAccessPolicy::assertCanRead(...)` | NativeProfileAccessPolicy检查活跃账号、双方正式Space成员、Space enabled及双向屏蔽 | 校验传入Space不等于解析服务端当前选择；不替代推荐资格/关系政策 |
| `ProfileScope::global()/event(int $spaceId)` | global与space:id分别存储；event逻辑字段对应Space | 存储作用域不是授权证明；Calendar仅为赛程 |
| `ConfirmedIdentityReader::read(int $ownerId)` | 单项确认昵称/identity_version | 显示身份适配，不能替代候选资格 |
| `ProfileRelationReader::read(...)` | 仍只有关系摘要契约，ideas/activities适配pending | 不当作候选列表、好友历史或想法授权源 |

`getProfile()` 会开事务并读取/锁定状态；仓储还有提交后缓存投影处理。循环调用几十至几百次不能宣布批量接口已完成。推荐适配器需要批量最小投影及批量版本/重验能力；由 P1 应用边界协调提供，不能为省事直接读其表。

## 3. 字段如何接入，不把原版当硬约束（R0.2–R0.3）

实际链路固定为：P1版本化语义目录→推荐显式用途配置→经过授权的最小值→规则特征。P1负责headline映射title、bio映射about、电话号码映射mobile等存储细节，推荐不要求这些列始终存在。

| 数据 | 推荐用途决定 |
|---|---|
| interest/direction、skill、role | 可按显式配置参与主题/贡献；用户未填是未知，不阻止安装或普通发现 |
| event_goal/seeking/role/contribution等 | 只取当前Space条目；新Space为空是合法状态，不偷偷复用旧活动偏好 |
| collaboration/communication、mbti等 | 仅本人确认的偏好及本次明确需求，默认不推断人格或设置绝配规则 |
| city/时区/时段 | 本次线下或时间需求激活后比较，明确必要条件才硬过滤 |
| contact_*、二维码/资源、姓名/年龄、来源原文 | 不纳入默认匹配配置；联系方式/原文不进入候选索引、依据或模型，即使authenticated |
| 新增字段、重复条目 | 新字段默认未映射；多条同key用attribute_id区别，不压成一个值 |

原生 `visible=1` 和 P1 `confirmed+authenticated+kind=profile` 均不是完整的推荐许可。用途白名单独立于可见性，配置不能关闭活动、屏蔽、授权与模型硬上限。禁用/删除映射只影响对应特征，不要求全库用户补齐可选字段。

旧 [四字段配置实验](examples/field-mapping/config.draft.json) 只验证被显式绑定的原生字段元数据，保留历史用途，不作为运行时schema。R2再实现配置发布、类型/枚举变更和失效行为，R0不把实验脚本改造成权限引擎。

### DTO 与版本

- 查询区分系统资格、用户显式硬条件与软偏好；未知不是满足条件。QueryIntent不承载viewer、Space或SQL执行权限。R0仅验证结构，feature/operator用途白名单在R2/HTTP边界执行；origin=user_confirmed必须由可信应用根据真实用户操作标注，不能相信模型或客户端自称已经确认。
- 可信活动上下文由服务端适配器取得；DTO只装数据，构造它不会获得权限。每次读取、分页/快照重放和结果发布均重新核验。
- global和当前space:id分别保存revision、permission_version及schema/policy版本；identity_version独立。不能把两种scope的revision取max合成一个版本。
- P1 permission_version不覆盖所有成员、屏蔽、好友和历史申请变化，活动与关系需独立版本/实时检查。
- 投影EvidenceRef关联稳定attribute_id或获准想法引用、scope、内容版本与权限版本。R2评分命中再把rule_id与这些引用组合成推荐理由；R0尚未执行规则。不得把字段标题或可能重复的key当唯一证据ID。
- 候选最小数据与显示资料区分，合法空集合与依赖故障区分；不可访问的对象不向调用者泄露具体屏蔽/隐私原因。

### 端口责任

| 端口 | 实现责任与缺口 |
|---|---|
| CurrentEventAccess | 从服务端会话/业务上下文解析当前Space并重验；P1成员校验可参考，当前选择、业务活动状态及版本尚需适配 |
| ProfileFieldCatalog | P1应用目录到纯数据结构；新字段默认关闭，勿传SQL/存储模型 |
| CandidateProjectionReader | 有界人物IDs、可信上下文及用途绑定→最小获准投影；≤200，逐对象/版本检查；批量生产适配待R3 |
| ContactEligibilityReader | 普通当前关系/屏蔽与AI人物所需完整本人申请历史分开；历史不可用只阻塞AI人物，不阻塞普通规则和想法 |
| AuthorizedIdeaReader | 当前查询所引用项目/想法上下文，不代表候选集合 |
| IdeaCandidateProjectionReader | 想法候选独立批量授权/版本；不能因作者已好友/pending/曾联系就排除想法 |
| CandidateRetriever | 结构化80、全文40、可选语义80；最多200合并粗排；不读取全活动原始资料，不把200当普通分页全部成员上限 |
| QueryInterpreter / CandidateReranker | 主模块定义，后续AI包实现；模型输出不授予授权，最终仍由主模块复核 |

R0 用假实现验证合同可对接。真实投影/关系/活动能力缺失必须明确不可用，不能以原生Profile、私信成员或空结果兜底。

## 4. HTTP 和公共合同（R0.4）

选择模块 `config.php → urlManagerRules` 直接注册 `/api/v1`，与P1普通会话API模式一致。未来推荐薄控制器负责登录及enabled账号校验、写请求CSRF、参数转换、调用用例及共享响应/错误；不继承rest BaseController，不因此添加rest必需依赖，不开放管理员用户接口。R0不注册任何路由。

P1的IdempotencyGuard把记录写在画像草稿存储中，不能拿来处理推荐请求。推荐自己的收据存储或后续真正独立的公共适配器承担幂等；actor+method+route+key，规范化payload，初始24小时；重放先重验权限。

签名cursor目前未发现通用实现，留R4实现推荐适配器。内容绑定viewer、当前Space、查询哈希、排序、位置、权限版本及15分钟到期；默认24/最大48。普通发现可遍历全部合法对象；批次最多200 IDs，模型最终5个限制不影响普通分页。

错误只映射共享契约已有类别：未登录401 AUTH_REQUIRED，缺活动400 EVENT_REQUIRED，活动资格失败403 EVENT_ACCESS_DENIED，不可知对象404 NOT_FOUND，版本/幂等冲突409，cursor到期410，参数422 VALIDATION_FAILED，依赖503 DEPENDENCY_UNAVAILABLE。P1的内部PROFILE_*错误在推荐HTTP边界转换，不直接新增公共枚举；限制原因不泄露被屏蔽者。AI错误与预算后续按既有500/429约定处理。

## 5. 数据与运行基础的所有权（R0.5）

| 数据/能力 | 所有者及实施阶段 |
|---|---|
| 正式资料、草稿、身份、确认/可见性 | P1；推荐不得直写其表或复制为正式库 |
| 当前Space/成员、好友/申请/屏蔽、想法 | 各业务域；推荐窄端口只读，不能借反馈生成好友或发消息 |
| 策略版本、映射、可撤权派生索引 | 推荐主模块，R2/R3/R4；索引只保存有用途的获准投影 |
| DiscoveryBatch、曝光、推荐反馈/Action、幂等收据、cursor签名适配 | 推荐主模块，R4及R6相关路径；批次不存全画像 |
| RecommendationRun/Item与候选快照 | 推荐主模块，R6；绑定viewer/Space/输入/策略版本 |
| AIJob执行状态、统一平台预算/配额 | 统一任务/平台能力是既有设计，当前未发现可复用实现；R6依赖显式接通，不能伪装已有 |
| run内次数、问题版本、单次搜索/修复计数 | 推荐主模块，R6；与统一任务/预算协作原子扣减，不能由AI包独立重置 |
| 模型客户端、提示/协议与提供者配置 | 可选AI包，R6；不拥有正式资料或业务授权结果 |

统一任务或平台预算未交付时M2不可真实开放，但不阻塞无AI M1。需要新增公共设施时单列后续任务，不把推荐私有表冒充全平台实现，不为R0提前建立空数据库表。

## 6. 运行与原版边界（R0.6–R0.7）

本机PHP路径为 `backend/.runtime/php-mysql/bin/php`，`-n`可跳过本地php.ini，仅跑纯合同测试。已读取的项目要求为PHP≥8.2，本机版本8.5.12；没有因此把插件最低版本提高到8.5。原版安装包锁定HumHub1.19.4。MySQL客户端执行 `backend/.runtime/php-mysql/bin/mysql --no-defaults --version` 显示9.7.4；这不是服务端连接或迁移检查。P1数据库适配要求MySQL≥8.0.16且拒绝MariaDB，实际服务端版本/迁移状态留真实集成验收。

原生测试include不能保证发现protected/modules下的外部插件；推荐使用自己的 `tests/contracts/run.php`。R0不启用HumHub、不通过composer加载应用、不安装依赖。未来集成测试须使用隔离库，不能复用预览库执行破坏性准备。

example-basic提供的是装配参考，不是推荐引擎。后续按其机制自建模块，不把示例控制器/设置表单当算法或权限服务，不复制默认字符串safe规则。固定提交及文件核验见 [03调研](03_GitHub参考后端调研.md)、[R0上游来源](sources/r0-example-basic-source-check_2026-11-11.json)。已重新读取7个关键源码/文档文件；许可入口是docs/LICENCE.md，其内容指向HumHub许可说明，不能据此推断全部文件均可任意再分发。本轮没有复制上游实现代码。HumHub原生disable进入卸载/设置清理流程，业务暂停必须是独立开关，留R7验证。

本轮开始前已对HumHub核心与vendor建立文件树散列基线，并对模块.gitignore、原生字段快照及冻结稿留存散列。结束时复核同一范围；这只能说明本轮前后该范围未变，不能推断整个工作区无人修改。P1正在并行建设，不回滚别人的改动。

记录见 [原版基线](sources/r0-native-baseline_2026-11-11.json)、[P1及运行接口快照](sources/r0-interface-snapshot_2026-11-11.json)。R0不修改现有modules/.gitignore；新目录的提交白名单由R1补充，不能仅靠git diff看不到文件就断言没有新增契约。
