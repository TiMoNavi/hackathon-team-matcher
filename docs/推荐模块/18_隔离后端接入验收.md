## 隔离与数据

- 环境：PHP 8.5.12、MySQL 9.7.4、HumHub 1.19.4。
- 唯一数据库 `humhub_recommendation_it_audit_20261112_7f2c9a`，独立随机密码测试账户仅授权该库。根凭据文件仅由 MySQL 客户端通过 `--defaults-extra-file` 使用，未读取、显示或复制内容。
- 唯一 HTTP 监听 `127.0.0.1:8112`，启动前验证空闲。未使用共享预览入口，未操作既有 worker。
- 从空库执行原生迁移、InitialData bootstrap、四模块原生启用与迁移；没有克隆共享 schema、用户或画像。
- 测试入口只加载原生 common/web/console 与隔离覆盖，不加载生产 `.env`、dynamic 配置或 `.local/`。数据库名、账户、socket、HTTP 目标、权限在任何 Yii/DB 初始化前验证，无主库 fallback。
- runtime/session/uploads/assets/themes/mail/cache/module discovery 均指向专用目录（0700），随机凭据配置 0600。邮件为文件传输；隔离库自然产生的 3 条 queue 记录未被消费，清理时随库删除。
- 只写 [tests/conversation_host](../../backend/protected/modules/matcher-recommendation/tests/conversation_host/)、本报告和 `sources/backend-host-*`。HumHub 原版、其他插件、冻结原稿未由本验收者修改。

建立 **28 个虚构普通 User、2 个 Space**，全局管理员组成员数为 0。HTTP 经原生用户名→密码双步登录，访问原生 `/admin` 为 403，没有使用 setIdentity 代替登录。

画像经 P1 公开 startDraft→updateDraft→confirmDraft 写入，昵称经 IdentityService 确认；使用真实 interest、skill、event_role，未引入 synthetic_project_experience。样本包含 authenticated、private、friends、草稿、其他活动、当前好友与屏蔽。会员创建复用原生 Space 已有创建者会员，避免重复。

NativeConversationFactory、当前活动、原生好友/屏蔽、P1CandidateProjectionReader、P8 DiscoveryBatchService 全部执行真实主程序代码。默认原生缺完整历史确实返回 503 history_unavailable，不能把没有历史记录解释为从未发出申请。

成功路径仅在测试 bootstrap 注入：无网络 deterministic provider、该批虚构账号的完整 synthetic sent history、明确允许/拒绝的 synthetic platform budget。history.readCurrent 主动抛错，真实当前关系始终走 NativeContactEligibilityReader。策略治理/重放另用明确测试端口，字段目录仍真实校验，经 PolicyLifecycle createDraft→validate→replay→publish 发布，没有直接填 ACTIVE。

## 真实验证

| 边界 | 观察结果 |
|---|---|
| 默认关闭与依赖 | 新迁移 runtime disabled、额度 0；关闭和 native history 不足均 503、0 次 provider |
| 普通登录与 CSRF | 匿名 401、普通用户可达；缺 CSRF 400；真实 session PUT 选择活动 |
| 活动/owner/输入 | 同时加入 A/B 也不能从 A 请求 B；非成员拒绝；其他 owner GET 404；额外 query/body viewer 和客户端 origin 拒绝 |
| 完整发送池 | 检查全部实际发送 ID，不仅最后卡片；排除本人、好友、曾发申请、private/friends/草稿匹配字段、屏蔽和其他活动 |
| 持久与幂等 | 跨请求恢复；create/turn/confirm 重复 key 不重复模型；改内容冲突；过时会话/需求版本拒绝 |
| 可信确认 | 显式完整快照成功；用户不能伪造 origin，公开视图不泄漏内部指纹 |
| 未入选正文撤权 | provider 正文实际提及未入选发送人的共同兴趣；P1 撤权后 GET 或不先 GET 的直接 submit 都清除来源 marker、历史和候选，0 次新增 provider |
| 模型前后授权 | respond 预留后撤权仅 plan 真正进入 provider；respond 内撤权阻止发布 |
| 宿主拒绝 | failed turn 明确 AI_BUDGET_EXCEEDED、0 模型，本地预留保守保留，无自动重试/降级 |
| MySQL 原子扣减 | 20 独立 PHP 进程争 7 额度：恰 7 成功、13 拒绝；reserved/ledger 均增加 7，重复 permit 不二次扣 |
| 生命周期 | pause/resume、AI 原生 disable/enable、切活动切回均不复活旧会话；模型内 pause 不发布晚到结果、不重试 |
| 无 AI | 禁用 AI 后普通发现 200、0 次 provider |
| 重复迁移 | 原生 migrate/up 无新增；conversation、runtime revision、预算、ledger、migration 计数保持 |

HTTP 同步 recommendation-conversations 是插件扩展，未伪造共享异步协议 job_id。

### 计量口径

respond 额度预留后、真正进入 provider 前撤权的场景中，provider 仅 plan 调用 1 次，而 HTTP model_calls_used=2。该字段是内核保守计入的尝试数，不能直接当供应商实际出站次数；本地额度也保留已预留量。没有导致越权或超预算。报告的 11 次按 provider 日志计，真实供应商 0；若要求精确出站计量，需协调字段命名及计入时点。

## 失败保留

| 记录/现象 | 修正与归属 |
|---|---|
| 初始 PHP/迁移配置失败 | 测试环境补显式 mysqlnd/pdo_mysql/gd 扩展、原生 migration 所需禁用 DbTarget、原生 SqlMode afterOpen、隔离 themes 与四模块发现目录；未改原版迁移 |
| event_role 校验失败 | fixture 的 codes 改成真实 code/label，仍经 P1 公开服务确认 |
| [控制读取失败](sources/backend-host-http_58d56b64.json) | helper 在 disabled 下调用 runtime.identity；status 改纯只读 quota 查询 |
| [登录失败](sources/backend-host-http_b0c9cd44.json)、[复现](sources/backend-host-http_5737a577.json) | 专用 router 的 SCRIPT_NAME/FILENAME 未归一，原生 GateManager 无法解析新 Request；只修测试 bootstrap |
| [活动选择失败](sources/backend-host-http_ec0d1026.json) | fixture 在原生 Space 自动会员之外又插入创建者，真实授权正确 fail closed；精确删除本次两条重复会员，seed 增加已存在检查 |
| 测试设计复核 | plan origin 改为协议的 interpreted_draft；来源撤权断言允许无事实通用错误提示但禁止来源 marker；history 通过 fixture IDs 关联，不依赖自增起点 |

最终 55 项成功文件没有覆盖失败文件。追加 MySQL 与生命周期一次通过。测试脚本编写期语法修正不算生产业务失败或实现修复。
