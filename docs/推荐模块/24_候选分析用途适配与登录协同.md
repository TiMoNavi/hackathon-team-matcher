## 3. GitHub 登录与画像的衔接

仓库已经存在 matcher-auth 的原生 GitHub provider 适配、账户绑定及首次导入协调器，本批先检查并复用。首次注册或明确绑定动作才可登记一次本人公开来源导入；普通再次登录、回调重放、刷新页面不重新抓取或重跑画像。导入失败不撤销已完成的登录，未确认资料不自动公开。

优先复用画像已有来源列表和 progress 读取。若首次登记尚无来源、失败或撤销状态确实无法由既有接口表达，再登记最小的本人只读状态出口；没有合同不先挂路由。状态读取不触发抓取、自动重试或模型，读取成功不等于画像生成完成。真实 OAuth 仍需本人操作，不能把本地替身测试称为已真实登录。

## 4. 验证与交接

### 4.1 本人选择与候选用途

- P1 新增 `SelectedSelfProfileReader`，`read` 必须给出明确 attribute IDs，`[]` 只返回版本元数据，SQL 不读取 attribute 值。独立 `options` 用例给本人挑选适用条目；选项出现不代表已经同意分析。只接受本人、confirmed、authenticated、获准用途及 global/当前 Space 的交集。没有读取全量 `getProfile`、private、draft、原始简历或联系人。见[画像侧增量记录](../用户画像收集/42_推荐本人选择窄读取增量.md)。
- 推荐自有 `matcher_recommendation_self_selection` 仅保存引用、版本及会话/context 哈希，不复制画像值或原始 session。GET 不写库；PUT 使用条件更新。版本在同 actor/session 跨活动单调递增，切活动不 DELETE/归零；失效写保留版本墓碑，防止 A→B→A 或旧 version=0 恢复旧选择。只承诺当前会话，不表示跨设备同步。
- 候选分析复用真实 P8 批量授权，并与原排名用途分离。已审查十种用途：方向、声明技能、项目明确技术栈、愿意提供的技能/角色、需要的技能/角色、时段、协作方式和沟通偏好。`project.tech_codes` 仅表示能力依据，不能重绑为愿意提供或需要；项目自由文本、兴趣、性格、活动目标不自动解释为项目方向或人格匹配。
- 37 字段目录的审核指纹固定为 `75fc32de2dae088716251675a1e2b5f6584cea2475e78b5c1da37e55ded06434`，映射版本 `p1-cooperation-page-v1`。目录或 shape 变化须重新审查，不由实时目录自行签发授权。字段仍是可选；缺项显示 unknown，不当必填条件。超出已有内核预算的候选 feature 整体 unknown；无法完整表达的本人明确选择拒绝处理，不偷偷截断或补零。

### 4.2 公共接口与页面

精确输入、错误与 DTO 已登记[共享契约 9.6](../共享数据与接口契约.md)及[HumHub 实施合同第 10 节](../睡前全自动运行/04_HumHub实施合同.md)。

| 接口 | 用途 | 副作用 |
|---|---|---|
| GET `/api/v1/events/{spaceId}/recommendation-analysis/self-selection` | 当前选择版本、已选 IDs、本人获准选项 | 只读，无模型 |
| PUT 同一路径 | 显式保存本人选择，可明确保存 `[]` | 仅推荐自有选择表；CSRF、版本和当前活动前置校验 |
| POST `/api/v1/events/{spaceId}/recommendation-analysis/people/{ownerId}` | 对当前可见人物生成五维规则依据 | 不写资料或关系，不调用模型 |

PUT/POST 都携带服务端发放的 `expected_current_event`（selection_revision、access_version）；只给 spaceId 不足以识别切走再切回。POST 还绑定本人选择版本、候选资料/身份/发现/隐私版本。装配在分析前后复核可发现性、本人选择与当前上下文。输入限 JSON 对象及 16 KiB，拒绝未知字段/query；失败不自动重试。

结果区分贡献能力、项目方向、角色互补、投入时间、协作安排，状态为 supported/partial/unknown/conflict，附获准事实与待确认项。`explanation_source=rules`，`hard_conditions_checked=false`；不输出总匹配分、人格概率或硬资格结论。此处展示规则依据，不改变既有排名。

页面使用宿主真实身份和当前活动，复用原普通发现 GET、动态人数、资料切片和签名 cursor，不补满六张卡或跨活动找人。用户主动打开本人选择器、保存后再点击分析；未保存和空选择状态分别呈现。切活动、退出及观察到撤权时清除旧投影。AI、收藏、社交动作未接入时明确提示，不能显示假成功。

### 4.3 审核中修复的缺陷

1. **选择版本复用与写后失效**：旧实现跨 context 重置会产生 ABA 竞争；改为跨 context 单调版本及条件墓碑。GET 不删除状态，旧写不能覆盖新版。
2. **GitHub 状态读取期间解绑**：旧实现可能仍返回 succeeded/source_id。现在两次紧凑来源验证，并在各次读取后复核当前本人、最新绑定、回执及模块；失效返回 revoked/unavailable 且隐藏引用。多个域的前后检查不等于跨域原子事务。
3. **分析迟到撤权被刷新忽略**：刷新列表的 query epoch 不能压掉同 controller 的已观察到 401/403 等权威失效。当前实例保守清除，已 dispose 的旧活动实例不影响新实例。
4. **无候选时文案误报未接分析**：已有分析接口时显示“先选择一位可见伙伴，再查看合作依据”，AI 状态单列。
5. **依赖声明过宽**：推荐的 P8 最低版本收紧至本批实际验证的 0.2.0，避免安装器放行未验证旧接口。
