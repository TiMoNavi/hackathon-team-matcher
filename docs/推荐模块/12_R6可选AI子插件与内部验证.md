## 1. 本轮交付与插件关系

AI 是推荐插件的可选扩展。两个包仍为 HumHub 原生模块，沿用 module.json、config.php、Module.php 及依赖声明；没有另造加载器或修改 HumHub 原版。

- 主包 [matcher-recommendation](../../backend/protected/modules/matcher-recommendation/Module.php) 定义解释、重排端口，掌握活动资格、字段映射、规则、召回、预算、运行状态与结果复核。
- 子包 [matcher-recommendation-ai](../../backend/protected/modules/matcher-recommendation-ai/Module.php) 实现解释和重排，单向依赖主包 ≥0.1.0。主包不引用子包具体类，普通规则请求不构造模型客户端。
- 子包经可信装配器 setProviders/attach 显式注册，detach 移除。只加载模块不会读密钥、联网或注册假提供者。
- 本轮支持 person 的直接结构化条件与自然语言条件草案；idea、本人 attribute_id 选择及 current_idea_id 明确拒绝，不将缺能力解释为字段为空。

代码只改两个推荐模块；P1、P8、HumHub core/vendor 本轮只读。文档只写本目录。没有连接现有数据库、启用模块、部署路由或执行现有库迁移。

## 2. 后端先筛选，AI 再挑选

~~~text
结构化条件 → 一次后端检索与规则评分 → 最小候选摘要 → AI 重排 → 主包复核
自然语言 → AI 条件解释/有限澄清 → 同一后端检索链 → AI 重排 → 主包复核
~~~

[AiRecommendationService](../../backend/protected/modules/matcher-recommendation/application/ai/AiRecommendationService.php) 提供内部 startStructured、startChat、answer、get、cancel，通过明确端口衔接，不依赖 Yii、数据库或模型 SDK。

[SearchAiCandidates](../../backend/protected/modules/matcher-recommendation/application/ai/SearchAiCandidates.php) 是有界后端检索用例。服务端注入身份与当前活动，模型只提交白名单条件草案，不能设置 viewer_id、event_id、任意字段、SQL、URL 或无限 limit。每个 run 最多一次检索，修复输出不重新召回。当前采用确定性的后端编排，不开放任意工具循环。

检索先验证完整申请历史能力，再召回最多 200 个 ID，批量读取获准投影、当前关系和历史申请，排除屏蔽、已有好友、双向 pending 及 ever_sent。随后运行真实 DeterministicRuleEvaluator；通过对应规则门槛者才进入 AI 池。规则继续使用语义字段绑定，不把原版 Profile 列设为必填。

现有 [NativeContactEligibilityReader](../../backend/protected/modules/matcher-recommendation/adapters/native/NativeContactEligibilityReader.php) 的 supportsSentHistory=false。使用该适配器的 AI 人物请求在召回、资料投影和模型调用前返回 history_unavailable；测试中完整历史来自明确的合成端口。该缺口不阻止普通零模型规则发现，不能用管理员权限或全 false 历史绕过。

## 3. 最小上下文与排序理由

[MinimalCandidatePoolBuilder](../../backend/protected/modules/matcher-recommendation/domain/ai/MinimalCandidatePoolBuilder.php) 最多保留 24 个摘要，每个序列化后不超过 768 个 UTF-8 字节。只抽取本次条件涉及且有授权证据的事实；整条裁减，不截断 UTF-8，不传完整资料、原始简历或 friends/private 字段。

摘要包含 target_type、id、rule_score、facts、unknown_features、unknown_count、omitted_fact_count。e- 前缀证据别名对应特征及完整证据束，真实 EvidenceRef 映射留在主包。完整模型请求包含提示、两处输出 schema、需求与候选，最多 24 KiB；超限确定性删除尾部候选。输出只能引用实际发送的子集。

[ValidateAiRerankOutput](../../backend/protected/modules/matcher-recommendation/application/ai/ValidateAiRerankOutput.php) 只接受 0–5 个池内唯一 ID 及对应已发送证据，要求实际正向主题/贡献事实。不接纳模型自由编写的事实、人格判断或“愿意加入”断言。最终理由由已确认事实机械构造。

rule_score 与 ai_rank 分开，不相加、不冒充成功概率。合法空 items 可以成功返回，不修复、不跨活动补人。小活动可以不足五人；无合格候选不精排。自然语言空池可能已发生一次条件解释，结构化空池为零模型调用。

模型返回前后复核整个已选匹配池，含未送模型的候选，最多 200 人。权限、资料、关系、历史、活动、策略或提供者 generation 变化会使旧结果失效。测试覆盖未发送候选的撤权、注销提供者、取消及晚到结果；失败终态不会被后续返回恢复成功。

## 4. 调用额度与内部状态

| 场景 | 正常调用 | 含一次合法修复的上限 |
|---|---:|---:|
| 结构化条件 | 1 次精排 | 2 |
| 自然语言，无澄清 | 1 次解释 + 1 次精排 | 3 |
| 有澄清 | 同一 run，最多 3 轮问题 | 整个 run 最多 5 |

解释、澄清、精排共享一次修复，只修非法输出。网络、鉴权及限流失败无隐式重试；每个 permit 只允许一次传输。解释/下一问题前预留剩余必要调用，不能产生第六次“修复”。

AiPlatformBudget 必须显式注入，在模型请求前 reserveAttempt，不默认无限预算。同实例内验证 question_id、expected_version、幂等键；重复续答不重复收费，换参数复用同键拒绝。GET 不调用模型；取消、失败及重复读取保持稳定。

**这些是内部同实例能力。** InternalAiRun 最多 128 个、15 分钟，未持久化。execution_status/applicability 采用既有枚举，但不是已装配的统一 AIJob，没有跨进程 CAS、持久平台预算或队列去重。R6.5/R6.8 仍未完成，不能直接作为正式跨请求存储。

## 5. 指定网关实际验证

用户指定网关的 /v1/models 返回 HTTP 200，14 个模型 ID 中包含 gemini-3.8-flash。真实 PHP 提供者随后调用 /v1/chat/completions。此名称是网关接受的 ID，不代表独立核验背后的厂商部署。

凭据保存在权限 0600 的本地私有配置，仅主代理读取；源码、文档、测试、报告与协作消息均不含密钥。真实调用只发送虚构需求和三名合成人物的最小摘要，没有读取真实画像。

前两轮生成测试收到 HTTP 200，但输出未满足 required items 结构，严格校验正确拒绝。随后将相同 JSON schema 同时写入 system 提示与 response_format；保留严格解析，不猜键或增加隐式重试。修正后一次完整测试通过：

| 场景 | 检索次数 | 模型调用 | 结果 | 修复 |
|---|---:|---:|---|---|
| 结构化条件 | 1 | 1 | completed/current，3 个合成人选 | 未使用 |
| 自然语言 | 1 | 2 | completed/current，3 个合成人选 | 未使用 |

成功测试的请求为 3,165、9,920、3,168 字节，均小于 24 KiB。整个调试共 7 次生成请求和 1 次 models 查询；前两次本地脚本诊断为零生成。失败和成功尝试均保留于 [真实调用记录](sources/r6-gateway-live-smoke_2026-11-11.json)，没有只统计成功的三次。

网关累计报告 prompt_tokens=5,893、completion_tokens=6,265、total_tokens=12,158。早期失败尝试的 completion_tokens 曾超过请求 max_tokens=1024，因此该参数不能承诺账单硬封顶；生产仍需平台额度、用量核对和供应商限制。实际账单未独立验证。

[手动 smoke](../../backend/protected/modules/matcher-recommendation-ai/tests/live_gateway_smoke.php) 要求显式 --allow-network 和受限本地配置。实际执行 SearchAiCandidates、规则与输出复核，仅底层人物/关系/预算为合成端口。统一离线测试只 lint 此文件，不自动联网执行。记录只保留状态、数量、字节、模型 ID、数值 usage 及结构诊断，不保存提示/响应原文。

## 6. 验证与分工

三个子 agent 分别完成提供者与检索工具、候选摘要与运行回归、独立审查。主代理完成运行编排、真实网关核验、整链装配和文档。

- [统一离线结果](sources/r6-ai-extension-test-results_2026-11-11.json)：32 套共 2,514 项通过（原 1,989 + 新 525），310 个 PHP 文件语法检查、68 个纯层文件依赖扫描通过；禁用 cURL/stream 网络函数，仅内存或新 SQLite 内存库。
- 新套件：候选 58、运行 125、检索 175、提供者 105、真实应用整链 62 项。200→24→5 使用真实应用用例，只有外部端口和模型是假实现。
- [独立审查](sources/r6-ai-extension-review_2026-11-11.json) 287 项，另复验普通规则与依赖边界；与主套件重叠，不相加。
- [开工基线](sources/r6-ai-extension-baseline_2026-11-11.json) 与 [完成核验](sources/r6-ai-extension-completion-checks_2026-11-11.json) 固定源码、其他插件、原版、冻结稿和文档结果。

发现并修复过异常参数暴露、合法零选择被拒、终态 GET 改版本、失败后晚到结果恢复成功及 schema 兼容问题，均加入回归。真实合成通过证明协议和内部链可运行，不等于大样本匹配质量验证。


验收期间观察到 P1 相对开工快照新增 8 个、修改 7 个文件，包含画像专用 ProfileAiJobService。本轮未写入或回退这些并行改动；统一测试采用的当前源码在测试期间及完成核验时一致。该服务目前只接受 extract/questions/compose，不等于推荐 run、澄清和整 run 预算已经接上。P8、HumHub core/vendor、原生字段快照与冻结稿哈希保持一致，不能把这项结论扩大为 P1 整棵目录未变。
