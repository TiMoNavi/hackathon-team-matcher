# R2 规则配置与评分验收

> 本文保留 R2 阶段记录。后续推荐侧 R3 适配及尚缺依赖见 [08 R3 核验](08_R3真实适配与依赖核验.md)。

> 2026-11-11，R2.1–R2.11 已完成，M0 内核可回放。用户在 R1 验收后要求继续推进并使用子 agent。本轮完成推荐主模块中的纯规则与内存应用用例，不连接真实资料、模型或数据库，不启用模块。

## 1. 工作划分

配置子 agent 负责严格字段绑定、有限转换器及策略草稿、校验、回放、发布与回退。规则子 agent 负责五类规则、维度归并、证据与评分。主代理负责有界结果选择、空结果原因、应用整合及文档；独立审查子 agent 核对规则与原版边界。

代码只进入 `backend/protected/modules/matcher-recommendation/`，文档只进入本目录。不改 P1、HumHub 核心、vendor、共享契约、冻结原稿或其他插件；不读本地凭据。开工记录见 [R2 基线](sources/r2-native-baseline_2026-11-11.json)。

## 2. 本轮边界

本轮继续使用 person 目标和直接结构化条件。项目缺口规则只处理本次明确提供的需求集合，不推测团队成员、容量或反向意愿。`currentIdeaId` 和本人选择字段仍需后续获准解析适配器，当前不能忽略这些输入并返回成功。

配置记录稳定语义键、作用域、类型与枚举，不要求原生 `about/title/city` 列存在或用户填满资料。配置不会授予可见性；规则只消费外层已获准的最小投影，真实批量授权留 R3。

无 AI 时规则必须可运行。模型、向量检索、真实批量接口与公共 HTTP 均不在本轮；配置发布验证在内存仓储中执行，不能写成已交付管理员页面或生产持久化。

## 3. 配置与发布

`PolicyValidator` 校验一个有限的参数格式。bindings 按逻辑特征显式登记 source_key、scope、cardinality、value_schema、transform、purpose 和 semantic；rules 只接受五种固定 operator，不执行表达式、SQL 或配置里的类名。`tests/policy/Fixtures.php` 是共享合成配置，不会默认注册到 Module。

语义与评分维度固定对应。主题及已确认文本归主题维度；明确能力和本活动声明贡献归贡献维度；可用时间归时间维度；协作偏好及自述人格标签归协作维度。不能把人格字段换个 purpose 就算作贡献证据，也不能用 alias 把两个不同人格或偏好映射成“兼容”。能力字段不能供给 supply_demand 或 coverage_gain。

`ProfileProjectionMapper` 仅转换外层已经授权并按用途筛选的最小属性。confirmed、authenticated、discovery_allowed 等元数据是额外校验，不是授权凭证。映射保留 attribute_id、作用域和内容/权限版本；新字段未绑定就不参与，标题变化不影响稳定键，删除、改类型、改枚举等不兼容变化让受影响特征变为未知，不猜替代字段。原始资料与联系方式不纳入映射。

`PolicyLifecycle` 提供 createDraft、edit、validate、replay、publish、rollback，用管理权限端口与具备事务/CAS 语义的仓储端口衔接。回放实际执行注入的规则评估器，将预期资格、分数范围及理由数量与结果比较；不能传一个“已通过”布尔值代替。发布绑定草案版本、参数摘要、目录语义摘要及当前回放套件；改草案或套件后必须重新验证。回退建立新版本，重新经过当前目录校验与回放，不能复活不兼容字段。

管理 HTTP、真实管理权限、持久化仓储及跨进程并发验证留后续阶段。本轮以内存适配器验证事务回滚、草案版本冲突和活动策略版本分离。

`semantic` 是可信管理配置的声明，只能保证声明之间一致，不能证明某个任意来源字段的真实含义或推荐用途。R3 必须接独立的来源语义与用途授权，不能靠字段名黑名单、visibility 或配置声明扩大权限。生产适配器还须将管理权限、目录版本保护维持到事务提交；内存中的写前复核不能替代数据库并发方案。规则语义升级时必须同步更新回放套件版本并重新回放。

## 4. 五类规则与分数

已知值采用以下 v1 语义。软条件未知统一记 0.5，另记 unknown 和证据覆盖；它不产生肯定理由。

| Operator | 1 | 0.5 | 0 |
|---|---|---|---|
| similarity | 明确标签覆盖所有本次要求 | 覆盖部分要求 | 没有共同标签 |
| supply_demand | 本活动声明愿供贡献覆盖全部需求 | 仅覆盖部分需求 | 没有对应贡献 |
| coverage_gain | 声明贡献覆盖本次全部明确缺口 | 仅覆盖部分缺口 | 无新增覆盖 |
| explicit_preference | 命中本次列出的任一可接受值 | 仅未知时使用中性值 | 已知但没有可接受值 |
| interval_overlap | 已确认时段覆盖全部要求时段 | 有正时长重叠但覆盖不完整 | 完全不重叠，仅边界相接也为 0 |

标签采用确定性规范化和显式别名。已确认文本仅按明确字面值比较，不从长篇简介抽取人格、意愿或技能；时间要求包含明确时区偏移，重复/重叠时间段先归并。硬条件逐条要求完整满足，未知或只有部分覆盖不通过。

同维度去重后的要求全部满足记 1、全部已知不匹配记 0，其余组合记 0.5；重复条件和同一需求的重复表达不增加权重。主题、贡献、时间、协作的基线为 .35/.35/.15/.15，只移除本次未提出的维度，再对所有候选使用相同权重。

```text
match_score  = sum(active_normalized_weight × dimension_score)
rrf_score    = sum(enabled_normalized_route_weight × 61 / (60 + rank))
coarse_score = 0.8 × match_score + 0.2 × rrf_score
```

路线权重基线为结构化 .4、全文 .2、语义 .4。未配置语义路线时关闭并统一归一化剩余路线；不因此构造模型客户端。未命中的已启用路线贡献 0，rank 从 1 开始。配置可以收紧召回上限，应用在读取投影前验证，不能只把限制写在配置里。

合格结果同时要求没有硬条件冲突、至少一项明确主题或贡献依据、match_score 至少 .35。单有人格偏好或可用时间命中不够；全未知的中性分不够。诊断保留版本、各维分数与权重、match/RRF、证据覆盖、未知、冲突及规则依据；分数不表示合作成功率。

## 5. 选择与真实不足

先按 coarse_score 降序、稳定 ID 排序，再以每组最高分为固定锚点形成分差不超过 .05 的组。组内可优先尚未展示的明确主题/贡献依据；使用是否有新依据的布尔值，不按标签数量奖励资料更长的人。

通过 `RecentExposureReader` 读取当前查看者在当前 Space 的近期曝光，可在同一分数组内提升最多一个较少曝光者。探索对象仍须达到全部门槛，不跨分数组，不修改分数。未配置历史端口时不编造曝光；已配置端口发生故障则明确失败。一次跳过、未回复、好友数和全站人气不进入这一接口，也不产生全局惩罚。

普通规则批次数量由 selection.max_results 控制且不超过召回上限 200；AI 五卡上限不用于截断普通结果。批次固定最终 IDs 和版本指纹，后续翻页不会重新选人。真实分页/API 仍待 R4。

返回前重取选中投影与关系，曝光读取期间撤权或屏蔽也能被复核；移除失效者后不补人。内部 outcome 区分获准候选为空、必要条件不满足、没有明确匹配及原候选已失效，仅给概括原因与主动调整条件/浏览当前活动的建议，不暴露被排除的个人或隐私计数。依赖故障继续抛出，不伪装成成功空结果。

在两个实现子 agent 完成后，主代理按同一份稳定源码执行全部测试。独立审查另用合成反例复核关键问题。结果为 441 项检查全部通过：

| 入口 | 通过数 | 实际范围 |
|---|---|---|
| tests/contracts/run.php | 57 | R0 端口合同回归 |
| tests/unit/run.php | 102 | R1 用例与边界回归，仍使用原合成评估器 |
| tests/integration/module.php | 24 | 原生 ModuleManager 隔离装配 |
| tests/rules/run.php | 86 | 五类正式规则、权重、证据、时间、硬条件、RRF |

另有 46 个纯层文件的静态依赖检查通过，61 个 PHP 文件语法检查通过。模块共 62 个文件，测试期间源码散列保持一致，R0 原有 17 个文件保持不变。完整命令、退出码、逐项断言与文件 SHA256 见 [R2 测试记录](sources/r2-test-results_2026-11-11.json)。

```sh

rec_module=backend/protected/modules/matcher-recommendation
for rec_test in tests/contracts/run.php tests/unit/run.php tests/integration/module.php tests/rules/run.php tests/policy/run.php tests/selection/run.php tests/integration/rules.php tests/architecture/run.php; do
  "$rec_php" -n -d allow_url_fopen=0 -d disable_functions=fsockopen,pfsockopen,stream_socket_client,curl_exec,curl_multi_exec "$rec_module/$rec_test" || exit

```

覆盖的具体情况包括：30/35/40 人中仅两人有明确依据时只返回两人；能力存在但愿供贡献未知时不能满足硬需求；只有人格命中或全未知时不产生明确匹配；字段改名须重新绑定；新增字段不自动参与；曝光读取期间发生撤权/屏蔽会在发布前剔除；下调召回上限实际生效；空候选池也拒绝非法操作符。

独立审查发现并关闭三项问题：下调召回上限未被用例执行、不同字段的软条件抵消未知硬条件、管理权限在发布依赖读取期间撤回后仍可写入。后两项用相同的独立合成反例复验，修复后均正确拒绝。额外补齐语义维度重标和人格 alias 限制，防止把人格偏好包装成贡献依据。

[R2 边界报告](sources/r2-boundary-checks_2026-11-11.json) 确认监测范围内 HumHub 核心 11,259 个文件、vendor 15,407 个文件的树散列未变；modules/.gitignore、原生字段快照、冻结稿，以及主模块原有三个装配文件均未变。本次算法明确排除符号链接和 .env 类文件，因此 vendor 数量不与 R1 不同排除规则的报告直接比较；没有读取这些凭据文件。未对 P1 或其他并行插件做整树前后比较，不把其他代理的工作计作本任务。

所有验收使用合成数据，数据库、网络与模型调用为 0。M0 仅证明独立规则内核可回放；M1 未完成。真实 P1 批量投影、服务端活动选择、关系/曝光适配及事务保护仍待 R3，公共 API、生产存储和分页待 R4，真实规模与质量验收待 R5，AI 子扩展待 R6。没有执行持久化启用、迁移、部署或 Git 提交。
