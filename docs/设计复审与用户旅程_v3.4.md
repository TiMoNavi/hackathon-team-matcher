# 设计复审与用户旅程 v3.4

> 日期：2026-11-10。范围：九份当前设计、AI 流程导读、导航与旧修订记录。
> 本文记录本轮设计审查、已写入文档的修订与用户体验推演，不是应用测试、用户访谈或上线证明。规范仍以完整方案、共享契约和相应专题为准。

## 1. 结论与修订依据

当前主线可以成立：用户自主确认画像，在当前活动发现人和想法，经明确申请进入交流；广场承接主动公开的跨活动联系。发现范围、字段可见性、好友与讨论分离等核心边界应保留。

实际问题集中在后续补充没有同步到共享契约、状态机、前端和验收，以及新用户限制与首日协作冲突。旧报告中的“无重大矛盾”“一致性 100%”不能代表本轮审查前的文件状态，本次不继续给没有测量依据的健康分。

用户本轮明确指出，注册后等待 24 小时开群、72 小时发外链不合理，并要求进一步调查、同步和优化。本次直接取消这些资格限制；同时补齐已承诺流程的合同，不把修改设计表述成已经实现功能。

用户随后进一步明确：简历上传与 GitHub 导入一定要有，并放在前面，以最快获得首批关键信息、避免重复填写。此要求已作为 R26 同步到当前设计；GitHub 首次注册自动关联公开来源，默认流程改为导入预填、本人确认和补缺，手填保留为兜底。

使用项目 [architecture-patterns 技能](../.agents/skills/architecture-patterns/SKILL.md) 的领域所有权、用例、适配器和可测试边界原则；保持模块化单体。冻结原稿、参考工程和本地凭据不属于修改对象。

## 3. 按用户阶段模拟体验

设想我是刚到活动现场的参与者小林，擅长设计，希望加入别人正在探索的项目，没有准备完整商业计划。以下为依据设计的桌面推演，不是实际用户的反馈。

| 阶段 | 我看到/做什么 | 我的感受与可能的疑问 | 修订后的处理 |
|---|---|---|---|
| 收到邀请、打开登录页 | 看到活动入口、GitHub 和邮箱验证码，背景有示意弹幕 | “没有 GitHub 也能参加；用 GitHub 登录后不要再让我填主页。” | 首次 GitHub 注册后自动关联公开来源；邀请验证与来源读取并行；来源失败不影响登录，示意弹幕不冒充实时成功案例 |
| 第 1 步提供资料 | 最先看到上传简历和 GitHub 资料，GitHub 登录后显示已连接 | “简历和项目里已有的东西，应该帮我带进来。” | PDF/DOCX 等简历先解析，GitHub 公开资料自动读取；可只提供其一。先整理现有材料，无资料时再用手填兜底 |
| 第 2 步等待整理 | 看到真实排队/读取/草稿阶段，各来源独立状态 | “PDF 失败会不会前面都白做？” | 成功项保留；重试指定项或手动继续，离开后恢复任务 |
| 第 3 步修改初步画像 | 昵称建议、技能、经历和作品已预填，有来源和待补项 | “我主要确认和纠错，不必从空白表格重打一遍。” | 明确同一作品才合并，冲突由我判断；只补未知项，后到结果不覆盖人工修改 |
| 第 4 步回答问题 | 一批 3–8 题补充合作方式、投入和目标 | “已确认的技能和项目不要重复问。” | 使用首批已确认信息生成固定问题；避开重复事实，只补未明确的协作维度，逐题不调用模型 |
| 第 5 步检查公开范围 | 每条选登录用户、好友或仅自己，可切换入口预览 | “好友可见是所有好友，还是我挑的人？跨活动的人能看什么？” | 明确普通字段对所有现有及未来好友动态生效；联系人另选；跨活动预览不含无权活动字段 |
| 第 6 步讲想法 | 我其实想加入项目，没有自己的题目 | “是不是必须先编一个项目才能找队友？” | 可选加入别人的项目，写贡献角色与探索方向作为草稿；不强迫公开招募 |
| 第 7–8 步整理与预览 | 想法分别成卡，已有可见性保留 | “我点保存，是不是已经让所有人看到？” | 保存、活动发布、广场发帖分开；每章可保存退出，回来接续，十步完成条件不伪造 |
| 第 9 步活动与推荐 | 确认当前活动、时间角色、是否允许被发现，然后主动启动推荐 | “我能看人，但能不能暂时不让别人找到我？” | 本人发现开关独立；无活动不推荐；少量候选如实返回，不用其他活动凑数 |
| AI 追问需求 | 我说找设计伙伴，系统追问方向或投入时间 | “刚答过的问题别刷新一下就重来。” | 同 run 恢复当前问题；最多三轮，合计五次调用；也可自己填结构化条件 |
| 第 10 步发申请 | 我看理由、编辑首条消息，决定是否附联系方式 | “我是否要一直等对方通过才能进去？” | 发送后可立即进入应用；好友成立后再聊天，联系人不自动全部开放 |
| 普通发现与随机看看 | 首轮之外还有分页网格、筛选与随机批次 | “原来不只有这五张卡，我也能自己找。” | 明确每页默认 24 条；普通浏览不调用模型；好友/待处理对象仍显示真实按钮 |
| 发布与参与想法 | 我发出原型方向、开放讨论；也可申请加入别人的群 | “现在就想拉人讨论，为什么要等明天？” | 首日满足资格即可开讨论；作者有待审批列表。关注、入群、好友三个动作仍分开，按钮说明实际结果 |
| 聊天与发作品 | 我想发送设计稿、仓库或演示链接，连续讨论 | “沟通刚开始就限制链接或消息，会很扫兴。” | 合法链接立即可发；取消新号附加限制，使用统一突发配额；真实超频保留输入并说明等待时间 |
| 关掉页面等回复 | 我选择开启通知，随后回到活动现场 | “回复时提醒我，但别把私信内容直接露在锁屏上。” | 首条及时尝试、随后合并；系统文案通用；不支持或拒绝推送时仍可返回消息页看未读 |
| 第二次活动 | 我加入活动 B，已经认识的人还在好友列表 | “不应该重新加一次好友；A 的投入安排也别带到 B。” | 好友与私聊全局保留，活动偏好与发现隔离；模型不会因为是好友就读取 friends 字段 |
| 以后修改/删除资料 | 我只改一个能力，或删掉旧简历，AI 恰好晚到 | “删源文件会影响哪些公开内容？旧结果会不会把我改回去？” | 删源须提示关联字段暂停展示/待重新确认；晚到建议只可单独审阅；重新确认条目不重跑全部引导或 AI |
| 活动结束 | 我还想和熟悉的人继续推进项目 | “活动结束是否整个交流空间都没了？” | 停止该活动新发现和新增活动来源联系；已有好友/私聊保留，已有群不自动归档；退出活动仍会撤销该活动群权限 |

体验上值得保留的是“整理—本人确认—自主建立联系”的顺序。十步仍有填表和等待成本，本次通过保存退出、早验邀请、允许加入方向和独立业务入口缓解，不把用户已选择的游戏式十步直接删掉。

## 4. 异常场景的结果必须说清楚

| 场景 | 用户应知道的事实 | 应有出口 |
|---|---|---|
| 邀请无效 | 账号与草稿还在，但没有获得该活动资格 | 更换邀请、继续手填、公开广场 |
| AI 预算不足 | 平台当前不能执行推荐，不是用户不合适 | 明确错误、用户主动普通发现；不自动重试花费 |
| 当前活动只有 0–2 位候选 | 真正的活动内候选不足，不是服务报错 | 展示实际数量、修改条件、普通浏览；不跨活动补数 |
| 人工修改后 AI 晚到 | 原建议基于旧输入，当前资料未被覆盖 | 仍获准时看差异，基于最新版选择保存；撤权结果不提供正文 |
| 联系方式在好友申请后变更 | 原待共享版本已不可用，好友申请尚未被接受 | 明确略过失效联系方式后接受，或等待发起者更新申请 |
| 暂时离线/服务超时 | 已保存的业务结果不能因推送失败被回滚 | 幂等重试、状态恢复、未读补拉 |
| 群新成员没有旧消息 | 只能看入群后的消息，这是既定隐私边界 | 说明规则，并在有权读取时引导查看想法公开目标；不能让 AI 越权总结旧群聊 |
| 删除来源 | 原始材料撤回，依赖字段可能暂停展示 | 先列出受影响条目，可转为本人自述后重新确认 |

## 5. 保留的规则与实际验证边界

- 保留十步、第 5/8 步逐条预览、至少一个有效想法/探索草稿作为正常引导完成条件；保存退出不是伪造完成。
- 保留 R03 当前活动边界和公开帖作者的跨活动联系例外，不增加全站人物搜索。
- 保留普通画像动态可见性、逐人联系人授权、朋友/关注/讨论互相独立。
- 保留 R21 预算不足直接报错；普通发现始终可由用户主动使用。
- 保留资料私存、无自动过期/定时抓取、AI 不覆盖人工确认、不读取私聊画像。
- 尚需应用实现后的验证：真实引导耗时/中断率、限流是否误伤、推荐质量、通知设备兼容性、数据库并发及 200/2,000/20,000 人场景。本次不为这些项目填写“通过”。
