# S7.2 P1/P8 资料概览与关系摘要实施记录

日期为 2026-11-12。本记录限于 P1/P8 后端实现和子任务自测；主预览部署、MySQL 升级与独立 HTTP 验收由主代理及独立验收记录单独说明。

## 1. 实施边界

- 使用项目 architecture-patterns Skill 的端口与适配器边界。P1 管理展示引用及普通资料，P8 组合本人逐对象分享、合法入口、对象来源和分页。
- P1 升级为 0.9.0，P8 升级为 0.2.0。P8 安装声明要求 P1 0.9.0；原有普通隐私入口和旧 discovery capability 检测保留。
- 全局资料与当前 Space 资料分别返回；概览只含已确认并获准的普通字段，所有 contact_ 字段及其定义均排除。联系人继续使用既有独立接口。
- 原生主主页已有 primary_portfolio_link 绑定，资料值继续复用 profile.url；额外作品继续在原资料条目内。新表仅保存 attribute_id，不复制学校、URL 或其他字段值。
- P1 ProfileRelationReader 由 P8 ProfileRelationService 实现。P1 可选获取该能力；P8 在外层运行时注入 matcher-ideas source，内层用例不硬依赖想法插件或 Messenger。
- 未改前端、core、vendor、参考工程、冻结稿；本子任务未读取凭据、连接主数据库、调用模型或外网。100 人资料由主代理负责保留与集成验证。

## 2. 新增存储

| 包 | 表 | 内容 | 迁移 |
|---|---|---|---|
| P1 | matcher_profile_presentation | 用户 id、version、education_attribute_id、primary_portfolio_attribute_id | m261112_000007_profile_presentation |
| P8 | matcher_profile_relation_sharing | owner_id、space_id、kind、object_id、version、visibility | m261112_000002_relation_sharing |

两张表均为增量创建，不修改原画像值。展示引用不设置到 attribute 的删除外键，删除后保留原选择 ID，确保不会自动切换到另一条教育或作品。分享唯一键为 owner_id + space_id + kind + object_id；省略的对象默认 private/version 0。

两个持久化保存均使用原子 compare-and-swap。首次写入使用 expected_version 0，成功后 version 加 1；并发首次插入或旧版本更新返回 409。迁移保留数据，不提供自动删表回滚。

## 3. API 与响应

响应沿用 P8 data/meta，meta 含 request_id；错误含 code/message/retryable/details。会话登录、真实用户身份与写请求 CSRF 沿用原生保护。写请求必须 application/json，并显式提交 confirmation_intent=confirm。

| 方法与路径 | 请求 | data 响应 |
|---|---|---|
| GET /api/v1/me/profile/presentation | 无查询参数 | version、education_attribute_id、primary_portfolio_attribute_id |
| PUT /api/v1/me/profile/presentation | expected_version、education_attribute_id、primary_portfolio_attribute_id、confirmation_intent | 同 GET，version 更新 |
| GET /api/v1/events/{spaceId}/profiles/{ownerId}/overview | 无查询参数 | owner_id、space_id、global、space、school_overview、primary_portfolio_link、additional_portfolio_links、presentation_version、policy_version |
| GET /api/v1/events/{spaceId}/profiles/{ownerId}/relations | kind、limit、cursor | owner_id、space_id、kind、items、next_cursor、has_more、limit、policy_version |
| GET /api/v1/me/profile/relation-sharing | space_id 必需，kind、limit、cursor 可选 | 同关系列表，本人可见真实候选的所有范围 |
| PUT /api/v1/me/profile/relation-sharing | query space_id；body expected_version、kind、object_id、visibility、confirmation_intent | owner_id、space_id、kind、object_id、version、visibility |

展示引用必须同时提交；值为 null 或本人已确认全局条目的 UUID，字段分别只能是 education、portfolio_link。首次读取不创建行；学校初始为空，主主页初始引用已有 native binding。保存过显式 null 后保持空。

本人可选择任何本人已确认条目，对外只在该条目当前范围获准时呈现。选中项被隐藏或删除后，对应概览为 null，不选择其他可见条目代替。额外作品仍按自身范围分别展示。global/space 复用获准普通资料投影；school/primary 为完整获准条目或 null，additional 为其他获准 portfolio_link 条目列表。

概览是真实详情入口，真实有效好友可读取 friends 字段；这些字段没有加入发现筛选或推荐匹配。普通发现仍只用 confirmed + authenticated 白名单。

kind 支持 activities/idea_groups，默认 activities；limit 默认 24、最大 48。关系项含 source 获准字段，再加 visibility、sharing_version。无设置时为 private/0。分享 object_id 为来源对象 ID 字符串，不能用 message_id 或任意资料 ID 代替。逐对象选择 authenticated/friends/private，分享不加入会话，也不授予聊天权限。

## 4. 授权与来源

- 所有概览/关系及本人关系设置均先通过已有 server-selected current Space 能力；路径或查询的 space_id 不能改变服务端选择。
- 非本人入口验证双方 active、真实成员、Space 生命周期、屏蔽、所有者发现开关和原生用户可见性，同时复用 P1 ConfirmedIdentityBatchReader 检查已确认公开昵称。访客自己关闭发现不妨碍浏览。本人免发现开关/昵称门槛，仍需当前真实 Space 和正式对象资格。
- 入口 DTO 只是参数，不是授权证明。不接收 caller grant；当前只接受真实当前活动入口或与本人匹配的 self。
- 活动候选只查询当前 Space，名称/简介来自 Space，角色来自正式 membership；尊重 Space hideMembers 及全局 defaultHideMembers，不能跨 Space 凑数。
- 想法候选调用 matcherIdeas.Module::getRelationSource()->readCandidates(viewerId,ownerId,spaceId)。source 提供正式发布、成员展示允许、实际参与、全部参与者仍属 Space 等条件成立的元数据；P8 再叠加本人范围，拒绝越界、重复或损坏候选。
- 未安装、未启用、缺少 source、第三方失败均明确返回 503，不伪装成功空结果。候选最多 2,000，超额 503，不截断。
- 白名单输出 kind/id/title/summary/href/event_id/membership_role/idea_id/version/conversation_available；原始 message_id、成员 ID 列表和消息正文不返回。合法非会话成员可看获准想法元数据；conversation_available 不授予新权限。
- 入口和来源使用主库、无缓存当前读，前后重验对象、所有者开关、成员、好友、确认身份和分享选择。概览也重读两个资料投影及展示设置。变化返回 409 或相应 403，撤权结果不展示。
- 分享写后再次验证对象与入口。若撤权，仅对本次确切版本做 CAS 补偿，以新版本恢复原范围；不覆盖本人更晚保存。
- 查询校验使用原始 query string，避免 Yii 命名路径参数被误当过滤器，同时拒绝查询注入 spaceId、ownerId 及伪造入口参数。

## 5. 签名分页

游标使用 HMAC-SHA256，派生于应用既有 cookieValidationKey 并使用独立用途前缀，不输出密钥。绑定 viewer、owner、Space、kind、limit、策略版本、当前候选/授权/分享快照、位置和初始时刻；有效期固定 900 秒，翻页不延长。

篡改、换用户、换目标、换活动、换种类、换 limit 或权限变动均无效；到期返回 410。候选按稳定对象 ID 排序，经过权限过滤后分页，真实不足即返回不足。关系与概览均为 0 次 LLM 调用，不改变 S6 已有计量。
