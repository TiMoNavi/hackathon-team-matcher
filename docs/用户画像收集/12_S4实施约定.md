# S4 无 AI 引导实施约定

2026-11-11。P2 matcher-onboarding 复用普通资料 P1 和独立隐私 P8，交付已有资料与手工补充、核对、规则补问、画像编辑、范围预览和确认。真实 GitHub/简历读取在 S5，AI 在 S6。

## 核心接口合同

### 存储与依赖

P1 新增 QuestionBatch、QuestionAnswer；P2 新增 OnboardingSession。会话只保存阶段、版本和资源引用，普通资料和自述进入独立 P1 onboarding 草稿，答案只保存一份。领域与用例无框架、数据库和模型客户端。ProfileWorkflow 端口统一事务，先锁 owner global state，再锁可选 Space state，随后锁 session/batch；在锁后验证当前账号及 Space 资格。

QuestionBatch 存储 id、owner_id、space_id、profile_versions（global/space 修订）、version、questions、generation_mode=rules、schema_version=1、policy_version、created_at、updated_at。QuestionAnswer 存储 id、batch_id、question_id、version、answer_type、selected_options、free_text、created_at、updated_at；(batch_id, question_id) 唯一。

Session 存储 id、owner_id、scope_key（global 或 space:ID）、space_id、version、stage、max_stage、status（active/completed）、resource_refs、created_at、updated_at、completed_at。resource_refs 保存 input_drafts/output_drafts（global/space ID）、profile_versions、question_batch_id、synthesis_batch_version、question_index、历史资源引用和确认收据。GET 返回完整会话并附 profiles、input_drafts、output_drafts、question_batch、generation_mode=rules、llm_calls=0；这些附加值按引用读取。

### HTTP 与动作

统一登录会话、CSRF、本人归属、JSON 包装。写入 expected_version 是目标对象当前版本，答案为单答案版本（尚未回答为 0）。

| HTTP | 载荷与返回 |
|---|---|
| POST /api/v1/onboarding/sessions | {space_id?: integer, generation_mode?: rules}；创建或恢复该本人/Space 的 active 会话；返回 SessionDTO |
| GET /api/v1/onboarding/sessions/{id} | 返回 SessionDTO |
| PUT /api/v1/onboarding/sessions/{id} | {expected_version, action, ...}；返回更新后的 SessionDTO |
| POST /api/v1/me/profile/question-batches | {session_id, expected_version, generation_mode:rules}；调用会话 prepareQuestions，返回 SessionDTO（question_batch 内有批次） |
| GET /api/v1/me/profile/question-batches/{id} | 返回 BatchDTO，包含 questions、answers、version、generation_mode、llm_calls |
| PUT /api/v1/me/profile/question-batches/{batch}/answers/{question} | {expected_version,answer_type:options/free_text/skipped,selected_options?:[code],free_text?:string}；返回更新后的 BatchDTO |
| POST /api/v1/me/profile/syntheses | {session_id,expected_version,expected_batch_version,generation_mode:rules}；返回 SessionDTO，output_drafts 已生成 |

PUT session 的 action：

- save_materials：global_fields/space_fields 为 P1 操作数组，draft_versions 为 {global:{draft_version,base_revision},space?:同结构}；保存本人候选，step 保持 materials/review。
- move：stage 为已到达的 materials/review/questions/draft/privacy；初始 materials 可进入 review，draft 可进入 privacy。其他前进由明确业务动作完成。
- review_confirm：confirmation_intent=confirm，draft_versions 同上；原子确认 input_drafts 中待确认条目，空草稿跳过。更新资料版本后进入 questions。
- question_position：question_index 为本批已存在问题的零基索引，仅记录进度。
- save_drafts：global_fields/space_fields 与 draft_versions 同上，编辑 output_drafts，保留本人修改与范围。
- reconcile：本人主动重新核对当前已确认资料，保留旧草稿和原批次/答案记录；建立新的空 input_drafts 并回到 review。之后重新准备问题会基于最新资料，原批次可追溯。
- complete：confirmation_intent=confirm，draft_versions 指向 output_drafts，expected_batch_version 指向生成时使用的批次版本；在同一事务确认两种范围并完成会话。全部跳过且草稿为空同样可完成，不补造事实。

### 服务签名

P1 QuestionService 构造 (QuestionRepository, ProfileWorkflow, ?clock)；prepare(ownerId,spaceId,profileVersions)、get(ownerId,batchId)、answer(ownerId,batchId,questionId,expectedVersion,payload)、compose(ownerId,batchId,expectedBatchVersion)。compose 返回 global_fields、space_fields、profile_versions、batch_version，不直接发布资料。

P2 OnboardingService 构造 (OnboardingRepository, ProfileWorkflow, QuestionService, ?clock)；start(ownerId,spaceId)、get(ownerId,id)、update(ownerId,id,expectedVersion,payload)、prepareQuestions(ownerId,id,expectedVersion)、synthesize(ownerId,id,expectedVersion,expectedBatchVersion)。所有返回富化 DTO。

### 问题和一致性

Question DTO 为 id（批内稳定 template_id）、template_id、target_key、scope（global/space）、prompt、reason、mode（single/multiple）、options（code,label）、allow_free_text=true、allow_skip=true。每批 3–8 题，优先缺项。单选最多一个选项，多选最多五个。free_text 保存本人自述，skipped 保存明确跳过；每题可返回修改。批次 version 随答案变更递增。

Synthesis 按该批次保存的 profile_versions 验证当前资料，按 expected_batch_version 验证答案；产生新的独立草稿并保留此前草稿。相同输入重试恢复原输出。返回补问后答案未变时，以当前会话版本再次整理会回到原画像草稿，保留草稿 ID、版本及手工修改；旧生成请求重放不改变后续进度，恢复请求本身也可幂等重试。重答后须主动重新生成，旧输出不能完成。普通编辑产生新确认修订时旧流程返回 409，用户主动 reconcile 后重新核对。各范围字段继续按目录验证，原有可见性保留，新确认条目默认 authenticated。

## 核心实现与内存验收

P1 的 QuestionService、RuleQuestionProvider 与 RulesProfileComposer 已实现上述规则。QuestionProvider/ProfileComposer 为显式领域端口，QuestionService 构造的第四、第五参数可选注入实现；现有三个构造参数保持兼容，本阶段模块仅绑定纯规则提供者。

规则直接映射本人选择与文字。已有多条字段若稳定 code 相同，则保留原条目与备注；生成的一句话介绍仅使用全局角色和兴趣，并继承所用字段最严格的可见性。JSON 对象键顺序不影响资料版本和值的比较。

OnboardingService 已实现恢复、返回核对、逐题进度、综合草稿和完成流程。已确认输入草稿在返回编辑时生成独立新草稿；reconcile 保存旧资源引用再建立新核对过程。全部跳过得到空的候选操作，仍可正常完成。跨 global/Space 确认由同一事务保证；后一范围或会话保存失败时，前一范围的资料和进度一起回滚。

领域与用例的 [内存测试](../../backend/protected/modules/matcher-onboarding/tests/unit/run.php) 完成 **91 项通过**，数据库调用与模型调用均为 0。测试覆盖完整五阶段、独立手工草稿、选项/文本/跳过、版本与重复综合、返回草稿保留手工修改、旧答案/资料冲突、两种范围、回滚、旧范围继承及字段限制；见 [领域证据](sources/s4-domain-unit_2026-11-11.json)。原 S2 资料用例 **147 项回归通过**，见 [回归证据](sources/s4-domain-s2-regression_2026-11-11.json)。数据库、HTTP、主预览部署和真实网页结果见 [实现报告](13_S4实现与验证报告.md) 与 [独立网页验收](14_S4真实网页验收.md)。
