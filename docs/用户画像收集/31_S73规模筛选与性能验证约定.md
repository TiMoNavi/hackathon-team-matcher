# S7.3 规模筛选与性能验证约定

> 2026-11-12，已完成规模验证。目标是验证真实 300–400 人活动数据下的普通发现筛选，记录查询耗时、扫描量与索引效果，按证据改进瓶颈。

## 本轮范围

采用 400 名明确虚构人物，主测试 Space 有 400 名成员，第二 Space 有其中最后 80 人；开启发现分别为 360 / 72。测试账号使用 s73_sim_ 前缀，与原有 100 名模拟人物分开。400 人只写入隔离测试库，主预览继续保留原 100 人和 S7.2 示例关系。

验证单编码、多值数组各项、同字段 OR / 不同字段 AND、需求数组后续项、完整时间覆盖、相邻/重叠区间、时区转换、空结果、末尾稀有技能、超过 200 候选的分批与完整分页。所有期望结果由独立验收从固定数据集计算。

普通发现只使用 confirmed + authenticated 白名单，保持当前 Space、本人发现开关、昵称、真实好友/申请状态及撤权检查。普通浏览、筛选和分页继续 0 次模型调用。

## 测量方法

1. 保留现有实现，先对真实 MySQL / HTTP 采样基线，记录运行环境、样本与参数。
2. 按请求统计 SQL 次数、执行时间、返回行数；数据库扫描量区分实测值和优化器估算。查询计划记录使用的索引，不把尚未接入普通发现的推荐索引当成已生效。
3. 若有明确瓶颈，再做小范围优化，并对相同数据/查询复测。不得省略权限重验、丢弃批次或用缓存延迟撤权。
4. 单机开发服务结果用于功能与局部性能验证；不是生产并发容量或完整压力测试承诺。
