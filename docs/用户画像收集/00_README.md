# 用户画像填写设计

> 更新日期：2026-11-12。包含需求、后端能力、数据字段、AI 扩展方案及实施记录。S1–S3 已提供普通资料、Space 上下文、独立隐私和基础编辑；S4 已实现无 AI 五阶段引导、规则问答与画像草稿。S5 已接通 GitHub、简历、个人网站和粘贴文字四种来源，统一私存、生成候选并采纳进草稿。S6 已通过独立与真实网关验收，提供 AI 提取、选项补问和画像草稿。S7.1 已接通普通发现并安装 100 名模拟人物；S7.2 已接通资料概览、获准关系摘要与正式想法。S7.3 已完成隔离 400 人筛选、性能测量与独立验收，P1 更新至 0.9.1；未证实稳定端到端提速。S7.6 已补齐后端阶段进度并完成基础组合验收，P1/P2 为 0.10.0/0.4.0；S7.7 已完成 AI 组合及真实网关链路，三个阶段均首次成功，生产模块版本不变；最新验收见 [S7.7 报告](38_S77_AI组合验收报告.md)。

先取得用户已有资料，整理已知信息，主动补问几个问题，再生成一份可修改、可选择展示范围的个人卡片。交互采用 Plan 模式的节奏。

**先完成无 AI 的后端流程，再接入 AI 提取、提问和归纳能力。** 基础模式使用资料映射、规则题库和固定模板，同样能够完成整个填写过程。

## 产品结构

- P1 matcher-user-profile 扩展 HumHub 原生用户资料，负责字段、草稿、确认版本及普通编辑页面。
- P8 matcher-profile-privacy 独立依赖 P1，负责逐条展示范围、合法入口、联系人读取和获准投影。
- P2 matcher-onboarding 已实现五阶段 rules 引导，负责步骤、问题展示和恢复；P1 保存 QuestionBatch、QuestionAnswer，资料继续进入原有草稿与确认接口。
- P3 GitHub 来源依赖 P1 与 auth-github，直接识别本人验证关联；P4 简历与 P5 网站/粘贴文字来源依赖 P1，三者已实现。来源读取器独立于引导页面。
- P6 matcher-onboarding-ai 已提供三类生成；P1 保存任务，P2 接回原会话。每题最后带“其他，我来填写”，三个阶段均返回本人复核提示。

- matcher-recommendation 0.2.0 已接通当前 Space 选择、独立发现开关、普通列表与详情；仅使用已确认且获准的字段。

- matcher-ideas 0.1.0 提供正式想法和显式会话关联；P1 0.9.0/P8 0.2.0 组合学校、主页与获准关系摘要。

## 实施顺序

普通资料后端 → 独立隐私与基础编辑 → 规则问答与模板画像 → 四种来源导入 → AI 增强与后续整合。S1–S6、S7.1–S7.3、S7.6 和 S7.7 已完成，余下 S7.4/S7.5 为正式前端与开场组件。当前集中后端，正式前端后续单独重做；具体执行以 [task.md](task.md) 为入口。

S1 字段基础与 S2 普通资料用例、草稿确认和版本 API 已部署到本机预览。S3 的“团队协作资料”页面已实现字段编辑、重复记录管理、草稿恢复、分批确认和本人/登录用户/好友三种服务器预览；P8 提供逐条隐私及原生资料出口适配。具体模块兼容范围见 [出口登记](11_S3原生出口适配登记.md)，验收与部署结论以 [主报告](10_S3实现与验证报告.md) 为准。

当前 **27 类全局条目与 10 类 Space 条目均为可选项**，新增确认资料默认 authenticated。性格、长期习惯、经历和联系方式在不同 Space 中共用；本次目标、角色和投入按 Space 分别填写。产品的“活动”对应 HumHub Space，Calendar 负责空间内赛程。S4 已实现已有资料与手工补充 → 信息核对 → 规则补问 → 画像编辑 → 范围确认。S5-A 已把 GitHub 与简历接入首屏；S5-B 通过后端 API 补齐网站与粘贴文字。S6 已通过后端 API 接入 AI；S7.2 已接入获准关系摘要，正式 React 主前端继续按后续阶段接入。

S4 核心接口和字段映射见 [实施约定](12_S4实施约定.md)，实际验收与部署结果见 [主报告](13_S4实现与验证报告.md)，真实页面测试见 [Playwright 验收](14_S4真实网页验收.md)。

第一阶段的核心验收是：用户能在模型调用数为 0 的情况下，完成资料输入、补充回答、画像编辑、隐私预览和确认保存。
