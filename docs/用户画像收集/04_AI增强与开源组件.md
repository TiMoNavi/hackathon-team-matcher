# AI 增强与开源组件

> 更新日期：2026-11-12。S6 已在完整基础流程上接入 AI 后端。当前实现与真实模型结果见 [S6 报告](23_S6实现与验证报告.md)，准确 API 以 [实施约定](22_S6实施约定.md) 为准。

## 1. AI 带来的体验提升

用户给出资料后，系统先整理已知信息，展示需要核对的内容，再提出几道与用户背景有关的问题。回答结束后，系统将事实和偏好组织成一份可编辑的个人卡片。

交互沿用 [用户画像填写需求](01_用户画像填写需求.md) 的五个阶段。AI 处理使用 `generation_mode=ai`，基础处理使用 rules，两者返回相同类型的字段、问题和草稿。

| 步骤 | AI 输入 | AI 输出 | 用户看到的结果 |
|---|---|---|---|
| 资料提取 | 本次选中的来源快照、允许字段定义 | 资料条目建议、证据引用、待核对项 | 已整理的信息清单 |
| 补问 | 首批确认资料、待了解维度、活动上下文 | 一批 3–8 个结构化问题 | 逐题出现的选择题和自由补充 |
| 画像表达 | 确认资料、选定回答、目标字段 | 结构化画像草稿与简介 | 可编辑卡片和逐条展示范围 |

普通资料用例负责验证输入、保存结果、检查版本并执行用户确认。模型适配器负责调用与结构化输出。

## 2. 提问设计

每个问题具有稳定 ID、目标维度、单选/多选模式、选项和跳过能力，最后提供“其他，我来填写”的独立自由回答入口。后端一次准备完整批次，页面逐题显示；每个答案直接保存。

问题围绕尚需了解的合作信息。例如已有作品与技能时，可以进一步询问希望承担的角色、偏好的沟通方式和本次投入。资料较少时，优先帮助用户表达能做什么、感兴趣什么。

问题可以带一句简短上下文说明，让用户理解为什么问这一题。资料充分时使用较短批次，问题集中在剩余维度。用户可以返回编辑答案，随后基于最新答案重新整理画像。

## 3. 资料提取设计

### GitHub

来源绑定本人已验证的 GitHub 身份。读取公开介绍及本轮选中的公开项目说明、语言与主题、README，默认最多 10 个项目。提取器将材料映射为项目、技能线索和作品介绍，交由本人核对。

### 简历

解析器先把文件转成正文与段落结构，模型据此提取经历、项目、教育和成果。每条建议关联相应来源位置，用户可查看、修改或补充。

### 个人网站

读取本人提交的公开个人主页或作品页面，取得标题、正文和链接。提取器整理页面中的个人介绍与作品信息，交由本人确认。动态网页按需要通过浏览器适配器读取。

多种来源先形成统一快照与片段，再由资料用例组织本轮抽取。所选材料、草稿版本和来源引用随任务记录保存。

## 5. 统一处理与任务接口

提取、补问和综合具有 rules 与 ai 两种处理方式。现有规则端口继续使用；AI 统一通过 ProfileAiEngine 和持久任务执行，再安装到相同来源、批次及草稿中，具体边界见 [后端设计](02_后端能力与插件设计.md)。

AI 请求通过 `/api/v1/me/profile/extractions`、`question-batches`、`syntheses` 发起，返回 job_id。页面根据任务状态显示排队、读取、整理和完成；结果仍适用于当前版本时进入本人草稿。

任务记录使用 execution_status 表示执行情况，applicability 表示对当前资料的适用性，并记录输入版本、schema/策略版本和实际用量。本人编辑后重新整理时，任务以最新选中数据建立输入。

正常短资料的完整 AI 路径包含资料提取、问题生成和画像综合三个生成步骤。回答、手工编辑、预览、确认使用普通后端功能；分段和重试按实际调用记录用量。

## 6. 运行与交付

当前指定模型为 gemini-3.8-flash，配置私存在本机 .local；API 仅返回可用性、模型名称与限额。用户材料通过受认证任务读取，日志记录任务 ID、用量与处理状态。原文与证据位于本人资料存储。

资料提取 → 问题生成 → 画像表达已完成独立与真实网关验证。每阶段返回 review_items；自然语言简介包含强制本人复核提示，引用校验不等于事实已核实。用户可以继续选用基础模式；启用 AI 时显示实际处理方式。

开源组件采购可按 ¥0 规划，模型调用和运行资源单独记账。验证重点为中文简历、公开项目、个人网页的字段质量与证据，问题的针对性，以及用户修改后的版本处理。

验收时分别记录基础模式与 AI 模式的完成率、修改量、耗时和模型用量，用实际结果决定后续优化。
