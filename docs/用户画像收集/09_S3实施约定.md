# S3 隐私插件、资料展示与基础编辑

> 2026-11-11。S1/S2 已完成，本轮实现 task.md 的 S3。此文记录实施约定；完成情况与测试证据另行报告。

## 本轮交付

用户从普通资料入口编辑全局资料与当前 Space 的偏好，为每条资料选择展示范围，预览本人、登录用户和好友看到的内容，再确认保存。已有草稿可以继续填写，多条技能、经历和项目可以独立管理。

新增独立模块 matcher-profile-privacy，依赖普通资料模块 matcher-user-profile，负责资格验证、逐条策略、联系人读取和获准展示。填写引导与 AI 继续作为后续独立模块。字段值、确认状态、范围和修订继续复用现有四张资料核心表。

## 字段与展示规则

37 类普通字段保持可选。新确认条目默认 authenticated；用户可选择 friends 或 private。本人主动选择的已有范围继续保留。填写某条记录时，校验该记录所需的名称、格式和图片归属。

authenticated 表示登录用户经合法入口可见；friends 随实际有效好友关系变化；private 仅本人可见。真实详情使用当前关系和资格，预览仅供本人模拟展示视角。隐藏条目的键、值与来源均从他人输出中移除。

联系方式沿用本轮用户确认的默认可见规则，具有独立读取用例与展示区，并使用相同的逐条范围选择。人物目录、搜索和推荐摘要只取适合这些场景的普通资料。共享契约中按好友逐项交换联系方式的设计，属于后续关系业务；本轮默认展示行为以用户最新要求和本目录实施约定为准。

全局资料包含性格、长期协作偏好、沟通习惯、技能、经历和联系方式。Space 资料包含本次目标、角色、需求、投入与时间安排。活动对应 HumHub Space，Calendar 处理 Space 内赛程。

## 入口与原生适配

合法详情入口包括服务端验证的当前 Space 成员、已有有效好友，以及当前可访问的公开帖子作者。好友的全局资料跨 Space 保持可访问；Space 字段仍验证该 Space 的成员资格。屏蔽、账号状态和关系变化在每次实际读取时检查。发现、搜索与列表保持当前 Space 范围。

个人主页、头像卡、显示名、人物目录、搜索与 REST 逐项接入获准投影。通知、模板、导出及已启用模块的读取点形成出口登记，明确字段和处理方式。原生受管单值和扩展条目采用同一策略。

旧资料优先沿用已有确认元数据；尚待本人核对的原生值进入本人候选清单。已确认昵称用于正常展示，待确认昵称使用稳定中性身份。

## 实施分工

| 工作 | 负责范围 | 验证方式 |
|---|---|---|
| 隐私用例 | 独立模块、策略接口、逐条修改、视角预览和联系人读取 | 纯内存用例与回归 |
| 原生投影 | 关系和入口适配、已有资料确认、原生页面与模块出口 | 独立 SQL 库与 HTTP 检查 |
| 基础编辑页 | 分组字段、多条记录、草稿确认、全局/Space、可见性预览 | 合成用户的真实浏览器操作 |
| 集成验收 | 接线、备份与升级、跨模块验证、文档和任务状态 | 主代理独立复核 |

三个子代理分别负责前三项。主代理管理运行库升级；写入测试在隔离库完成，主预览升级前保存私有备份。完成后更新本目录的任务、字段与报告。

基础编辑页用于本阶段的可操作验收，沿用已安装的 HumHub 页面资源；正式 React 主前端整合按 S7 推进。
