# S7.3 400 人筛选与性能独立验收

日期：2026-11-12。结论：400 人普通发现的筛选、完整分页与权限回归在隔离的真实 MySQL / HTTP 环境通过独立验收，当前没有本包未解决的 P0 / P1。性能证据已完成独立复核，但本轮未证实稳定的端到端提速，也未验证生产并发容量。

## 范围与隔离

依据 [S7.3 约定](31_S73规模筛选与性能验证约定.md)、[普通发现合同](25_S7普通发现与模拟人物实施约定.md) 与 [S7.2 独立验收](30_S72独立验收.md)，采用项目 [architecture-patterns Skill](../../.agents/skills/architecture-patterns/SKILL.md) 的纯领域规则、应用用例和真实外层适配器测试边界。

本包只修改 s73_audit 前缀的独立测试、证据与本报告。真实测试固化数据库 humhub_profile_s73_test_audit_b7a2c940、HTTP 127.0.0.1:8103 和 s73_sim_001–s73_sim_400 合成账号。SQL helper 在 bootstrap 前拒绝其他目标，HTTP origin 固定且不接受环境覆盖。主预览、原 100 人、冻结稿和生产实现不在独立审计的修改范围。不读取 .local/，不访问外部网络或调用真实模型。

真实 MySQL 中有 400 个新合成账户；主 Space 400 名成员、360 人开启发现，第二 Space 80 名成员、72 人开启发现。实际保存 880 个资料范围、16,511 条确认属性（16,111 条普通属性加 400 个昵称）、88 条编辑草稿记录；JSON 的 128 是草稿属性数，二者不混用。这些人数来自实际入库查询，不以内存卡片冒充规模证据。

## 独立期望值

[Python oracle](../../backend/protected/modules/matcher-recommendation/tests/s73_audit_oracle.py) 直接读取 [400 人 JSON](examples/s73-people_2026-11-12.json) 的原始字段，不使用生成器的 expected、boundary_cases 或生产筛选结果。逐字段取已确认 authenticated 白名单，按编码集合交集实现同字段 OR 与跨字段 AND；需求的 role_codes / skill_codes 逐数组位置处理。时间采用独立端点推进算法，将相邻和重叠时段视为连续，并要求每个请求时段被完整覆盖。

relevance 的独立排序键为命中请求编码数，再按 owner_id 降序；实际 role OR 场景包含不同命中分数，不能只靠 ID 排序通过。recent 从克隆中的获准确认字段和身份确认记录单独读取时间，再由 Python 排序。两种名单都与实际 HTTP 的完整有序结果比较，不只检查数量或第一页。

400 人 JSON SHA256 为 90bc52cf4df27b27af97068f875c870a636ebbc4e073d127bd0b050464297fe6，前后保持。最后 400 号的唯一公开技能由原始字段独立识别为 s73-wasm-component-model。

主 Space 排除访问者 321 号后，实际取得 359 人。limit 24 是 14 页 24 人加末页 23 人，共 15 页；limit 48 是 7 页 48 人加末页 23 人，共 8 页。均超过首个 200 候选批次、没有重复或漏项。每张卡片的两类资料逐条等于原始 JSON 的获准白名单；private / friends / draft 哨兵和联系方式均未进入列表或筛选。第 400 人稀有技能精确返回 1 人。

第二 Space 实际返回 71 名其他成员，第 400 人的活动资料与第二 Space 的 JSON 精确相同；主活动独有成员的详情拒绝。无匹配结果真实为空，不跨活动补足。

## 权限与恢复

真实 HTTP 覆盖未登录、缺少当前活动、CSRF、未知 query、非法结构化数组、签名篡改，以及 viewer / 筛选 / 排序 / 页大小 / 当前活动选择版本的 cursor 绑定。

关闭候选发现后，详情返回 404、旧 cursor 失效，稀有技能返回空；访问者自己关闭发现仍可浏览其他人。实际单向申请和双向好友状态保留；成为好友不使 friends 字段进入普通发现。稀有技能改 private / friends 后即时退出筛选和详情。

昵称改 private / friends / draft 后，卡片入口和旧 cursor 立即失效。双向屏蔽、Space 屏蔽、成员退出、账号停用均通过真实详情及旧 cursor 检查；访问者退出 Space 后，空筛选也不能绕过 403。切换活动后原路径拒绝，切回仍不能复用旧选择版本的 cursor。

finally 恢复合成好友、屏蔽、成员、账号状态、昵称确认/可见性、稀有技能可见性与发现开关。对比 [测试前 SQL](sources/s73_audit_sql_before_2026-11-12.json) 和 [恢复后 SQL](sources/s73_audit_sql_after_2026-11-12.json)，成员、开关、确认属性、编辑草稿和测试关系基线保持。revision、permission_version、identity_version 没有倒退；保留合法修订历史，不声称数据库逐字节恢复。

实际 API 前后计数保持 message 4、user_message 9、message_entry 0、notification 2、queue 0、AIJob 0。这些会话和通知是克隆原有条件，本包没有创建会话、加入会话参与者或发送消息。400 人命名空间 AIJob 也是 0。本轮普通读取的零模型结论只适用于 S7.3，不抹去 S6 已有调用及计量。

## 性能证据独立复核

[72 项复核](sources/s73_audit_performance_review_2026-11-12.json) 对照同一克隆的 6 组场景，每组保留基线和复测各 3 次。五个被记录实现文件中只有 P1 FieldCatalog 发生变化；固定 schema 按值返回，既不缓存用户数据也不缓存权限。P1 版本升级到 0.9.1。应用用例、批量适配器和普通发现授权逻辑哈希保持。额外的 [4 项定义等价检查](sources/s73-performance-catalog-equality_2026-11-12.json) 验证 37 类字段完整定义字节相同；实施包的 630 项回归与本包独立计数分开报告。

每次 CLI 用例仍执行 66 次 SQL，共返回 47,644 行，包含重复授权与资料重读。359 名获准其他成员分成 200 + 159，两遍完整读取均保留；6 组排序结果摘要相同。四组复测中位数更慢，不能描述为已取得一致的端到端提速。主执行人的 [HTTP 基线](sources/s73-http-baseline_2026-11-12.json) 与 [HTTP 复测](sources/s73-http-final_2026-11-12.json) 也分别报告，三组复测均更慢，不用 CLI 用例耗时冒充页面请求耗时。

现有 state 前导索引 default / USE / IGNORE 对照的结果一致，属性表均为 ALL 扫描、没有选中属性索引。EXPLAIN ANALYZE 中该属性表节点每轮读取 20,559 行、1 轮，这是一个被采样的 200 人属性 SELECT 的迭代器实际值，既不是单个请求的精确 rows_examined，也不是唯一用户量。返回行总数和 Handler_read 操作同样不能互换成扫描行数。普通发现没有调用推荐召回索引。

首次 EXPLAIN 默认 TREE 的表格解析未获得有效估算，该结果保留且明确无效；补采使用显式 FORMAT=TRADITIONAL，原始场景耗时保留。所有这些结果属于单机开发环境，不能外推生产并发容量、吞吐或 SLA。

独立功能运行总时长 614.953 秒，228 次请求中有 144 次成功的普通列表 GET；这些列表请求的混合样本中位数为 2,668.883 ms，范围 2,296.340–11,071.346 ms。该样本混合不同筛选、页码和权限状态，执行时间也不同，只用于诊断，不能与主执行人的受控场景直接计算提速比例。[逐请求记录](sources/s73_audit_requests_2026-11-12.json) 只保存方法、路径、状态、字节量和耗时，不保存 cookie、CSRF、cursor 或资料正文。

## 限制与复跑

本包没有进行生产并发或长时间压测；15 分钟 cursor 到期边界沿用既有注入时钟回归，本次没有等待 15 分钟 HTTP 到期，也不把它计入 173 项真实 HTTP 断言。主预览部署、旧 100 人浏览器回归和临时环境清理由主执行人分别记录。

    python3 backend/protected/modules/matcher-recommendation/tests/s73_audit_rules.py
    python3 backend/protected/modules/matcher-recommendation/tests/s73_audit_performance_review.py

第三条仅在专用克隆安装 400 人、8103 服务启动且没有性能基准采样竞争时运行；脚本不接受主预览目标覆盖。后续重跑支持阶段 checkpoint。独立验收首次运行全程通过，未发现需要改动生产代码的功能缺陷。
