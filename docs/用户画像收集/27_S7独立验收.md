# S7.1 普通发现独立验收

日期：2026-11-12。结论：S7.1 普通发现后端在本轮隔离库通过独立验收。两处真实 HTTP 接合缺陷经实现人修复后，全套重新执行通过；当前没有未解决的 P0 / P1。主预览部署由主执行人另行验收，本页不替代部署报告。

## 范围与隔离

本轮独立审查 [S7 实施约定](25_S7普通发现与模拟人物实施约定.md) 中的当前 Space 普通人物发现、每 Space 发现开关、签名游标及 100 名固定虚构人物。产品代码只读；独立测试使用 `s7_audit` 前缀。严格使用主执行人分配的本轮隔离数据库与本机 HTTP 服务，不读取 `.local/`、不连接主数据库、不调用真实模型、不发送外部消息。

实际环境为 MySQL 克隆 `humhub_profile_s7_test_audit_c51bb175` 与 `127.0.0.1:8099`，两个模拟 Space ID 为 3 / 4。HTTP 使用真实 HumHub session 和 Yii CSRF；登录入口仅接受 `s7_` 合成账户。SQL 测试工具硬性限定该数据库，人物仅从 100 个精确 `s7_sim_001` 至 `s7_sim_100` 名称取得 ID。本轮测试中对合成好友、屏蔽、成员、可见性与发现开关的变化均在 finally 中恢复逻辑状态，不修改原克隆用户资料；合成资料的版本和历史仍保留测试痕迹，不声称整库逐字节回到测试前。

采用项目 [architecture-patterns Skill](../../.agents/skills/architecture-patterns/SKILL.md) 的应用用例与适配器边界检查：权限规则能经内存端口验证，数据库、会话与 HTTP 由外层适配器承担。

100 人仅是本轮功能数据集，不是 S7.3 原定 300–400 人规模性能验收。正式前端、真实 GitHub OAuth 和 AI 推荐均不在本页通过声明范围。

## 发现与修复

- 初稿排序差异已修正：实现采用共享契约中的 `recent/relevance`；`id` 作为未知排序返回 422。recent 只使用获准确认字段与身份确认时间；relevance 是请求公开编码的命中数，不是团队适合概率。
- P1：原画像模块的宽泛 `/api/v1/me` 规则先匹配，当前活动接口返回 404 `NOT_FOUND` / Unknown profile API endpoint。实现人在原兜底前保留明确发现路由；真实 HTTP 重跑通过，原未知路径防护保留。
- P1：Yii 将命名路径参数合并到 queryParams，无 query 的发现路径被误判为 422 `UNKNOWN_QUERY_FIELD`。实现改为检查原始 queryString，保留路径参数的服务端绑定。无 query 的正常读取、客户端 `spaceId` / `ownerId` 注入拒绝均已实测。
- P8 增补获准 `event_seeking` 规则，新普通来源在原成员/屏蔽门控之外连接每 Space opt-in；关闭、撤权和可见性变更均通过真实重验。

## 实测结果

已独立执行 92 项离线 / 内存检查及 129 项真实 HTTP / SQL 断言。最终完整 HTTP 运行共 127 次本机请求，用时 79.542 秒，包含分页、权限变化和清理；这是功能回归时长，不是延迟、吞吐或负载基准。不引用实施 agent 自测数量，也不将端口中的 100 张测试卡冒充真实安装数据。

MySQL 的 [测试前统计](sources/s7_audit_sql_before_2026-11-12.json) 与 [恢复后统计](sources/s7_audit_sql_after_2026-11-12.json) 确认：100 名虚构人物，主活动 100 名 / 90 开启发现，第二活动 20 名 / 18 开启；220 个画像 scope，3948 个普通确认条目加 100 个已确认昵称，共 4048 条；22 个编辑中草稿承载 32 个未确认字段。模拟 081 在主活动看见 89 人，四页穷尽无重复；切到第二活动看见 17 人。第 100 人的唯一技能 `wasm-component-model` 能被正常检索，关闭其发现或改成 private/friends 后真实为空。

模型调用为 0 的结论仅适用于本轮普通发现：依赖接合不调用 AI 服务，隔离 bootstrap 禁用真实 AI 配置，100 名合成账户的 AIJob 数在前后均为 0。S6 真实模型链路的既有计量不受此结论影响。

## 安装器与能力边界

安装器静态审查确认显式目标库和 loopback MySQL 限制、主预览备份校验、journal + GUID 认领、同名/同邮箱冲突拒绝、已提交资料与已初始化发现开关保留、队列/动态/邮件拦截，以及拒绝自动加入旧 Space 或冲突邀请。真实安装/重放由主执行人执行，参见 [首次安装](sources/s7-root-people-seed_2026-11-12.json)、[相同内容重放](sources/s7-root-replay_2026-11-12.json)、[主动修改后的重放](sources/s7-root-modified-replay_2026-11-12.json) 与 [主执行人 HTTP 复核](sources/s7-root-http_2026-11-12.json)。此处明确区分独立静态审查与主执行人实测。

首次安装与未修改重放的最终内容 SHA-256 一致，重放新增人数为 0；显式改动的昵称与活动发现开关由主执行人验证保留。独立审查发现早期重放输出中的 `later_profile_edits_preserved=100` 与未变最终哈希不符。实现人已删除该误导性计数，保留 preserved_people 与最终内容哈希；旧 journal 字段仅作兼容，不再解释为用户修改。历史输出中的 100 不能解释成 100 人都发生了后续编辑，也不作为“不覆盖”结论依据。

普通来源当前最多完整处理 2000 名 opt-in 候选，P8 / P1 每批不超过 200；超过容量显式 503，不截断凑结果。独立验收使用实际 100 人，未执行 2000 人负载验证。正式界面、推荐算法、想法关系接合、真实 GitHub OAuth 和 300–400 人规模验收仍属于后续阶段。
