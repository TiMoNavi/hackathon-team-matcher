> 日期：2026-11-12。本轮继续 HumHub 后端实施，三个子 agent 分别完成资料呈现/隐私、想法来源、独立验收，主 agent 集成部署。S7.2 已验收并部署到主预览；原有 100 人资料、前端和模型工作进程保留。

## 交付内容

个人资料现在可以指定学校概览和主主页，额外作品分别展示。选择直接引用本人已确认的原有属性，具体字段仍使用原数据库；选中资料隐藏、删除或主动清空后，相应概览返回空值。长期能力、经历、习惯与当前 Space 的意愿、需求、可用时间分别返回。

参与活动和想法通过独立关系摘要接口呈现。活动只取当前服务端已验证 Space；想法使用正式确认的标题与简介。本人逐对象选择 authenticated/friends/private，默认 private；想法作者的成员展示开关也需开启。正常浏览使用 0 次模型调用。

新模块 matcher-ideas 0.1.0 提供本人私有草稿、正式确认、按 Space 发布/归档、显式关联既有 Messenger 会话及获准详情。一个会话只绑定一个 IdeaActivity；同一长期想法在不同 Space 使用不同活动关联和会话。关联操作核验想法作者、原会话创建者和全部当前参与者的 Space 资格，普通会话不会自动变成想法。

这些接口供后续前端直接接入；本轮没有新增正式页面。想法关注、讨论申请、自动建群及聊天发送不在这批交付内。open_to_discussion 保持 false，现有会话的可读/参与权仍由原生业务控制。

## 权限与一致性

非本人概览和关系入口复用当前活动卡片资格：双方有效账号、正式成员、未屏蔽、资料本人开启发现、存在公开确认昵称。访问者自己关闭发现仍可浏览。概览允许真实好友按现有政策查看 friends 字段，这些字段不会被纳入普通发现筛选。

资料内容、展示选择、活动资格和对象状态在读取时重验。关系分页默认 24、最多 48，签名 cursor 有效 15 分钟，绑定访问者、资料本人、当前 Space、种类、页大小和权限快照。对象归档、退群、离开 Space、隐藏成员或撤回分享后，旧游标/详情入口不能继续暴露关系。

想法关系只返回白名单元数据与 conversation_available 提示，不返回原始 message_id、参与者 ID 列表或消息正文；看到想法简介不会获得聊天权限。来源缺失和超出容量明确报错。
