## 体验与进度层次

前端可以展示“第 3 / 5 阶段，正在准备补充问题”“已处理 4 / 6 题”“画像已生成，等待本人核对”“资料已变化，请重新核对”等动态状态。刷新、退出再进入或 worker 重启后，状态来自后端已保存的资源和任务。

区分两类进度：填写流程是 materials、review、questions、draft、privacy 五个业务阶段及 completed；来源导入和 AI 任务分别提供真实处理状态。阶段序号用于步骤导航，题目计数来自实际答案，长任务的 percent 为 null。模型等待期间提供当前任务与处理阶段，不推测 token 百分比或剩余秒数。

## 兼容接口

保留既有 SessionDTO、SourceDTO、JobDTO 的所有字段，新增 progress 对象。新增三个适合轮询的紧凑 GET：

| 入口 | 作用 |
|---|---|
| GET /api/v1/onboarding/sessions/{id}/progress | 本人会话的步骤、题目计数、当前会话任务、恢复原因与下一步动作 |
| GET /api/v1/me/profile/ai-jobs/{id}/progress | 本人单个 AI 任务的状态、适用性、操作、下一步动作 |
| GET /api/v1/me/profile/sources/{id}/progress | 本人来源读取的状态与最后读取任务摘要 |

紧凑响应不包含画像值、原文、候选正文、模型输入、凭据和内部 JSON 上下文。沿用原生登录、本人归属、有效 Space 资格、private/no-store 和既有错误信封。只读轮询不创建任务、运行模型、抓取资料或推进会话；过期租约回收和撤权沿用现有任务规则。

## Progress v1

统一字段为 schema_version=1、state、phase、label_code、message、updated_at、poll_after_ms、percent=null、next_actions。message 是固定中文提示，不拼接用户原文。next_actions 为稳定动作代码，是前端交互提示；真实提交仍执行现有权限、版本、配额和确认校验。

AI 任务根据现有 operation 与 execution_status/applicability 投影：queued；running 对应 extracting / preparing_questions / composing_profile；成功且仍适用时 ready；失败 failed；取消 cancelled；过期结果 superseded / revoked。失效优先于“成功”，不能将失效结果显示为可使用。仅 current 的 queued/running 推荐继续轮询，默认 1000 ms；其余为 0。失败不自动重试，重试次数达到限制时不提示 retry。

来源任务投影 reading_source / ready / failed，删除和失效继续遵循本人来源规则。导入来源是本人全局资源，不将未绑定来源伪装成当前会话的任务。当前同步读取器不改造成另一套队列，也不声称已经提供流式解析。

会话额外返回 session_id、session_version、scope_key、space_id、stage、stage_index（1–5，完成后仍为 5）、stage_count=5、steps、questions、tasks、reasons、revision_token。questions 返回 total、answered、skipped、remaining、current_index；跳过单独计数，remaining=total-answered-skipped。当前业务步骤和已访问/已完成步骤分别表示，不把曾经到达视作最终确认。

会话 state 为 waiting_input / processing / ready / needs_attention / completed。资料版本变化、答案变更导致草稿过期或 AI 结果失效时，返回准确 reasons 和 reconcile / synthesize 等动作。任务成功只表示待核对结果就绪，完成整套流程仍需原 complete 确认。

tasks 只取该 owner + session_id 的任务，优先当前 queued/running，随后最近历史；总量最多 20，保证已有 active 上限 10 内的任务不被历史挤出。复用 context_json.session_id 与现有 owner 索引实现有界读取，先不增加表或迁移。任务结果在返回前继续校验现有适用性和租约。读取已保存任务不依赖 P6 模型可用。

新完成会话在现有 resource_refs 中保存题目计数与批次版本；旧 AI 完成会话通过 P1 的授权计数用例恢复相同结构，只返回计数、不开放失效题目正文。GET 不回填新元数据。

revision_token 是进度内容的稳定摘要，只用于判断变化，不是可排序版本或写入权限。同一会话仅题目答案变化时，也应因 batch version/计数变化而更新；轮询本身不制造新的进度。客户端可在收到主动动作的响应后更新，再按 poll_after_ms 轮询，终态停止；失败和取消保留明确恢复动作。

## S7.6 验收

- 无 AI 的完整输入、核对、选项/自由回答/跳过、草稿、展示范围与确认；逐步核对进度，普通资料确认不受引导绑定。
- 保存退出后恢复原会话、题目位置、答案和手工草稿；GET 进度不推进步骤，不增加模型或读取器调用。
- 关闭 P6 后规则流程与已保存进度可用；关闭 P2 后 P1/P8 普通资料仍可用；重新启用后恢复原数据。插件开关只作用于隔离环境。
- 来源读取状态、AI 排队/处理中/失败/取消/过期/失效的投影，以合成 reader/engine 和实际持久状态验证；不使用真实网关或读取 .local。
- 本人/他人、有效 Space/已撤销成员、输入变化/旧结果、任务重试、cursor 以外的进度版本变化；不展示不适用结果或私有正文。
- 旧数据升级、重复升级、禁用/恢复与既有资料保持；前端文件、冻结稿、原版 core/Messenger 和原 100 人预览数据保留。
