# S4 独立真实网页验收

> 2026-11-11。独立测试子代理已在隔离环境执行真实 Playwright 网页操作，含追加返回路径回归，最终 **78 项检查全部通过**。主代理负责的部署与整体验收另见 [S4 实现报告](13_S4实现与验证报告.md)。

## 验收方式

测试使用本地隔离数据库、合成用户和两个 Space。主路径通过真实网页按钮、输入框和选择项操作；API 用于读取持久化结果、构造第二会话并发编辑和核对访问拒绝，不拦截或伪造业务响应。浏览器只允许访问当前隔离服务器，记录被阻止的外部请求、JavaScript 异常和 HTTP 500。

范围为 S4 的现有资料与手工输入、规则补问、规则画像草稿、隐私预览和确认。真实简历、GitHub 来源读取属于 S5；本次检查会核对页面如实呈现当前能力。

## 实际结果

最终结果见 [浏览器验收 JSON](sources/s4-browser_2026-11-11.json)。测试使用本机 Microsoft Edge 的 Chromium 引擎，由 Playwright 驱动；桌面视口为 1280 × 900，手机视口为 390 × 844。每次完整重跑均创建新的合成账号。未使用浏览器注入来替代产品交互，也未伪造接口返回。

真实流程涉及三名合成用户：主要用户完成两个 Space 的填写；第二名用户验证纯全局全部跳过；第三名用户验证普通资料与引导之间的并发冲突。第二名用户还用于检查主要用户的私有工作流和实际访客资料范围。

规则会话、问题批次和四条验收流程的画像生成 HTTP 返回均为 generation_mode=rules、llm_calls=0。另核对了 QuestionService、RuleQuestionProvider、RulesProfileComposer 及 P2 服务组装，当前调用链使用本地规则和资料仓储，没有配置模型客户端。浏览器无外部请求是独立检查项，不单独作为服务端零模型调用的依据。

## 联调修正与视觉核对

首轮发现阶段面板读取了错误的 data 属性，造成输入框存在但不可见；修正后从新账号完成全流程。代码核对同时发现旧 disabled 状态可能覆盖更新后的步骤状态，最终浏览器已验证下一题后能返回修改。随后发现本地发布的 JavaScript 仍是旧资源，主代理按 Yii 资源发布规则刷新后，实际 HTTP 脚本更新并恢复正常显示。

主代理复审又发现“已生成草稿 → 返回补问 → 答案不变再次整理”的复用分支可能停留在问题页。领域子代理修复阶段转换后，本测试增加四条真实页面断言，并从新账号重跑全部流程。现在再次整理会回到原草稿，保留全局/Space 草稿 ID、草稿版本和本人刚保存的自述。

完成前的中文呈现复核覆盖沟通习惯、协作方式和活动目标，预览中显示“文字异步沟通”“先明确分工”“完成一个可展示原型”，对应代码继续作为后端稳定值保存。最终断言确认预览未直接显示 async、clear_roles 或 prototype。

已实际查看最终运行的桌面隐私页、手机完成页、重新核对页和返回后复用草稿页截图。全局资料与本次 Space 偏好分组明确，范围选择和最终确认可辨认；390px 完成页内容正常换行。截图仅含合成资料。主代理另外保留了 [桌面隐私页](sources/s4-privacy-desktop_2026-11-11.png) 和 [手机完成页](sources/s4-completed-mobile_2026-11-11.png)，其余隔离运行文件统一清理；JSON 证据保留四张截图的尺寸与校验值。
