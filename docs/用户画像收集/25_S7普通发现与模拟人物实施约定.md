# S7 普通发现与模拟人物实施约定

2026-11-12，已验收。本轮推进 S7.1，并按用户要求生成 100 名明确标记的模拟人物。复用现有 P1/P8 获准批量投影与 matcher-recommendation 的当前活动校验；普通发现使用 0 次模型调用。

## 本轮交付

1. 当前 Space 的显式选择、本人发现设置、普通人物列表与详情 API。当前活动来自已验证的登录会话，访问路径必须与所选 Space 一致。
2. 只用已确认且允许发现的 authenticated 字段筛选和出卡，角色、技能、兴趣、寻找的协作方向及本次可用时间来自已有字段。普通列表保留好友及申请中成员的真实关系状态。
3. 每个 Space 的 discoverable 设置独立保存，默认 false，由本人明确开启；关闭不改变成员、好友和私聊关系。
4. 排序支持 recent / relevance：recent 使用获准卡片 updated_at 与 ID 降序，relevance 使用公开筛选编码的命中数与稳定 ID。普通列表默认 24、最多 48，使用服务端签名的 15 分钟 cursor；读取时重新检查当前活动、成员资格、发现开关和可见性。
5. 用 100 名模拟人物完成真实 MySQL / HTTP 验证，再将这批虚构数据安装到本机专用模拟 Space，保留现有用户资料与既有预览。

## 数据集

固定生成 100 名不同背景的虚构人物，昵称和简介带有模拟标记。全局资料包含能力、经历、长期习惯和偏好；活动目标、贡献、角色、需求、时段按 Space 分开。邮件和作品链接使用 example.invalid / example.org 等示例地址，测试不发送外部消息或模型请求。

主模拟 Space 包含这 100 人，其中 20 人同时加入第二个模拟 Space 并填写不同活动上下文，用于验证切换。发现开关、private/friends 字段、部分未确认资料和稀有技能设置为固定边界样例。模拟人物按显式测试标记重复安装，不能通过重名覆盖真实用户。

## 后端接口

以下接口使用原生登录会话。写入需 CSRF，响应使用 data/meta 与统一 error 结构，设置 private, no-store。普通发现不创建模型任务。

| 方法与路径 | 请求或结果 |
|---|---|
| GET /api/v1/me/current-event | 读取本会话当前 Space；未选时返回 409 CURRENT_EVENT_REQUIRED |
| PUT /api/v1/me/current-event | space_id 和 expected_revision；首次选择使用 null，之后使用上次 selection_revision |
| GET /api/v1/me/events/{spaceId}/discovery-settings | 本人该 Space 的 discoverable、version；无记录时 false / 0 |
| PUT /api/v1/me/events/{spaceId}/discovery-settings | expected_version 与布尔 discoverable；版本冲突返回 409 |
| GET /api/v1/events/{spaceId}/discovery | 当前 Space 的人物列表，接受 target_type=person、filters、sort、limit、cursor |
| GET /api/v1/events/{spaceId}/discovery/people/{ownerId} | 与列表相同的当前 Space、资格、开关和可见性验证 |

**filters** 是一个 JSON 对象。role、skill、interest、direction、event_role 接受编码数组；event_seeking 接受 role_codes / skill_codes 数组；event_availability 接受 starts_at / ends_at 时间段数组。同一字段多编码按任一命中，不同字段同时满足；时间按 UTC 合并相邻区间后检查完整覆盖。单个编码列表最多 30 项、时间段最多 20 项，拒绝未知字段或用 JSON 对象伪装数组。

**排序与翻页**：recent 使用获准可见字段和确认身份的最新确认时间，再按 owner_id 降序。relevance 按本次请求中公开筛选编码的命中数排序，再按 owner_id 降序；它表示查询符合程度。默认每页 24、最多 48；cursor 签名绑定本人、会话选择版本、Space、筛选、排序、页大小与当前获准快照，有效期 15 分钟。变更条件或权限后重新请求第一页，过期返回 410。

**卡片**包含 owner_id、space_id、display_name、identity_version、avatar_ref、global、space、updated_at、relationship、discovery_version、privacy_policy_version。身份来自已确认的公开昵称/头像；没有公开确认昵称的成员不会获得替代身份卡。字段来自 P8 明确白名单，只读取 confirmed + authenticated；联系方式由其独立接口控制。已有好友和申请中成员保留，relationship 返回原生真实关系。

**完整扫描**：每批最多 200 人，覆盖当前 Space 内全部符合候选资格的成员后再筛选、排序、分页；上限 2,000 人，超过时明确返回 503。返回前再次核对当前上下文与获准资料。此边界是保护预算，性能结论按实际验收样本单独报告。

## 存储与模块接合

P1 升至 0.8.0，增加已确认身份批量读取端口，复用现有资料与原生身份表。P8 继续为 0.1.0，发现白名单版本改为 discovery-fields-v2，加入 event_seeking。matcher-recommendation 0.2.0 接合普通列表、本人 Space 选择和发现开关，规则推荐及 AI 仍沿用独立配置。

新的 matcher_recommendation_discovery_settings 以 owner_id + space_id 为主键，保存本人独立开关和版本；不会把活动偏好移进全局资料，也不会复制一套画像。原有服务端选择表绑定登录会话。P1 的通用 /me 路由前保留两个新路径，覆盖模块注册先后顺序；路由参数和用户 query 分开处理。

## 验收口径

普通发现覆盖空结果、最后一位人物匹配、多值字段、完整时段覆盖、分页、开关关闭、权限变化、切 Space 与详情重验。本轮 100 人结果不冒充 S7.3 原定 300–400 人的规模验收；正式前端、想法关系接合与 AI 推荐算法保持各自阶段。S7.1 已完成并部署；完整结果见 [主报告](26_S7普通发现与模拟人物验证报告.md) 与 [独立验收](27_S7独立验收.md)。
