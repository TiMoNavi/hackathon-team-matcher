# S2 资料服务实施约定

> 2026-11-11，依据本轮用户要求。实施代码沿用 matcher-user-profile；本目录保存需求、任务和验收记录。

## 本轮规则

普通画像与联系方式均可按需填写；填写某条记录后校验其必要内容，例如项目标题、联系电话格式。已确认资料默认 visibility=authenticated，即登录用户通过合法画像入口可见。源文件、未确认草稿和上传候选仍属于本人编辑过程。新默认值用于新增/新确认条目，既有明确设置的范围保留；逐条隐私配置和更完整的好友策略交给 S3。

新增六类全局可选联系方式：contact_wechat（微信号）、contact_wechat_qr（微信二维码资源引用及说明）、contact_qq（QQ 号）、contact_phone（联系电话，主号码复用 profile.mobile）、contact_email（主动填写的联系邮箱）、contact_other（其他联系入口，可多条）。二维码使用经校验的本人上传资源；登录邮箱与联系邮箱分别维护。现有条目表承载这些字段，保持首批四张核心表。

## 全局与 Space

性格、沟通习惯、长期协作偏好、技能、经历和联系方式保存为 global。本次目标、希望角色、需要帮助、投入时数、具体可用时间、现场/远程安排保存为 space:<id>。新 Space 的专属字段从空上下文开始，由本人填写；切换 Space 时继续复用全局资料。

产品口头的“活动”对应 HumHub Space。event_* 逻辑键和 event_id 的兼容接口继续映射到 Space；Calendar 只是空间内的赛程模块。Space 资格使用正式成员状态，读取、编辑和确认时均重新验证。

## S2 的对外服务

ProfileService 是框架无关的应用服务，使用仓储和访问策略接口，提供 getProfile、startDraft、getDraft、updateDraft、confirmDraft、reconfirm、getRevision 和 adminProposal。数据库适配负责真实事务、state/draft 行锁、原生单值写入、扩展条目、不可变快照及提交后刷新。

资料返回 scope、space_id、revision、permission_version、attributes、field_definitions、policy_version 和编辑草稿状态。条目包含 attribute_id、key、value、visibility、confirmation、last_confirmed_at。昵称与头像使用独立 identity_version。

草稿 fields 是显式操作列表：upsert 为默认操作，已有条目携带 attribute_id，新条目由服务端分配；delete 必须携带已有 attribute_id。省略字段保持现状。更新比较 draft_version；确认同时检查草稿版本及 base_revision。重复确认同一版本返回同一确认结果；不同内容或旧版本返回 409。

普通用户身份由服务端登录会话确定。本人草稿、历史和上传候选只接受本人访问；admin_proposal 由管理员创建、资料本人采纳。所有写用例检查维护状态。原生资料编辑和用户时区编辑进入统一版本用例，管理员资料修正形成建议草稿。

## API 与资源

统一使用 /api/v1。提供本人资料、草稿读取/创建/更新/确认、重新确认、历史版本和 Space 上下文接口；身份使用 PATCH /me，头像使用 POST /me/avatar。额外提供 POST /me/contact-qr 上传微信二维码。文件只接受有界 JPEG/PNG/WebP，按实际内容检验并重新编码。头像生成 1024 和 256 两个版本；二维码保留可辨识图像。资源候选在本人确认之前仅本人可读。

S2 提供当前 Space 合法成员之间的确认画像读取，用于验证默认可见的资料和联系方式。完整的好友、公开帖子入口与逐条隐私投影在 S3 接入。API 使用一致 JSON 成功/错误包装，测试覆盖未登录、越权、CSRF、参数错误、版本冲突、跨 Space 访问及资源归属。

## 分工与验收

应用服务与内存用例、SQL/原生适配与迁移、HTTP/身份与媒体适配分别实现。父代理执行合成资料的接口和并发验证，并核对实际部署与既有资料。S2 完成后更新 task.md 并在本目录交付实施报告。
