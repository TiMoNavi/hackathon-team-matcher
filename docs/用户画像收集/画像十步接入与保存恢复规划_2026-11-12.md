# 画像十步接入与保存恢复规划

2026-11-12。本文是 V5 原型接入真实业务的执行规划，尚未修改原型、实现新接口或完成浏览器验收。前端规划子任务中断后，由 root 汇总已核对材料成稿，交同型号独立 agent 复核。依赖与分工见[总计划](画像接入总计划与并行协作_2026-11-12.md)，真实后端签名与缺口见[后端能力差异](画像接入后端能力与差异_2026-11-12.md)。

最新原型材料为工作区 `frontend/用户画像收集——前端/docs/11_范围切换与紧凑填写.md`、`12_添加条目与个人照片.md` 及该目录 `lib/onboarding/model.ts`、`components/onboarding/`。它们含另一团队尚未单独发布的修改，本批不代提交。原型的本地保存、计时任务、示例活动和社交布尔值均不作为真实业务证据。既有[40号V4对照](40_画像前端V4与后端能力对照.md)保留，不能代替本次 V5 核对。

## 1. 保留界面，替换数据与动作

保留 V5 顶部分类、紧凑段落、左侧简介、长文专注编辑、添加条目和照片位；继续使用用户已选择的 AffectUI 与 Shadcn UI Kit，不引入其他组件来源。正式实现以业务适配层接同源 HTTP、原生会话和 CSRF；不复制用户、当前活动、好友或消息事实。共享导航、客户端、样式入口和构建资源只由交接后的单写者集成。

原型 `Draft` 中的 `profileConfirmed`、`savedFinal`、`completed`、`matches`、`pendingFriends` 等只能用于演示；真实页面分别读取各对象的服务器状态与回执。当前 `JOB_STEPS` 中“合并已确认的资料”等演示文案也须按新私有核对阶段重映射，不能因为文案存在而在 G03 调用正式确认。

## 2. 十步逐项接入

| 步骤与现有名称 | 页面动作与服务器事实 | 保存、返回与失败行为 | 实施批次 |
|---|---|---|---|
| G01 提供资料 | 先读本人来源能力、已有来源及首次 GitHub 导入状态；上传简历、主动选择已有来源或手填 | 源未就绪逐项显示；允许使用成功材料或手填。普通登录/刷新不再次抓取，不要求 GitHub 用户重贴主页 | N07-A |
| G02 整理信息 | 只有明确发起处理才提交 rules 或 AI；区分同一 HTTP 内执行的来源 reader 与真实 AI 队列 | 保存 source/job/draft 引用及版本；离页/超时先重读实际来源或任务状态，不承诺来源自动续传/恢复执行，不用定时器宣布完成。取消订阅与业务取消分别处理 | N07-A；AI 为 N07-B |
| G03 初步核对 | 编辑重复段落、标题、分类、身份建议；保存私有草稿及核对快照 | 仅本人可见，旧正式资料继续有效；禁止调用现有 review_confirm 或 PATCH /me 来完成本步。快照绑定草稿、来源、会话和基线版本 | N06-A/B → N07-A |
| G04 补充偏好 | 从核对快照准备真实问题批次，按 question_id/option code 保存答案、跳过和当前位置 | 返回修改输入使旧问题/合成失效；保留已存答案并显示需重核对，不靠题目文字匹配。现有自由回答上限1,000字符，长文另存段落草稿 | N06-A/C → N07-A/B |
| G05 确认画像 | 显示最终草稿与本人/登录用户/好友预览；用户明确确认所选条目与范围 | 保留 P2 同一工作流内 global/Space 草稿确认的既有事务与各 scope 版本；身份等跨领域操作用独立版本和回执，不误拆原有原子性，也不假设新的跨域原子提交 | N07-A |
| G06 讲讲想法 | 复用正式想法草稿入口，多个想法独立 ID；探索方向与项目想法如实区别 | 保存引用与版本，不写进画像字段或本地成功标志；未连接时明确状态，可保存离开，不假装已完成 | 对应领域完成后 N11 |
| G07 完善想法 | 手动完善为基础；可选整理按想法领域实际能力执行 | 没有 AI 能力仍能编辑；结果保持草稿，用户逐项确认。取消/失败不自动建群或发布 | 对应领域完成后 N11 |
| G08 最后确认 | 聚合资料、身份、想法和活动设置引用；按对象确认并显示逐条可见性 | 不重交已成功对象；部分失败只处理失败项。预览不等于发布，完成引导不等于入群/加好友/发消息 | N06-C 合同；N11 真实接线 |
| G09 本活动寻找 | 推荐团队提供唯一当前活动、普通发现和可选推荐的真实结果 | 候选不足如实显示；不借他活动或示例人物补齐。普通发现0新增模型调用，AI预算失败明确显示 | 推荐团队验收后 N11 |
| G10 遇见同伴 | 聊天/社交团队提供申请、接受、会话和消息的真实动作及回执 | 卡片浏览不发送申请；发送须本人操作。切活动保留合法好友/私聊，想法讨论的成员和消息按活动隔离 | 聊天团队验收后 N11 |

N07-A 的真实前五步不是整个 S7.4 或十步完成。N07-B 为可选画像 AI；N07-C/S7.5 为开场呈现、暂停/静态/键盘路径，独立于 P6 可用性及模型预算。实际放行仍遵守 N04 真实双登录 → N05 活动桥 → N06 所依赖能力实施验收，不能用合同定稿代替接口存在。

保留“什么都不填，先去看看”与保存退出分支，未完成引导不阻止具备资格的普通业务；未填也不伪标完成。无当前 Space 时可以进入已有全局资料编辑，活动发现/推荐及活动专属写入明确要求选择合法活动，不自动选择示例活动。这里的批次前置是本次新旅程接入的验收依赖，不是对现有普通业务新增引导门槛。

## 3. 条目、分类与联系方式

V5 的分类 `scope` 仅用于基本介绍、作品经历、技能偏好等界面分组；持久化 global/Space 归属及 authenticated/friends/private 是另两种语义。适配时使用明确的分类字段，不让同一属性兼任三者。分类切换只过滤；改标题、排序或分组不得改变安全类型、数据归属或授权。

每条重复/自定义段落有稳定服务器 ID，新增未同步项可有临时客户端 key，并在成功后明确映射；禁止按标题或数组下标覆盖已有记录。取消新增不产生空记录。拟新增段落类型须有完整正文、标题、分类、顺序、版本和来源引用合同，不把任意长文强塞旧有限 bio 字段。

单段20,000 Unicode字符完整往返，保留换行与emoji；分别验证单段字符、序列化字节、总条数及存储容量。精确20,000与20,001边界需真实测，原型19,000字证据不能替代。保存可按完整段落分批，服务器逐批校验版本，页面准确显示哪些尚未保存；超限不截断。

新增已确认普通条目和可选联系方式默认 authenticated，旧明确范围保留；所有未确认草稿私有。联系方式保持服务器类型/用途和独立 contact 投影，改名“关于我”或改分组也不能进入普通摘要。通用文本不承诺自动识别每个电话号码；类型转换和导入映射必须有明确规则，不能靠模型推测决定授权。

本人/登录用户/好友是服务器模拟预览，不是访问凭据。侧栏昵称、简介和照片按相应对象真实可见合同展示，其他视角不出现添加、更换或编辑控件。authenticated 仍需合法读取入口，friends 动态核验有效关系，活动内容再核验 Space 资格；本人预览不能绕过真正访问者授权。

G08 的本人活动控制设置及对应目录项在登录用户/好友预览隐藏；获准的 Space 资料字段仍按服务器投影显示。控制设置和可分享的活动资料是不同对象，不能一起公开或一起隐藏。

## 4. 昵称与照片

G03 保存待确认昵称、候选 avatar_ref 或移除意图以及 identity_version 基线；这项私有身份草稿合同尚需新增。昵称按既有2–32字符约束，不能和20,000字符正文混用。原型本地 data URL/750,000字符照片缓存不作为正式媒体引用。

真实上传沿用服务器5MiB、JPEG/PNG/WebP和受控候选能力，服务端生成主图与缩略图。上传成功只产生本人候选，不立即公开；G05 才用明确动作更新正式身份。更换失败保留旧头像；移除也须区分私有意图与正式已移除。身份冲突保留待保存输入，重新读正式版本供本人处理，不伪报所有资料均成功。

## 5. 服务端恢复与上下文

旅程拟新增持久状态只保存 owner、当前步骤/位置及受控资源引用、版本和各对象回执。资料、来源、问题、AI任务、想法和活动设置仍属于原领域，不复制整份浏览器 Draft 成为第二套真相。资源引用由服务端验证本人、scope、Space、状态和版本，不接受任意内部对象拼接。

| 场景 | 必须读取或保留 | 禁止行为 |
|---|---|---|
| 首次进入 | 身份、本人已有草稿/正式修订、来源与能力；本会话有效当前活动 | 每次挂载自动建会话、导入或发模型请求 |
| 主动重编辑 | 新私有草稿引用及旧正式基线；本人明确选择使用的资料 | 普通浏览、改可见性或切活动隐式开启重编辑 |
| 刷新/返回/另一设备 | 服务端旅程、原问题批次、草稿版本、任务 current 状态及逐对象回执 | 用本机 completed/profileConfirmed 证明服务器成功 |
| 网络超时 | 未确认保存的输入；读取对象真相；支持幂等的端点复用原键与原payload | 对不支持幂等的旧端点盲重试，或换键重复确认 |
| 版本冲突 | 最新版本、用户未保存的差异及可处理错误 | 静默覆盖新版本、清空长文或假报已保存 |
| A→B及A→B→A | 当前选择版本、授权版本、发起请求时scope及草稿版本；B自己的上下文 | 将A响应/草稿/任务采纳进B，或只靠取消HTTP替代服务端重验 |
| 登出/换账号 | 清本账号私有内存、取消订阅；必要的离线缓存必须账户隔离 | 新账号读取前账号原文、照片、任务或回执 |
| 删除来源 | 当前源/证据/任务授权和删除结果；已明确采纳条目另行处理 | 自动重抓已删来源，或默默删除全部已确认画像 |

当前活动按用户与认证会话保存，并非跨设备共享值。另一设备先读取本会话当前选择，缺失时明确选择；旅程旧 space_id 不自动切换活动。A的已保存私有草稿可以保留，返回A仍重验成员、来源、输入版本及任务适用性。现有 P1 成员检查/P2 AI context 尚无完整 selection_revision/access_version 绑定，这是 N05/N06 待补能力。

未保存文本必须显示“未保存/保存中/保存失败”，只有服务端回执到达才显示“已保存”。关闭页签或离线不能保证异步写必然送达；不得靠浏览器卸载事件宣称跨设备可恢复。

## 6. 异步任务与错误呈现

现有 rules 问题准备和合成返回201 SessionDTO，AI返回202 JobDTO；客户端按实际返回类型读取问题批次/输出草稿，不假定统一 job。新私有核对输入合同完成前，不能给旧请求增加未知字段或提前确认以绕过缺口。

progress 只反映已有状态，按 poll_after_ms 调度；终态、离页和身份变化停止订阅。percent=null 使用不定进度，不伪造百分比或倒计时；暂停开场动效不等于暂停服务器任务。execution_status 与 applicability 分别呈现，superseded/revoked 优先于 succeeded，失效正文不可显示或采纳。

普通读取/保存恢复不新增模型调用，但响应可包含历史累计用量。失败不自动重试，不静默切rules；用户可明确选择重试或手填/rules。画像默认每owner2个current活跃任务、UTC日20个新任务、链首次加最多2次显式重试，实例配置另验；不要套推荐run额度。中断未知用量保持null。

全文保存不承诺全文AI处理。现有来源段32KiB、采集文本合计64KiB、AI输入128KiB/结构化输出64KiB等边界不能直接扩成任意20,000字符；只提交明确选定且版本匹配的片段，显示未处理范围。不得自动分拆成多次收费请求或静默截断后声称已理解全文。

错误区分认证失效、权限撤销、版本冲突、请求超限、能力不可用、预算不足与网络结果未知。保留可修正输入，错误显示在具体条目旁；日志只保存安全错误码/请求标识，不记录正文、邮箱、验证码或私有媒体。部分对象成功时显示其真实回执，只重试失败对象。

## 7. 前端文件与可执行验收

实现开始后，画像适配单写者负责领域DTO映射、旅程状态和来源/身份/预览组件接线；共享宿主写者负责挂载、导航、全局CSS和最终资源发布。推荐和聊天模块只消费其团队交接的真实组件/接口。实施前重新核对各文件写者，不覆盖当前 V5 原型或他队首页增量。

| 验收组 | 需留存的证据 |
|---|---|
| 前五步真实闭环 | 普通本人上传或手填→私有核对→规则问题→预览→确认→普通资料页读取同一正式结果；0新增模型调用 |
| 长文与条目 | 精确20,000字符、中英文/emoji/换行、同名重复、自定义标题、删除/排序/分类、分批失败恢复；服务器往返不丢字 |
| 照片与身份 | 私有候选恢复、未确认不公开、坏文件/过大/上传失败保留旧图、移除、独立版本冲突 |
| 权限与活动 | 本人/合法登录陌生人/好友/匿名/被屏蔽/失效成员，contact独立投影，A/B切换和撤权后的晚到结果 |
| 恢复与部分失败 | 刷新、返回、跨设备、换号、网络未知、版本冲突；G08成功对象不重复提交；旧任务不得覆盖新稿 |
| 视觉与交互 | 1440/768/390/320、日夜、长文展开/专注编辑、无意外横溢、可缩放、至少44px操作目标及手机16px输入；虚拟键盘/角色不遮输入和保存按钮；关闭专注编辑恢复位置与触发焦点，减少动效 |
| 表单可访问性 | 输入有标签；字段错误用aria-describedby关联；提交失败焦点到可聚焦错误摘要且可跳转具体字段，不仅toast/红框；不在每次输入时抢焦点；中文输入法组词中的Enter不触发发送或提交 |
| 开场与进度 | 暂停/静态/键盘路径在无AI时可用；真实progress和未知值准确显示；动画结束不伪报业务成功 |

交互审查使用 ui-ux-pro-max 的既有界面与表单指导，本地定向检索命中 Web 的 Focusable Error Summary、Error Messages、Error Placement；不据此宣称应用通过无障碍验收。本轮未运行浏览器、构建、业务HTTP或模型。后续分别记录静态、合成、真实HTTP、浏览器及外部请求证据，N04和N05未放行前只推进准备工作。
