# S3 原生出口适配登记

更新日期：2026-11-11。

本文记录当前本地 HumHub 免费模块包体中的资料展示、搜索、通知及导出出口。总体验收见 [S3 实现与验证报告](10_S3实现与验证报告.md)，规则见 [S3 实施约定](09_S3实施约定.md)。

## 1. 适用包体

以 [S3 启用清单](sources/s3-baseline_2026-11-11.json) 为基准，第三方模块为 Calendar 1.9.9、Clean Theme 2.5.3、Gallery 1.9.1、Link List 0.9.2、Messenger/mail 3.4.6、PDF Viewer 1.1.8、Questions 1.1.6、REST 0.12.7、Text Editor 1.2.0，另有资料插件 P1 和本阶段隐私插件 P8。

Online Users、Suggested Following 等未启用模块不在本次兼容验证范围。后续启用模块或升级版本时，应重新检查其直接读取原生资料、搜索用户、生成通知、序列化和导出的位置。

## 2. 共同规则与接入方式

- P1 保存确认字段与独立草稿；P8 根据访问者、字段范围、入口及实时关系返回可见投影。
- 普通资料详情通过已验证 Space、合法公开帖子作者入口、好友入口或本人入口访问。Space 是产品中的活动，Calendar 是空间内的赛程。
- 原生字段仍保留在原数据库。有效旧值先进入仅本人可见、未确认的迁移草稿；已有编辑草稿时推迟迁移。
- 昵称读取已确认身份，副标题和人物列表使用摘要投影。好友限定字段不会作为公共搜索关键词或列表摘要。登录邮箱用于账号与邮件投递，联系方式从确认后的资料项读取。
- 兼容代码放在 P8 内，通过控制器映射、依赖注入、事件和 Yii classMap 接入。没有修改 HumHub core、vendor 或原版第三方模块文件。访问者可见结果不写回数据库或共享 User 实例。

入口为 [NativePrivacyHooks.php](../../backend/protected/modules/matcher-profile-privacy/adapters/native/NativePrivacyHooks.php)。classMap 兼容文件保留对应版本主体，升级 Calendar 或 REST 时需要对比上游变化并重跑回归。

## 3. 原生页面、发现和关系

| 原生出口 | S3 接入 | 验证范围 |
| --- | --- | --- |
| Profile About、副标题、资料字段 | NativeProfileController、NativeProfilePresenter；正文和联系方式分别请求投影 | 实际验证好友字段可见、private 字段及定义不可见、联系方式独立读取 |
| People、搜索、自动补全 | NativePeopleController、NativeSearchController、NativeUserSearchProvider、ScopedPeopleQuery | SQL 先按当前 Space 成员过滤，再搜索和分页；无 Space 返回空，无权 Space 拒绝；隐藏姓名和好友字段不命中 |
| PeopleDetails 通用 Twig、标签 | NativePeopleDetails、NativePeopleTags | P8 摘要替换任意原生字段读取，浏览器真实点击验证见第 7 节 |
| 元搜索缓存 | UncachedProfileMetaSearch | 不复用原生 180 秒 User 结果缓存，避免范围或关系变化后返回旧结果 |
| People、头像、Post 作者、Profile 菜单链接 | NativeProfileLinks；People 显式生成带 Space 的 About 链接 | 真实链接保留上下文，公开帖子使用准确 Post.id；33 项浏览器检查通过 |
| ProfileField 显示、搜索、目录过滤开关 | PrivacySchemaInstaller、protectLegacyFields | 原值保留，旧出口开关关闭；管理员修改开关也不能重新开放原始资料出口 |

关系由 [NativeProfileRelations.php](../../backend/protected/modules/matcher-profile-privacy/adapters/native/NativeProfileRelations.php) 实时读取。测试覆盖正式成员与申请人、好友申请与双向好友、好友模块关闭、双向拉黑、Space 拉黑，以及 REPEATABLE READ 下已撤回范围和成员关系不会被旧快照恢复。

## 5. 通知与邮件

以下位置经过源码检查，用户可见姓名从统一 displayName 获取：

- Gallery：notifications/MediasUploaded.php。
- Questions：notifications/NewQuestionNotification.php、AnsweredNotification.php。
- Calendar：notifications/CanceledEvent.php、EventUpdated.php、ReopenedEvent.php、ParticipantAdded.php，以及 widgets/mails/views/eventInfoHtml.php、eventInfoText.php。
- Messenger：models/MessageNotification.php 的通知正文和发送者名称，以及 widgets/views/conversationEntry.php。

Messenger 使用账号邮箱向本人投递通知，这不是对外联系方式展示，因此保留。本检查没有发送真实邮件或通知，不代表外部 SMTP 验收。

## 6. 原生管理能力边界

REST 完整原生账号定义仅在明确的 rest/controllers/user/UserController 管理路径，且当前账户具有 ManageUsers 权限时保留。管理员访问普通展示路径也使用资料投影。

RestUserDefinitions 的鉴权、密码、会话、分组等原生辅助方法保留，由原生控制器鉴权。管理邀请的目标邮箱属于管理员邀请流程，未新增普通用户读取入口。

集成验证包含管理员明确账号管理仍可用、管理员普通路由没有账号邮箱绕过。这不等同于所有 REST 管理操作的端到端回归。

## 7. 回归证据

[s3_native.php](../../backend/protected/modules/matcher-profile-privacy/tests/integration/s3_native.php) 在隔离 S3 库完成 **57 项通过**，包含数据库查询、原生 Messenger 模板、ICS 生成、REST 定义和迁移。

真实入口用例 [s3_entry_links_browser.cjs](../../backend/protected/modules/matcher-profile-privacy/tests/integration/s3_entry_links_browser.cjs) 完成 **33 项通过**，覆盖 People 卡片、公开 Post 头像和姓名、Space/public_post/friendship 标签往返、About 菜单、好友字段与联系人、非好友裸入口拒绝、公开作者入口不扩大 People，以及正文和时间链接保持原行为。浏览器未请求主预览 8090 或外部地址，也未出现 500。

共同持久化修改另在独立 S2 前缀库运行未修改的四个 runner，SQL **28**、native **25**、concurrency **10**、timezone race **4**，合计 **67 项通过**；根任务另行复验并保存 JSON。这些检查覆盖状态锁、原生字段写回、身份存储和并发行为。

测试使用隔离库和合成数据，本子任务未修改主预览库或发送外部消息。根任务的 HTTP、浏览器、迁移与部署验收，以 [主报告](10_S3实现与验证报告.md) 及证据文件为准。
