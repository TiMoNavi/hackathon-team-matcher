## 真实业务链路

使用独立创建的三个合成账号和既有隔离 Space，顺序验证了以下行为。

1. 四类来源能力同时存在。匿名请求不能读取来源，写操作需要实际登录、CSRF 和幂等键；web 与 text 拒绝不属于其类型的字段、伪造 owner_id 和 visibility。
2. 粘贴来源保存中文、换行、段落定位和明确字段候选。所有候选证据都指向同一快照内的段落；ownership_basis 明确为 self_declared。
3. 来源刚导入时不更新确认资料。本人必须逐项采纳候选；已有手填介绍和 private 范围保持，新条目沿用 authenticated 默认范围。
4. 其他账号不能读取、刷新、删除或采用该来源。来源列表省略快照正文，详情响应设置 no-store。原文中未被采用的合成标记不会进入草稿或获准个人资料。
5. 相同请求重放与相同文本重导入复用来源；复用幂等键提交不同文字返回冲突。文本刷新要求原内容，不能用改写文字替换原来源身份；刷新生成新版本，旧版本不能继续采纳。
6. 删除来源后详情不可读、不可继续采纳。直接 SQL 复查确认旧版和刷新版快照均已物理清理，来源身份清空，相关任务为 revoked，任务回执只含引用和结果状态。
7. 已明确采纳的字段继续保留在普通编辑草稿中。随后通过 review 明确确认、规则补问、规则生成、展示范围确认，完成整套流程；本人 private 介绍在其他 Space 成员读取时保持隐藏。
8. 切换到下一个 Space 后，全局已确认项目保留，新 Space 专属资料为空，没有把本次活动偏好写进全局来源。

HTTP 服务没有注入网站网络传输。该组实际走通的是 text 来源；其中危险 URL 请求在输入验证时被拒绝，未请求对应地址。网站来源的完整 HTTP 组合由主 agent 在另一隔离环境验收，不能把两组结果混称为同一次网络测试。

## 网络和解析检查

危险目标全部使用固定 DNS/HTTP 夹具，没有尝试访问本机服务、云元数据、内网或用户私有材料。

- 拒绝回环、私网、共享地址、链路本地、文档地址、保留地址、多播、IPv4 映射 IPv6、NAT64 和转换地址等输入；同时确认普通公网 IPv4/IPv6 可以通过地址策略。
- 拒绝数字别名/IP 字面量、凭据型 URL、非 HTTP(S) 方案、非标准端口、控制字符、无效转义和本地域名。URL 规范化和相对跳转保留明确的原目标语义。
- 同一 DNS 回答混入私有地址即整组拒绝。每次跳转重新解析验证，同主机下一跳变成私有地址也不能继续连接；跳转次数、累计字节和总时间受限。
- 实际 cURL 适配器以 CURLOPT_RESOLVE 固定已批准 IP，保留域名用于 TLS 主机验证，并复核真实连接 IP；自动跳转、环境代理和 netrc 关闭。请求不携带 Cookie、Authorization 或表单内容。
- 实际传输回调拒绝超限响应、超限头部、重复敏感响应头和控制字符。网络故障与超时只暴露稳定错误码，不输出底层诊断原文。
- DOM 解析不执行 JavaScript，不加载外部资源，去除脚本、样式、表单、模板、导航及明确隐藏节点。内部实体声明和过密标签在 DOM 解析前被拒绝；中文编码、长行切片与证据定位保留。
- 网站 canonical_url 保留规范化后的提交目标，跳转终点仅进入 metadata.final_url。identify 和 status 不联网，文本处理不联网，所有处理不调用模型。

## 解释清楚的限制

HTTP 401/403 返回明确访问失败。HTTP 200 的静态正文可能只是登录提示、验证码或反爬说明，当前解析器不判断这类页面的业务含义。独立测试实际验证了一个带 password 表单的 200 登录提示页面仍会留下可读提示文字；这些文字只形成本人未确认来源，仍需审核，不能当成已经识别并绕过了登录墙。

解析器处理静态 HTML，不执行页面 JavaScript、不渲染 CSS。hidden、inert、aria-hidden 和明确的内联隐藏样式会去除；外部样式表或 class 导致的可见性没有浏览器计算结果。因此动态个人站点可能没有可用正文，复杂页面也可能需要改用文本粘贴。

ownership=self 是用户对来源描述本人的声明，不是域名控制权证明，也不是事实核验。读取成功不自动发布资料，候选仍需本人采纳并确认。此次验收没有测试 AI 提取、模型精排、真实 GitHub OAuth 回调或新的 React 主前端。
