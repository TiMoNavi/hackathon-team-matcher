## 测量口径

所有性能采样顺序执行，避开数据安装和独立权限测试的数据库写入。使用同一个 321 号访问者、Space、400 人数据和查询参数，每个场景重复 3 次，报告中位数与原始样本。这是本机 PHP 开发服务的单客户端测量，尚未覆盖生产并发。

HTTP 时间包含请求、服务端会话/当前 Space 校验、查询、序列化和响应传输；CLI 用例测量通过固定的可信选择适配器调用正式 BrowsePeople，不含 HTTP 与会话选择查询。两者分别报告。

SQL 返回行数包含重复授权读取；Handler_read 计数表示数据库引擎读取操作；EXPLAIN rows 是优化器估算。这三项分别标注，不作为精确 rows examined。已有推荐索引尚未接入普通发现，不能据此宣称普通筛选已采用推荐索引。

## 索引与扫描证据

对实际属性 SELECT 的 default / USE INDEX / IGNORE INDEX 三组只读对照返回相同结果。当前查询形态下，属性表均为 ALL、key 为空；现有 state 索引未改变这组计划，尚无依据增加或强制生产索引。推荐专用索引仍未接入普通发现。

EXPLAIN ANALYZE 的属性表迭代节点实际读取 20,559 行，指一个 200 人批次的代表性属性查询，不是整个请求的 rows examined。完整请求另存各类 Handler_read 计数，不能与迭代行数或返回行数混称扫描量。

MySQL 当前默认 EXPLAIN 输出为 TREE，测量工具首次将其按表格解析，导致估算计划为空。已保留原测量记录、使用 FORMAT=TRADITIONAL 补采计划，并保留原基线耗时；这是测量工具修正，不是生产查询优化。

后续性能工作应先稳定测量环境，再针对批量资料装载、字段筛选与排序建立独立优化任务，保持当前 Space、获准字段和版本重验。当前证据不能用于承诺生产并发容量或快速响应。

## 独立验收

[真实 HTTP / MySQL 验收](sources/s73_audit_http_2026-11-12.json)通过 173 项断言、228 次 loopback 请求。全列表分别按 24 / 48 返回 15 / 8 页，39 组筛选共遍历 95 页，名单、顺序和获准字段逐一与独立 Python oracle 对照。主 Space 359 人、第二 Space 71 人完整出现，无重复或漏项，末尾稀有技能可找到第 400 人。

验收覆盖多值编码、需求数组后续项、不同字段 AND、同字段 OR、时区等价、相邻/重叠区间与完整覆盖；实际修改发现开关、昵称可见性、好友/申请、屏蔽、成员和账号状态后，详情及旧 cursor 均按当前权限重新校验。随后恢复合成账号的业务状态，资料和权限版本保持递增。

消息会话 4、参与者 9、消息正文 0、通知 2、队列 0、AIJob 0 在验收前后相同。本轮普通发现与验证均为 0 次模型调用。另有 272 项独立纯规则核对、6 项目标保护和 72 项性能证据审查；具体范围见 [33 S7.3 独立验收](33_S73独立验收.md)。

功能验收的混合请求耗时只用于描述此次运行，不与固定场景性能采样直接比较；900 秒 cursor 过期由既有可控时钟用例验证，不声称本轮进行了 15 分钟真实等待。
