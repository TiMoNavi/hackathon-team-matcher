# S5 GitHub 与简历导入实现报告

2026-11-11。S5-A 的 GitHub、简历两个来源插件及原画像流程集成已完成，并部署到本机 HumHub 预览。独立 Playwright 56 项、主预览部署后只读 49 项检查通过。

## 用户现在可以做什么

从“画像填写引导”选择填写范围并开始，第一屏提供 GitHub 与简历入口。已有 GitHub 登录关联时，服务器取得关联的稳定用户 ID，再确认当前 GitHub 名称和主页地址，用户无需填写用户名或链接。首次开始填写时读取一次；已保存来源直接复用，再次登录、刷新页面不会自动重新抓取。本人删除过来源后，也由本人明确重新导入。

简历支持有文字层的 PDF、DOCX、Markdown 和 TXT。上传后展示结构化文本、段落和明确字段候选；用户选择要带入的内容，进入同一份引导草稿，再继续“核对信息 → 几个补问 → 编辑画像 → 范围与确认”。未能直接映射的内容保留在本人原文预览中。

采纳会保留既有单值与手填，跳过相同条目。两份材料可以补充同一资料草稿，用户在核对页继续修改。来源读取和采纳本身不更新已确认资料，也不公开原文；最终展示仍走原 P1/P8 的逐条范围规则。

## GitHub 读取范围

原生 auth-github 在 user_auth 中保存 source=github 与稳定数字 ID。GitHub 名称没有作为可靠永久字段保存在该关联表中，因此来源插件按 ID 查询当前公开账号，验证返回 ID，再拼出主页。已有验证关联即使本次用其他方式登录，仍可导入本人的来源。

读取公开介绍、地点、组织说明、公开邮箱和网站，以及最多十个本人公开非 fork 仓库的说明、语言、主题和 README。另读取个人主页同名仓库 README，避免它因为仓库排序而遗漏；重复来源只读一次。原文按定位对象保存，候选只来自明确字段。所有处理均为 rules，模型调用为零。

HTTP 固定访问 GitHub 官方 API，不跟随重定向，不接收用户输入的目标 URL。一次读取最多十三次请求、三十五秒和两 MiB 响应；单篇 README 最多二十四 KiB，截断与局部失败记录在 metadata.warnings。第一次公开账号读取失败形成可重试失败状态；部分 README 失败不丢弃已经取得的公开资料。

## 简历解析范围

PDF 使用固定版本 pypdf 6.13.2（BSD-3-Clause），DOCX 使用 Python 标准库解析文本 XML，MD/TXT 使用文本解码。独立 Python 环境位于 backend/.runtime/resume-python；[安装脚本](../../backend/protected/modules/matcher-resume-import/runtime/install.py) 和 [依赖锁](../../backend/protected/modules/matcher-resume-import/runtime/requirements.lock) 可复现运行依赖。

上传上限五 MiB，PDF 最多三十页，解析文本最多一 MiB、两千个段落；解析进程有十五秒超时和解压/内存限制。损坏、加密、无文字层、超限、非法编码和不支持格式返回明确状态。解析器不访问网络，不执行文档脚本，也不启动模型或 OCR。

完整解析文本和段落保存在私有数据库，上传的原始 PDF/DOCX 等二进制仅用于本次解析，不另行留存。来源不会自动过期。简历重试需选择同一文件；更新过的简历作为新来源上传，以便保留独立内容版本。

明确标签的姓名、城市、联系方式、技能、教育、项目、工作、获奖、链接和日期可映射为候选。英文教育/工作记录中的 Summary 归属当前经历，独立个人 Summary 才映射为个人简介。自由叙述保留原文，进一步语义提取属于 S6。

## 存储与一致性

新增 matcher_profile_source、matcher_profile_source_snapshot、matcher_profile_source_job 三张 P1 表，普通资料的三十七类字段保持不变。快照保存文本、定位、候选与证据；读取任务保存版本和 execution_status/applicability，采纳回执只留资源引用，不复制原文。

网络读取和解析在数据库事务外执行，结果写回时再次校验来源版本。刷新后旧结果失效，晚到结果不能覆盖新版本或恢复已删除文本。本人删除来源会清除其全部私有快照并撤销对应结果；已经主动采纳到草稿或确认的内容继续按普通资料规则管理。

采纳与草稿版本、回执保存处在同一事务；失败一起回滚。普通用户只能读取自己的来源与任务，列表不带原文，详情返回 private/no-store。当前所有来源仅映射全局资料；本次 Space 目标和投入继续由原流程独立填写。

完整 API、载荷和状态见 [S5 实施约定](15_S5实施约定.md)。
