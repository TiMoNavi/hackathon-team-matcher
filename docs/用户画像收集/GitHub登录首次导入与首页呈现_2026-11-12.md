## 本次新增

### 本人首次导入状态

新增 `GET /api/v1/auth/github/import-status`，契约由主执行者在 [HumHub 实施合同 9.1](../睡前全自动运行/04_HumHub实施合同.md) 登记。响应只有 `state` 与 `source_id`，不返回 provider subject、request key、邮箱、token、原始文本或候选内容。

| state | 含义 |
| --- | --- |
| not_requested | 本人没有首次导入回执，不据此触发导入 |
| pending / running | 仅表示已保存的待处理 / 执行中回执；不制造进度百分比 |
| succeeded | 公开来源读取已成功，不代表 AI 画像生成、选择或用户确认 |
| failed | 首次导入失败，可进入既有资料页主动处理；登录会话不因此失败 |
| skipped_existing | 保留既有导入历史，不自动抓取或恢复已删除来源 |
| revoked | 身份解绑 / 变更 / 歧义、已撤销回执或来源删除；隐藏引用 |
| unavailable | 模块停用、无法确认当前授权来源或损坏的成功引用；隐藏引用 |

读取只允许当前已登录、启用账号本人，不接受 owner 或其他查询参数。401 未登录、403 账号不可用、400 查询参数、405 非 GET、500 固定内部错误；响应 `private, no-store`。这个只读控制器自身拒绝所有变更方法，关闭不适用于该只读动作的 CSRF 前置解析，以保证非 GET 的 JSON 405。它不调用导入、重试、reader、snapshot 或模型。

对已有来源，服务端复用 P1 `getProgress` 验证归属和删除状态。界面再读取既有 `/api/v1/me/profile/sources/{id}/progress`，显示当前状态；404/撤销覆盖旧成功回执，superseded 提示核对最新来源。每次手动读取最多两个 GET，没有定时导入或自动重试。状态出口与界面都不生成或确认画像。
