# S5-B 网站与粘贴文字来源约定

2026-11-11。已实现并部署至本机预览，验收见 [实现报告](20_S5B实现与验证报告.md) 与 [独立后端验收](21_S5B独立后端验收.md)。本轮只推进后端，新增 P5 matcher-web-import。复用 P1 来源快照、版本、读取任务与草稿采纳，后续前端通过 API 接入。

## 来源与插件

P5 依赖 P1 ≥ 0.6.0，提供 web 与 text 两个 ProfileSourceReader。getSourceReader(kind) 返回对应读取器。P3/P4 保持原 getSourceReader() 与既有行为；P2 无新增依赖。

P4 随共享映射器升级为 0.1.1，明确依赖 P1 ≥ 0.6.0；升级顺序为 P1、P4、P5。P4 本次仅改共用映射依赖，不改简历解析规则、候选身份或上传接口。

输入均为本人主动提交，必须包含 ownership=self 的明确声明，记录 ownership_basis=self_declared。该声明不等于域名控制权验证，也不直接将网页内容视为已确认个人事实。内容先保存为本人来源，候选经本人核对后才进入展示资料。

网页输入为 {url,ownership:self}；文本输入为 {text,label?,ownership:self}。每次读取返回现有 external_id/label/canonical_url/raw_text/sections/candidates/metadata 结构；locator 为对象，evidence 指向段落 ID。仅映射可明确提取的全局字段，保留不能直接映射的正文。

网站采用规范化 URL 的哈希作为稳定来源身份，canonical_url 保留该输入地址，最终响应地址保存在 metadata。刷新只读取原目标，不允许通过刷新换成另一网址。文本使用 UTF-8 内容哈希作为身份，修改文字作为新的来源，不把原文复制进任务回执。

## 共用接合

P1 新增可选端口 `humhub\modules\matcherProfile\domain\ports\IdentifiedProfileSourceReader extends ProfileSourceReader`，方法 `identify(int $ownerId, array $input): array`。该方法在联网前校验并规范化输入，返回 `external_id:string`、`canonical_url:?string`、可选 `label:string` 和 `ownership_basis:self_declared`；不返回原文、不联网或持久化。P3/P4 不必实现此扩展。P1 在首次读取前保存网页原始规范地址，读取失败后仍可重试；文本重试需本人提供相同规范内容。

`external_id` 分别为 `web:` + 原始规范 URL 的 SHA-256、`text:` + 规范 UTF-8 文本的 SHA-256。文本规范化去除开头 UTF-8 BOM，将 CRLF/CR 统一为 LF，保留其余内容。文字最多 128 KiB；HTTP JSON 请求总大小最多 256 KiB，JSON 转义也计入请求限制。网站响应解析受 P5 网络和正文限额约束。

API 沿用 /api/v1/me/profile/sources：POST 支持 kind=web 与 kind=text，字段严格区分；刷新、删除、详情与 extractions 复用已有合同。GET source-capabilities 同时返回 github/resume/web/text 能力。所有写操作验证登录身份、CSRF、版本和幂等键。

| API 操作 | JSON 请求体或传输 | 行为 |
|---|---|---|
| POST sources，GitHub | `{kind:github}` | 复用服务端验证账号，不接受用户名 |
| POST sources，网站 | `{kind:web,url,ownership:self}` | 先识别规范地址，再进行有界读取 |
| POST sources，文字 | `{kind:text,text,label?,ownership:self}` | 仅本地规范与明确字段映射 |
| POST sources/resume | 既有 multipart file | 原上传 API 与文件哈希身份保持 |
| POST sources/{id}/refresh，网站/GitHub | `{expected_version}` | 网站由后端重建原 URL 与 ownership，不接受替换目标 |
| POST sources/{id}/refresh，文字 | `{expected_version,text,label?,ownership:self}` | 相同正文哈希才能重试；不同正文返回 SOURCE_IDENTITY_CHANGED，需新建来源 |
| POST sources/{id}/refresh，简历 | 既有 multipart file + expected_version | 必须保持原文件哈希 |

表内采用字段示意；实际请求须为合法 JSON。各操作拒绝不属于当前来源类型的额外字段。POST 导入返回 HTTP 201，刷新返回 HTTP 200；读取/解析阶段失败保留 `status=failed` 与 `last_job.error_code`，不保留异常原文。输入身份校验失败直接返回错误响应，不建立来源。20 个活跃来源限制四种类型合计计算。读取器结果中的网站 canonical_url 必须与预存原始规范地址一致，重定向最终地址仅进入 metadata。

简历纯规则映射已抽取为 P1 `humhub\modules\matcherProfile\domain\ExplicitTextCandidateMapper::map(array $sections): array`。P4 `ResumeCandidateMapper` 保留同签名薄适配，原 resume-* 稳定候选 ID、字段代码和映射优先级保持不变，供网站与文字读取器复用；不改变已有字段值、前端 DTO 或确认逻辑。

P1 升级为 0.6.0，新增 `m261111_000005_profile_source_kinds`。迁移仅将现有来源 kind CHECK 原子扩为 github/resume/web/text；旧迁移文件保持原样，不改已有来源、快照、任务或原生资料行。首次安装与重复安装均校验相同约束。

## 网络与解析边界

网页只执行有界 HTTP/HTTPS GET，限制方案、端口、URL 长度、DNS 结果、跳转次数、总时间和字节数。禁止回环、私网、链路本地、保留地址以及凭据型 URL；每跳重新验证并固定实际连接 IP，避免 DNS 重绑定与跳转绕过。请求不携带用户登录 cookie、OAuth token 或本地凭据。

只处理可读取的静态 HTML 与纯文本，不运行页面 JavaScript。解析移除脚本、样式与非正文内容，保留标题、可追溯段落和正文；HTTP 401/403、无文本、非支持媒体或超限返回明确状态。HTTP 200 的登录提示、验证页可能被解析为未确认文字，用户仍需核对来源内容。网络错误不影响已有 GitHub/简历来源或普通资料。

网站累计下载最多 1 MiB，抽取文字最多 256 KiB，最多 3 次跳转；网络总预算 15 秒，每次 DNS 子进程最多 3 秒，单次请求最多 10 秒，均受剩余总预算约束。支持标准端口的 ASCII/punycode DNS 主机名；正文解析最多 20,000 个标记、128 层递归、2,000 个段落，每段 16 KiB。依赖 PHP CLI、proc_open、cURL、DOM 与 mbstring；PHP-FPM 可由服务器配置 DNS 子进程的 CLI 路径。

纯文字本地处理，保留中文和换行，限制文本和段落大小。两类来源不调用模型。所有原文、快照和候选仅本人可读，不自动过期；刷新旧版本、删除和迟到结果沿用既有来源规则。
