# S6 AI 后端实现与验证报告

2026-11-12。本轮自 11 月 11 日开始，完成 task.md 的 S6.1–S6.6。三个子 agent 分别负责模型插件、任务接合和独立验收，主 agent 完成真实网关测试及本机部署。

## 已交付的流程

本人选取已有资料 → AI 提取候选和证据 → 本人核对采纳 → AI 生成 3–8 个补充问题 → 保存选项、自由填写或跳过 → AI 生成可编辑画像 → 本人核对展示范围并确认。

每题带独立的 `free_text_option`，内容为“其他，我来填写”，`position=last`。该入口以 `answer_type=free_text` 保存，普通选项仍使用稳定 code。提取、补问、综合三个阶段分别返回 `review_items`，包括缺失、冲突、不确定和缺少支持的提示。

本轮交付后端 API。现有原生页面继续使用基础流程；新的 React 页面可接入同一套会话、问题、任务和草稿接口。本轮没有实现新的 AI 操作界面。基础 rules 模式和普通资料编辑继续可用。

## 真实模型结果

已核验并使用用户指定网关的模型 ID `gemini-3.8-flash`。凭据仅保存在本机私有配置，未复制给子 agent、放入文档或返回 API。真实验收只发送编造的测试资料。

| 操作 | 成功耗时 | 网关报告 tokens | 结果 |
|---|---:|---:|---|
| 提取 | 18.171 秒 | 5,078 | 返回带来源证据的候选，进入原草稿 |
| 补问 | 13.447 秒 | 7,553 | 返回有选项、最后自由填写入口和审核提示的问题 |
| 综合 | 30.048 秒 | 12,112 | 返回可编辑画像，保留本人手工 private 简介 |

完整真实链路通过 **44 项检查、49 次 HTTP 请求**。其中综合前两次请求均在 45 秒超时，经明确重试后第 3 次成功；已完成的提取和补问沿用保存结果，没有重复生成。本链路总计 5 次模型请求，3 次成功报告合计 24,743 tokens，两次超时 usage 未知。

早期协议核验及 PHP 兼容排障另有 6 次模型请求。本轮合计 11 次请求，已报告 tokens 合计 24,965，6 次请求的 token 消耗未知；这些未知值不能按零费用计算。详见 [完整链路证据](sources/s6-live-http_2026-11-11.json)、[全部尝试与排障计量](sources/s6-gateway-attempts_2026-11-12.json)、[协议核验](sources/s6-gateway-protocol_2026-11-11.json)。

综合重试使用诊断 executor 执行真实 cURL，仍经过生产 P6 输出校验和普通 SQL 结果安装，随后经真实 HTTP 完成编辑、隐私确认和下一 Space 检查。这属于单组合成资料验证，没有据此推定提供方的稳定性或所有真实简历的效果。

独立专项包含 P6 95、任务 67、HTTP 64、SQL/worker 24 项；另外重跑旧规则及来源 188 项。前后重复执行、实现 agent 和主 agent 的重跑不累计为独立新增检查。所有独立测试使用合成引擎，没有真实模型费用。

本轮修复了两个实际问题：

- PHP 8.5 下 `curl_close()` 的弃用警告被 Yii 转成异常，成功的 HTTP 响应因此误报网络失败。P6、GitHub 与网站传输改为释放 CurlHandle；P6 加入资源释放回归，GitHub 严格错误处理下公开接口检查和网站传输策略检查通过。
- worker 日志将未知调用数显示为 0。现在保留 `llm_calls=null` 与 `accounting_complete=false`，独立真实 CLI 复验通过，保留 [修复前失败证据](sources/s6-audit-races-before-fix_2026-11-11.json)。

针对真实综合请求延迟，总超时调整为 90 秒，连接超时仍为 5 秒，worker 租约为 120 秒。独立 [90 秒限额复验](sources/s6-audit-p6-timeout90_2026-11-12.json) 通过。每个任务最多一次模型请求；取消、失败、预算不足和显式重试均保留清晰状态，不自动重发或切换规则模式。

## 本机部署与使用

主预览仍位于 `http://127.0.0.1:8090`。升级前备份已校验，迁移核对原生用户、资料、Space 和已有插件记录，旧值保持；详见 [主预览升级证据](sources/s6-main-upgrade_2026-11-12.json)。

AI 后台 worker 已启动，并纳入 [本机预览启停脚本](../../backend/deploy/preview.py)。`python3 backend/deploy/preview.py status` 包含 `profile_ai_worker_running`；后续 start/stop 会同时管理它。日志在本地运行目录，仅写任务 ID、状态与计量；本机进程异常退出后可重新执行 start。正式部署需要自己的进程管理器。

后续前端通过 `/api/v1/me/profile/ai-capabilities` 读取能力，以 `generation_mode=ai` 提交提取、问题或综合，收到 202 后查询任务；结果有效时继续读取原 SessionDTO/BatchDTO，按本人操作采纳、编辑和确认。普通读取、改展示范围和切 Space 不触发模型。

## 验证边界与下一阶段

结构化字段、证据引用、权限、范围与版本有服务端校验。自然语言简介仍可能包含引用无法证明的语义断言，服务器提供强制复核提示，用户需要逐句检查后确认。审核提示帮助核对资料，不等于真实性认证。

当前仍未配置真实 GitHub OAuth；公开资料读取和隔离关联测试不能代替真实登录回调。新 AI 交互界面、正式 React 主前端、300–400 人查询与负载验证留在后续阶段。

下一项为 S7.1：将确认画像转换为当前 Space 内普通发现可使用的获准投影；长期偏好和 Space 专属需求继续分开。S7.4/S7.5 的界面和开场组件按前端阶段安排。最终文件保护与文档核验见 [交付检查](sources/s6-document-check_2026-11-12.json)，隔离环境回收见 [清理记录](sources/s6-cleanup_2026-11-12.json)。
