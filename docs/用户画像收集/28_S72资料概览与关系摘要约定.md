# S7.2 资料概览与获准关系摘要约定

> 2026-11-12，已验收并部署。继续后端阶段，复用已安装的 100 名模拟人物，按独立资料、想法业务与授权投影接合。完成记录见本轮主报告。

## 本轮范围

1. 学校概览、主主页与额外作品链接引用已有确认属性；全局能力与当前 Space 意愿分区返回。本人选择的条目隐藏或删除后概览为空，不替选另一条记录。
2. 参与活动摘要来自原生 Space 与正式成员关系，只返回当前服务端已验证的 Space。每条关系的本人展示选择独立保存，缺省 private。
3. 新的 matcher-ideas 保存本人正式确认的想法标题/简介、独立 Space 发布与显式 Messenger 关联。聊天正文不作为简介，普通私聊不会自动成为想法。
4. 想法作者开启成员展示、资料本人允许分享、当前对象/活动授权均成立时，才展示参与关系。当前 Space 内的合法查看者可查看正式元数据；聊天权限仍由真实参与关系决定。
5. 关系摘要采用签名 cursor、默认 24/最多 48、15 分钟有效期；读取前后验证成员、对象、选择和可见性版本。

## 资料接口

| 方法与路径 | 语义 |
|---|---|
| GET/PUT /api/v1/me/profile/presentation | 本人全局概览选择；PUT expected_version、education_attribute_id、primary_portfolio_attribute_id、confirmation_intent=confirm，两个引用可空且完整替换 |
| GET/PUT /api/v1/me/profile/relation-sharing | 本人当前 Space 的候选关系/分享选择；query 必须 space_id；GET 可带 kind/cursor/limit；PUT expected_version、kind、object_id、visibility、confirmation_intent=confirm |
| GET /api/v1/events/{spaceId}/profiles/{ownerId}/overview | 当前 Space 合法入口的获准概览；不包含联系方式 |
| GET /api/v1/events/{spaceId}/profiles/{ownerId}/relations | kind=activities 或 idea_groups；签名 cursor 分页 |

overview 返回 owner_id、space_id、global、space、school_overview、primary_portfolio_link、additional_portfolio_links、presentation_version、policy_version。relations 返回 owner_id、space_id、kind、items、next_cursor、has_more、limit、policy_version。每条关系携带自己的 visibility/sharing_version；首次设置版本为 0。P8 控制器 action 为 overview、relations、presentation、relation-sharing。非本人入口与发现卡片保持一致：当前 Space 成员、有效账号、未屏蔽、资料本人开启发现且有确认公开昵称；访问者自己可以关闭发现。本人读取仍检查真实 Space 和对象资格。所有写入使用本人会话与 CSRF，返回 data/meta 或统一错误结构，private, no-store。

## 想法业务接口

采用已有共享契约的草稿/确认/Space 关联语义，最小落地以下接口。关注、讨论申请、聊天发送与 AI 整理留在各自业务阶段。

| 方法与路径 | 最小载荷/结果 |
|---|---|
| GET /api/v1/me/ideas | 本人正式想法列表；有界读取超过 200 条明确报错 |
| POST /api/v1/me/ideas/drafts | idea_id?、fields?:{title,summary}、raw_text?；得到私有草稿 |
| GET/PUT /api/v1/me/ideas/drafts/{draftId} | PUT expected_version、fields?、raw_text?；仅本人 |
| POST /api/v1/me/ideas/drafts/{draftId}/confirm | expected_version、fields?；返回 idea_id/version/draft_id/draft_version，确认不自动发布 |
| POST /api/v1/ideas/{ideaId}/activities | event_id、expected_version（想法版本）、members_visible?；Space 必须等于已验证的当前选择 |
| PUT /api/v1/idea-activities/{activityId} | expected_version、members_visible?、status?:published/archived；作者修改 |
| PUT /api/v1/idea-activities/{activityId}/messenger | expected_version、message_id、confirmation_intent=bind_existing_conversation |
| GET /api/v1/ideas/{ideaId}?idea_activity_id=N | 当前 Space 的正式元数据；不输出私有草稿/原文或会话 ID |

本轮 Space 发布保存正式元数据，open_to_discussion 固定 false；开放讨论申请和自动建群仍未接入。现有原生多人会话可显式绑定用于真实参与摘要。非空 context 或 open_to_discussion=true 返回未支持错误，不能把接口占位表述为完整讨论功能。

关系来源内部接口为 Module::getRelationSource()->readCandidates(viewerId,ownerId,spaceId)。返回 idea_group 的 IdeaActivity ID、正式 title/summary、获准想法详情 href、event_id、membership_role、idea_id、version 与 conversation_available。没有原始 message_id 或消息内容。最多 2,000 条候选，超过明确报错。

绑定必须由想法创建者明确发起，校验其为原生会话创建者和当前参与者；会话所有现存参与者都须为该 Space 的有效成员。同一会话全局唯一关联一个 IdeaActivity，不能复用于另一 Space。读取摘要再次核验这些事实、对象发布状态和作者 members_visible 开关；该开关默认 false。

## 数据与依赖

P1 0.9.0 新增 matcher_profile_presentation，保存本人选择的已确认 attribute_id 与版本；学校、作品等具体数据仍在原属性表。P8 0.2.0 新增 matcher_profile_relation_sharing，以 owner/space/kind/object 识别独立展示选择。

matcher-ideas 0.1.0 新增 matcher_idea、matcher_idea_activity、matcher_idea_conversation、matcher_idea_draft。会话绑定只有 ID 关联，消息和原生参与事实保留在 Messenger。P8 通过可选来源端口读取，未启用来源时明确返回 503。想法模块使用独立数据库连接进行当前 Space 授权，资料写入仍在原事务内；这保证原有“新鲜权限读不能复用写事务快照”的限制继续成立。
