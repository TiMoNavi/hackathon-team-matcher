# S3 独立隐私与基础资料编辑实现报告

> 2026-11-11。S3 已完成并部署到本地 HumHub 预览。三个子代理分别实施，主代理独立复验后交付；当前进度为 S1–S3 完成，下一阶段是无 AI 引导。

## 用户现在能做什么

从“团队协作资料”进入普通编辑页面，填写全局资料，或选择自己正式加入的 Space 填写本次偏好。字段按类别组织；技能、项目、教育和其他多条记录可以分别添加、编辑、排序和删除。

保存草稿后可以退出再继续。确认时明确勾选本次要保存的条目，其余内容保留在草稿。页面支持本人、登录用户和好友三种服务器预览；预览中的未确认候选仍留在本人编辑过程。版本冲突时保留页面输入，用户重新读取后继续处理。

昵称与头像使用独立身份确认，普通资料确认不会顺带发布尚未确认的昵称。微信二维码先作为本人上传候选，确认联系方式条目后按选定范围展示。旧原生资料提供本人采纳入口，用户可修改后再确认。

## 两个独立插件

| 插件 | 职责 |
|---|---|
| matcher-user-profile 0.3.0 | 字段值、身份、草稿、修订、普通编辑和 Space 上下文 |
| matcher-profile-privacy 0.1.0 | 逐条策略、合法入口、联系人读取、预览与原生获准展示 |

隐私插件依赖普通资料插件 0.3.0 及以上版本。填写引导和 AI 可以在后续独立接入，两者均不作为普通资料编辑或隐私判断的前提。字段值和可见性元数据继续复用原有四张核心表，原生 ProfileField 保持 31 项。

普通字段仍为 **27 类全局条目和 10 类 Space 条目**，均可选。新增确认条目默认 authenticated。用户可将某条改为 friends 或 private；可见性变化推进修订和权限版本，保留未提交草稿。只调整范围或排序时，内容的确认时间保持原值。

## 展示与入口

| 情形 | 实际行为 |
|---|---|
| 本人编辑 | 可以读取本人当前资料、草稿和旧资料候选 |
| 当前 Space | 服务端验证双方正式成员及 Space 状态，再展示获准资料 |
| 已有好友 | 通过好友入口读取全局 authenticated 和 friends 字段；切 Space 后关系继续有效 |
| 公开帖子作者 | 验证确切帖子、作者及当前可访问性后，读取获准全局资料 |
| Space 专属字段 | 继续验证该 Space 的成员资格 |
| 普通目录与搜索 | 在 SQL 候选查询前验证当前 Space，仅匹配可用于该场景的公开确认信息 |
| 联系方式 | 使用独立读取接口和详情展示区，沿用默认可见与逐条范围 |

好友申请的单向记录不算有效好友。好友变化、成员资格、屏蔽和帖子可见性在实际读取时检查；二维码复用相同的联系人策略。隐藏条目的值、键和来源不出现在他人资料中。

性格、长期沟通习惯与联系方式保持全局。本次目标、角色、时间投入和参与安排按 Space 保存。产品的活动是 HumHub Space，Calendar 继续负责空间内赛程。

## 原生系统与旧数据

个人简介、人物卡、显示名、搜索、REST 及已启用模块的资料读取分别接入适配器。原生通用 ProfileField 展示和检索标志由隐私模块管理，获准详情由统一投影呈现；值仍保存在原生列，编辑不会改成第二份数据。

已确认字段沿用现有范围。尚待核对的原生值进入本人审核草稿；若用户已有编辑中的草稿，升级保留当前工作，旧值继续作为本人候选供主动采纳。缺失原生 profile 行时，受管字段和昵称写入明确失败并回滚，不推进虚假的成功版本。

待确认昵称使用稳定中性身份，确认后切换为本人昵称。资料范围、内容、身份和草稿各自使用对应版本。数据库读取在 state 锁后验证当前权限事实，嵌套的旧事务快照不能恢复已经撤回的范围或成员资格。

## 接口与页面

S2 的草稿、确认、历史、身份和媒体接口继续使用。S3 增加以下接口，统一返回 JSON 包装，写入要求登录会话、CSRF 和期望版本。

| 接口 | 用途 |
|---|---|
| GET /api/v1/me/profile/preview | 本人、登录用户、好友视角预览；可指定本人草稿 |
| PATCH /api/v1/me/profile/visibility | 确认逐条展示范围，保留内容和未提交草稿 |
| GET /api/v1/me/contacts | 本人联系方式 |
| GET /api/v1/profiles/{ownerId}/contacts | 经好友或公开帖子等合法入口读取联系人 |
| GET /api/v1/spaces/{spaceId}/profiles/{ownerId}/contacts | 当前 Space 中的获准联系人 |
| GET /api/v1/profiles/{ownerId} | 获准全局资料；带 Space 时另返回该空间资料 |

entry_type、space_id、post_id 仅描述入口证据，服务端重新验证实际关系和对象。隐私修改发送 expected_version、changes 和 confirmation_intent=confirm；changes 中每项包含 attribute_id 和 visibility。原有 Space 路径继续可用。

基础编辑入口为 /matcher-user-profile/editor/index，原生账户资料菜单和本人个人页均有“团队协作资料”入口。本轮页面沿用现有 HumHub 资源用于完整操作验收；正式 React 主前端按 S7 整合。

### 本地部署与恢复

普通资料 0.3.0 和隐私 0.1.0 已启用到主预览 `http://127.0.0.1:8090`。登录后可从账户菜单进入“团队协作资料”，路径为 `/matcher-user-profile/editor/index`。

升级前已保存私有数据库备份并验证校验值。隔离库完成最终版本升级与重复执行，主库升级前后 user、profile、space、space_membership 的行数及内容哈希相同；原生 31 个字段定义和 37 类逻辑资料字段保持完整。迁移调整通用字段的展示/搜索配置，并为待核对旧值建立本人审核候选。证据见 [最终版本与幂等升级](sources/s3-root-final-upgrade_2026-11-11.json) 和 [主预览部署](sources/s3-preview-deployment_2026-11-11.json)。
