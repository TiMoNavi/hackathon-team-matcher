# S4 无 AI 用户画像引导实现报告

2026-11-11。task.md 的 S4 九项已完成。领域服务、数据库与 HTTP 适配、五阶段页面已部署到本机 HumHub 预览；独立 Playwright 网页验收 78 项、主预览只读检查 42 项通过。

## 用户流程

从“画像填写引导”选择全局资料或已正式加入的 Space，开始或恢复自己的填写进度。

1. **提供资料**：带入本人已确认资料，补充一句话介绍或自述，保存为引导专用草稿。
2. **核对信息**：编辑和增删条目，调整逐条范围，明确确认首批资料。
3. **几个补问**：根据已确认信息安排 3–8 题，支持单选、多选、自由回答、跳过和返回修改。
4. **编辑画像**：规则把明确答案映射到普通字段，组织可修改的卡片。已有项目、技能与范围继续保留。
5. **范围与确认**：查看本人、登录用户、好友三种服务器预览，明确保存全局与当前 Space 资料。

每次保存记录服务器版本；刷新、保存退出和再次进入可恢复阶段与答案。全部问题跳过也能完成，不为缺项编造经历或偏好。长期性格、合作习惯等属于全局资料，本次角色、目标和投入属于所选 HumHub Space；Calendar 保持空间内赛程用途。

S4 当前支持已有确认资料和直接手填。S5 接通真实 GitHub、简历与网页读取；S6 接通 AI；正式 React 主应用整合按 S7 执行。本阶段的资料流程对应完整产品十步引导中的资料部分。

P1 原有四张核心表与原生 user/profile 字段继续复用。S4 新增 QuestionBatch、QuestionAnswer、OnboardingSession 三张表；会话只保存步骤与资源引用，资料值和问答各自保持单一存储来源。37 类普通资料字段仍均可选，新增确认条目默认 authenticated，已有明确范围保持。

P2 可单独停用并保留会话、问题、答案和迁移历史；P1 普通资料编辑、P8 隐私继续工作。重新启用后恢复原进度，并核对停用期间发生的资料修改。插件通过原生模块注销服务实现这一行为，数据删除仍走独立的维护流程。

QuestionProvider 和 ProfileComposer 是可注入的领域端口，默认实现为固定题库与规则映射。当前流程不安装或调用模型客户端；API 返回实际模式 rules，AI 模式明确返回不可用。模板生成的一句话介绍继承所用事实的最严格范围。

## 一致性和恢复

引导使用独立 onboarding 草稿，不接管普通资料页的手工草稿。最终确认通过同库事务按全局、Space 的固定顺序锁定状态，再验证当前身份和正式成员资格；两种范围一起提交，失败一起回滚。

问题批次保存稳定题目和选项代码。单题 expected_version 对应该答案版本，答案更新推进批次版本。重新回答后，之前生成的画像不能直接完成；用户重新整理得到新草稿。普通资料在另一页面更新时，旧引导返回版本冲突并保留输入，用户通过“重新核对最新资料”继续；已保存的旧草稿与批次保留引用记录。

资料确认、问题回答、页面进度与最终完成分别验证版本。完成请求和相同输入的重复综合可安全重试。返回补问而未修改答案时，再次整理回到原画像草稿，保留草稿 ID、版本与手工修改；旧生成请求重放不将后续阶段退回。服务端始终重新验证资源归属与 Space 资格，客户端传入 ID 不构成授权。

MySQL 的 JSON 对象键排序与业务值分别处理，profile_versions 比较按确定键值进行，避免把正常读取误判为冲突。前端资源发布沿用 Yii 机制，部署时刷新源资源目录时间，发布更新后的脚本与样式。

## 页面与接口

入口为 `/matcher-onboarding/flow/index`，账户资料菜单中显示“画像填写引导”。页面使用本地 HumHub 资源，操作经真实登录会话、CSRF 与 `/api/v1` 接口完成。

| 接口 | 用途 |
|---|---|
| POST /api/v1/onboarding/sessions | 创建或恢复本人当前范围的活跃会话 |
| GET/PUT /api/v1/onboarding/sessions/{id} | 读取进度，保存资料、移动阶段、核对与完成 |
| POST /api/v1/me/profile/question-batches | 创建并保存规则问题批次 |
| GET /api/v1/me/profile/question-batches/{id} | 恢复已保存的问题和答案 |
| PUT /api/v1/me/profile/question-batches/{batch}/answers/{question} | 保存单个答案或明确跳过 |
| POST /api/v1/me/profile/syntheses | 根据当前资料与答案版本生成独立画像草稿 |

完整动作、载荷与 DTO 见 [S4 实施约定](12_S4实施约定.md)。普通资料编辑、草稿读取和隐私预览继续使用 S2/S3 的同一组接口。

### 本地部署

主预览地址为 `http://127.0.0.1:8090`。登录后打开账户资料菜单中的“画像填写引导”，或进入 `/matcher-onboarding/flow/index`。浏览页面不自动创建会话，用户明确开始后才保存引导进度。
