# 画像接入总计划与并行协作

日期：2026-11-12。用户要求继续安排认证、活动及其他接入工作，重点规划用户画像收集；推荐与聊天交给独立 agent。本轮交付是可执行的接入规划与只读核对，没有将画像原型接上真实业务，也没有执行新迁移、外呼或模型调用。

阅读顺序：[既有40对照](40_画像前端V4与后端能力对照.md) → [后端能力与差异](画像接入后端能力与差异_2026-11-12.md) → [十步与恢复](画像十步接入与保存恢复规划_2026-11-12.md) → 本计划。40记录V4时期判断，保留不改；本轮另核对V5、范围切换以及添加条目／照片增量。

## 1. 目标与复用范围

先交付可独立完成的真实画像主线：已验证身份 → 取得本人已有资料或手填 → 私有核对 → 真实问题与补充 → 编辑与逐条预览 → 用户明确确认 → 普通资料页读取同一份正式资料。没有AI、没有推荐结果、尚未聊天时也能保存退出和继续。

复用现有普通资料、隐私、来源、问答、AI任务与progress能力，不重建用户库或另一套画像事实。原型保留在 `frontend/用户画像收集——前端/`；后续增加真实适配层，示例体验必须继续显式标识，不能把localStorage、固定名单或定时器当服务端保存。

| 能力 | 当前依据与本轮处理 |
|---|---|
| P1资料／身份／草稿／正式修订 | 能力已有；当前源码0.10.1与既有隔离安装回执0.10.0分别记录，不能混作同一验收版本 |
| P2引导与问题／合成编排 | 五阶段已有，当前源码0.4.0；十步旅程与第3步私有核对需补合同 |
| P8逐条权限与联系人 | 当前源码0.2.0；复用真实授权，新增长文与分类不得绕开其投影 |
| GitHub／简历／网站／文字来源 | 复用各来源插件、版本和本人权限；首次GitHub衔接由认证专项交接 |
| 画像AI和三个progress | 已有历史验收；只消费已存状态，当前实例可用性与有限真实验证另记 |
| V5界面与照片增量 | 用于最新交互目标；已有原型证据不等于同源后端接入完成 |

## 2. 必须先确定的五个边界

### 2.1 第3、5、8步的确认语义

- 第3步仅保存本人可恢复的核对结果。当前P2 `review_confirm` 会正式确认，禁止直接接到“核对完成”。拟新增私有核对快照及其问题／合成引用，准确动作、版本和错误结构先进入公共合同。
- 第3步待确认昵称／头像同样私有。已有头像上传能产生候选，`PATCH /me` 却会立即更改正式身份；需要私有身份编辑引用与恢复合同，第5步再显式提交，不能只靠页面隐藏。
- 第5步确认当前草稿、选定条目与范围；保持P1现有版本及P2同一工作流内global／Space草稿确认的既有事务边界，不误拆原有原子性。身份与资料若分属独立用例，界面逐对象显示结果，不能宣称未实现的跨对象全局原子提交。
- 第8步聚合本人资料、活动安排、想法等真实对象引用及版本；仅明确选中的对象执行各自保存／确认。部分失败保留已成功结果，只处理失败对象，不用“完成引导”替代发布、入群或好友接受。

### 2.2 完整长文与结构化字段

每段20,000个Unicode字符、换行、重复同类条目与自定义标题完整往返，不按UTF-8字节冒充字符数。精确上限、总字节、数量和存储限制分别验证；超限明确返回错误，不截断，也不把整份文档塞入单一有限bio字段。

新长文条目、稳定ID、排序、版本、显示分类以及与结构化字段的来源引用仍是拟补合同。前端V5的显示分类 `scope`、后端global／Space数据归属、authenticated／friends／private受众是三件独立的事，需显式映射字段，不能互相代用。

保存全文不等于可以全量发送模型。现有请求字节和AI输入／输出约束不随20,000字符显示承诺自动扩大；选择相关片段、来源版本及本人采纳必须明确，失败时保留完整正文。自定义联系方式不能伪装普通公开段落绕过独立contact投影。

### 2.3 默认可见性与身份

新增**已确认**普通画像与可选联系方式默认authenticated，保留已有明确范围；所有未确认来源、候选、草稿仅本人。第5／8步显示逐条本人、登录用户和好友预览，实际读取仍由服务端按合法入口授权。

authenticated不等于仅同活动，friends随有效好友动态变化，private的值和私有来源信息不返回给他人。联系方式独立读取；不将旧通用设计中的额外联系人分享授权当作本轮默认流程。头像使用受控候选和正式avatar_ref，不能把本机data URL当正式可见媒体。

### 2.4 全局资料、活动与删除

长期经历、习惯、性格和联系方式全局复用；目标、角色、需求、投入和可用时段按Space存储。切新活动时专属上下文为空，复用唯一current-event，读／写／确认／采纳均重新校验成员资格；旧活动的晚到响应不得显示在新上下文。

当前活动选择按本人和认证会话保存，并非账号跨设备共享的全局值。另一设备恢复画像时先取得该设备会话的有效选择；不能用旅程中旧space_id自动覆盖当前选择。现有画像成员检查和AI context尚不能据此证明已绑定选择版本；N05/N06需补相关端口与版本核验。切换活动不意味着自动删除A活动的私有草稿，但A任务的晚到结果不得展示或采纳到B；再次进入A也必须重验成员、来源、输入版本和任务适用性。

来源删除即时影响原文、证据和失效任务访问；已被本人明确采纳到正式资料的条目需另行编辑或删除，不能默默全删或自动重抓。原始资料私存、不自动过期；浏览、切活动、改范围和普通再次登录不触发重新编辑、抓取或AI。

### 2.5 真实恢复与AI边界

旅程只存步骤、草稿／来源／问题／任务／想法／活动等引用及版本，不存替代各领域事实的巨大Draft副本。刷新和跨设备恢复需要服务端合同；当前浏览器本地恢复不能标作已经满足。问题按真实question_id和option code恢复，不按显示文字猜字段。

只在用户明确选择的处理中创建任务，轮询遵守progress的poll_after_ms、终态和离页取消订阅。percent=null保持不定进度，失败不自动重试，不静默切rules；用户可以主动选择手填或规则模式。

AI execution_status与applicability分别处理，superseded/revoked优先于succeeded，失效正文不可展示／采纳。日额、并发、重试和网关预算引用画像P6合同，不能套推荐run额度；真实模型另设有限合成样例验收，无本轮规划调用。

P6当前源码默认每用户最多2个current且queued/running任务、UTC日内最多20个新建任务；失败、取消及显式重试创建的任务仍计日额，幂等重放不重复创建。重试链最多3次尝试，即首次加最多2次本人显式重试；这些是可配置限额，接入时另核实实例配置，不写成全平台worker上限。单任务至多一次transport请求，预检失败可以没有请求；中断后的未知用量仍保持null，不能算作0。只读接口可能返回过去调用的累计值，零新增调用不等于把历史计量清零。

### 2.6 首次、重编辑与恢复

| 入口 | 读取与草稿 | 确认／退出后的结果 |
|---|---|---|
| 首次引导 | 读取本人的已有来源与首次GitHub导入状态；没有来源时可上传或手填；不重复导入 | G03仍私有；G05才正式确认，退出保留服务端草稿和对象引用 |
| 主动重新编辑 | 以现有正式修订和identity_version建立新私有草稿；仅本人明确导入或选用资料时启动对应处理 | 编辑中仍展示旧正式版本；新确认冲突不得覆盖另一设备的新版本 |
| 保存后继续／换设备 | 先读服务端会话与引用，再核验版本、权限和任务当前性；本地未同步输入须单独提示 | 不自动新建任务、重新抓取或重复确认；失败对象可单独恢复 |
| 进入新Space | 复用全局资料，只加载新Space的已有上下文；没有填写时为空 | 不复制旧Space目标与时段；不因切换确认草稿或触发模型 |

### 2.7 容量与模型覆盖范围

单段20,000字符的正文可以采用完整单段分批写入256KiB请求预算；每批仍核验实际UTF-8序列化大小、总段数及版本。不把存储限额与模型限额混成一个开关。现有来源section上限32KiB、AI来源采集文本总量64KiB、结构化输出64KiB，不能直接容纳任意20,000字符正文；20,000个四字节字符的正文已有80,000字节，尚未计JSON。

因此长文完整保存与AI片段处理分别定合同。后续明确选择片段／摘要引用、覆盖区间、原文版本、输出与总调用预算；未覆盖内容标记未处理，完整原文不丢失。现有单任务不能承诺完整重写任意20,000字符，不能自动分拆成多次收费请求或静默截断。

## 7. 本轮结论与尚未实施
