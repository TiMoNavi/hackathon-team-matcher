## 2. 与现有接口的对应

下表路径均位于同源 `/api/v1` 下；客户端不传 owner ID，服务器从有效原生会话取得本人身份。

| 客户端操作 | 现有接口与实际实现 | 核对结果 |
| --- | --- | --- |
| `profile` | `GET /me/profile`，P1 `ApiController::actionProfile` / `ProfileService::getProfile` | global 或指定 Space；返回正式属性、字段目录及当前编辑草稿引用。旧候选不映射为正式条目。 |
| `draft` | `GET /me/profile/drafts/{id}`，P1 `getDraft` | 以本人、scope、草稿 ID 校验；保留草稿版本、基线与当前修订。`preview_attributes` 的 pending/draft 标记不提升为 confirmed。 |
| `preview` | `GET /me/profile/preview`，P8 `PrivacyService::preview` | 本人请求的 owner/authenticated/friends 模拟；原样消费服务器的 profile 与 contacts 两个投影。校验 scope、draft ID、视角和 `simulated=true`。 |
| `sources` | `GET /me/profile/sources`，P1 `ProfileSourceService::list` | 仅映射清单摘要；保留来源 ID、版本及已存快照/任务引用，不返回正文、provider 身份或内部作业结果。 |
| `sourceCapabilities` | `GET /me/profile/source-capabilities`，P1 `capabilities` | 读取 github/resume/web/text 的真实可用状态；剔除 provider 身份、内部配置和来源约束以外的元数据。此读取不导入资料。 |
| `legacySessionProgress` | `GET /onboarding/sessions/{id}/progress`，P2 `getProgress` | 必须已有服务器 session ID；仍是五阶段、`percent=null`，保留真实状态、版本、问题计数。没有虚构 active/current 查询或 POST 恢复兜底。 |

## 4. 发布与挂载边界

1. 读取客户端只返回结果，没有身份/当前活动的状态容器。未来宿主必须在登出、换号、活动切换、权限撤销时取消请求并核对 actor 与请求代次；相同 `space_id` 的回包校验不能独立防止 A→B→A 的迟到结果。当前只读层尚未挂载，此项是正式接线前置，不宣称已经完成。
2. P1/P2 当前成员授权及本次 scope 校验，不等于完整的 `selection_revision/access_version` 上下文绑定。N06 的事务内写入和 AI 采纳仍须按当前活动合同补齐；无当前活动时的本人全局编辑不应新增活动选择门槛。
3. `legacySessionProgress.next_actions` 仅是旧服务端动作提示，不能动态据此调用写端点。尤其旧 `review_confirm` 会调用 `confirmDrafts` 正式提交，不可绑定 G03 的“核对完成”。旧五阶段完成也不能标成新十步完成。
4. 联系方式保持独立数据类型和投影，改标题或显示分类不改变权限。服务器模拟预览不是真实访问凭据；普通详情、好友、Space 和公开帖来源仍由实际访问入口验证。
5. 文本表示和 Unicode/UTF-8 计数函数没有提供存储能力。既有 bio 上限仍为 10,000 字符；本次不能宣称新增长文 20,000 字符写入、来源全文导入或全量 AI 处理。
6. `UNCONNECTED_PROFILE_OPERATIONS` 明确列出私有核对快照、长文段落写入、私有身份草稿、G05 确认及十步恢复。没有新增上传、写入、自动建会话、问答准备、资料确认或 AI 调用方法。
