# 首次注册与开场引导 · 优化设计

> 状态：已批准方案的可编辑衍生设计；更新日期：2026-11-11。
> [用户人工原稿（冻结）](首次注册与开场引导_用户原稿_冻结.md) 原样保留。本文件落实后续确认的登录方式、逐条可见性、活动边界及好友规则，不冒充人工原文。
> 文档职责：定义首次使用、信息录入、确认和重新编辑的前端行为。数据与接口以 [共享契约](共享数据与接口契约.md) 为准；画像处理见 [Agent 用户画像与资料处理](Agent用户画像与资料处理设计.md)，进入应用后的页面见 [主应用交互](前端主应用交互设计.md)。

## 1. 目标、章节与职责

资料阶段采用“先了解资料、主动补问几个问题、形成可编辑画像”的体验。基础后端用规则题库和模板走通完整流程，随后接入 AI 提取、提问与归纳。专项要求见 [用户画像填写需求](用户画像收集/01_用户画像填写需求.md)。

开场保留游戏式逐步引导、两次画像预览、独立想法、首轮推荐和电路接通反馈。十步顺序不变，四章仅用于展示进度：

| 章节 | 对应步骤 | 用户得到的结果 |
|---|---|---|
| 认识你 | 1–3 | 有来源、可以修改的能力与经历资料 |
| 了解你的偏好 | 4–5 | 根据回答整理的个人画像与逐条可见性 |
| 让想法成形 | 6–8 | 一个或多个独立想法及组合预览 |
| 遇见同频者 | 9–10 | 当前活动内的人选或想法，及可主动发送的好友申请 |

顶部显示当前章节、已完成节点和保存状态，允许返回已经到达的步骤。按钮使用“开始整理”“确认画像”“保存想法”等具体动作。动画可以立即跳过，不以动画时长拖延已经完成的任务。

十步和两次预览保留，但每章都提供“保存退出”。用户可先进入有权浏览的主应用页面，进度仍标记未完成；回来接续原步骤，不伪造完成状态。发布、加好友等具体操作只验证其必要资料和权限，不用是否走完十步代替业务资格。

按项目 architecture-patterns 的原则，页面只呈现数据和收集用户动作；引导用例编排阶段，画像和想法领域分别拥有自己的版本，AI 网关与存储是后端适配器。前端不直连模型、不自行发 SQL、不根据动画完成推断业务完成。接口统一使用 **/api/v1**，本文件不另定义一套草稿、确认或授权接口。

## 2. 三类范围分别控制

### 2.1 发现范围

发现列表、随机浏览、人工搜索、首轮推荐及 AI 找人均限制在服务端验证的当前活动。人物必须具备该活动有效资格；想法必须关联该活动。任何列表、详情、分页和晚到的摘要都不能借其他活动补足结果。

首期由组织者提供邀请链接或邀请码加入活动。登录回跳可以保留邀请上下文，加入资格仍由后端校验。用户可以加入多个活动，发现只使用当前选中的一个。无活动时可以完成本人资料录入、保存想法草稿及进入公开广场；不能回退为全站发现。

### 2.2 画像字段可见性

每条正式画像使用以下值，逐条控制；下表描述全局画像条目，“所有登录用户”不等于“仅同活动用户”。活动条目还必须同时满足相应活动资格，即 visibility 条件 AND 活动权限；好友预览也不能展示无权查看的活动字段。

| visibility | 界面标签 | 含义 | 预览模式 |
|---|---|---|---|
| authenticated | 所有登录用户可见 | 登录用户通过合法入口可读；推荐工具使用此类字段 | 显示“非好友登录用户视角”，另选择同活动或公开帖入口 |
| friends | 好友可见 | 所有已通过好友可读；推荐中不展示，详情页才按关系显示 | 显示"好友视角"，模拟成为好友后看到的完整内容 |
| private | 仅自己可见 | 只用于本人管理，不进入他人的展示投影 | 显示"仅你可见"，其他人完全看不到 |

**权限预览工具**（第 5 步和第 8 步使用）：
- 提供"切换视角"按钮：[我的视角] [陌生人视角] [好友视角]
- **陌生人视角**：只显示 authenticated 字段，模拟推荐卡片和详情页中其他活动成员看到的内容
- **好友视角**：显示 authenticated + friends 字段，模拟成为好友后对方看到的内容
- **我的视角**：显示全部字段（包括 private），便于用户检查完整性
- 每个视角说明当前模拟的关系、入口和活动。推荐卡只使用 authenticated；好友详情才加入 friends，不能把二者标成同一种所见内容
- 视角切换实时生效，不需要保存或重新加载
- 在逐条可见性设置界面，修改某字段后自动刷新当前视角的预览

**实现细节**：
- 前端在本人有权持有的草稿上按 visibility AND 活动资格预览；提供“同活动入口 / 跨活动公开帖入口”，后者不展示仅当前活动有资格的字段
- 视角切换可本地完成，但使用与服务端策略一致的受众上下文和测试样例；本地预览不是他人访问的鉴权依据
- 预览时使用与实际详情页相同的样式和布局，确保所见即所得
- 移动端可用滑动手势切换视角，PC 端用标签页切换

可访问入口包括活动内发现、可访问的广场帖子作者页及既有好友会话。字段公开不创建全站用户搜索，不解除发现活动边界。普通画像可见性和本人是否授权模型处理资料是两件事；模型允许使用哪些字段由画像与推荐契约约束，前端不能自行扩大。

未确认 AI 草稿不是正式展示数据。原始简历、来源全文、OAuth 凭据、私信和内部处理记录不提供公开切换。联系人由独立控件明确选择，不能因为成为好友自动读取全部联系人。昵称、头像等最小身份展示遵循共享契约，不借条目隐藏机制伪造账号身份。

### 2.3 发布范围

画像、想法和广场帖子独立保存。画像设为所有登录用户可见，不等于发布广场帖子；保存一个想法也不等于公开发布它。公开广场的帖子头像可以跨活动进入作者展示页并申请好友，仍走用户确认首条消息、对方接受的普通业务流程。

## 3. 登录舞台与账号入口

中央固定显示“使用 GitHub 继续”和“使用邮箱验证码继续”。GitHub 是推荐入口，但不阻挡没有 GitHub 的设计、产品等参与者。首期不显示未实现的微信登录和邮箱密码入口。

GitHub 首次注册入口旁明确说明“登录后自动连接并读取你的 GitHub 公开资料，用于预填个人信息”。该次真实登录操作同时建立已验证的 GitHub 来源，用户无需再次粘贴主页、重复绑定或填写同样的信息；资料整理与公开展示仍是不同动作。已有账号再次登录只恢复现有来源与进度，不重新抓取或重跑画像。

| 区域 | 字段与状态 | 动作及失败处理 |
|---|---|---|
| GitHub 登录 | 未开始、跳转中、回调处理中、已连接/资料读取中或失败 | 首次注册成功后自动关联本人 GitHub 并读取公开资料，恢复原邀请/页面；读取失败不使登录失败；取消仍可选择邮箱 |
| 邮箱登录 | 邮箱、验证码、后端返回的可重发时间 | 发送验证码后展示目标邮箱；允许修改邮箱；重复提交防重；限流和过期按后端结果提示 |
| 邀请提示 | 活动名称或“待验证邀请” | 可以保留上下文；邀请失效不删除账号和个人草稿，也不伪装已加入活动 |
| 返回用户 | 服务端引导进度、未完成草稿摘要 | 提供继续引导或进入主应用；已有账号不因再次登录重做画像 |

带邀请进入的新用户，登录成功后立即验证并兑换邀请，显示活动状态；这与本人 GitHub 公开资料读取并行，不阻挡首屏上传简历。无效邀请立即说明，但本人导入、资料确认与广场仍可继续；第 9 步复核资格，重复兑换不消耗第二次邀请名额。

背景浮现低对比度的匿名昵称、能力短句和想法需求。首期可使用明确标注为示意的内容。真实背景材料必须有独立的公开展示授权；authenticated 不授权未登录舞台展示。背景不可点击检索人物，不表示这些人属于当前活动或正在在线。

提供暂停背景控制；减少动态效果开启时使用静态内容。读屏忽略装饰弹幕，焦点不随动画移动；登录面板在手机键盘展开时仍可操作。邮箱验证码可粘贴和自动填充，错误由文本说明，不能只变红。

## 4. 十步逐屏设计

### 第 1 步：提供已有资料

提示“先给我一些已有资料，我来帮你整理”。简历上传与 GitHub 是资料页的两个主要入口，个人网站、粘贴文字和直接填写作为补充。

| 输入 | 行为 | 状态与保存 |
|---|---|---|
| 简历 | 上传文本型 PDF、DOCX、MD、TXT | 显示文件名、读取进度与正文状态，按来源分别保存 |
| GitHub | 显示首次注册已连接账号；邮箱用户可主动连接 | 关联本人已验证身份，显示公开资料读取状态 |
| 个人网站 | 输入公开个人主页或作品页地址 | 保存页面标题、链接、读取状态与快照 |
| 粘贴文字 | 输入经历、能力或作品说明 | 保存原文与来源引用 |
| 直接填写 | 点击“直接开始” | 进入第 3 步的基础信息编辑 |

本人可以使用一种或多种材料。昵称建议可以来自已连接账号或资料，在第 3 步私有核对，第 5 步明确提交后更新正式身份。首次 GitHub 公开读取与邀请验证可并行进行；来源就绪后参与整理。

主操作为“继续整理”。基础模式使用结构映射，AI 模式使用语义抽取，实际方式以 generation_mode 显示。用户选用 AI 时，页面说明本次所选材料的处理用途。

来源私密保存在数据库，用户可以在个人资料页管理、刷新或删除。普通再次登录恢复已保存资料与进度。每个来源有独立读取状态，用户可以使用已成功材料继续。

### 第 2 步：整理已有信息

页面显示实际处理阶段，如“读取资料”“整理已有信息”“准备核对清单”。基础模式采用规则映射，AI 模式展示对应任务的排队与处理状态。

来源读取分别反馈成功和待处理项，提供重试、继续使用已成功材料和直接填写的操作。离开后返回以服务端状态恢复。

完成后展示当前版本的整理结果，进入核对页面。

### 第 3 步：核对初步资料

显示“目前了解到的你”，列出昵称建议、经历、项目、技能与来源。基础模式预填明确结构化字段，并提供正文参考；AI 模式增加语义整理。用户可以修改、删除或补充条目。

直接填写的用户使用同一页面，先核对待确认昵称，再填写自己希望提供的内容。已有正式个人资料可以作为草稿基线复用，页面突出本次需要核对的部分；核对中的修改不覆盖旧正式版本。

主操作“这些信息正确，继续”。后端保存本人私有草稿及其核对快照，作为补充问题的依据；此步不正式确认画像或身份。待确认昵称、头像引用及移除意图同样须由服务端私有保存，不能仅存浏览器。HumHub 现有 review_confirm 会正式确认，PATCH /me 会立即更新身份；新私有核对合同需按 N06 补齐后才能接线。

### 第 4 步：主动补问 3–8 个问题

系统基于第 3 步私有核对快照及其版本准备一批 3–8 题，快照可以包含旧正式资料基线。基础模式从题库按待补维度和优先级选题，AI 模式生成更贴近用户背景的题目。完整批次先保存，页面逐题展示；新输入衔接仍须完成 N06，不通过提前正式确认来兼容旧 action。

题目关注贡献方式、兴趣、沟通习惯、协作节奏和当前活动目标。以单选、多选为主，提供“我想自己说”和“暂时说不准”；可在题目旁简短说明为何需要这项信息。资料较完整时使用较短批次。

每次回答保存后显示进度，允许返回修改。刷新恢复原批次、题目顺序与答案。全局偏好和本次活动偏好按题目作用域分别保存。

AI 处理失败时，用户可主动选择基础题库继续，页面显示本次实际处理方式。

### 第 5 步：生成画像、编辑与逐条预览

系统综合私有核对快照和本批回答，生成可编辑卡片。基础模式使用字段映射和固定模板，AI 模式进一步归纳并组织表达。卡片包括基本介绍、能力与作品、合作方式、当前活动安排。

用户可直接修改文字、增删条目，或返回编辑答案后重新整理。每条内容提供“所有登录用户可见 / 好友可见 / 仅自己可见”，支持先分组选择再逐条调整。已有条目沿用当前展示范围，新草稿作为本人编辑资料保存。

页面提供本人、普通登录用户、好友三种视角，并说明当前入口和活动。好友视角按有效好友关系展示；活动字段同时验证对应资格。必填标记来自普通资料字段规则，可见性由本人选择，联系人通过独立控件管理。

点击“保存我的资料”，以期望版本正式确认所选条目和展示范围；昵称和头像按独立 identity_version 明确提交。界面分别展示画像与身份的真实结果，不假设已有跨对象原子提交。普通个人资料页使用同一确认结果。用户可以保存退出，或进入后续想法阶段。

### 第 6 步：讲讲你的创新或项目想法

提示“你想和别人一起讨论或做成什么？”按独立卡片录入，可添加多个想法。一句话即可开始；可选补充遇到的问题、想做的第一步、当前阶段、希望别人提供的帮助。

保留至少一个想法草稿作为正常完成引导的条件。尚无完整点子可选择“我想加入别人的项目”，填写希望贡献的角色与具体探索方向，保存为探索草稿，无须假装发起项目或公开招募。用户可以保存并离开，回来继续；未完成引导不能被伪标为已完成。

每个想法有独立本地编辑状态和后端草稿标识；增删一个不会覆盖其他想法。个人画像与想法分别保存。主操作“整理这些想法”，用户也可以手动补齐后继续。

### 第 7 步：AI 整理想法

一次批量整理本轮选中的原始想法，逐个产生标题、问题、目标、阶段和希望的贡献。保留原始输入和结果对应关系，不将两个想法擅自合并，也不生成用户未提交的新想法。

逐项显示状态，允许使用已成功的结果、重试指定项或改为手动编辑。用户修改后旧结果晚到，标为已被更新内容取代；不能覆盖修改。整理成功只得到草稿，不自动发布、不自动邀请任何人。

### 第 8 步：画像与想法组合预览

上方是个人画像，下方是独立想法卡片。每个想法可单独编辑、保留草稿或移除；至少保留一个有效草稿，才可标记正常引导完成。可以保存退出，不要求用空白想法凑数。

再次显示每条画像的可见性和三种阅读视图，用户可最后修改。沿用第 5 步已保存的选择，不重置到默认，不把所有条目批量公开。若有改动，依共享契约分别确认画像版本和各想法版本；部分保存失败时清楚指出失败对象，不宣称全部保存成功，也不回滚已成功的用户修改。

“保存画像与想法，准备推荐”明确只保存所选数据；发布到活动或广场是另外的用户动作。推荐可以依据本人的私密想法草稿理解需求，但只向他人展示用户已经允许展示的内容。

第 9 步前复核当前活动：已兑换邀请则复核原资格；多个已加入活动时明确选择；无活动时提供邀请码/邀请入口和“先去广场”。活动偏好在此用简短表单补齐或确认，并明确询问“允许本活动成员发现我”；新成员发现开关默认关闭，只有本人确认才经 discovery-settings 开启，关闭也可浏览本人有权访问的活动内容。新想法是否关联当前活动由用户明确选择，不能因为切换活动把全部长期想法自动搬过去。

### 第 9 步：在本活动寻找同频者

文案“正在本活动中寻找可以交流的人和想法”。后端先校验当前活动、预算和候选权限，再筛选与生成推荐解释。可先显示处理阶段和已保存的本人需求，不把未完成精排的候选当作最终结果。预算不足明确报错，用户可主动进入零 LLM 普通发现；不为等待摘要重新生成整份画像。

前端使用 **POST /api/v1/events/{event_id}/recommendation-runs** 创建本次推荐，使用 **GET /api/v1/recommendation-runs/{id}** 获取状态与结果。重复刷新恢复已有有效 run，不自动再创建任务。参数、幂等、进度订阅及错误结构遵循共享契约。

切换活动增加客户端上下文版本，并取消订阅或废弃旧展示；服务端仍独立检查权限。旧活动的结果、详情或摘要晚到也不能填入新活动。无有效活动不发推荐请求；服务故障与成功但零结果分开显示。

### 第 10 步：卡片、好友申请与进入应用

复用登录舞台背景，展示当前活动内 3–5 张人物/想法卡。少于 3 张按真实数量展示；零结果给出友好说明，不从其他活动补齐。卡片标注类型、依据和待确认点，提供略过、详情、添加好友和“进入应用”。

人物卡“添加好友”打开首条消息编辑页，结构化模板只作草稿；用户主动选择“帮我改写”才调用 AI。页面显示接收人、来源活动、首条消息及两种预览：“对方现在能看到的”“成为好友后能看到的”。普通画像预览来自既定 visibility，不为这次好友关系重新勾选一套画像授权。

联系人独立选择，默认不因发申请而自动共享；是否在好友成立后分享指定联系方式遵循联系人契约。用户点击发送后，通过 **POST /api/v1/connection-requests** 创建申请，来源为 **source_type=event_card**。后端验证卡片来源与接收人，不能信任模型提供的任意 user_id。

想法卡分别提供“关注想法”“申请加入讨论”“向发起者添加好友”。关注不等于入群，入群不等于好友；发起好友申请必须指向明确的人。广场头像使用同一个申请界面和普通业务接口，来源为 **source_type=public_post**，允许跨活动，不能误加同活动校验。

收到申请时，接收人看到首条消息和 authenticated 画像，接受请求携带当前 **expected_version**，只有服务端确认双方同意并建立好友后才开放 friends 画像及已选联系人。重复提交、对方撤回或已处理时刷新真实状态，不在本地假定成功。

好友成立事件触发电路接通弹窗。事件按通知标识去重，不能把活动 event_id 当通知标识；断线重连不能反复播放。提供“开始聊天”“查看好友资料”，动效可关闭。申请等待、拒绝或无人可推荐均不阻挡进入应用。

## 5. 保存、任务与返回恢复

### 5.1 三种状态独立保存

| 状态 | 权威来源 | 前端职责 |
|---|---|---|
| 引导阶段、题号、问题批次 | 后端引导会话 | 刷新后恢复；路由参数不能越过后端前置条件 |
| 资料、画像、答案、想法版本 | 各领域草稿与确认版本 | 展示保存状态；确认动作携带预期版本；不让 AI 直接覆盖 |
| AI 执行及适用性 | AIJob | 展示真实任务状态；只采用仍适用、校验通过的输出 |

编辑态显示“保存中 / 已保存 / 保存失败 / 版本冲突”。输入停止或失焦可触发草稿保存；下一步等待必要保存完成。网络失败保留本页输入并允许重试；离开未保存页面时提示。原始简历、完整画像、答案和联系人不写入 URL、分析埋点或持久浏览器缓存。

多标签页冲突不自动覆盖，以当前服务端版本和本地未保存内容供用户比较；重新读取成功也不能悄悄丢弃正在输入的文字。登录失效后重新登录恢复服务端草稿；退出登录清除客户端账号数据。

### 5.2 AIJob 的两维状态

| 字段 | 值 | 展示与动作 |
|---|---|---|
| execution_status | queued | 排队中，可离开或取消 |
| execution_status | running | 显示真实阶段，不承诺虚构百分比 |
| execution_status | succeeded | 仍须检查 applicability，成功不等于可以采用 |
| execution_status | failed | 提示可理解的原因；重试或手动继续 |
| execution_status | cancelled | 已取消，不等待旧响应完成动画 |
| applicability | current | 输入、来源与权限仍适用，用户可查看确认 |
| applicability | superseded | 输入已有新版本，旧结果不自动采用 |
| applicability | revoked | 来源或授权已撤回，不能继续展示/采用旧结果 |

例如 succeeded + superseded 显示“资料已经更新，这份整理结果未采用”；succeeded + revoked 显示“来源授权已变更，请重新选择资料”。是否保留可审阅的历史内容由权限服务决定，前端不能将已撤回结果留作备用正文。

SSE/实时订阅失效时按共享契约轮询并显示连接状态，不把连接中断当作任务失败。重新进入页面只恢复任务，不隐式重试调用 AI；重试必须由本人动作触发。

## 6. 异常与空状态文案

| 情况 | 提示 | 可执行动作 |
|---|---|---|
| 某资料无法解析 | 这份资料暂时无法读取，其他资料已经保留。 | 重试此项 / 粘贴文字 / 用成功资料继续 |
| 用户拒绝第三方 AI 处理 | 你可以手动填写，之后也能重新选择整理。 | 手动编辑 |
| 画像保存冲突 | 另一处已经更新了资料，请比较后再保存。 | 查看新版本 / 保留本地修改重新提交 |
| 邀请失效或无活动 | 先加入一个活动，才能查看其中的人和想法。 | 输入有效邀请 / 先去广场 |
| 只有 1–2 张候选 | 先看看这些与你有交集的人和想法。 | 如实展示 |
| 当前活动零候选 | 你的方向很有特点，这个活动里暂时还没找到合适连接。 | 进入应用 / 修改想法 |
| 推荐出错 | 这次寻找没有完成，你的资料已经保存。 | 重试 / 进入应用 |
| AI 摘要失败 | AI 推荐未完成，你的资料已经保存。 | 主动进入普通发现 / 重试，不自动展示规则卡冒充成功 |
| 平台 AI 预算不足 | 这次 AI 推荐暂不可用，你的资料已经保存。 | 主动选择普通发现 / 进入应用，不自动降级 |
| 申请待回复 | 好友申请已发送，回复后会通知你。 | 进入应用 |
| 对方未接受或申请已过期 | 这次好友关系没有建立，可以继续发现。 | 继续浏览；不公开拒绝原因 |

冻结稿中的原句不修改；本表是实现文案。后台错误不能被包装成“你太独特，所以没有人适合”。

## 7. 个人中心的独立重入

| 入口 | 复用步骤 | 更新边界 |
|---|---|---|
| 修改资料/添加来源 | 1–3，需要时 5 | 本人启动；旧确认版本持续生效；新 AI 输出先为草稿 |
| 修改偏好 | 4–5 | 直接改已有答案不逐题调模型；明确重新生成才创建新批次 |
| 修改活动偏好 | 活动确认表单 | 只改所选活动，不写回全局协作偏好 |
| 修改条目可见性 | 5、8 的控件 | 普通保存，影响所有符合受众条件的读取，不需 AI |
| 新建或修改想法 | 6–8 | 仅处理所选想法，不重写画像和其他想法 |
| 预览展示页 | 5、8 的预览 | 非好友登录用户、好友、本人三种视图 |
| 重新寻找 | 9–10 | 验证当前活动并由本人启动新 run |
| 管理联系人共享 | 联系人管理 | 与普通画像分开；撤回阻止之后读取，不能追回对方已保存的信息 |

资料不因久未使用自动失效；不设置每日/每周画像刷新。本人修改上游资料后可以提示下游内容可能待更新，但不会静默调用 AI、重新发消息或重放整个开场。

## 8. 移动端与可访问性

手机按单屏任务逐步展开，底部主要动作避开安全区和键盘；PC 保持居中的表单宽度，允许章节导航与预览并列。来源和想法卡片纵向排列，不把全部输入压成桌面多列表格。

所有输入有可读标签，单选/多选与可见性控件支持键盘。切换题目或加载完成后将焦点移到新标题，不能回到页顶；错误摘要链接到具体字段。任务进度只在阶段变化时适度播报，装饰背景不进入读屏顺序。拖拽、滑卡和动画均有按钮替代；颜色不单独承担私密/公开和成功/失败的含义。

## 9. 交付验收

- GitHub 与邮箱验证码均可完成登录；邀请回跳恢复，过期邀请不会破坏账号和草稿。
- 简历上传和 GitHub 导入位于首个资料页面顶部且首期可用；GitHub 首次登录自动关联来源，不再粘贴主页；第 3 步默认预填并补缺，手填为兜底，未知能力不虚构。
- 问题正常一次生成 3–8 题，刷新、返回和网络重连不换批次、不重复计费；其他选项和不回答均有明确状态。
- 全局偏好与活动投入分开保存；先答题后加入活动不会把活动字段混入永久画像。
- 第 5、8 步均能逐条设置三种 visibility 并预览；普通画像对全部好友统一生效，没有隐含的每好友授权。
- 跨活动登录用户通过公开帖子可见 authenticated 条目；非好友读不到 friends，任何他人读不到 private 和原始材料；未登录用户看不到 authenticated 画像。
- 资料私密保存且没有自动到期刷新；重新登录、打开个人中心和切换活动均不会自动重跑画像 AI。
- 多想法独立保存，部分失败明确定位；保存草稿不自动发活动或广场帖；关注、入群、好友三个动作不互相代替。
- 每种 AI 执行状态与 applicability 组合正确处理；已取代或撤回的结果不覆盖用户版本。
- 无活动不运行发现；候选少或为零均如实显示；切换活动后旧卡片和摘要不能出现。
- 用户点击确认发送后才发首条消息；接受绑定 expected_version；重复通知只产生一次成功反馈。
- 刷新、返回、登录失效、多标签冲突和手机键盘场景不丢已保存内容；减少动效和键盘操作可完成全流程。
- 冻结原稿未改变；接口细节、错误码和字段结构只维护在共享契约中，本文件的验收用例纳入 [联调验收](联调验收与交付路线.md)。
- 首日用户可保存退出后返回原步骤、发布想法并开放讨论、发送合法作品链接；没有注册时长等待。
- 同活动/跨活动公开帖两种入口的预览分别计算活动资格；好友视角不泄露另一活动字段。
